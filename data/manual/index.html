Zene Studio

Zene Studio is a music workstation built around one main window: the arrangement in the middle, the browser on the left, the Inspector on the right and the editors and the mixer below. Three views arrange these panels for the job at hand - Arrange, Mix and Edit (Alt+1 to Alt+3). Everything a click does is also a named command, so a script, an agent or a controller can do it too. Changes to the project can be undone (Edit > Undo, or Window > Undo History); actions outside it - files written to disk, messages sent to hardware - cannot.

Hover over a control to see what it does; press Shift+F1 (Help > What's This?) and click a control for its full description. Help > Command Reference lists every command with its arguments, and the Command Palette finds any menu item or command by name: Enter runs it, or opens its settings when it has any, Shift+Enter runs it with its defaults, and a command that cannot be undone is marked; Help > Keyboard Shortcuts lists every shortcut, and Project tools > Customise > Keyboard Shortcuts changes them.

One key, four contexts. A shortcut can belong to the arranger, the note editor, the automation editor or Perform instead of the whole window: the Keyboard Shortcuts list gives every row an action and a context, so you can give Ctrl+Alt+J to the arranger's Knife tool, the note editor's Erase tool, the automation editor's Erase mode and Perform's Stop All at once. Only the panel holding the keyboard acts on it - focus the arranger and the arranger's meaning runs, focus the note editor and the note editor's does - and a panel's own keys (P/B/D in the note editor, Shift+D/E/C/T in the automation editor, the digits and Escape in Perform) keep working until you bind a scoped action over them. A clash is two actions of the SAME context on one key: the list marks it, Set Keys refuses it until you turn on Force, which moves the key there and unbinds the other action of that context only - a binding in another context is never touched. The choices are saved with your configuration, so they are there at the next start.

Plug-ins from the keyboard. Every context's list has Open Selected Track's Editor (the track's instrument, or on a track with no instrument its first effect) and Open Selected Track's First Effect: give either a key and it opens that device of the track selected when you press it - the plug-in's own window when it has one, otherwise Zene's view of it. To load a plug-in from a key, press Bind a Plug-in... in Keyboard Shortcuts, choose the context, the plug-in and the key. Pressing it loads that plug-in onto the selected track or mixer channel, as adding it by hand does: an effect goes at the end of the chain and Undo removes it; an instrument replaces the track's instrument, which cannot be undone. A target that cannot take it (an instrument on a sample track, anything on an automation track, or nothing selected) loads nothing and a message says why. The same actions are in Project tools > Selected Track, and the binding's row takes Set Keys and Unbind like any other, where Unbind removes it from the list.

Quick start

Six short guides, in the order most projects need them. Each names the controls and menu paths it uses, links to the area reference below, and points at the command an agent sends for the same job. The Find field searches all of this text.

Make a first beat

  1. Open the Browser and drag an instrument onto the arrangement, or use the Add track to button on the Song Editor's track toolbar (track.add).
  2. Double-click the track at bar 1 to make a MIDI clip, then double-click the clip to open the note editor (note.add).
  3. Draw a kick and a snare with the pencil; Space plays and stops.
  4. Take the tour: Help > Tours > Your first beat (app.tour, tour first-beat).

Reference: Arranging, Editing notes.

Arrange clips

  1. Drag clips to move them and their edges to trim; one drag is one undo step.
  2. Choose the Range tool, drag over the tracks, then split, delete, crop, fade or bounce from Navigate > Range.
  3. Use arrangement.get_state to read positions and lengths, and clip.move or clip.resize to make the same edit from an agent.

Reference: Arranging.

Edit notes

  1. Open a MIDI clip in the note editor and pick the draw, paint, delete or select tool from its toolbar.
  2. Notes > Quantise, Transpose, Scale and Transform change the selection; the lanes below edit per-note expression.
  3. From the keyboard, Alt+Left/Right walks the notes and Shift adds; note.edit writes a validated batch as one undo step.

Reference: Editing notes.

Add an instrument or effect

  1. Drag an instrument from the Browser to a track, or choose it in the track's instrument window (plugin.load).
  2. Drag an effect onto a mixer strip or into the Device panel's chain; right-click a device to insert, copy or bypass it.
  3. The selected channel's rack and macros are in the Device panel; plugin.load is the agent route to the same chain.

Reference: Devices, Mixing.

Record and comp takes

  1. Arm a track with the round button in its header (track.set_arm) and choose its input in the track's Record menu.
  2. Press Record (or R); Record > Count-In and Pre-Roll start early, and Record Mode chooses overdub or replace.
  3. Looped passes become take lanes in the Inspector. Drag along a lane to comp a range, or double-click to cycle the take there.
  4. The recording tour is Help > Tours > Recording (tour recording).

Reference: Recording.

Mix, export and hand off

  1. Open Mix (Alt+2). Each strip has trim, pan, sends, inserts and a meter; right-click for its Strip, Listen and Mixer View menus.
  2. Read the mix with mixer.get_state, then export from File > Export (render.render).
  3. Mixing tour: Help > Tours > Mixing (tour mixing). Projects are ordinary files; the command reference lists the save and render commands.

Reference: Mixing, Projects.

The window

  • Header - transport (play, stop, record), tempo, time signature, position, the master level, the transpose, the CPU load and the loudness readout. Right-click it to choose which buttons it shows. Right-click the CPU readout and choose CPU diagnostics... to see what the load is made of: every instrument track's own synthesis share of the audio period - the instrument alone, apart from its mixer channel and effects (several cores working at once can take it past 100%) - and the late periods, the renders that took longer than the period lasts, each at the bar.beat it started at, newest first. A late period is the engine missing its deadline, not the audio device reporting an xrun. The window refreshes twice a second and shows exactly what agents read from mixer.cpu_load (its tracks and late_periods); track.overview gives each instrument track's synthesis_cpu_percent beside its channel's cpu_percent. Below them, Audio device shows whether the device's timing plays a part: the backend, the engine's own sample rate and period, and what the device negotiated - its output sample rate, the input's own sample rate (a separately chosen ALSA capture interface can run at a different rate; input latency is timed at it), period and buffer in frames, its input and output latency (frames, milliseconds and what the figure is read from: JACK's port latency ranges, or ALSA's playback buffer and, while capture is open, one capture period) - and the device's own xruns (JACK's xrun notifications, ALSA's playback underruns), counted apart from the engine's late periods. A reading the backend does not report says unavailable, never 0: JACK does not say how many periods it queues, and with no audio device (the Dummy) every device reading is unavailable while the CPU and late-period readings carry on. Agents read the same state as mixer.cpu_load's audio_device, each reading {available, value, unit}. The readings are live only: nothing is saved with the project. Pressing Play hands the period's work to the worker threads and wakes any that are asleep; that wake is a single atomic word, so it never waits for a lock or allocates, on macOS as on every other platform. On the Apple build the supported floor is macOS 10.13 (High Sierra); a build for a newer macOS runs the same wake.
  • Footer - a switch for each panel, grouped by where it opens, Tools (every tool that opens in a window of its own: controller rack, project notes, scales and keymaps, undo history, tempo map and more), and the views. Narrower, the switches show icons only, and the ones that still don't fit are under More; the header's right-hand buttons do the same. An area that holds several panels shows a tab for each: click one, or use the arrow keys, to open it, and use the cross to hide the area.
  • Browser - devices, presets, samples and projects. Search is the first control and filters the current tab as you type; Up and Down move the highlight, Enter loads the highlighted result (Shift+Enter puts a sample on a sample track) and Ctrl+F jumps to it. A click or Space previews, and the preview stops when you pick another result, change the query, tab or location, or leave the Browser. The Search source finds files across the library: every word must match (kick 808 finds items with both), kick OR snare, -loop excludes, "bass drum" is a phrase, and tag: kind: name: path: ext: narrow a word. Beside the field, Kind, Where to look and Category narrow by what the files are, where they sit and how you classified them - pick a category a file carries, or Any category to see everything again - and Whole library searches the built index instead of walking the folders. Right-click a result and use the Category submenu to give a file its one category. A Tempo row under them narrows the audio files to a BPM range (leave a side at Any for an open end) and a Key picker narrows to one key; both read the tempo and key the library index measured when it scanned the files (Rescan Library measures new ones), and a file whose tempo or key is not known is never listed by an active filter - unknown is not a value. The filters combine (tempo and key and category and tags) and work in Whole library mode too, answering the same files; the agent commands browser.query and browser.index_query take the same tempo_min, tempo_max and key arguments, and a saved collection keeps them. The Search file metadata checkbox also matches what the audio files themselves say rather than just their names - the embedded title, artist, album, comment and genre tags, and the sample rate, channel count, length in frames and duration (so 44100 for 44.1 kHz or 0.116 for a 116 ms file finds files by those values, not just by name). It opens at most 200 files per search to read that data, and the result says how many it read; a library wider than that is best narrowed with kind:, a tag or a folder until the audio candidates fit. Probing reads only the file headers, not the audio. The checkbox is unavailable while Whole library is on, because the whole-library index stores names and tags but not embedded metadata. Save a search as a collection to keep it; Project Media lists every file the saved project references with a Uses count (every clip and supported instrument reference adds one) and a state: used, unused, missing, external or unresolved. Unused Only keeps the unreferenced files in the project's media/ folder visible beside the missing and external references that are never cleanup candidates. Select unused rows and choose Clean Up Selected...: the exact paths are shown and must be confirmed, and the cleanup rescans the saved project immediately before removing anything, so a file that is referenced again is refused. Cleanup is irreversible - a removed media file cannot be restored by undo - and it refuses while the open project has unsaved changes, because the scan reads the saved document. A file dragged out of the Browser - from its list or a search result - carries the file itself as well, so a plug-in editor's window, the desktop or a file manager that takes files receives the file, while Zene's own drop targets (a sample clip, a track, the session grid) load it as they always did.
  • Inspector - the selected track, clip or mixer channel: its settings, its sends and inserts, its take lanes.
  • Device panel - the devices of the selected track or channel as cards, with the rack's macro knobs.

Arranging

Drag clips to move them; drag their edges to trim. Choose a range with the Range tool (Navigate > Arranger Tool > Range: drag over the tracks; the Smart tool does the same from a clip's upper half), then split, delete, crop, fade or bounce it from Navigate > Range. A clip dragged onto another trims it (Navigate > Overlap chooses trim, crossfade or free), and before you let go the arranger shows what will be cut and what the clip snaps to. A locked clip can be selected but not moved, trimmed or deleted - a padlock marks it. Sections, markers and tempo have lanes of their own under the bar ruler (right-click them to show or hide one); a pinch or Ctrl+wheel zooms around the pointer, the zoom keys around the selection or the play position. Ctrl+wheel zooms smoothly - a touchpad as finely as you turn it. Where labels would overlap they are shortened or left out; hover to read them. Double-click a section or a marker in its lane to zoom to it. Drag a section's block (the hand cursor) to move the section and its material on every track, with clips crossing its edges cut there: on Gap the rest stays where it is, leaving a gap at the source; on Ripple what the section passes moves the other way by its length, so the song is reordered with no gap. Right-click the lanes to choose (it is the Ripple mode of Navigate), hold Shift while dropping for the other one, or Alt for no snap. One undo puts everything back. Navigate holds the zoom, the zoom history, markers, ripple and overlap modes; Alt+arrows nudge and select clips. Navigate > Zoom Back steps to an earlier zoom extent and Navigate > Zoom Forward steps back over extents Zoom Back passed, like the browser's back and forward, so several prior zooms can be walked through; a new zoom cuts the forward walk off. Navigate > Zoom Toggle swaps the current zoom with the extent just left, so pressing it twice returns to where you were; unlike Zoom Back and Zoom Forward it does not walk the history. The same three actions are the agent commands arrangement.zoom_back, arrangement.zoom_forward and arrangement.zoom_toggle. Navigate > Range also holds Render Selection..., which renders the selected range to a file at its exact start and end, and Export Sections..., which writes one file per named section, each bounded to its own ticks. A file is named after its section with characters a filesystem refuses (/ \ : * ? " < > |) removed and leading dots dropped; trailing dots and spaces become one _, and a Windows-reserved name (CON, PRN, AUX, NUL, COM1-9, LPT1-9, even with an extension) gets a _ added (CON.wav becomes CON_.wav), so the same project writes the same file names on every system. Two sections whose names match when capitals and accents-versus-composed letters are ignored (Intro and intro) would be one file on Windows and macOS, so the later one gets -2 (intro-2.wav), the next -3, and a section really named intro-2 is moved on to intro-2-2. The Project > Export... dialog carries a Render preset picker: choose a saved preset, or Save Preset... to store the settings shown; the chosen preset sets the render's file format, sample rate, bit depth, channels and stereo mode, and a stem export (Export Tracks...) follows it too. Drop a MIDI file or an audio file on the arranger - from a plug-in editor's window, the desktop or a file manager - to make a clip of it: on a track's lane, on a clip or on a track's name (the clip starts where you let go, on the grid), or on the empty space below the tracks, which adds a new track for it. A MIDI file becomes one MIDI clip on an instrument track (all its channels and tracks together; its tempo is not used); an audio file becomes a sample clip on a sample track. One drop is one undo step. A file that cannot be used - missing, empty, damaged, not MIDI or audio this build reads, a MIDI file that would run past the end of the song, or the wrong kind for the track - is refused with a message in the status bar and nothing in the project changes. Only the first file of several dropped together is used. Audio that a plug-in leaves in the system's temporary folder is copied into the clip, so it survives the plug-in deleting it; other audio stays a link to its file. The same action is the agent command clip.import_file.

A dropped audio file - from the desktop, a plug-in editor or the browser onto a sample track - is analysed for its tempo and key, and the status bar says what was found (for example "Detected 100.3 BPM, A Major"). With Edit > Auto-Warp Dropped Loops checked the new clip follows the project: it is played at the project tempo from its detected tempo (rounded to a whole BPM, the pitch kept), so a four-bar loop fills four bars at any project tempo, and when the project has a key (a sample clip's Warp menu, Detect and Apply to Project..., sets one) the clip is transposed the nearest way so its tonic is the project's - an A loop in a C project goes up 3 semitones. Unchecked, the clip keeps its own speed and pitch, as before; the detected values are still kept with it. Hold Alt while dropping to take the other choice for that one drop; the setting stays as it is. The project's own tempo and key never change, the match is made once when the clip is created (changing the project key later does not retune it), and what could not be applied - no tempo or key found, a project without a key, a build without Rubber Band for the transpose - is said in the message instead of guessed. One undo removes the clip and its new track. Agents do the same with clip.import_file and its loop_mode (follow_project, keep_unstretched or preference), set the remembered choice with settings.set on import/loopwarp, and read a clip's detected and applied values with clip.source_get_state.

Sample clips show fade handles near their top corners and, with Navigate > Show Transients, their transients. A sample clip's own gain is the square handle on its left edge: drag it up or down and the clip's level follows the pointer while you drag, the drawn waveform growing or shrinking with it; let go and the new level is one undo step (the agent command clip.set_gain). The dashed line across the clip is that gain. Click the drawn level line - the dashed gain line, or the envelope once it has points - to add a gain-envelope point there and drag it: the point moves in time and in level, and points can be dragged past each other, with the waveform between them following the curve as the audio does (clip.gain_envelope_set). A plain press within reach of an existing point takes and moves it. No modifier is needed for any of this, so Alt and Ctrl keep their arranger meanings on a clip (unsnapped move or resize, and copy on macOS). The Gain and fades submenu also lists Invert polarity, which renders the clip with its sign flipped and mirrors its drawn waveform, while the source sample keeps every sample it had (clip.set_polarity); all of these are in the Gain and fades submenu besides the drags. A sample clip can carry realtime effects of its own: right-click it and choose Clip effects.... The window lists the clip's effects in the order they process, each with On or Bypassed and its parameter values. Add effect... picks a device from the same catalogue the track's chain uses, Move up and Move down reorder, Bypass (or Turn on) switches the selected effect without removing it, Remove takes it off, and double-clicking a parameter sets a new value. Each change is one undo step. The effects process this clip only, live and without changing its audio: another clip on the same track, even where the two overlap, is not affected, and the track's own effects still run on the sum afterwards. A clip with effects shows FX in its bottom-right corner (with the count when it has more than one), and the menu item says how many it has. The effects, their settings, their order and their bypass state are saved with the project, and copies, splits and duplicates of the clip carry their own copy. Agents use the plugin commands with the clip as the target (plugin.load, plugin.move, plugin.bypass, plugin.param_set, plugin.unload with target clip-<n>) and read the chain with dsp.get_state. Limits: MIDI and pattern clips have no clip effects; an effect's tail stops when the clip's playback ends; a clip effect's latency is not compensated; a Process edit changes the clip's source audio and leaves its clip effects in place, running on the result; and Consolidate renders the clips' source audio without their clip effects, so the consolidated clip has none (one undo brings the original clips and their effects back). A sample track's More menu (on its header, or the Inspector's) has Insert Test Signal...: it opens the sample.generate command's form with that track set and a tone at position 0 and length 192 ticks filled in, and Run makes a new sample clip from it - one undo step removes the clip and its audio. Change the position, length, kind (tone, white noise, pink noise or silence), frequency or level in the form first if you want something else; the same command is what a script or an agent calls. A sample clip's Process menu bakes a change into its audio - Normalize, Amplify, Reverse, Fade in or out - each on the whole source and each one undo step (the Sample Editor is where a range is edited). Project > Sections names the song's parts (verse, chorus) as bands over the ruler and selects one as the range; Clip List finds a clip by name; Next and Previous Transient move the play position through the audio's hits. A clip's Sample Editor... (its menu) raises or lowers by 3 dB, silences, deletes, reverses, fades or crops a selection of its audio; Split to stems (a sample clip's menu) separates its audio into stems on tracks of their own. A split runs at one of three qualities - fast, standard or high - which set how much the model's overlapping passes over the audio overlap (25 %, 50 % or 75 %): high takes about twice as long as standard and fast about two thirds of it. Measured on the real model over four 30-second excerpts of test songs with known stems, high separated 0.05 dB better than standard on average (signal-to-distortion ratio) and fast 0.11 dB worse. These are small differences, and high was not better on every song, so standard is a sound default; choose fast for quick drafts and high when the extra time does not matter. Split to stems is a submenu: pick Fast, Standard or High quality and the split starts at it (the one you used last is ticked; standard until you choose another). The progress window and the message at the end name the quality the job actually ran at, and the original clip stays on its track, unchanged, next to the new stem tracks. The menu goes through the same command an agent uses: the quality argument of stem.job_start, and stem.job_status shows the quality a job runs at. A sample clip's Process menu also converts its whole source to mono with (L + R) / 2 on both sides (one undo step), or writes its left and right channels as two mono WAV files at the source rate and length (Split Stereo to Two Mono Files..., which leaves the clip unchanged). A sample clip's menu removes its silent stretches, crops its sample to what it plays, makes it unique, converts its melody to MIDI notes or splits it at the play position. A crossfade's two sides can have their own lengths and shapes. A folder's row draws its children's clips as summary clips. Click one to select it, Shift+click for several; clips Ctrl+clicked in the arranger are edited with them, a clip reached twice changing once. Drag a summary clip's edge to resize it: outwards, the clips at that edge follow; inwards, the clips crossing the new edge are cut and those past it removed. Its menu splits it at the pointer, across the child tracks and sub-folders. Each edit is one undo step. With summary clips selected, Ctrl+Alt+Left/Right resizes their end (hold Shift to resize their start), Ctrl+Alt+K splits at the play position, Ctrl+Alt+Page Up/Down moves them, Delete removes them and Escape deselects them; Ctrl+Alt+G selects the summary clip at the play position (Shift adds). Moving a folder track moves every clip inside it. A clip's Snap Point (its menu) is the place inside it that lands on the grid when you drag it - a downbeat after a pickup. Navigate > Show Navigator puts the whole song in a strip under the arranger: click or drag in it to scroll, turn the wheel to zoom; it names the sections and shows the markers, the loop and the play position, and Alt-click or a double-click on one zooms the arranger to it. Navigate > Second Tool on a Modifier Key gives Alt, Ctrl or Shift a tool of its own while held. A focused track header's Menu or Shift+F10 opens its actions menu; the time ruler's opens the loop menu at the play position. Track > Versions keeps several versions of a track's clips and switches between them. An audio clip's Speed menu ramps its speed (the pitch going with it) or adds a tape start or a tape stop.

Splits and trims can land on an exact sample, and with Navigate > Snap Cuts to Zero Crossings on, the knife and an edge drag move to the nearest zero crossing so the cut does not click. A track's menu adds a spacer below it (Add Spacer Below): an empty band that separates groups of tracks and moves with the track.

Long jobs run in the background so the window stays usable: plug-in scans, renders in the render queue, stem splits (the source is decoded and resampled in the background too, and a recorded or pasted clip is prepared there first) and the waveform of a long sample selected in the browser. Each appears in the Tasks list in the status bar with its progress and Cancel; selecting another sample stops the waveform read in progress, and a cancelled job leaves the project and your files as they were. Agents follow the same jobs with app.tasks and stop them with app.task_cancel; browser.peaks_start starts a waveform read.

Sample Editor (a clip's menu, Sample Editor...): drag across the waveform to select a range, or drag the [ and ] handles at its edges. Start, End and Length show the range in the unit Units picks - time from the source's start, bars and beats at the song's tempo from the clip's start, or samples - and can be typed into (Enter applies; a suffix such as s, smp or bars overrides the unit) or stepped with Up and Down. End is the first frame after the range. Ctrl+wheel zooms the waveform around the pointer, the wheel scrolls it, and Zoom In, Zoom Out, Zoom to Selection and Show All do the same from the keyboard. Each range operation edits only the range the fields show, as one undo step; the line under the buttons says what was done, or why it was refused. The range buttons are -3 dB, +3 dB, Silence, Delete, Reverse, Fade In, Fade Out and Crop: Silence keeps the range's length, Delete closes the gap so what followed the range moves earlier, and Crop keeps only the range. Range gain applies no limiter and the two fades are linear; there is no noise reduction among these range tools. To Mono and Split Stereo... act on the whole source instead: the first bakes the documented (L + R) / 2 downmix, the second asks for two destinations and writes the left and right channels as mono WAV files. The Process menu's Normalize..., Amplify..., Reverse and Fade are separate whole-source bakes, and Crop the Sample discards the audio outside the clip's play window.

A warped sample clip's menu has a Warp mode submenu that picks how the clip fills its warped length. Besides Beats, Tones, Texture, Re-Pitch, Complex and the WSOLA stretch it offers two transient modes: Repeat transients plays each piece of the clip from one transient to the next at its own speed and pitch, and starts it again from its transient at every repeat interval until the next transient's turn comes; Gate transients plays each piece once and cuts it off at the first interval. Either way the clip lasts exactly its warped length; at the end of the clip the last interval is simply cut short. Warp mode > Repeat rate sets the interval: Synced 1/4, 1/8, 1/16 (the default) or 1/32 of a whole note follows the song's tempo, so 1/8 is 250 ms at 120 BPM and 500 ms at 60 BPM; Free 50, 100, 250 or 500 ms stays the same at any tempo. The rate is kept when you change modes, it is saved with the project, and each change is one undo step. The clip's transients are found when you choose one of the two modes (the same detector the transient tools use). Agents use the same command, warp.stretch with mode repeat or gate and rate_division (1/1 to 1/32) or rate_ms (5 to 2000); warp.list reports repeat_rate (including the interval in milliseconds at the current tempo) and transient_count. A clip with no warp markers and no source tempo has nothing to fill, so the two modes are refused for it, as the other pitch-keeping modes are.

Edit > Tempo Map... lists the song's tempo and metre changes: add, remove and ramp them, or import and export them as a Standard MIDI File.

Edit > Progression... lists the named progressions and spells each one out in the selected scale and key; Write puts the chosen progression into the selected MIDI clip as notes, as one undo step.

Automation can be switched off for reading or writing across the whole song (Project > Automation Read / Write), and writes can be limited to the punch region. A control's trim offsets its automation without changing the curve. Before an automation clip's first point the controlled parameter holds its authored initial value (or the point you drew at the clip's start), so starting at the beginning and returning there give the same value every time; a clip saved with a later first point keeps that value when the project is reopened. A trim (relative) clip is not affected: before its first point it adds the same offset as before.

Automation lanes sit under the track they automate. Adding a lane to a track (the agent command automation.lane_add) draws it as an indented child row directly beneath its owner, however the tracks are reordered: moving the owner moves the lane with it, and a lane whose owner is gone keeps a row of its own so it can still be reached. A track that owns lanes shows a small triangle in its header; click it, or choose Fold automation lanes (Unfold automation lanes) in the track's Actions menu, to fold its lanes out of sight and bring them back - the agent command automation.lanes_set_collapsed does the same, and folding is one undo step. Hiding the owner, or collapsing the folder it is in, hides its lanes as well; showing it brings them back. Select a lane's clip by clicking it and double-click it to open the automation editor and edit its points. Deleting the owner deletes its lanes in the same undo step, and undo brings the owner and its lanes back together. The fold is saved with the track; a project saved before lanes could be folded opens with every lane shown. automation.get_state reports each lane's owner (follows) and each track's lane count and folded state, the same state the arranger draws.

Automation clips that carry a curve (Linear or CubicHermite) render at sample precision by default, so the curve reaches the mixer, effect chains and instrument tracks at every frame inside an audio block. Discrete clips keep their per-tick step, and a CubicHermite curve is approximated as one straight segment per tick. Each audio block's ramp holds 32 knots; a block that needs more has the surplus knots refused and counted (automation.ramp_get reports refused_knots), and a clip in a pattern is refused by automation.ramp_set because a pattern has no single block timeline. A project file's sample_accurate attribute or automation.ramp_set is the only way to set it; there is no interface toggle.

Editing notes

Double-click a MIDI clip to open it in the note editor. Opening a clip fits its length to the view and its used pitches with a little room; a very wide range stays centred at the smallest readable row, and an empty clip opens around C5. With Draw, a translucent note previews the click under the pointer, and dragging up or down while drawing moves the preview, the audition and the note to that pitch. The note area's cursor names the next action (draw, erase, slice or play), and choosing a tool from the toolbar or its letter shows it at once. The tools follow FL Studio's piano roll: P draw, B paint, D delete, T mute, C slice, E select, Y play, Z zooms to the selection (1-7 also pick them). With any tool the right button deletes every note it crosses (one undo step); a double-click on a note opens its properties; Ctrl selects (Ctrl+Shift adds), Shift and Ctrl lock pitch and timing while dragging, Alt bypasses the grid and Alt+wheel changes velocity; a new note takes the last note's length; Ctrl+C, X, V and B copy, cut, paste and duplicate; the lanes below edit velocity, pan, chance, timbre, pressure, micro-pitch, release velocity, velocity spread and repeats, and the clip's controller curves. The Notes menu quantises, transposes, scales, strums and transforms; Pitch Curve draws a bend on each note. Notes > Tools inverts, arpeggiates, flams, repeats, moves notes a degree up or down in the key, makes them follow the chord track, writes a Euclidean rhythm, moves notes to another track, splits a drum loop into a track per key and detects the key. Group keeps notes together when you select them; Lyrics lays syllables on the notes ("Hal-le-lu-jah"). Play On chooses the passes of the loop a note plays on; the Repeats lane plays a note several times inside its length; the Velocity Spread lane varies its velocity each time. Articulation picks one of the track's articulations (Track > Articulations... sets the keyswitch, program or controller each one sends). New Note Length fixes the length a click draws; Audio Behind the Notes shows an audio clip's waveform under them. The controller lane can also hold program changes.

A MIDI clip also reads as a melodic step grid, for agents and scripts: note.step_get_state lists every note by its step (a column of step_ticks ticks, a sixteenth by default), key, velocity, chance and ratchet, says which notes are in the set scale and their degree, and lists each column's stacked pitches. note.step_set edits those cells as one undo step: name a note or a step and key, and give velocity, chance (0 never to 1 always), ratchet (1 to 16 evenly spaced attacks inside the note), length or remove. With a scale set, a new or changed pitch is snapped to the nearest in-scale key (scale_mode snap; strict refuses, off leaves it), and a note that is already out of the scale stays editable. The cells are ordinary notes of the clip, so the piano roll shows the same notes, an old project opens with chance 1 and ratchet 1, and one Undo restores the notes as they were.

CC lanes and device automation. A clip's CC lane and one device parameter of the clip's own track can be turned into each other by an agent (the note editor's menu entry follows in the next release): clip.controllers_to_automation copies a cc:<n> lane onto the parameter's automation - CC 0 to 127 spans the parameter's minimum to maximum - and clip.controllers_from_automation copies the parameter's automation that lies inside the clip back into the lane, rounding to the nearest CC step and adding the curve's value where the clip cuts it. Points keep their place on the song's timeline, including the clip's start offset and an automation clip that starts later. The source stays; the target's points between the first and last converted tick are replaced, and the automation clip is made linear (a CC lane is linear between points). parameter may be left out only when it names one candidate; otherwise the call is refused and lists them. Pitch bend, aftertouch and program lanes, switches and lists of choices, trim clips, a point that would fall before its automation clip and a non-linear clip with other points outside the span are refused, and a refusal changes nothing. One undo takes a conversion back.

MPE pressure and timbre on the built-in synths. A note's pressure and timbre (CC74) values - from the Pressure and Timbre lanes, from an MPE controller with Edit > MPE Input on, or from note.expression_set - now change the sound of the built-in instruments (Triple Oscillator, Monstro, Organic, Kicker, the AudioFileProcessor sampler and every other instrument that plays each note itself; LB302, OpulenZ, the SF2/GIG/SFZ players and ZynAddSubFX play one stream for all notes and are not affected). Pressure makes that note louder (up to twice its level at full pressure); timbre makes it brighter (up to +12 dB above about 1 kHz at full CC74). Both are neutral at 0, so a note with no expression, or with both at 0, sounds exactly as before, and older projects play unchanged. Live changes move only the note on that MPE channel and glide over one audio block, so they do not click. Hosted plug-ins and MIDI outputs still receive the values as MIDI and choose their own mapping.

Each lane under the notes names what it shows and its scale - for example Velocity, 0 % to 200 %, with the values at its top, middle and bottom on the right. Point at a stem and the lane reads out that note's value and the value at the pointer; while nothing is pointed at, the header shows the selected notes' values. Controller lanes keep MIDI's 0 to 127 (pitch bend: -8192 to +8191 around its centre) and read out the curve's value at the pointer's position. Selected notes have square heads; a note whose key is folded away has a hollow one. A muted note has a dashed outline, a note that may not play a dotted one and its chance in its label, and a very short note can be clicked a little beside it.

Project > Global Swing delays every off-beat 16th (or 8th) of the song; Chase Notes sounds a note playback starts, loops or jumps into the middle of, or one already under the playhead when its track or clip is unmuted; MIDI Playback Offset starts every note a little later, to line up a slow instrument.

Mixing

Each strip has its trim, polarity, mono and pan mode (balance, dual or width), sends with their own pan, inserts and a meter line with the clip light and the gain reduction. Right-click a strip for Speak Meter (Ctrl+Shift+M: its post-fader peak and the master's LUFS-S) and Peak Watch (off, or -18, -12, -6, -3 or 0 dBFS; the input and master each announce a rising crossing once and re-arm after the level falls). More holds its Strip, Listen and Mixer View menus: show or hide sections, change the strip width, show only some channels, switch the meter between peak, RMS and pre-fader. VCA groups have their own strips at the right of the mixer: right-click one for Links (which of level, mute and solo reach its members) and Put Inside (nesting), right-click a mixer channel for VCA group (join a group or make one), and use Project tools > Groups... to rename or remove a group, add and remove its edit-set tracks and switch its phase lock; a clip's menu has Move With Edit Group.... Solo can be exclusive or additive (Mixer View > Solo Mode). A return's Mixer View menu has Show Sends to Here on Faders: every channel's fader then sets its send to that return (Channel Faders goes back). A strip can swap its left and right sides; a send can be switched off and on again and keeps its level; Create a Return makes a bus fed by the channel; Adjust Channels Together moves several faders by the same amount. Project > Pan Law chooses how much a centred signal is cut (none, 3, 4.5 or 6 dB), Control Room > Mono Check folds what you hear to mono, Order the Mixer by Tracks lines the channels up with the tracks, and Find a Channel searches the names. Each send in the Inspector has a meter beside it, and instrument and sample track headers show their level. Mixer View > Compare Channel EQ draws two channels' EQ over each other. Mixer View > Masking Report finds where channels fight over the same frequencies: tick two or more channels, give each a priority (Front, Middle or Back), and press Report. Each clash names the two channels, the frequency range they share and a proposed cut (1 to 6 dB) on the lower-priority channel; at equal priority the channel that is quieter in that range gets the cut. The report reads the audio clips on the tracks playing into each channel, through that channel's own EQ (instrument tracks are not analysed yet), and gives the same answer for the same audio and priorities. Reporting changes nothing: apply a cut yourself with the channel's EQ (Show Console Section) and undo it as usual. Agents use mixer.masking_report. The Control Room (Project menu) switches between three sets of speakers, each with its own trim, and dims, mutes or checks the mix in mono - on what you hear only, never on an export. A channel's "Play Previews Here" sends the browser's previews to it instead of the master. With the keyboard, Tab and Shift+Tab move through a strip's controls and wrap inside it, while Ctrl+Tab and Ctrl+Shift+Tab move to the same control on the next or previous channel and stop at the first and last channel; arrows, Page Up/Down, Home and End adjust a focused fader or knob, and Space toggles Mute or Solo. Every control is announced with its channel's name.

Mixer View > Show Console Section adds a Console section to every strip (it is off by default, and kept between sessions): small knobs for the channel's trim, its EQ (low shelf at 100 Hz, a mid bell and its frequency, high shelf at 8 kHz) and switches for each side's polarity. When the channel carries a Console device (Console Across the Mix puts one on every channel), the section also turns that channel's Console drive and its glue compressor - a switch, threshold, ratio and makeup - and changes that channel only; a channel without a Console says so. A knob's drag is one undo step. The glue compressor is off until you switch it on, so a Console sounds exactly as before. Scripts and agents use mixer.console_strip.

Each strip can show its own meter: the strip's Strip > Meter Mode chooses Peak (after the fader), RMS, Pre-fader, VU or LUFS for that strip alone - Default follows Mixer View > Meter. VU integrates over 300 ms and reads 0 VU for a steady tone at the studio reference (meter.set_reference, -18 dBFS unless you change it); LUFS shows the channel's own short-term loudness and true peak on the strip's meter line. The LUFS field in the transport bar and Large Meters' loudness line are always the master's. Mixer View > Input Meters... shows a meter for every input of your audio interface and, under them, one for each record-armed track's chosen input - whether or not the track monitors it.

Track Delay (an audio or instrument track's menu) and Channel Delay (a channel's Strip menu) move that track or channel later - or, with a negative number, earlier - by a number of samples, shown in the menu entry; the automatic delay compensation keeps everything else lined up. It is saved with the project and one undo puts it back (an instrument track's note delay, which starts notes later, is a separate setting).

Freeze a bus to save the work of playing everything that feeds it: right-click the bus strip and choose Freeze bus. Its output - every track and channel routed to it, through the bus's own trim, devices, VCA and pan - is rendered once to a 32-bit WAV beside the project (in its -bounces folder), and from then on, while the song plays, the bus plays that recording in place of its inputs. Everything after it still works live: its fader, its sends to other buses and to the master, its taps and its meters. Choose Unfreeze bus to hear the live inputs again; nothing about the tracks or the routing was changed, and the recording stays on disk. Both are one undo step, and a frozen bus stays frozen when the project is saved and opened again. If the recording has gone missing the bus stays frozen but plays its live inputs, so nothing goes silent; unfreeze it, or put the file back. Freezing needs something routed to the bus and the project's one tempo (turn the tempo map off first). The recording follows the song: while it is stopped, or past the recording's end, the bus is live. Agents use freeze.bus and freeze.unfreeze_bus with the bus's channel id, and bus.list shows frozen, frozen_audio and frozen_audio_ready.

A channel's Hardware I/O menu sends it to your interface's outputs as well as the mix, builds up to four cue (headphone) mixes with their own sends, and adds a hardware insert: send to an output, return from an input, with the round trip measured by a ping and compensated. Hover the channel's strip to see the insert's latency in frames and milliseconds - the measured round trip, or the figure you typed in place of it ("typed"); "not measured" means the insert is on but adds nothing yet, so ping it or type a figure. An agent reads the same number in pdc.report (hardware_insert_latency_frames, with hardware_insert_latency_source). An ordinary export runs no audio device, so it bypasses hardware inserts and writes the dry signal; an agent's render.render reply says so in hardware_inserts (hardware unavailable, the inserts it bypassed). To print the outboard gear, choose Hardware I/O > Render Through Hardware (Real Time)... and give a .wav path: the song plays once through your interface from its start to its end plus a short tail (loop and metronome off for the pass), and the master mix, with every insert's return, is written at the interface's sample rate and the export bit depth. The delay compensation head is trimmed, so the file lines up with an offline export. The form shows the file, its length and the inserts it played; if an insert's send or return is beyond what the interface opened, or the interface has no inputs, it refuses and writes nothing - it never falls back to a dry render. Agents run the same render.realtime command. Interface Channels names your interface's inputs and outputs and pairs them; the names are kept per device, not per project. Its Surround > Format menu sets a channel to LCR, quad, 5.1, 7.1, Mono, or a Discrete layout of 2 to 8 channels: the Surround Panner places a channel's sends into a speaker layout on a 2-D room with an LFE send and spread, and a stereo master or a stereo export gets the standard downmix. Mono has one M channel. A Discrete layout has no speaker positions at all: channel 1 goes to the first output, channel 2 to the next, and so on, with no speaker folding or reordering, and its channels are numbered rather than named. Extra channels need a backend with more than two outputs (JACK or ALSA). With a surround master, the WAV export's Channels row can write it as it is - Surround: one channel per speaker (6 for 5.1, 8 for 7.1) in the standard WAV order with its speaker mask; Stereo, the default, folds it with the downmix.

The mode bar across the top of the mixer shows and sets how it is laid out and what mode it is in. View: Mix shows levels, pan and processing; Routing shows, on every strip, where its signal comes from and where it goes, by channel name, with each send's amount and the hardware output. Density: Compact keeps only the essentials (no inserts or macro knobs, routing on one line); Expanded shows every section turned on in Mixer View. Strips never shrink below their width; use Show to filter channels, or scroll. The mode buttons name what the faders drive, the solo mode (exclusive or additive), who is listening (AFL or PFL) and where the master plays and in what speaker format; click one to change it. Every strip has a badge saying what it is (Master, Return, Group, Track, Channel or VCA, plus its surround format) and a line for the modes it is in (AFL/PFL, Solo safe, Surround pan, Cue, HW insert). Routing Matrix... opens every channel against every channel; filter the senders by name, and double-click or press Enter on a cell to make or change that send.

The mixer's body is four regions: the master strip, the channels, the VCA strips and the effect rack. Dock one of them on either side of the channels from the mode bar's Zones button - its menu names each region and the side it is on - and drag the separator between two regions to resize them. The arrangement and the widths are interface state: they are kept with the window layout (Window > Layouts, below), so File > Save writes them with the project and reopening the project brings them back, while a project or a layout saved before this feature opens with the arrangement the mixer always had: master left, channels in the middle, VCA strips and rack right. window.mixer_zones reads and sets the same arrangement for an agent or a script: dock ("rack=right", or just "rack" for the other side), sizes in pixels, and reset for the default. Dragging a separator runs that same command with the widths you left (live), so the interface and a script never take two different roads to the layout.

Devices

The instrument window's keyboard is a touch performance surface: on a touch screen, two or more fingers play two or more notes at once, each finger its own note, and a finger's note lasts until that finger lifts - lifting, sliding off or cancelling one finger never releases another's. A white key is loudest at its bottom edge and a black key at its top, as with the mouse; sliding a held finger to the next key moves only that finger's note. Two fingers on the same key sound one note, held until the last of them lifts. Sliding one held finger off the key bed - down past the last key, up into the octave strip or out of the keyboard - silences only that finger's note; the others keep sounding, and sliding the same finger back onto the keys sounds its note again. The mouse and the computer keyboard play the keyboard exactly as before, and the touch notes go into the same MIDI input, so record arming, monitoring, the track's input transform and MIDI recording all see them. A widget that loses the keyboard focus drops every touch note (nothing is left hanging), and the keyboard accepts touch events only for the surface itself, so Qt's fallback that turns an unhandled touch into a mouse click is never a second note for the same finger.

Add a device from the browser or the rack's menu; right-click a device to insert another before or after it, copy it or its whole chain to other channels, or compare two settings (A/B). Racks hold parallel chains, macros (each mapping with its own range and curve) and key or velocity zones; Wrap into Rack moves a chain into a rack chain. Plug-in windows have a header with presets, and an effect's also has bypass and A/B. Favourite, hide or file plug-ins into folders from the effect picker or the plug-in manager (Project > Plug-in Manager); Preferred Plug-in Format lists a plug-in installed in several formats once. Project tools > Plug-in Modules... lists every file the scan found with its path, its per-file status and the error it failed with, and quarantines or releases one from its row (Edit > Plugin Quarantine adds and releases entries too). Its Rescan and Edit > Plugin Quarantine > Rescan Plugins (agent: plugin.scan_start) scan in the background: the window stays usable, the Tasks list in the status bar shows the progress and Cancel, and a cancelled scan keeps the plug-ins you had. Scans are safe with plug-ins loaded: devices already in the project keep working and save as before, and the new scan applies to devices you add or reload afterwards. A device card's dot lights while the device processes audio. The rack menu bypasses every device, switches them all back on, removes the bypassed ones and opens an XY pad that plays two macros at once. Modulators can be random, smooth random, a step sequence or a retriggered envelope as well as an LFO; a modulator can run a formula of its own (sin(2*pi*t), tri(t) * rand(x)...) and restart on every note a track plays. In Edit > Modulators, each parameter a modulator drives has a Per sample switch (agent: modulator.per_sample_set): on, the parameter moves smoothly inside each audio block, so a fast LFO does not zipper; off, it moves once per block. It is saved with the project, and Undo restores it.

A rack can split its input between its parallel chains (Rack > Split the Input): by frequency band, mid and side, or left and right - the chains add back to the whole. A device's menu finds, renames and randomises its parameters (a renamed parameter keeps its own name for macros and modulators), blends its A and B settings, folds its card to the header, plays only what the device changes (the card's Δ button), and sets compatibility options: the generic editor instead of the plug-in's window, keep running on silence, a latency override, the editor zoom. The Device panel shows the level of the channel its devices play into. Native devices: De-esser, Transient Shaper, Vocoder (the voice on the sidechain), Console (Mixer > Console Across the Mix puts one on every channel), Dynamic EQ (bands that move with the level, on the mid or the side alone), Convolution Reverb (Load Impulse Response... from its menu) and Recorder (records what passes it; its menu puts the last take on a new track). An audio clip's Process menu prints a chain's effects onto the clip.

The Audio File Processor (the sampler) has an Attack and a Release knob, in milliseconds, and a Voice limit box in the strip under its title. A note fades in from silence over the attack time and, after its key is let go, fades out over the release time; both can be automated, and a project saved before they existed plays exactly as it did (no attack, a 3 ms release). The voice limit (1 to 64, the most sounding notes the sampler keeps) decides what a new note does when that many are already sounding: it takes the voice that was released the longest ago, or, if every note is still held, the one that started the longest ago. That voice fades out over 3 ms and the new note starts from the beginning of the sample with its own attack; the other held notes are not touched. An agent reads and sets the same three values with plugin.param_get and plugin.param_set on the track's inst plug-in.

The SFZ Player plays instruments in the open SFZ format (sfizz): samples with velocity layers, round robins and key switches. Add it from the browser or the instrument list, or open an .sfz file from the file browser (double-click) - the new track holds the player with that file loaded. The window shows the file that is loaded and how many regions it has; Open SFZ... loads another. Volume (dB) and Sample quality apply at once; Polyphony and Oversampling reload the file. The file is saved with the project by its path (a path relative to the project where it can be), so keep the SFZ and its samples where the project can find them: if the file is missing the player is silent and the project keeps its name. An agent loads a file into a track's SFZ Player with plugin.open_file (one undo step) and reads and sets the settings with plugin.param_get and plugin.param_set.

Rack > Chain Canvas... on a mixer channel opens its chain as a patcher graph: the input, one node per device in order, and the cables between them. Drag from a node's output port to another node's input port to connect; click a cable and press Delete to remove it; Shift-click a cable and drag to give its source a second destination while the first stays. Drag a node sideways (or Move Left / Move Right) to reorder the chain, Add device... to append a device, Remove to take one out. Every edit is the same command an agent runs (patcher.set_wiring, plugin.move, plugin.load, plugin.unload), one undo step each, and the picture always shows what patcher.get_state reports. Cables can only be changed on a chain whose devices the engine routes through its graph; on a chain of the built-in devices the cables are shown and the window says why they cannot be edited, while adding, reordering and removing devices work as usual. Wiring you author is not saved with the project.

Which third-party plug-ins have actually been run? The compatibility page, docs/PLUGIN-COMPATIBILITY.md, lists the VST3, CLAP and LV2 plug-ins that were tried, each by its package, version and file hash, with whether it loaded, whether its own editor opened and whether its saved state came back, and every failure. A plug-in that is not on that page is untested - that Zene lists it as loadable only means the host accepted it.

A VST3 or CLAP plug-in's own editor (Show plugin editor, or Open Editor in a device card's Actions menu; the agent command plugin.editor_open) opens in a window of its own on Linux, Windows and macOS: Zene puts the editor inside the system's own kind of window (an X11 window on Linux, a Windows window, a macOS view). A plug-in whose editor cannot go inside that kind of window does not open; the line under the button says why, naming the system and the plug-in's window type - for example cannot embed on Windows (VST3 platform type HWND) - and no empty window is left behind. On a Wayland desktop see below. The device's Editor zoom (plugin.options editor_scale) is passed to the plug-in on Linux and Windows; on macOS the system scales the editor for the screen itself, so a VST3 editor is only given the larger size and a CLAP editor keeps its own size. Windows and macOS editors have so far been proved with Zene's test plug-ins only; the compatibility page says which real plug-ins have been opened where.

Undoing what you did in a plug-in's editor. Drag one knob in a VST3 or CLAP editor and let go, and that whole drag is one undo step: one Edit > Undo puts the value back where it was before the drag, and one Edit > Redo puts its final value back, however long the drag took. It shares the project's history with everything else, so an agent's control.undo takes back a drag and Edit > Undo takes back an agent's plugin.param_set. This covers parameter changes the plug-in reports with a start and an end. A change the plug-in reports with neither - a preset loaded in its own browser, say - is a step per change that Zene sees, and a change it does not report as a parameter is not in the history at all. Two drags finished within a tenth of a second are still two steps. Dragging two controls at once is one step per control.

Plug-in windows on a Wayland desktop (KDE, GNOME). On Linux a VST3 or CLAP plug-in's own editor can only be placed inside an X11 window. So on a Wayland desktop Zene Studio runs through XWayland, the X11 layer KDE and GNOME provide, and editors open there as they do on an X11 desktop. Zene chooses this when it starts and prints one line about it in the terminal. To choose yourself, set QT_QPA_PLATFORM before starting: QT_QPA_PLATFORM=wayland zene runs natively on Wayland, and QT_QPA_PLATFORM=xcb forces X11. Zene never overrides a value you set. When an editor cannot open - Zene runs natively on Wayland because you asked for it, the desktop has no XWayland (enable or install it, then restart), or the plug-in has no X11 editor - Open Editor, the Show plugin editor button and the agent command plugin.editor_open say why, and no empty window appears. The device's knobs and the generic editor work either way.

Presets keep their controller bindings. A track preset (track menu > Track Preset > Save Preset... / Load Preset..., track.preset_save / track.preset_load) and an effect chain preset (track menu > Effect chain presets, chain.save / chain.apply) carry the MIDI controller bindings of their devices' parameters - channel, CC, soft takeover and feedback - and a load puts each one back on the same parameter of the device it just loaded, never on another parameter of the same name elsewhere. Load Preset's form and the chain menu then say what happened: "2 of 2 controller bindings restored: ..." - or which ones were skipped because the loaded device no longer has that parameter (by name, channel and CC); a skipped binding makes no mapping at all. Agents read the same as bindings (restored, skipped, a one-line summary) in the load's reply. One undo takes the load back, bindings included. Presets saved before this release load as before.

On macOS, Zene also hosts Audio Units (AUv2 effects and instruments). They come from the system's own list of installed Audio Units - there is no folder to set - and appear in the device picker and the instrument browser with the format Audio Unit (plugin.list format au, each entry naming its component, for example aufx:bpas:appl for Apple's AUBandpass). An Audio Unit effect goes on a track's or a mixer channel's chain like any other device, with bypass, wet/dry and its latency compensated; an Audio Unit instrument plays the track's notes and live MIDI. Every parameter is a knob in the device's window, a plugin.param_get / plugin.param_set parameter and an automation target. The unit's own settings are saved with the project and with plugin.state_save, and come back with plugin.state_load or when the project is opened. Show plugin editor opens the unit's own Cocoa editor, or Apple's generic editor for a unit that has none. Each Audio Unit is listed under Project tools > Plug-in Modules by its own path, such as /AudioUnits/aufx/dist/appl, and quarantining that path hides that one unit; a unit that cannot be created is refused with the reason the system gave (for example AudioUnitInitialize failed (status -10875, kAudioUnitErr_FailedInitialization)). Windows and Linux builds have no Audio Unit format. Audio Unit v3 extensions are not hosted.

VST2 instruments through Carla. When a Carla runtime is installed, Zene hosts VST2 instruments through it: native Linux plug-ins (.so) in Carla itself, and 64-bit Windows plug-ins (.dll) through Carla's Wine bridge (32-bit ones too where Carla's 32-bit bridge is installed). Zene looks for them in the folders named by VST_PATH, the VST folder in Settings, ~/.vst, ~/.lxvst, /usr/lib/vst, /usr/local/lib/vst and /usr/lib/lxvst; setting ZENE_VST2_PATH replaces that whole list. Each binary is opened only by Carla's own discovery tool, in a separate process, so a plug-in that crashes while it is being listed cannot take Zene down. The instruments appear in the device picker and the instrument browser with the format VST2 (plugin.list format vst2; each entry carries its file, VST2 unique_id, binary - native, win64 or win32 - and bridged), and load with Replace Instrument... in the device card's Actions menu or plugin.load. Each one is a Carla Rack holding that plug-in: its parameters are knobs in the Params window, plugin.param_get / plugin.param_set parameters and automation targets; Show plugin editor (or plugin.editor_open) opens the plug-in's own editor - inside a Zene window for a native plug-in, in a window of its own from Wine for a Windows one. Zene runs Carla for each VST2 instrument on a thread of its own, two audio periods ahead, so neither a slow plug-in nor the Wine bridge can stall playback; the track compensates for those two periods. The plug-in's settings, including its private state (its chunk), are saved with the project, in presets (plugin.preset_save / plugin.preset_load) and with plugin.state_save, and come back when they are loaded. Without a Carla runtime no VST2 instrument is listed, and a project that used one keeps it as a placeholder until Carla is installed. VST2 effects through Carla, and opening projects saved with the older VeSTige and VST effect hosts as Carla devices, come in later releases; until then those older hosts are unchanged.

Each device card has an Actions button (⋯), and the same menu opens on a right-click: Bypass, Open Editor, Presets, A/B, Replace With…, Move Left, Move Right and Remove, then Insert, Copy, Parameters and Hosting. Under the card's header a line says the device's state in words: Bypassed, which A/B setting you hear, the delay it adds, whether its plug-in host crashed or was quarantined, and the preset it last loaded or saved. When the chain changes, the cards that did not change stay where they are. Add device, Insert and Replace open the device picker. With a mixer channel selected, Add device fills the channel's selected parallel chain (Rack > Route to); an empty parallel chain has its own Add device... button under its heading. Start typing to filter it by name, vendor, format or type. The arrow keys move through the list, Enter adds the highlighted device and Escape cancels. Each row shows the device's type, format, vendor and state; favourites come first.

The Inspector keeps its place as you move through a project: a section that still shows the same track, clip or channel is left as it is, and a changed section keeps your keyboard focus and scroll position. When the selected notes differ, a field says 'Multiple values', and a key, velocity or length you type there is given to every selected note; a typed start moves the first note there and keeps the spacing. Volumes read in dB, velocities and pan in %, and times in the time format. Rename a track or a mixer channel by typing in its name field.

Recording

Arm a track with the record button in its header (or Record > Arm All Audio Tracks), choose its input from its Record menu and press Record. Record > Count-In and Pre-Roll starts the take bars early; Record Mode chooses what a pass does to what is already there, for MIDI and for audio alike (the same three choices are in the header's Rec mode readout - right-click it - and in transport.record_options for scripts and agents): Overdub keeps the notes a MIDI pass plays over, and mixes an audio pass into the clip's audio so the old audio stays audible beside the new (a clip that is trimmed, reversed, warped, pitched or gain-adjusted is left untouched and the pass is added over it as a clip of its own); Replace erases the notes a recorded note overlaps, at any pitch - notes only; controllers and automation are kept - and replaces the clip's audio with the pass (one undo brings the earlier audio back); Keep History keeps the clip's earlier audio and every new audio pass as take lanes of the clip: the new pass is the active take, and Next Take Here, comp.take_select or the take-lanes view brings an earlier one back; one undo takes the whole recording back, and the lanes are saved with the project. A MIDI pass in Keep History keeps its notes as Overdub does (MIDI take lanes are not kept yet). The readout shows which mode is set. Positions and lengths read in bars and beats - right-click a position, or use the Tempo Map's picker, for ticks or time; any of them can be typed. After a looped recording, Split into Loop Passes (the sample clip's menu) puts every pass on its own take lane: drag along a lane in the take-lanes view to comp that range, double-click to cycle the take (or Record > Next Take Here). Retrospective capture keeps what you played without recording - save it as a clip or a take afterwards. Record > Punch In Here and Punch Out Here set the punch region at the play position while you record, and the Song Editor's ruler draws that region in a band of its own under the loop brace: drag either end handle to set punch-in and punch-out, or drag the band to move the whole range. The toolbar's Punch in/out button arms and disarms it without losing its bounds, Clear punch range forgets them, and neither the handles nor the button change the loop markers - the two ranges are independent. Metronome Sound and Level chooses the click, its level, the accent and whether it clicks only while recording. A sample track with take lanes shows one row per lane in the arrangement, each take at its own place with its waveform drawn to the bar ruler; the take-lanes panel keeps the same takes in its comp strip, with each take's waveform under the highlighted comp segments, and a touch screen can swipe along a lane to comp that range just as a mouse drag does. Track > Takes and Comping moves the edge between two takes, or comps several tracks (a kit) at once. The header's Rec left readout shows how much recording time the disk's free space still allows at what the armed routes write (record.remaining - "-" when a volume cannot be measured, "0m" when the budget is spent); scripts and agents ask the same command. A recording route can take the master or a channel instead of the input (record.route_source), before or after the channel's devices or fader - if you also monitor what you record, lower the level first: a signal recorded from what it feeds can howl. Track > MIDI Out sends an instrument track's notes to a hardware synth (on ALSA each note leaves at its own frame inside the audio period, so a fast 1/32-note line keeps its spacing - measured within 1 ms); record its audio back on an audio track that monitors the input. Track > MIDI Out > External Device... opens the track's External MIDI device card: the output port, the channel (-- keeps each note's own), the bank select (MSB and LSB, Off sends none) and the program the gear is told to select, and the device's presets. A change to the bank or program sends bank select (CC 0 and CC 32) and then the program change to the chosen port once, so the synth does not step through the patches in between; changing only the port or the channel sends no patch. Name a preset and Save keeps the port, channel, bank and program in the track (and so in the project); Recall applies them and sends the patch even when the settings were already those, and says so if the preset's port is not connected now (the rest is still applied); Delete removes it. A device keeps up to 64 presets. One undo puts the whole device back and tells the gear the patch that returns. Agents use device.external_get_state, device.external_set, device.external_preset_save, device.external_preset_recall and device.external_preset_remove for the same things. This stage covers the MIDI half: the audio return, monitoring and latency offset are separate. AudioFileProcessor and SlicerT also record the input straight into the sampler: Record take in the instrument's window captures a bounded take (click again to stop, or let it reach its length), then loads it so the waveform and, for SlicerT, the slices are ready to play. The take is a WAV in Recordings; one undo puts the sampler's previous sample back. Agents use record.sampler_capture, record.sampler_capture_stop, record.sampler_capture_status and record.sampler_capture_land for the same take.

SlicerT's window has a per-slice bar between the waveform and the sample name. Slice picks one playable slice (slice 0 plays on the key above the base note; the base note still plays the whole sample) and the waveform shades it. Gain (-48 to +12 dB), Pan (-1 left to +1 right; a balance, so 0 leaves the stereo sample alone), Filter (below 0 a low-pass that closes to 100 Hz at -1, above 0 a high-pass that opens to 8 kHz at +1, 0 off) and Random (0 to 1) then belong to that slice only: a note on its key plays it that way, and the other slices are untouched. Random makes every trigger of the slice differ a little - gain by up to 6 dB and pan by up to 0.5, times the amount - and 0 means none. Type a value and press Enter, or use the arrows; each edit is one undo step. Deleting a slice point keeps the earlier slice's values for the merged slice, and double-clicking to add a point gives both halves the slice's values; Reset slices and detecting slices again start every slice neutral. The values are saved with the project (a project without them opens neutral). Agents use plugin.slice_get (one slice or all of them: key, start, end and the four values) and plugin.slice_set (any of gain, pan, filter, random on one slice; a value outside its range is refused and nothing is written) - the panel calls these same commands.

Project > Low-Latency Monitoring helps you play in through a latent device. On, it stops each device whose latency is over 3 ms on the chains a record-armed track plays through (its own, the channels it plays into and the master), and a record-armed instrument track whose instrument reports more than 3 ms of latency keeps playing but is no longer held back to line up with a later path: delay compensation normally delays it until the slowest other track catches up, and now you hear it after its own latency only. Every other track stays lined up exactly as before, an unarmed latent instrument is left alone, and Off puts the normal alignment back. Arm another track and choose On again to take it in. The mode belongs to the session: it is not saved with the project and makes no undo step. Scripts and agents use transport.low_latency, whose answer lists the devices it stopped and each instrument path it took (track, mixer channel, latency, and the alignment frames skipped); max_ms sets the threshold and scope all applies it to every track.

An instrument track's Instrument Setup menu - on its header menu, the Inspector's More menu and its instrument's device card - holds what a multi-output, multitimbral or layered instrument needs. Output Buses lists a plug-in's extra outputs: route one to a mixer channel, or make a channel for each. MIDI Parts sends the notes in a key and velocity range on a MIDI channel of their own, so one track plays several parts of a multitimbral plug-in; edit a part in place or remove it. Layers > Layer Rack stacks more instruments on the track, each with Mute, Solo, a Level and its own window, and Layer Zones picks which layers a note plays on. Per-Voice Modulation makes a modulator run once per note of the track and binds it to a parameter of the instrument; Modulation Assignments changes a depth or removes a binding.

Drum rack pads. A drum rack is a folder track of sample pads: each pad is a sampler track playing one sample, with a mixer channel of its own (the pad's chain, for its effects) that sends to the rack's bus channel. On a folder's track menu, Folder > Drum Rack Pads... opens the rack's pads: a row per pad with its name, its trigger key (the note that plays the sample at its own pitch) and its sample. Type a new name or key and press Return to change it, Sample... plays another file, and Add Pad... asks for a sample file and adds a pad for it on the next key after the rack's pads. Each change is one step of Edit > Undo. A pad is stored as the ordinary tracks and channels it is made of, so a rack saved by an earlier version opens and plays the same and shows its pads here. Agents use track.drum_rack (build a rack), track.drum_rack_pad_add, track.drum_rack_pad_set and track.drum_rack_get_state, which reads back what the project saves.

A pad's own effects. Each row of the pad panel also shows the pad's chain - the effects on its own mixer channel, in the order they play - and an Effects button. Its menu adds a built-in effect (Add Effect), switches one off or back on (Bypass / Switch On) and removes one (Remove). An effect put on one pad plays on that pad only: the other pads have channels of their own. When a pad plays through a channel that is not its own - the master, a channel another track also plays into, or one another channel sends into - the panel says so and Add Effect is greyed out, since an effect there would change more than that pad. Each change is one step of Edit > Undo, and the chain is saved with the project as any channel's effects are. Agents read the chain in track.drum_rack_get_state (each pad's chain and chain_shared) and edit it with plugin.load, plugin.bypass and plugin.unload on the pad's channel - the commands the menu runs.

The launcher

Show the launcher from the footer's Clip Launcher button, View > Clip Launcher or Alt+L. Each cell plays a pattern or an audio file; drop a sample on a cell to fill it. Each column is headed by its track's name. A cell's play mark shows its state - ▷ stopped, ▷… queued, ▶ playing - and a scene's mark shows its row's, so you can see what will launch. Dragging a sample over a filled cell shows "Replace" before you let go; after the drop, Undo Replace (or Edit > Undo) puts the old clip back. Cells launch on the next bar (or the cell's own quantisation) in trigger, gate, toggle or repeat mode, and scenes launch a row. Launcher > Launch Scene 1-8 can be given keys (Project tools > Customise > Keyboard Shortcuts); Launcher > Controller binds the notes of a MIDI controller to cells and scenes, and binds a note or a control change to a built-in command that needs no arguments (Bind a Command to a Note or Control Change..., Unbind a Command... and Command Bindings list them): a note runs its command on the press and is ready again when you let go, and a control change runs it once as the knob leaves zero and is ready again at zero, so a sweep is one action rather than 127. Launcher > Controller > Bind a Workflow lists every workflow in the library in use; pick one and Bind a Note... or Bind a Control Change... to play that workflow from the controller, with the same press/release and sweep rules, so a saved run of commands - shared, or kept with the project - is one pad or one knob away. The workflow is looked up when the control is moved, so editing it, or switching between the shared and per-project libraries (Workflows > Keep Workflows), is followed; if that library no longer has a workflow of that name the binding simply does nothing until it comes back, and Workflow and Command Bindings says so. Launcher > Record What I Played Into a Cell puts what you just played (with Keep Listening on) into a cell as a new pattern. A Gate cell plays while you hold it. Right-click a cell for its Follow Action Chain (the action after it, its chance and timing) and Jump To (move a playing cell inside its clip); right-click a scene to play scenes in order or launch a folder's cells together; the grid's menu captures the playing cells as a new scene and keeps a setlist of songs to step through. A marker can run a command when playback crosses it (marker.set 'action'). Launches and stops are announced once they actually play or stop, not when queued, and one scene launch is one scene announcement rather than one per cell; view.announcements gates these routine messages.

Editing a cell while it plays. The launcher always plays what the grid holds. Give a playing cell another pattern or audio file (Edit Cell..., Set Pattern, Audio File... or a drop) and it sounds the new one at once, without a relaunch. Clear Cell on a playing or queued cell stops it the way the column's stop button does, and its track's arrangement plays again; shrinking the grid (Grid Size...) stops the cells it removes; clearing the whole launcher stops everything. Edit > Undo and Redo of any of these follow the same rule: they put the cell back as it was written, but an undo never launches a cell - press it again to hear it. Deleting a pattern track empties (and stops) the cells that played that pattern, and every other cell keeps the pattern it had even though the pattern numbers move; moving a pattern track up or down does not change what any cell plays. A saved project keeps the cells, never what was playing: it opens with nothing launched (session.set_slot, session.clear_slot, session.set_grid, session.clear).

An audio cell's gain, pitch, loop and warp. Right-click an audio cell and open Playback and Warp. Gain, Pitch, Loop and Warp... shows every playback setting of the cell at its current value: gain (dB), transpose (semitones), detune (cents), the loop region (loop start and loop length, in ticks; a length of 0 loops to the end of the file), warp and the clip's own tempo (warp BPM), and RAM mode. Change any of them and press Run. Warp to Song Tempo On/Off switches the tempo warp alone: a warped cell plays at the song's tempo, keeping its pitch, as if it was recorded at its warp BPM. Transpose and detune change the pitch the way a sampler does, so the clip also gets shorter or longer.

Saving an audio cell to the library. Right-click a cell that holds audio and choose Save to Library... The cell's name is filled in; change it if you like, add tags, and press Run. The audio the cell plays is written to your samples library under Clips, which the browser's Samples list shows, and the project is not changed. The library entry is the audio itself, at the file's own rate and length: the cell's gain, transpose, detune, loop and warp are playback settings of that cell and are not baked into it, so putting the entry in another cell plays the same audio and its own playback settings apply there. After you save and reopen the project the entry is still in the browser; drag it onto another cell, or give a cell the Audio File..., to use it again. An entry that already exists is refused rather than replaced unless you ask to overwrite it, and saving is one Edit > Undo step: undo removes the new file again (or puts back the file an overwrite replaced). A very long file is refused with a message saying how much audio it holds instead of being loaded whole; a MIDI cell is not saved this way (its notes are stage 2). An agent does the same with browser.save_clip and the cell's track and scene, and finds the entry with browser.query.

Reset Gain, Pitch, Loop and Warp puts them all back to their defaults. Each change is one Edit > Undo step and is saved with the project. A cell with settings away from their defaults shows them after its name, for example "-6.0dB +12st +50ct ⟲ W128" (gain, transpose, detune, a loop region, warped from 128 BPM), and a screen reader hears them in words. RAM mode is kept with the cell but does not change playback yet. An agent sets the same fields with session.set_slot (gain_db, transpose, detune, loop_start, loop_length, warp, warp_bpm, ram).

For a show, View > Perform Mode (or Launcher > Perform Mode) opens a window made to be read from a distance: the setlist's song and the next one, Play and Stop, the bar and beat, the tempo with - and + (each an undoable change), the scene playing and the scene that plays next, one big button per scene, what each track is playing, and a large Stop All. Its keys: 1-9 launch scenes 1-9, Up and Down choose the next scene, Enter launches it and moves on to the one after, Space starts or stops, Escape stops every clip, Page Down and Page Up change song (asking about unsaved work first). With a controller connected (Launcher > Controller > Connect...), press Learn MIDI and then a scene button or Stop All: the next note you play is bound to it.

A sub-scene is part of a scene - some of its tracks - that you can launch on its own, for example only the drums of the chorus. Ctrl+click the cells (or Ctrl+Space on a focused cell) to select them, then right-click and choose Sub-scenes > Make a Sub-scene From the Selection; it takes the cells of one scene. The scene's Sub-scenes menu then launches, renames and deletes it. Its cells launch as the scene would launch them, on the same bar lines, and the other tracks play on.

Ableton Link. The Ableton Link button in the arranger's toolbar (also Project > Sync) plays the project in time with Ableton Live, Bitwig, Reason and every other Ableton Link app on your network or on this computer. The tempo is shared both ways - a tempo another app sets is not an undo step - and while the song plays it stays on the session's beat grid: started on its own, it waits for the session's next bar (the quantum, 4 beats unless Project > Sync > Quantum changes it). With Project > Sync > Share Start and Stop on, play and stop in any app that shares them start and stop the others. The button shows how many apps are connected and the session tempo; link.get_state has the rest.

MIDI Clock. Edit > MIDI Clock makes the project a MIDI clock master (Send Clock) or follows an incoming clock (Follow External Clock, and Follow Its Tempo to write the measured tempo into the song); a line in that submenu says what the clock is doing, from not sending through following with no lock to locked at a measured BPM, and names a refusal. Clock Source there chooses which input drives the follower - Any Input or one of the readable MIDI ports - and clock messages from any other port are dropped and counted. The drift bound (how far one pulse may stray from the average before the lock is lost, 0-100 ms) has no item of its own: open Project tools > Sync > Follow MIDI Clock... for the form of the same clock.slave_set command, which sets the mode, the source port and the drift bound together - one undo step. Send MIDI Clock... beside it opens the master's form. An agent sets the same fields over the control socket or MCP and reads them back with clock.get_state, so the menu, the forms and a script all drive one implementation. The clock's own limits are in Known Limitations: a client with one unnamed input can only follow any input, and an incoming start, stop or song position is counted but does not move the transport.

Capturing an external synth for an exact length. Set Edit > MIDI Clock > Send Clock to the synth's port (Send MIDI Clock... names it), connect the synth's audio output to an input, then right-click an empty cell of a sample track in the Clip Launcher and choose Record Bars with MIDI Clock Start/Stop... or Record Steps with MIDI Clock Start/Stop... (a step is a sixteenth note, the grid MIDI Clock counts in). The form asks for the number of bars or steps - one of the two - and Run arms the cell. On the cell's launch line the clock sends START; when the chosen length is up it sends STOP, with exactly that span's clock pulses between, and the take is that many bars or steps of audio, landed in the cell when it finishes (the same landing as Record Audio for Bars...). While the capture runs the clock follows the capture, not the song's transport; with Send Clock off the entry is refused and tells you to turn it on. Saving the project keeps the cell pointing at the take's WAV file, which keeps its length. An agent does the same with session.record_slot (bars or steps, and clock_sync: true), reads session.record_slot_status (clock shows the START and STOP ticks and the pulses sent) and lands with session.record_slot_land. If the clock's previous messages have not all left yet when the take starts (a stalled MIDI output), the take records without the clock rather than start the synth with no guaranteed STOP; clock.refused in the status counts that.

Patterns, clips and cells

Zene has three ways to place music, and they store different things. A pattern is a reusable grid of notes in the PatternStore, shown one pattern column at a time in the Pattern Editor. A PatternTrack in the arrangement references a pattern; its PatternClip is an empty placeholder that says where on the timeline that pattern plays. The placeholder has no instrument and no mixer channel of its own - the instrument tracks inside the PatternStore make the pattern's sound. A MIDI clip is different: it is placed directly on an instrument track and its notes live in the clip at that position, not in a pattern. A launcher cell is not on the timeline at all: it references a pattern or an audio file and launches on the session's next bar (or its own quantisation). A MIDI cell plays its referenced pattern through the PatternStore tracks; an audio cell on a sample track's column plays through that track's devices, fader, pan and mixer channel.

For example, put a recurring kick-and-snare groove in PatternStore pattern 0 - the Pattern Editor's first pattern column - and place the PatternTrack that references it, with its empty PatternClip placeholder, at bar 1. The groove can repeat for the whole song without copying a note. Add a one-bar MIDI fill directly to an instrument track at bar 9; its notes live only in that clip at that position. Then launch kick.wav from an audio cell in the sample track's launcher column. The first is reusable content, the second is positioned content, and the third is a launchable reference with its own launch timing.

Following the signal to the mixer. Select the sample track and read the Inspector's "To ..." field; the track header shows the same channel number. Mix view's Routing page (Mix > Routing) names where every strip's signal comes from and where it goes, with each send's amount and the hardware output. An agent reads the same assignment with track.overview: the track's channel is a ch-<n> id, and the matching entry in mixer.get_state has that id and its name. track.set_mixer_channel changes the assignment, exactly as the Inspector's menu does, as one undo step.

Choosing where a new track plays. The Add track to button on the Song Editor's track toolbar lists Instrument track to and Sample track to, each with the mixer's regular channels, and adds the track playing into the one you pick. Add tracks to new bus... asks for a number, a track type and a name, then makes that many tracks and one new channel they all play into. One undo removes everything the action made. Here a bus is a regular mixer channel: a parallel bus (Mixer View's return bus, bus.create) takes no direct track input, so it is not offered, and track.add refuses it rather than leave the track silent. An agent uses track.add with output (a ch-<n> id) and, optionally, instrument, and track.add_to_new_bus with count, type, bus_name and name.

A mixer channel for every new track. Settings > General has Give each new instrument or sample track its own named mixer channel (off by default; an agent sets app/autotrackchannel to 1 with settings.set). While it is on, a new instrument or sample track with no destination chosen gets a channel named after it: from the toolbar, from the Browser (a double-click or a drop on the arrangement), from browser.load and from clip.import_file. Renaming the track renames the channel and renaming the channel renames the track, also after you reopen the project. A track routed elsewhere stops renaming that channel; routing it back gives the channel the track's current name, and one undo of that routing puts both back. Turning the setting off affects only tracks added later; opening a project never assigns anything. Removing a track leaves its channel in place. Tracks made from other material (bounce, freeze, stems, slices, recording) and tracks in the Pattern Editor keep their existing routing. With the setting off, nothing changes: a new track plays into the master. A track opened from the Browser has no undo step, with or without its channel.

A PatternTrack placeholder never appears as a channel owner: track.overview and track.set_mixer_channel address the song's own instrument and sample tracks. The PatternStore's instrument tracks make the pattern's sound, each with its own mixer channel set in the Pattern Editor, and a MIDI launcher cell follows those PatternStore tracks - not an instrument that happens to sit on its launcher column. For the rest of the model, arrangement.get_state lists the song tracks and their clips, session.pattern_list names the patterns a MIDI cell can play, session.get_state shows the cells and their launch settings, and session.set_slot fills one.

Projects

Revisions. Project tools > Revisions... lists the revisions still available for the open project, newest first, with each row's id, source, UTC time and size. The list gathers the existing sources: the rotation (<file>.rev0 to .rev2, the three saves the keep-3 policy holds before overwriting the project, 8 MiB each), the backup (<file>.bak, left by a save from the interface), the autosave (recover.mmp, timed by its .info sidecar's savedUTC value, and recover.mmp.bak when present, timed by its file timestamp) and, where the project lives in a git repository, git - the newest ten commits that touched it; git is optional and bounded, skipped when you turn include_git off or no git is installed, and the list says which. Compare With Now compares the selected revision with the file on disk and reports each document's element counts and the tags that differ - a structural summary, not a musical diff. Restore asks first, replaces the file on disk and keeps the file it replaced in the rotation so the restore can be undone; it does not reload the session already open, which keeps the state it had until you reopen the project. Numbered saves (File > Save as New Version) and named Alternatives are separate: they change which file the session works on, and they are not sources in this list. An agent gets the same ids from revisions.list and runs the same revisions.compare or revisions.restore; a restore changes the file on disk, so the agent reopens the project with project.open to work with the restored bytes.

Collect Media copies every file a project uses beside it; Project > Hand Off writes a folder someone else can open with a list of the devices to install first. Import Tracks copies tracks from another project; Save as Template keeps a project to start from.

Project > New Document starts a production, mastering or live project from its own template (your own type.mpt in the templates folder wins); the window title names a mastering or live document. A mastering document also has a release sequence: Project Tools > Mastering Release... lists the songs of the release in order, each an audio file with its own processing - one of the engine's mastering candidates, or none to play the file as it is - a fade-in, a fade-out, and the silence that follows it before the next song. Add a song with its audio file, edit one in place, move it to the top or bottom (or to any position), and remove one; the last song's gap is the silence after the release and is not inserted between two songs. The list is saved with the project and is the same state an agent reads and edits through mastering.sequence_list and mastering.song_add, song_set, song_move and song_remove, and every edit is one undo step (Ctrl+Z). Project > Other Projects opens another project as a read-only reference beside this one and copies its tracks, clips or devices across, and switches to a recent project - keeping the one you left open as the reference if you like. Project > Import AAF... brings in an AAF from another editor: its audio tracks, clips, fades, clip gain and markers (embedded audio is extracted beside the project; OMF is not read). View > Video Window shows a project's video in time with the transport, with a strip of its frames over the arranger. A project's video track holds several clips, each a file placed at its own song position: View > Add Video Clip... adds one at the play position, double-click empty space in the arranger's video lane (or right-click it, Add Video Clip Here...) to add one there, drag a clip to move where it starts, and right-click a clip to move its start to the play position or remove it. A click on a clip moves the play position there. The video window always shows the clip at the play position and shows no picture before, after or between clips. Right-click the lane and choose Render Video Frames of Loop Range... to write the picture at each moment of the loop range as PNG images (25 per second of song time). Each clip keeps its own id: video.clip_add returns the new id, video.set_offset and video.clip_remove accept one clip id, video.get_state lists every clip, and video.render_frames renders the whole track; every edit is one undo step, and a project saved with one video before opens as one clip. A clip's sound can be extracted to an audio track. Edit > Collaborate... lets someone on your network (or across the internet, where your router allows it) join the project: you share an invite code, every edit is sent to the others, and a remote invite gives a phone or another machine the transport and faders only. Nothing listens until you host, and you are asked first.

Damaged drawn waveforms. Watsyn, BitInvader, FreeBoy, Vibed and Xpressive save the waveforms you draw, and Wave Shaper, Dynamics Processor and Multitap Echo save their curves, inside the project or preset. When one of those saved graphs is damaged - cut short, too long, not readable, or holding values that are not numbers - Zene does not use it: the device keeps the waveform it already had (a freshly opened device keeps its default; Dynamics Processor returns to its default curve), the rest of the project loads normally, and the problem is listed in the load error report that appears after opening (agents read the same lines in project.open's errors). A graph that is simply absent, as in projects saved before the device stored it, loads silently as before. Saving the project writes the waveform the device now holds.

Scripts, agents and controllers

Every command is reachable over the control socket (JSON-RPC) and from the MCP bridge; Lua scripts (zene.command) reach all of them except those that change your own configuration or start other scripts (shortcuts, workflows, scripts, crash reporting, telemetry). The socket accepts connections only from your own user account (it is created readable and writable by you alone); anything connected to it can do whatever the menus can - save, render, delete - so connect only programs you trust. A controller can drive the remote-control pages (eight knobs following the selected device), a Mackie Control surface, or any parameter through MIDI learn. window.note_editor_set opens a clip in the note editor and sets its tool and view; window.get_state's note_editor reports the active tool and the same zoom, row height and visible top and bottom key.

Closing a MIDI device. When you quit (File > Quit, or control.quit), an ALSA Raw-MIDI device (the MIDI interface chosen in Settings) that is waiting for input closes at once: its reader is woken and stopped before the device is released, instead of being waited on for a second and then killed. On ALSA Raw-MIDI, ALSA Sequencer, JACK, WinMM and CoreMIDI, incoming MIDI stops before the project's tracks are closed; with the ALSA sequencer the last note-offs your tracks send still go out. If at start-up a raw device opens but cannot be watched for input, it is closed straight away and treated like a device that failed to open, so Zene falls back to the next interface it would try, or to no MIDI.

Following project changes from another program. A program connected to the control socket can keep its own view of the open project current without polling. events.subscribe makes that connection receive one line for each change to the project, whoever made it: another program, a script, or you in the interface, including undo, redo and opening or starting a project. Each line says what changed (the command and its arguments when a command made it) and carries a number, seq, that rises by one with every change; events.unsubscribe stops the lines. Zene never waits for a slow program and never stores more than a limited number of lines for it (256 by default, at most 4096 and 1 MiB): a program that falls behind gets the lines already held, then one events_overflow line saying which changes it did not receive, and its subscription ends. After that, or after losing the connection, it should subscribe again and then read the project again (project.get_state and the other read commands); missed changes are never sent later. The seq a new subscription reports tells it whether it missed anything while away. Subscribing changes nothing in the project, is not an undo step and is not saved. An interface edit is reported when it leaves an undo step; the few interface settings that leave none (such as a window's position) are not project changes and make no line. The commands are for programs on the socket: over the MCP bridge the lines are skipped, because a tool call cannot receive them.

Controller scripts (Customise > Controller Scripts). A control-surface script is a Lua file that stays loaded and answers a MIDI controller: Start Script... (controller.script_start) takes a name, the file, and the MIDI input and output to bind; every event from the input calls the script's on_midi(event) (event.type - note_on, note_off, cc, pitch_bend ... - channel 1-16, then key/velocity or controller/value). The script runs any registered command with zene.command(id, args) - the same commands, refusals and undo as the menus - and lights LEDs or moves motor faders on the output with surface.send_cc(channel, cc, value) and surface.send_note(channel, key, velocity). data/scripts/controller-surface.lua is an example: CC 7 drives the master fader and is echoed back; notes 94 and 93 play and stop. Scripts run on the interface thread, never the audio thread, sandboxed (no files, no system calls), with 1,000,000 Lua instructions per call and 8 MiB of memory; an error is logged in Script State (controller.script_state), and eight in a row stop the script until you start it again. If the input disappears (a cable pulled) Script State says so, and the binding is made again when it returns. Scripts are not saved with the project. The bindings themselves - which knob drives which parameter - are edited in Customise > MIDI Mappings..., saved with the project.

OSC control (Customise > OSC Control Server). An opt-in OSC 1.0 server over UDP; nothing listens until you start it, and it is not saved with the project or remembered after a restart. Start... asks for the address (127.0.0.1 by default: this machine only), the port (9000 by default; 0 picks any free port) and the scope, and runs osc.start; State (osc.get_state) shows where it listens and how many requests it received, ran and refused; Stop (osc.stop) closes the port. The address map: a message to /zene/<command-id> runs that registered command - for example /zene/transport.play, /zene/transport.get_state or /zene/mixer.set_volume. Its arguments are either none, one string holding the command's JSON arguments, or key/value pairs (a string key, then its value), e.g. "channel" "ch-1" "volume" 0.5. The sender gets /zene/reply with the command id and the result as JSON (a fader write answers with its channel and the applied volume; a state read answers with the state), or /zene/error with the id, the error kind (malformed, unsupported, not_found, refused, invalid_args, too_large ...) and a message of at most 512 characters. Requests over 8 KiB, bundles and blobs are refused; a malformed packet never stops the server. The remote scope (the default) allows transport, markers, mixer faders and state reads; full allows every command except scripts and controller scripts, sessions, crash and telemetry uploads, the OSC server itself and quitting, names no file, and binds only a loopback address. An OSC edit is the same command as the menu's, with the same single undo step.

Live code (Edit > Live Code). The panel edits a Lua script and schedules it on the transport: Every bar, Every beat or Transport play/stop, under an id of your choosing (an id that already exists is replaced in place, one slot). Schedule compiles the buffer first - a script that does not compile is refused in the panel, with the parser's message, and the version that was already scheduled keeps running. Cancel Schedule takes the selected schedule off the clock and Undo (one step) rearms it with the script it held; Undo after a replacement puts the previous script's text, hook and budget back - a schedule's fire and error counters are runtime history and are not rewound. Load Source reads the selected schedule's captured script back into the editor (the same livecode.get_source command an agent calls), so a schedule an agent made can be edited here. The table shows each schedule's id, hook, instruction budget, source bytes, fire/error/over-budget counts, last fire position and last failure. Every fire gets a fresh Lua state, so Lua globals and closures do not persist between bars: keep state in the project (tracks, clips, values), not in the script. A source is capped at 65,536 bytes, the clock holds at most 64 schedules, and the transport is observed every 25 ms, so a fire lands up to one poll after its boundary rather than sample-accurately; more than four crossings in one observation are coalesced rather than fired late, and a seek or meter change re-anchors the grid. Each fire is bounded by its instruction budget (0 inherits the engine's 5,000,000) and Lua memory per run by File > Script Memory Budget (64 MiB by default, 512 KiB to 1 GiB). Schedules live in this process only - they are not saved in the project and do not come back after a restart - and they never run on the audio thread.

Customising and the Window menu

Project tools > Customise > Theme chooses (from the next start) the palette (dark, high contrast or light), the workspace (standard or touch), the interface zoom and accessible mode, and edits the theme's colours one by one - export a theme to share it, import one, or reset to the palette's own. Window > Layouts (also Customise > Window Layouts) saves the panels' arrangement under a name and brings it back; it says what a layout keeps (the view, the open, pinned and floating panels and their sizes - not the zoom, the scroll or the selection). Save never overwrites a name in use; Replace asks first. A project can remember a layout of its own, put back when it opens; your own layout comes back when you open a project without one, or start a new one; the Workflows menu (and Customise > Workflows...) records a run of commands and plays it again, shared by every project or kept with each (Keep Workflows). Drag a panel's header out of the window to float it - on another monitor if you like - and drag it back onto its place, or press Dock, to return it (Ctrl+Shift+F floats or docks the focused panel). Customise > Settings finds any setting by a word, backs all of them up to a file and restores them, and keeps named settings presets (folder paths never travel in a preset or a backup). While a workflow is being recorded the header says so - "Recording workflow ..." with the steps so far - and its Stop button stops and saves it. A workflow that stops at a step that fails says which step and why, which steps applied (they stay applied; undo each with Edit > Undo) and which did not run, in a report that stays open: Retry Step runs that step again, Skip Step and Continue runs the rest without it (both are in the Workflows menu too).

The Window menu holds the track manager (every track in one list: mute, solo, hide, rename, colour, icon, move, remove, and how much processing its mixer channel takes), a large clock, a tuner (it listens to the input, or to the master), the undo history (double-click a command, or select it and press Undo to Here, to go back to before it), memory locations (a named place with its range and zoom) and saved selections (a named range and clips) - each says what it keeps; Replace Memory Location and Replace Saved Selection ask before overwriting. The floating tools (also under the footer's Tools) open where you last left them. The View menu opens the floating windows: Controller Rack (Ctrl+6), Project Notes (Ctrl+7), Scales and Keymaps and the Classic Piano Roll. The Window menu also keeps the main window on top, cascades or tiles the floating windows, shows a cross-hair cursor across the arranger, and moves the keyboard focus from panel to panel with F6 and Shift+F6. A pinch on a touch screen or a trackpad zooms the arranger; a finger tap selects the clip under it. With accessible mode on (Project tools > Customise > Theme), the touch layout makes the controls at least 44 × 44 logical pixels with at least 8 logical pixels between neighbours, so a finger can hit the transport and the editor toolbars: tap Play and Stop, a clip or a note instead of reaching for a mouse. In the note editor each note is a 44 pixel-high target with 8 pixels to the next pitch row, so the vertical zoom stops at that row height; a short note is hit through a wider target around it.

Access

Project tools > Customise > Theme sets the interface zoom (one control sizes text, icons and controls together), the palette, accessible mode - the touch-first layout: click targets at least 44 × 44 logical pixels with at least 8 logical pixels between adjacent targets, strong focus rings, the high-contrast palette and reduced motion - and the workspace (standard or touch), from the next start. With accessible mode on, a finger tap selects an arranger clip or a note and operates Play and Stop, as the mouse does. The touch workspace holds the clip launcher's cells, scene buttons, stop buttons and Stop All to at least 44 × 44 Qt logical pixels at 100% zoom, so a fingertip is enough even though the artwork stays its size; it is a workspace of its own and turns neither accessible mode nor its palette on. An agent chooses it the same way, with window.appearance {"workspace": "touch"} (or reads it with no argument), one undo step each way, and the choice is kept in the user's configuration - not in a project - so the next start opens in it. Knobs, faders, number fields, lists and buttons are reached with Tab and worked with the arrows, Page Up/Down and Home/End, and tell a screen reader (NVDA, VoiceOver, Orca) what they are and their value - Help > Accessibility Check lists any control with no name, role or value, and the interface names them from their parameter or tooltip at start; the keyboard reaches every menu and most lists, and F6 moves between the panels.

Help > Ask answers a question from this manual and the command reference, offline: nothing is sent anywhere. Help > What's New shows the release notes, once per version at start; Help > Tours walks through the window part by part.

F1 (Help > Help for This) shows what the focused control is, the command it runs and its shortcut, above the manual opened at its section - no hovering needed. The manual has a find field (Enter: next match, Shift+Enter: previous); the Command Reference groups every command under these sections, names it as the menus do and finds it by a task ("mixing"), a shortcut or a word of its description. Help > Keyboard Shortcuts lists every shortcut by task; Enter runs the highlighted one, and Presets... applies the recommended accessibility map or a migration map for Ableton Live, FL Studio or Logic Pro after saving the current map as a timestamped backup. Lists - revisions, missing files, plug-ins in the project and the rest - have a find field, sort by a column title (numbers by value; a third click restores the list's own order), run their main action on Enter or a double-click and offer every action on the row from the Menu key, Shift+F10 or a right-click; each action's outcome stays in the Results log under the list.

Press Shift+F1 on any knob, fader, number or menu to learn its drag, wheel, keys and right-click options. Theme, zoom, palette, workspace and accessible-mode changes apply at the next start, and each change says so; a colour that makes text or a control fall below WCAG AA contrast is refused unless you allow low contrast.

Editing without a mouse. Every editing canvas has keys and an editable list. Note editor: Alt+Left/Right previous/next note (Shift adds), Alt+Up/Down the chord's note above/below, Home/End first/last; Ctrl+Left/Right shorten/lengthen, Ctrl+Up/Down velocity (Ctrl+Shift finely); Insert adds a note after the cursor; Enter opens its properties. Expression lane: Left/Right note to note, Up/Down value (Page Up/Down by 10); with several notes selected, one key changes every selected note - including the timbre, pressure and micro-pitch lanes - as one undo step. Controller lane: Left/Right a grid step, Ctrl+Left/Right point to point, Up/Down value at the cursor, Insert adds a point, Delete removes it. XY pad: arrows 1 % (Shift 10 %). Sample Editor: Tab to the waveform, Left/Right move the cursor, Shift+Left/Right extend the selection, Home/End go to the ends, Ctrl+Plus/Minus zoom, Ctrl+0 shows all and Ctrl+A selects all; Tab to an operation and press Space. Comp lanes: Up/Down lane, Left/Right beat (Ctrl bar), Shift marks a range, Enter comps it, C cycles the take. Arranger: Shift+Alt+Up/Down clip on the track above/below, Ctrl+Alt+Left/Right resize; Ctrl+Alt+G selects the folder summary clip holding the selected clip (Shift adds), and with one selected Ctrl+Alt+Left/Right moves its end edge (Shift its start edge), Ctrl+Alt+K splits at the play position, Ctrl+Alt+Page Up/Down moves it, Delete deletes it, Escape deselects. Ctrl+Shift+L on any of these opens its list: a table you can read cell by cell and edit by typing (positions as 5.2.1, pitches as C5); Insert, Delete, + and - work there, and every edit is one undo step.

Announcements. Zene tells your screen reader about errors, refused edits, recording starting and stopping, saving or opening a project, and completed launcher cell and scene changes; the announcements level (view.announcements) sets this to all, errors only, or off. Meter movement is not narrated continuously: Speak Meter (Ctrl+Shift+M, or a strip's menu) reports the focused strip's peak and the master's short-term loudness on request, and Peak Watch speaks once when the input or master crosses a threshold you set, then stays quiet until it falls below again. Accessibility Check can run its checks separately: names, roles, values, keyboard reach and duplicate names.

Screen-reader setup. Zene supports the platform bridge used by NVDA on Windows, VoiceOver on macOS and Orca on Linux. Turn on accessible mode under Help > Appearance, then use Tab and the arrow keys for controls and F6 / Shift+F6 to move between panels. The manual and Help > Accessibility Check read the same names, roles and values the bridge exposes. The tested workflow matrix records each platform's actual screen-reader runs and explicitly marks the ones not yet tested.

Reporting an accessibility blocker. If a workflow is blocked or unclear with a screen reader, magnifier or other assistive technology, use the accessibility blocker form. It asks for the affected workflow, the assistive technology and version, and the steps to reproduce. You do not need to give a diagnosis or any personal medical information. Agents can open this topic with app.help topic "access".

Background tasks - renders from the render queue, stem splits, mastering, library indexing and background video-audio extraction - appear under TASKS in the footer. Click it (or press Space on it) to see each job's progress; Cancel stops the jobs that support it. The list never blocks the window.
