Zene Studio

Zene Studio is a music workstation built around one main window: the arrangement in the middle, the browser on the left, the Inspector on the right and the editors and the mixer below. Three views arrange these panels for the job at hand - Arrange, Mix and Edit (Alt+1 to Alt+3). Everything a click does is also a named command, so a script, an agent or a controller can do it too. Changes to the project can be undone (Edit > Undo, or Window > Undo History); actions outside it - files written to disk, messages sent to hardware - cannot.

Hover over a control to see what it does; press Shift+F1 (Help > What's This?) and click a control for its full description. Help > Command Reference lists every command with its arguments, and the Command Palette finds any menu item or command by name: Enter runs it, or opens its settings when it has any, Shift+Enter runs it with its defaults, and a command that cannot be undone is marked; Help > Keyboard Shortcuts lists every shortcut, and Project tools > Customise > Keyboard Shortcuts changes them.

One key, four contexts. A shortcut can belong to the arranger, the note editor, the automation editor or Perform instead of the whole window: the Keyboard Shortcuts list gives every row an action and a context, so you can give Ctrl+Alt+J to the arranger's Knife tool, the note editor's Erase tool, the automation editor's Erase mode and Perform's Stop All at once. Only the panel holding the keyboard acts on it - focus the arranger and the arranger's meaning runs, focus the note editor and the note editor's does - and a panel's own keys (P/B/D in the note editor, Shift+D/E/C/T in the automation editor, the digits and Escape in Perform) keep working until you bind a scoped action over them. A clash is two actions of the SAME context on one key: the list marks it, Set Keys refuses it until you turn on Force, which moves the key there and unbinds the other action of that context only - a binding in another context is never touched. The choices are saved with your configuration, so they are there at the next start.

Quick start

Six short guides, in the order most projects need them. Each names the controls and menu paths it uses, links to the area reference below, and points at the command an agent sends for the same job. The Find field searches all of this text.

Make a first beat

  1. Open the Browser and drag an instrument onto the arrangement, or choose Track > Add Instrument Track (track.add).
  2. Double-click the track at bar 1 to make a MIDI clip, then double-click the clip to open the note editor (note.add).
  3. Draw a kick and a snare with the pencil; Space plays and stops.
  4. Take the tour: Help > Tours > Your first beat (app.tour, tour first-beat).

Reference: Arranging, Editing notes.

Arrange clips

  1. Drag clips to move them and their edges to trim; one drag is one undo step.
  2. Choose the Range tool, drag over the tracks, then split, delete, crop, fade or bounce from Navigate > Range.
  3. Use arrangement.get_state to read positions and lengths, and clip.move or clip.resize to make the same edit from an agent.

Reference: Arranging.

Edit notes

  1. Open a MIDI clip in the note editor and pick the draw, paint, delete or select tool from its toolbar.
  2. Notes > Quantise, Transpose, Scale and Transform change the selection; the lanes below edit per-note expression.
  3. From the keyboard, Alt+Left/Right walks the notes and Shift adds; note.edit writes a validated batch as one undo step.

Reference: Editing notes.

Add an instrument or effect

  1. Drag an instrument from the Browser to a track, or choose it in the track's instrument window (plugin.load).
  2. Drag an effect onto a mixer strip or into the Device panel's chain; right-click a device to insert, copy or bypass it.
  3. The selected channel's rack and macros are in the Device panel; plugin.load is the agent route to the same chain.

Reference: Devices, Mixing.

Record and comp takes

  1. Arm a track with the round button in its header (track.set_arm) and choose its input in the track's Record menu.
  2. Press Record (or R); Record > Count-In and Pre-Roll start early, and Record Mode chooses overdub or replace.
  3. Looped passes become take lanes in the Inspector. Drag along a lane to comp a range, or double-click to cycle the take there.
  4. The recording tour is Help > Tours > Recording (tour recording).

Reference: Recording.

Mix, export and hand off

  1. Open Mix (Alt+2). Each strip has trim, pan, sends, inserts and a meter; right-click for its Strip, Listen and Mixer View menus.
  2. Read the mix with mixer.get_state, then export from File > Export (render.render).
  3. Mixing tour: Help > Tours > Mixing (tour mixing). Projects are ordinary files; the command reference lists the save and render commands.

Reference: Mixing, Projects.

The window

  • Header - transport (play, stop, record), tempo, time signature, position, the master level, the transpose, the CPU load and the loudness readout. Right-click it to choose which buttons it shows. Pressing Play hands the period's work to the worker threads and wakes any that are asleep; that wake is a single atomic word, so it never waits for a lock or allocates, on macOS as on every other platform. On the Apple build the supported floor is macOS 10.13 (High Sierra); a build for a newer macOS runs the same wake.
  • Footer - a switch for each panel, grouped by where it opens, Tools (every tool that opens in a window of its own: controller rack, project notes, scales and keymaps, undo history, tempo map and more), and the views. Narrower, the switches show icons only, and the ones that still don't fit are under More; the header's right-hand buttons do the same. An area that holds several panels shows a tab for each: click one, or use the arrow keys, to open it, and use the cross to hide the area.
  • Browser - devices, presets, samples and projects. Search is the first control and filters the current tab as you type; Up and Down move the highlight, Enter loads the highlighted result (Shift+Enter puts a sample on a sample track) and Ctrl+F jumps to it. A click or Space previews, and the preview stops when you pick another result, change the query, tab or location, or leave the Browser. The Search source finds files across the library: every word must match (kick 808 finds items with both), kick OR snare, -loop excludes, "bass drum" is a phrase, and tag: kind: name: path: ext: narrow a word. Beside the field, Kind, Where to look and Category narrow by what the files are, where they sit and how you classified them - pick a category a file carries, or Any category to see everything again - and Whole library searches the built index instead of walking the folders. Right-click a result and use the Category submenu to give a file its one category. The Search file metadata checkbox also matches what the audio files themselves say rather than just their names - the embedded title, artist, album, comment and genre tags, and the sample rate, channel count, length in frames and duration (so 44100 for 44.1 kHz or 0.116 for a 116 ms file finds files by those values, not just by name). It opens at most 200 files per search to read that data, and the result says how many it read; a library wider than that is best narrowed with kind:, a tag or a folder until the audio candidates fit. Probing reads only the file headers, not the audio. The checkbox is unavailable while Whole library is on, because the whole-library index stores names and tags but not embedded metadata. Save a search as a collection to keep it; Project Media lists every file the saved project references with a Uses count (every clip and supported instrument reference adds one) and a state: used, unused, missing, external or unresolved. Unused Only keeps the unreferenced files in the project's media/ folder visible beside the missing and external references that are never cleanup candidates. Select unused rows and choose Clean Up Selected...: the exact paths are shown and must be confirmed, and the cleanup rescans the saved project immediately before removing anything, so a file that is referenced again is refused. Cleanup is irreversible - a removed media file cannot be restored by undo - and it refuses while the open project has unsaved changes, because the scan reads the saved document. A file dragged out of the Browser - from its list or a search result - carries the file itself as well, so a plug-in editor's window, the desktop or a file manager that takes files receives the file, while Zene's own drop targets (a sample clip, a track, the session grid) load it as they always did.
  • Inspector - the selected track, clip or mixer channel: its settings, its sends and inserts, its take lanes.
  • Device panel - the devices of the selected track or channel as cards, with the rack's macro knobs.

Arranging

Drag clips to move them; drag their edges to trim. Choose a range with the Range tool (Navigate > Arranger Tool > Range: drag over the tracks; the Smart tool does the same from a clip's upper half), then split, delete, crop, fade or bounce it from Navigate > Range. A clip dragged onto another trims it (Navigate > Overlap chooses trim, crossfade or free), and before you let go the arranger shows what will be cut and what the clip snaps to. A locked clip can be selected but not moved, trimmed or deleted - a padlock marks it. Sections, markers and tempo have lanes of their own under the bar ruler (right-click them to show or hide one); a pinch or Ctrl+wheel zooms around the pointer, the zoom keys around the selection or the play position. Ctrl+wheel zooms smoothly - a touchpad as finely as you turn it. Where labels would overlap they are shortened or left out; hover to read them. Double-click a section or a marker in its lane to zoom to it. Navigate holds the zoom, the zoom history, markers, ripple and overlap modes; Alt+arrows nudge and select clips. Navigate > Zoom Back steps to an earlier zoom extent and Navigate > Zoom Forward steps back over extents Zoom Back passed, like the browser's back and forward, so several prior zooms can be walked through; a new zoom cuts the forward walk off. Navigate > Zoom Toggle swaps the current zoom with the extent just left, so pressing it twice returns to where you were; unlike Zoom Back and Zoom Forward it does not walk the history. The same three actions are the agent commands arrangement.zoom_back, arrangement.zoom_forward and arrangement.zoom_toggle. Navigate > Range also holds Render Selection..., which renders the selected range to a file at its exact start and end, and Export Sections..., which writes one file per named section, each bounded to its own ticks. A file is named after its section with characters a filesystem refuses (/ \ : * ? " < > |) removed and leading dots dropped; trailing dots and spaces become one _, and a Windows-reserved name (CON, PRN, AUX, NUL, COM1-9, LPT1-9, even with an extension) gets a _ added (CON.wav becomes CON_.wav), so the same project writes the same file names on every system. Two sections whose names match when capitals and accents-versus-composed letters are ignored (Intro and intro) would be one file on Windows and macOS, so the later one gets -2 (intro-2.wav), the next -3, and a section really named intro-2 is moved on to intro-2-2. The Project > Export... dialog carries a Render preset picker: choose a saved preset, or Save Preset... to store the settings shown; the chosen preset sets the render's file format, sample rate, bit depth, channels and stereo mode, and a stem export (Export Tracks...) follows it too. Drop a MIDI file or an audio file on the arranger - from a plug-in editor's window, the desktop or a file manager - to make a clip of it: on a track's lane, on a clip or on a track's name (the clip starts where you let go, on the grid), or on the empty space below the tracks, which adds a new track for it. A MIDI file becomes one MIDI clip on an instrument track (all its channels and tracks together; its tempo is not used); an audio file becomes a sample clip on a sample track. One drop is one undo step. A file that cannot be used - missing, empty, damaged, not MIDI or audio this build reads, a MIDI file that would run past the end of the song, or the wrong kind for the track - is refused with a message in the status bar and nothing in the project changes. Only the first file of several dropped together is used. Audio that a plug-in leaves in the system's temporary folder is copied into the clip, so it survives the plug-in deleting it; other audio stays a link to its file. The same action is the agent command clip.import_file. Sample clips show fade handles near their top corners and, with Navigate > Show Transients, their transients. A sample clip's own gain is the square handle on its left edge: drag it up or down and the clip's level follows the pointer while you drag, the drawn waveform growing or shrinking with it; let go and the new level is one undo step (the agent command clip.set_gain). The dashed line across the clip is that gain. Click the drawn level line - the dashed gain line, or the envelope once it has points - to add a gain-envelope point there and drag it: the point moves in time and in level, and points can be dragged past each other, with the waveform between them following the curve as the audio does (clip.gain_envelope_set). A plain press within reach of an existing point takes and moves it. No modifier is needed for any of this, so Alt and Ctrl keep their arranger meanings on a clip (unsnapped move or resize, and copy on macOS). The Gain and fades submenu also lists Invert polarity, which renders the clip with its sign flipped and mirrors its drawn waveform, while the source sample keeps every sample it had (clip.set_polarity); all of these are in the Gain and fades submenu besides the drags. A sample track's More menu (on its header, or the Inspector's) has Insert Test Signal...: it opens the sample.generate command's form with that track set and a tone at position 0 and length 192 ticks filled in, and Run makes a new sample clip from it - one undo step removes the clip and its audio. Change the position, length, kind (tone, white noise, pink noise or silence), frequency or level in the form first if you want something else; the same command is what a script or an agent calls. A sample clip's Process menu bakes a change into its audio - Normalize, Amplify, Reverse, Fade in or out - each on the whole source and each one undo step (the Sample Editor is where a range is edited). Project > Sections names the song's parts (verse, chorus) as bands over the ruler and selects one as the range; Clip List finds a clip by name; Next and Previous Transient move the play position through the audio's hits. A clip's Sample Editor... (its menu) raises or lowers by 3 dB, silences, deletes, reverses, fades or crops a selection of its audio; Split to stems (a sample clip's menu) separates its audio into stems on tracks of their own. A split runs at one of three qualities - fast, standard or high - which set how much the model's overlapping passes over the audio overlap (25 %, 50 % or 75 %): high takes about twice as long as standard and fast about two thirds of it. The menu splits at standard, the quality every split used before the setting existed; an agent picks one with the quality argument of stem.job_start, and stem.job_status shows the quality a job runs at. A sample clip's Process menu also converts its whole source to mono with (L + R) / 2 on both sides (one undo step), or writes its left and right channels as two mono WAV files at the source rate and length (Split Stereo to Two Mono Files..., which leaves the clip unchanged). A sample clip's menu removes its silent stretches, crops its sample to what it plays, makes it unique, converts its melody to MIDI notes or splits it at the play position. A crossfade's two sides can have their own lengths and shapes. Moving a folder track moves every clip inside it. A clip's Snap Point (its menu) is the place inside it that lands on the grid when you drag it - a downbeat after a pickup. Navigate > Show Navigator puts the whole song in a strip under the arranger: click or drag in it to scroll, turn the wheel to zoom; it names the sections and shows the markers, the loop and the play position, and Alt-click or a double-click on one zooms the arranger to it. Navigate > Second Tool on a Modifier Key gives Alt, Ctrl or Shift a tool of its own while held. A focused track header's Menu or Shift+F10 opens its actions menu; the time ruler's opens the loop menu at the play position. Track > Versions keeps several versions of a track's clips and switches between them. An audio clip's Speed menu ramps its speed (the pitch going with it) or adds a tape start or a tape stop.

Splits and trims can land on an exact sample, and with Navigate > Snap Cuts to Zero Crossings on, the knife and an edge drag move to the nearest zero crossing so the cut does not click. A track's menu adds a spacer below it (Add Spacer Below): an empty band that separates groups of tracks and moves with the track.

Sample Editor (a clip's menu, Sample Editor...): drag across the waveform to select a range, or drag the [ and ] handles at its edges. Start, End and Length show the range in the unit Units picks - time from the source's start, bars and beats at the song's tempo from the clip's start, or samples - and can be typed into (Enter applies; a suffix such as s, smp or bars overrides the unit) or stepped with Up and Down. End is the first frame after the range. Ctrl+wheel zooms the waveform around the pointer, the wheel scrolls it, and Zoom In, Zoom Out, Zoom to Selection and Show All do the same from the keyboard. Each range operation edits only the range the fields show, as one undo step; the line under the buttons says what was done, or why it was refused. The range buttons are -3 dB, +3 dB, Silence, Delete, Reverse, Fade In, Fade Out and Crop: Silence keeps the range's length, Delete closes the gap so what followed the range moves earlier, and Crop keeps only the range. Range gain applies no limiter and the two fades are linear; there is no noise reduction among these range tools. To Mono and Split Stereo... act on the whole source instead: the first bakes the documented (L + R) / 2 downmix, the second asks for two destinations and writes the left and right channels as mono WAV files. The Process menu's Normalize..., Amplify..., Reverse and Fade are separate whole-source bakes, and Crop the Sample discards the audio outside the clip's play window.

Edit > Tempo Map... lists the song's tempo and metre changes: add, remove and ramp them, or import and export them as a Standard MIDI File.

Edit > Progression... lists the named progressions and spells each one out in the selected scale and key; Write puts the chosen progression into the selected MIDI clip as notes, as one undo step.

Automation can be switched off for reading or writing across the whole song (Project > Automation Read / Write), and writes can be limited to the punch region. A control's trim offsets its automation without changing the curve. Before an automation clip's first point the controlled parameter holds its authored initial value (or the point you drew at the clip's start), so starting at the beginning and returning there give the same value every time; a clip saved with a later first point keeps that value when the project is reopened. A trim (relative) clip is not affected: before its first point it adds the same offset as before.

Automation lanes sit under the track they automate. Adding a lane to a track (the agent command automation.lane_add) draws it as an indented child row directly beneath its owner, however the tracks are reordered: moving the owner moves the lane with it, and a lane whose owner is gone keeps a row of its own so it can still be reached. A track that owns lanes shows a small triangle in its header; click it, or choose Fold automation lanes (Unfold automation lanes) in the track's Actions menu, to fold its lanes out of sight and bring them back - the agent command automation.lanes_set_collapsed does the same, and folding is one undo step. Hiding the owner, or collapsing the folder it is in, hides its lanes as well; showing it brings them back. Select a lane's clip by clicking it and double-click it to open the automation editor and edit its points. Deleting the owner deletes its lanes in the same undo step, and undo brings the owner and its lanes back together. The fold is saved with the track; a project saved before lanes could be folded opens with every lane shown. automation.get_state reports each lane's owner (follows) and each track's lane count and folded state, the same state the arranger draws.

Editing notes

Double-click a MIDI clip to open it in the note editor. Opening a clip fits its length to the view and its used pitches with a little room; a very wide range stays centred at the smallest readable row, and an empty clip opens around C5. With Draw, a translucent note previews the click under the pointer, and dragging up or down while drawing moves the preview, the audition and the note to that pitch. The note area's cursor names the next action (draw, erase, slice or play), and choosing a tool from the toolbar or its letter shows it at once. The tools follow FL Studio's piano roll: P draw, B paint, D delete, T mute, C slice, E select, Y play, Z zooms to the selection (1-7 also pick them). With any tool the right button deletes every note it crosses (one undo step); a double-click on a note opens its properties; Ctrl selects (Ctrl+Shift adds), Shift and Ctrl lock pitch and timing while dragging, Alt bypasses the grid and Alt+wheel changes velocity; a new note takes the last note's length; Ctrl+C, X, V and B copy, cut, paste and duplicate; the lanes below edit velocity, pan, chance, timbre, pressure, micro-pitch, release velocity, velocity spread and repeats, and the clip's controller curves. The Notes menu quantises, transposes, scales, strums and transforms; Pitch Curve draws a bend on each note. Notes > Tools inverts, arpeggiates, flams, repeats, moves notes a degree up or down in the key, makes them follow the chord track, writes a Euclidean rhythm, moves notes to another track, splits a drum loop into a track per key and detects the key. Group keeps notes together when you select them; Lyrics lays syllables on the notes ("Hal-le-lu-jah"). Play On chooses the passes of the loop a note plays on; the Repeats lane plays a note several times inside its length; the Velocity Spread lane varies its velocity each time. Articulation picks one of the track's articulations (Track > Articulations... sets the keyswitch, program or controller each one sends). New Note Length fixes the length a click draws; Audio Behind the Notes shows an audio clip's waveform under them. The controller lane can also hold program changes.

Each lane under the notes names what it shows and its scale - for example Velocity, 0 % to 200 %, with the values at its top, middle and bottom on the right. Point at a stem and the lane reads out that note's value and the value at the pointer; while nothing is pointed at, the header shows the selected notes' values. Controller lanes keep MIDI's 0 to 127 (pitch bend: -8192 to +8191 around its centre) and read out the curve's value at the pointer's position. Selected notes have square heads; a note whose key is folded away has a hollow one. A muted note has a dashed outline, a note that may not play a dotted one and its chance in its label, and a very short note can be clicked a little beside it.

Project > Global Swing delays every off-beat 16th (or 8th) of the song; Chase Notes sounds a note playback starts, loops or jumps into the middle of, or one already under the playhead when its track or clip is unmuted; MIDI Playback Offset starts every note a little later, to line up a slow instrument.

Mixing

Each strip has its trim, polarity, mono and pan mode (balance, dual or width), sends with their own pan, inserts and a meter line with the clip light and the gain reduction. Right-click a strip for Speak Meter (Ctrl+Shift+M: its post-fader peak and the master's LUFS-S) and Peak Watch (off, or -18, -12, -6, -3 or 0 dBFS; the input and master each announce a rising crossing once and re-arm after the level falls). More holds its Strip, Listen and Mixer View menus: show or hide sections, change the strip width, show only some channels, switch the meter between peak, RMS and pre-fader. VCA groups have their own strips at the right of the mixer: right-click one for Links (which of level, mute and solo reach its members) and Put Inside (nesting), right-click a mixer channel for VCA group (join a group or make one), and use Project tools > Groups... to rename or remove a group, add and remove its edit-set tracks and switch its phase lock; a clip's menu has Move With Edit Group.... Solo can be exclusive or additive (Mixer View > Solo Mode). A return's Mixer View menu has Show Sends to Here on Faders: every channel's fader then sets its send to that return (Channel Faders goes back). A strip can swap its left and right sides; a send can be switched off and on again and keeps its level; Create a Return makes a bus fed by the channel; Adjust Channels Together moves several faders by the same amount. Project > Pan Law chooses how much a centred signal is cut (none, 3, 4.5 or 6 dB), Control Room > Mono Check folds what you hear to mono, Order the Mixer by Tracks lines the channels up with the tracks, and Find a Channel searches the names. Each send in the Inspector has a meter beside it, and instrument and sample track headers show their level. Mixer View > Compare Channel EQ draws two channels' EQ over each other. The Control Room (Project menu) switches between three sets of speakers, each with its own trim, and dims, mutes or checks the mix in mono - on what you hear only, never on an export. A channel's "Play Previews Here" sends the browser's previews to it instead of the master. With the keyboard, Tab and Shift+Tab move through a strip's controls and wrap inside it, while Ctrl+Tab and Ctrl+Shift+Tab move to the same control on the next or previous channel and stop at the first and last channel; arrows, Page Up/Down, Home and End adjust a focused fader or knob, and Space toggles Mute or Solo. Every control is announced with its channel's name.

Mixer View > Show Console Section adds a Console section to every strip (it is off by default, and kept between sessions): small knobs for the channel's trim, its EQ (low shelf at 100 Hz, a mid bell and its frequency, high shelf at 8 kHz) and switches for each side's polarity. When the channel carries a Console device (Console Across the Mix puts one on every channel), the section also turns that channel's Console drive and its glue compressor - a switch, threshold, ratio and makeup - and changes that channel only; a channel without a Console says so. A knob's drag is one undo step. The glue compressor is off until you switch it on, so a Console sounds exactly as before. Scripts and agents use mixer.console_strip.

Each strip can show its own meter: the strip's Strip > Meter Mode chooses Peak (after the fader), RMS, Pre-fader, VU or LUFS for that strip alone - Default follows Mixer View > Meter. VU integrates over 300 ms and reads 0 VU for a steady tone at the studio reference (meter.set_reference, -18 dBFS unless you change it); LUFS shows the channel's own short-term loudness and true peak on the strip's meter line. The LUFS field in the transport bar and Large Meters' loudness line are always the master's. Mixer View > Input Meters... shows a meter for every input of your audio interface and, under them, one for each record-armed track's chosen input - whether or not the track monitors it.

Track Delay (an audio or instrument track's menu) and Channel Delay (a channel's Strip menu) move that track or channel later - or, with a negative number, earlier - by a number of samples, shown in the menu entry; the automatic delay compensation keeps everything else lined up. It is saved with the project and one undo puts it back (an instrument track's note delay, which starts notes later, is a separate setting).

A channel's Hardware I/O menu sends it to your interface's outputs as well as the mix, builds up to four cue (headphone) mixes with their own sends, and adds a hardware insert: send to an output, return from an input, with the round trip measured by a ping and compensated. Interface Channels names your interface's inputs and outputs and pairs them; the names are kept per device, not per project. Its Surround > Format menu sets a channel to LCR, quad, 5.1, 7.1, Mono, or a Discrete layout of 2 to 8 channels: the Surround Panner places a channel's sends into a speaker layout on a 2-D room with an LFE send and spread, and a stereo master or a stereo export gets the standard downmix. Mono has one M channel. A Discrete layout has no speaker positions at all: channel 1 goes to the first output, channel 2 to the next, and so on, with no speaker folding or reordering, and its channels are numbered rather than named. Extra channels need a backend with more than two outputs (JACK or ALSA). With a surround master, the WAV export's Channels row can write it as it is - Surround: one channel per speaker (6 for 5.1, 8 for 7.1) in the standard WAV order with its speaker mask; Stereo, the default, folds it with the downmix.

The mode bar across the top of the mixer shows and sets how it is laid out and what mode it is in. View: Mix shows levels, pan and processing; Routing shows, on every strip, where its signal comes from and where it goes, by channel name, with each send's amount and the hardware output. Density: Compact keeps only the essentials (no inserts or macro knobs, routing on one line); Expanded shows every section turned on in Mixer View. Strips never shrink below their width; use Show to filter channels, or scroll. The mode buttons name what the faders drive, the solo mode (exclusive or additive), who is listening (AFL or PFL) and where the master plays and in what speaker format; click one to change it. Every strip has a badge saying what it is (Master, Return, Group, Track, Channel or VCA, plus its surround format) and a line for the modes it is in (AFL/PFL, Solo safe, Surround pan, Cue, HW insert). Routing Matrix... opens every channel against every channel; filter the senders by name, and double-click or press Enter on a cell to make or change that send.

Devices

Add a device from the browser or the rack's menu; right-click a device to insert another before or after it, copy it or its whole chain to other channels, or compare two settings (A/B). Racks hold parallel chains, macros (each mapping with its own range and curve) and key or velocity zones; Wrap into Rack moves a chain into a rack chain. Plug-in windows have a header with presets, and an effect's also has bypass and A/B. Favourite, hide or file plug-ins into folders from the effect picker or the plug-in manager (Project > Plug-in Manager); Preferred Plug-in Format lists a plug-in installed in several formats once. Project tools > Plug-in Modules... lists every file the scan found with its path, its per-file status and the error it failed with, and quarantines or releases one from its row (Edit > Plugin Quarantine adds and releases entries too). A device card's dot lights while the device processes audio. The rack menu bypasses every device, switches them all back on, removes the bypassed ones and opens an XY pad that plays two macros at once. Modulators can be random, smooth random, a step sequence or a retriggered envelope as well as an LFO; a modulator can run a formula of its own (sin(2*pi*t), tri(t) * rand(x)...) and restart on every note a track plays.

A rack can split its input between its parallel chains (Rack > Split the Input): by frequency band, mid and side, or left and right - the chains add back to the whole. A device's menu finds, renames and randomises its parameters (a renamed parameter keeps its own name for macros and modulators), blends its A and B settings, folds its card to the header, plays only what the device changes (the card's Δ button), and sets compatibility options: the generic editor instead of the plug-in's window, keep running on silence, a latency override, the editor zoom. The Device panel shows the level of the channel its devices play into. Native devices: De-esser, Transient Shaper, Vocoder (the voice on the sidechain), Console (Mixer > Console Across the Mix puts one on every channel), Dynamic EQ (bands that move with the level, on the mid or the side alone), Convolution Reverb (Load Impulse Response... from its menu) and Recorder (records what passes it; its menu puts the last take on a new track). An audio clip's Process menu prints a chain's effects onto the clip.

The Audio File Processor (the sampler) has an Attack and a Release knob, in milliseconds, and a Voice limit box in the strip under its title. A note fades in from silence over the attack time and, after its key is let go, fades out over the release time; both can be automated, and a project saved before they existed plays exactly as it did (no attack, a 3 ms release). The voice limit (1 to 64, the most sounding notes the sampler keeps) decides what a new note does when that many are already sounding: it takes the voice that was released the longest ago, or, if every note is still held, the one that started the longest ago. That voice fades out over 3 ms and the new note starts from the beginning of the sample with its own attack; the other held notes are not touched. An agent reads and sets the same three values with plugin.param_get and plugin.param_set on the track's inst plug-in.

The SFZ Player plays instruments in the open SFZ format (sfizz): samples with velocity layers, round robins and key switches. Add it from the browser or the instrument list, or open an .sfz file from the file browser (double-click) - the new track holds the player with that file loaded. The window shows the file that is loaded and how many regions it has; Open SFZ... loads another. Volume (dB) and Sample quality apply at once; Polyphony and Oversampling reload the file. The file is saved with the project by its path (a path relative to the project where it can be), so keep the SFZ and its samples where the project can find them: if the file is missing the player is silent and the project keeps its name. An agent loads a file into a track's SFZ Player with plugin.open_file (one undo step) and reads and sets the settings with plugin.param_get and plugin.param_set.

Rack > Chain Canvas... on a mixer channel opens its chain as a patcher graph: the input, one node per device in order, and the cables between them. Drag from a node's output port to another node's input port to connect; click a cable and press Delete to remove it; Shift-click a cable and drag to give its source a second destination while the first stays. Drag a node sideways (or Move Left / Move Right) to reorder the chain, Add device... to append a device, Remove to take one out. Every edit is the same command an agent runs (patcher.set_wiring, plugin.move, plugin.load, plugin.unload), one undo step each, and the picture always shows what patcher.get_state reports. Cables can only be changed on a chain whose devices the engine routes through its graph; on a chain of the built-in devices the cables are shown and the window says why they cannot be edited, while adding, reordering and removing devices work as usual. Wiring you author is not saved with the project.

Which third-party plug-ins have actually been run? The compatibility page, docs/PLUGIN-COMPATIBILITY.md, lists the VST3, CLAP and LV2 plug-ins that were tried, each by its package, version and file hash, with whether it loaded, whether its own editor opened and whether its saved state came back, and every failure. A plug-in that is not on that page is untested - that Zene lists it as loadable only means the host accepted it.

Each device card has an Actions button (⋯), and the same menu opens on a right-click: Bypass, Open Editor, Presets, A/B, Replace With…, Move Left, Move Right and Remove, then Insert, Copy, Parameters and Hosting. Under the card's header a line says the device's state in words: Bypassed, which A/B setting you hear, the delay it adds, whether its plug-in host crashed or was quarantined, and the preset it last loaded or saved. When the chain changes, the cards that did not change stay where they are. Add device, Insert and Replace open the device picker. With a mixer channel selected, Add device fills the channel's selected parallel chain (Rack > Route to); an empty parallel chain has its own Add device... button under its heading. Start typing to filter it by name, vendor, format or type. The arrow keys move through the list, Enter adds the highlighted device and Escape cancels. Each row shows the device's type, format, vendor and state; favourites come first.

The Inspector keeps its place as you move through a project: a section that still shows the same track, clip or channel is left as it is, and a changed section keeps your keyboard focus and scroll position. When the selected notes differ, a field says 'Multiple values', and a key, velocity or length you type there is given to every selected note; a typed start moves the first note there and keeps the spacing. Volumes read in dB, velocities and pan in %, and times in the time format. Rename a track or a mixer channel by typing in its name field.

Recording

Arm a track with the record button in its header (or Record > Arm All Audio Tracks), choose its input from its Record menu and press Record. Record > Count-In and Pre-Roll starts the take bars early; Record Mode chooses what a pass does to what is already there, for MIDI and for audio alike (the same three choices are in the header's Rec mode readout - right-click it - and in transport.record_options for scripts and agents): Overdub keeps the notes a MIDI pass plays over, and mixes an audio pass into the clip's audio so the old audio stays audible beside the new (a clip that is trimmed, reversed, warped, pitched or gain-adjusted is left untouched and the pass is added over it as a clip of its own); Replace erases the notes a recorded note overlaps, at any pitch - notes only; controllers and automation are kept - and replaces the clip's audio with the pass (one undo brings the earlier audio back); Keep History keeps the clip's earlier audio and every new audio pass as take lanes of the clip: the new pass is the active take, and Next Take Here, comp.take_select or the take-lanes view brings an earlier one back; one undo takes the whole recording back, and the lanes are saved with the project. A MIDI pass in Keep History keeps its notes as Overdub does (MIDI take lanes are not kept yet). The readout shows which mode is set. Positions and lengths read in bars and beats - right-click a position, or use the Tempo Map's picker, for ticks or time; any of them can be typed. After a looped recording, Split into Loop Passes (the sample clip's menu) puts every pass on its own take lane: drag along a lane in the take-lanes view to comp that range, double-click to cycle the take (or Record > Next Take Here). Retrospective capture keeps what you played without recording - save it as a clip or a take afterwards. Record > Punch In Here and Punch Out Here set the punch region at the play position while you record, and the Song Editor's ruler draws that region in a band of its own under the loop brace: drag either end handle to set punch-in and punch-out, or drag the band to move the whole range. The toolbar's Punch in/out button arms and disarms it without losing its bounds, Clear punch range forgets them, and neither the handles nor the button change the loop markers - the two ranges are independent. Metronome Sound and Level chooses the click, its level, the accent and whether it clicks only while recording. A sample track with take lanes shows one row per lane in the arrangement, each take at its own place with its waveform drawn to the bar ruler; the take-lanes panel keeps the same takes in its comp strip, with each take's waveform under the highlighted comp segments, and a touch screen can swipe along a lane to comp that range just as a mouse drag does. Track > Takes and Comping moves the edge between two takes, or comps several tracks (a kit) at once. The header's Rec left readout shows how much recording time the disk's free space still allows at what the armed routes write (record.remaining - "-" when a volume cannot be measured, "0m" when the budget is spent); scripts and agents ask the same command. A recording route can take the master or a channel instead of the input (record.route_source), before or after the channel's devices or fader - if you also monitor what you record, lower the level first: a signal recorded from what it feeds can howl. Track > MIDI Out sends an instrument track's notes to a hardware synth; record its audio back on an audio track that monitors the input. AudioFileProcessor and SlicerT also record the input straight into the sampler: Record take in the instrument's window captures a bounded take (click again to stop, or let it reach its length), then loads it so the waveform and, for SlicerT, the slices are ready to play. The take is a WAV in Recordings; one undo puts the sampler's previous sample back. Agents use record.sampler_capture, record.sampler_capture_stop, record.sampler_capture_status and record.sampler_capture_land for the same take.

An instrument track's Instrument Setup menu - on its header menu, the Inspector's More menu and its instrument's device card - holds what a multi-output, multitimbral or layered instrument needs. Output Buses lists a plug-in's extra outputs: route one to a mixer channel, or make a channel for each. MIDI Parts sends the notes in a key and velocity range on a MIDI channel of their own, so one track plays several parts of a multitimbral plug-in; edit a part in place or remove it. Layers > Layer Rack stacks more instruments on the track, each with Mute, Solo, a Level and its own window, and Layer Zones picks which layers a note plays on. Per-Voice Modulation makes a modulator run once per note of the track and binds it to a parameter of the instrument; Modulation Assignments changes a depth or removes a binding.

The launcher

Show the launcher from the footer's Clip Launcher button, View > Clip Launcher or Alt+L. Each cell plays a pattern or an audio file; drop a sample on a cell to fill it. Each column is headed by its track's name. A cell's play mark shows its state - ▷ stopped, ▷… queued, ▶ playing - and a scene's mark shows its row's, so you can see what will launch. Dragging a sample over a filled cell shows "Replace" before you let go; after the drop, Undo Replace (or Edit > Undo) puts the old clip back. Cells launch on the next bar (or the cell's own quantisation) in trigger, gate, toggle or repeat mode, and scenes launch a row. Launcher > Launch Scene 1-8 can be given keys (Project tools > Customise > Keyboard Shortcuts); Launcher > Controller binds the notes of a MIDI controller to cells and scenes, and binds a note or a control change to a built-in command that needs no arguments (Bind a Command to a Note or Control Change..., Unbind a Command... and Command Bindings list them): a note runs its command on the press and is ready again when you let go, and a control change runs it once as the knob leaves zero and is ready again at zero, so a sweep is one action rather than 127. Launcher > Record What I Played Into a Cell puts what you just played (with Keep Listening on) into a cell as a new pattern. A Gate cell plays while you hold it. Right-click a cell for its Follow Action Chain (the action after it, its chance and timing) and Jump To (move a playing cell inside its clip); right-click a scene to play scenes in order or launch a folder's cells together; the grid's menu captures the playing cells as a new scene and keeps a setlist of songs to step through. A marker can run a command when playback crosses it (marker.set 'action'). Launches and stops are announced once they actually play or stop, not when queued, and one scene launch is one scene announcement rather than one per cell; view.announcements gates these routine messages.

For a show, View > Perform Mode (or Launcher > Perform Mode) opens a window made to be read from a distance: the setlist's song and the next one, Play and Stop, the bar and beat, the tempo with - and + (each an undoable change), the scene playing and the scene that plays next, one big button per scene, what each track is playing, and a large Stop All. Its keys: 1-9 launch scenes 1-9, Up and Down choose the next scene, Enter launches it and moves on to the one after, Space starts or stops, Escape stops every clip, Page Down and Page Up change song (asking about unsaved work first). With a controller connected (Launcher > Controller > Connect...), press Learn MIDI and then a scene button or Stop All: the next note you play is bound to it.

A sub-scene is part of a scene - some of its tracks - that you can launch on its own, for example only the drums of the chorus. Ctrl+click the cells (or Ctrl+Space on a focused cell) to select them, then right-click and choose Sub-scenes > Make a Sub-scene From the Selection; it takes the cells of one scene. The scene's Sub-scenes menu then launches, renames and deletes it. Its cells launch as the scene would launch them, on the same bar lines, and the other tracks play on.

Ableton Link. The Ableton Link button in the arranger's toolbar (also Project > Sync) plays the project in time with Ableton Live, Bitwig, Reason and every other Ableton Link app on your network or on this computer. The tempo is shared both ways - a tempo another app sets is not an undo step - and while the song plays it stays on the session's beat grid: started on its own, it waits for the session's next bar (the quantum, 4 beats unless Project > Sync > Quantum changes it). With Project > Sync > Share Start and Stop on, play and stop in any app that shares them start and stop the others. The button shows how many apps are connected and the session tempo; link.get_state has the rest.

MIDI Clock. Edit > MIDI Clock makes the project a MIDI clock master (Send Clock) or follows an incoming clock (Follow External Clock, and Follow Its Tempo to write the measured tempo into the song); a line in that submenu says what the clock is doing, from not sending through following with no lock to locked at a measured BPM, and names a refusal. Clock Source there chooses which input drives the follower - Any Input or one of the readable MIDI ports - and clock messages from any other port are dropped and counted. The drift bound (how far one pulse may stray from the average before the lock is lost, 0-100 ms) has no item of its own: open Project tools > Sync > Follow MIDI Clock... for the form of the same clock.slave_set command, which sets the mode, the source port and the drift bound together - one undo step. Send MIDI Clock... beside it opens the master's form. An agent sets the same fields over the control socket or MCP and reads them back with clock.get_state, so the menu, the forms and a script all drive one implementation. The clock's own limits are in Known Limitations: a client with one unnamed input can only follow any input, and an incoming start, stop or song position is counted but does not move the transport.

Patterns, clips and cells

Zene has three ways to place music, and they store different things. A pattern is a reusable grid of notes in the PatternStore, shown one pattern column at a time in the Pattern Editor. A PatternTrack in the arrangement references a pattern; its PatternClip is an empty placeholder that says where on the timeline that pattern plays. The placeholder has no instrument and no mixer channel of its own - the instrument tracks inside the PatternStore make the pattern's sound. A MIDI clip is different: it is placed directly on an instrument track and its notes live in the clip at that position, not in a pattern. A launcher cell is not on the timeline at all: it references a pattern or an audio file and launches on the session's next bar (or its own quantisation). A MIDI cell plays its referenced pattern through the PatternStore tracks; an audio cell on a sample track's column plays through that track's devices, fader, pan and mixer channel.

For example, put a recurring kick-and-snare groove in PatternStore pattern 0 - the Pattern Editor's first pattern column - and place the PatternTrack that references it, with its empty PatternClip placeholder, at bar 1. The groove can repeat for the whole song without copying a note. Add a one-bar MIDI fill directly to an instrument track at bar 9; its notes live only in that clip at that position. Then launch kick.wav from an audio cell in the sample track's launcher column. The first is reusable content, the second is positioned content, and the third is a launchable reference with its own launch timing.

Following the signal to the mixer. Select the sample track and read the Inspector's "To ..." field; the track header shows the same channel number. Mix view's Routing page (Mix > Routing) names where every strip's signal comes from and where it goes, with each send's amount and the hardware output. An agent reads the same assignment with track.overview: the track's channel is a ch-<n> id, and the matching entry in mixer.get_state has that id and its name. track.set_mixer_channel changes the assignment, exactly as the Inspector's menu does, as one undo step.

A PatternTrack placeholder never appears as a channel owner: track.overview and track.set_mixer_channel address the song's own instrument and sample tracks. The PatternStore's instrument tracks make the pattern's sound, each with its own mixer channel set in the Pattern Editor, and a MIDI launcher cell follows those PatternStore tracks - not an instrument that happens to sit on its launcher column. For the rest of the model, arrangement.get_state lists the song tracks and their clips, session.pattern_list names the patterns a MIDI cell can play, session.get_state shows the cells and their launch settings, and session.set_slot fills one.

Projects

Projects keep their history: Project > Revisions restores or compares an earlier state. Collect Media copies every file a project uses beside it; Project > Hand Off writes a folder someone else can open with a list of the devices to install first. Import Tracks copies tracks from another project; Save as Template keeps a project to start from.

Project > New Document starts a production, mastering or live project from its own template (your own type.mpt in the templates folder wins); the window title names a mastering or live document. Project > Other Projects opens another project as a read-only reference beside this one and copies its tracks, clips or devices across, and switches to a recent project - keeping the one you left open as the reference if you like. Project > Import AAF... brings in an AAF from another editor: its audio tracks, clips, fades, clip gain and markers (embedded audio is extracted beside the project; OMF is not read). View > Video Window shows a project's video in time with the transport, with a strip of its frames over the arranger; the video's sound can be extracted to an audio track. Edit > Collaborate... lets someone on your network (or across the internet, where your router allows it) join the project: you share an invite code, every edit is sent to the others, and a remote invite gives a phone or another machine the transport and faders only. Nothing listens until you host, and you are asked first.

Scripts, agents and controllers

Every command is reachable over the control socket (JSON-RPC) and from the MCP bridge; Lua scripts (zene.command) reach all of them except those that change your own configuration or start other scripts (shortcuts, workflows, scripts, crash reporting, telemetry). The socket accepts connections only from your own user account (it is created readable and writable by you alone); anything connected to it can do whatever the menus can - save, render, delete - so connect only programs you trust. A controller can drive the remote-control pages (eight knobs following the selected device), a Mackie Control surface, or any parameter through MIDI learn. window.note_editor_set opens a clip in the note editor and sets its tool and view; window.get_state's note_editor reports the active tool and the same zoom, row height and visible top and bottom key.

Live code (Edit > Live Code). The panel edits a Lua script and schedules it on the transport: Every bar, Every beat or Transport play/stop, under an id of your choosing (an id that already exists is replaced in place, one slot). Schedule compiles the buffer first - a script that does not compile is refused in the panel, with the parser's message, and the version that was already scheduled keeps running. Cancel Schedule takes the selected schedule off the clock and Undo (one step) rearms it with the script it held; Undo after a replacement puts the previous script's text, hook and budget back - a schedule's fire and error counters are runtime history and are not rewound. Load Source reads the selected schedule's captured script back into the editor (the same livecode.get_source command an agent calls), so a schedule an agent made can be edited here. The table shows each schedule's id, hook, instruction budget, source bytes, fire/error/over-budget counts, last fire position and last failure. Every fire gets a fresh Lua state, so Lua globals and closures do not persist between bars: keep state in the project (tracks, clips, values), not in the script. A source is capped at 65,536 bytes, the clock holds at most 64 schedules, and the transport is observed every 25 ms, so a fire lands up to one poll after its boundary rather than sample-accurately; more than four crossings in one observation are coalesced rather than fired late, and a seek or meter change re-anchors the grid. Each fire is bounded by its instruction budget (0 inherits the engine's 5,000,000) and Lua memory per run by File > Script Memory Budget (64 MiB by default, 512 KiB to 1 GiB). Schedules live in this process only - they are not saved in the project and do not come back after a restart - and they never run on the audio thread.

Customising and the Window menu

Project tools > Customise > Theme chooses (from the next start) the palette (dark, high contrast or light), the workspace (standard or touch), the interface zoom and accessible mode, and edits the theme's colours one by one - export a theme to share it, import one, or reset to the palette's own. Window > Layouts (also Customise > Window Layouts) saves the panels' arrangement under a name and brings it back; it says what a layout keeps (the view, the open, pinned and floating panels and their sizes - not the zoom, the scroll or the selection). Save never overwrites a name in use; Replace asks first. A project can remember a layout of its own, put back when it opens; your own layout comes back when you open a project without one, or start a new one; the Workflows menu (and Customise > Workflows...) records a run of commands and plays it again, shared by every project or kept with each (Keep Workflows). Drag a panel's header out of the window to float it - on another monitor if you like - and drag it back onto its place, or press Dock, to return it (Ctrl+Shift+F floats or docks the focused panel). Customise > Settings finds any setting by a word, backs all of them up to a file and restores them, and keeps named settings presets (folder paths never travel in a preset or a backup). While a workflow is being recorded the header says so - "Recording workflow ..." with the steps so far - and its Stop button stops and saves it. A workflow that stops at a step that fails says which step and why, which steps applied (they stay applied; undo each with Edit > Undo) and which did not run, in a report that stays open: Retry Step runs that step again, Skip Step and Continue runs the rest without it (both are in the Workflows menu too).

The Window menu holds the track manager (every track in one list: mute, solo, hide, rename, colour, icon, move, remove, and how much processing its mixer channel takes), a large clock, a tuner (it listens to the input, or to the master), the undo history (double-click a command, or select it and press Undo to Here, to go back to before it), memory locations (a named place with its range and zoom) and saved selections (a named range and clips) - each says what it keeps; Replace Memory Location and Replace Saved Selection ask before overwriting. The floating tools (also under the footer's Tools) open where you last left them. The View menu opens the floating windows: Controller Rack (Ctrl+6), Project Notes (Ctrl+7), Scales and Keymaps and the Classic Piano Roll. The Window menu also keeps the main window on top, cascades or tiles the floating windows, shows a cross-hair cursor across the arranger, and moves the keyboard focus from panel to panel with F6 and Shift+F6. A pinch on a touch screen or a trackpad zooms the arranger; a finger tap selects the clip under it. With accessible mode on (Project tools > Customise > Theme), the touch layout makes the controls at least 44 × 44 logical pixels with at least 8 logical pixels between neighbours, so a finger can hit the transport and the editor toolbars: tap Play and Stop, a clip or a note instead of reaching for a mouse. In the note editor each note is a 44 pixel-high target with 8 pixels to the next pitch row, so the vertical zoom stops at that row height; a short note is hit through a wider target around it.

Access

Project tools > Customise > Theme sets the interface zoom (one control sizes text, icons and controls together), the palette, accessible mode - the touch-first layout: click targets at least 44 × 44 logical pixels with at least 8 logical pixels between adjacent targets, strong focus rings, the high-contrast palette and reduced motion - and the workspace (standard or touch), from the next start. With accessible mode on, a finger tap selects an arranger clip or a note and operates Play and Stop, as the mouse does. The touch workspace holds the clip launcher's cells, scene buttons, stop buttons and Stop All to at least 44 × 44 Qt logical pixels at 100% zoom, so a fingertip is enough even though the artwork stays its size; it is a workspace of its own and turns neither accessible mode nor its palette on. An agent chooses it the same way, with window.appearance {"workspace": "touch"} (or reads it with no argument), one undo step each way, and the choice is kept in the user's configuration - not in a project - so the next start opens in it. Knobs, faders, number fields, lists and buttons are reached with Tab and worked with the arrows, Page Up/Down and Home/End, and tell a screen reader (NVDA, VoiceOver, Orca) what they are and their value - Help > Accessibility Check lists any control with no name, role or value, and the interface names them from their parameter or tooltip at start; the keyboard reaches every menu and most lists, and F6 moves between the panels.

Help > Ask answers a question from this manual and the command reference, offline: nothing is sent anywhere. Help > What's New shows the release notes, once per version at start; Help > Tours walks through the window part by part.

F1 (Help > Help for This) shows what the focused control is, the command it runs and its shortcut, above the manual opened at its section - no hovering needed. The manual has a find field (Enter: next match, Shift+Enter: previous); the Command Reference groups every command under these sections, names it as the menus do and finds it by a task ("mixing"), a shortcut or a word of its description. Help > Keyboard Shortcuts lists every shortcut by task; Enter runs the highlighted one, and Presets... applies the recommended accessibility map or a migration map for Ableton Live, FL Studio or Logic Pro after saving the current map as a timestamped backup. Lists - revisions, missing files, plug-ins in the project and the rest - have a find field, sort by a column title (numbers by value; a third click restores the list's own order), run their main action on Enter or a double-click and offer every action on the row from the Menu key, Shift+F10 or a right-click; each action's outcome stays in the Results log under the list.

Press Shift+F1 on any knob, fader, number or menu to learn its drag, wheel, keys and right-click options. Theme, zoom, palette, workspace and accessible-mode changes apply at the next start, and each change says so; a colour that makes text or a control fall below WCAG AA contrast is refused unless you allow low contrast.

Editing without a mouse. Every editing canvas has keys and an editable list. Note editor: Alt+Left/Right previous/next note (Shift adds), Alt+Up/Down the chord's note above/below, Home/End first/last; Ctrl+Left/Right shorten/lengthen, Ctrl+Up/Down velocity (Ctrl+Shift finely); Insert adds a note after the cursor; Enter opens its properties. Expression lane: Left/Right note to note, Up/Down value (Page Up/Down by 10); with several notes selected, one key changes every selected note - including the timbre, pressure and micro-pitch lanes - as one undo step. Controller lane: Left/Right a grid step, Ctrl+Left/Right point to point, Up/Down value at the cursor, Insert adds a point, Delete removes it. XY pad: arrows 1 % (Shift 10 %). Sample Editor: Tab to the waveform, Left/Right move the cursor, Shift+Left/Right extend the selection, Home/End go to the ends, Ctrl+Plus/Minus zoom, Ctrl+0 shows all and Ctrl+A selects all; Tab to an operation and press Space. Comp lanes: Up/Down lane, Left/Right beat (Ctrl bar), Shift marks a range, Enter comps it, C cycles the take. Arranger: Shift+Alt+Up/Down clip on the track above/below, Ctrl+Alt+Left/Right resize. Ctrl+Shift+L on any of these opens its list: a table you can read cell by cell and edit by typing (positions as 5.2.1, pitches as C5); Insert, Delete, + and - work there, and every edit is one undo step.

Announcements. Zene tells your screen reader about errors, refused edits, recording starting and stopping, saving or opening a project, and completed launcher cell and scene changes; the announcements level (view.announcements) sets this to all, errors only, or off. Meter movement is not narrated continuously: Speak Meter (Ctrl+Shift+M, or a strip's menu) reports the focused strip's peak and the master's short-term loudness on request, and Peak Watch speaks once when the input or master crosses a threshold you set, then stays quiet until it falls below again. Accessibility Check can run its checks separately: names, roles, values, keyboard reach and duplicate names.

Screen-reader setup. Zene supports the platform bridge used by NVDA on Windows, VoiceOver on macOS and Orca on Linux. Turn on accessible mode under Help > Appearance, then use Tab and the arrow keys for controls and F6 / Shift+F6 to move between panels. The manual and Help > Accessibility Check read the same names, roles and values the bridge exposes. The tested workflow matrix records each platform's actual screen-reader runs and explicitly marks the ones not yet tested.

Reporting an accessibility blocker. If a workflow is blocked or unclear with a screen reader, magnifier or other assistive technology, use the accessibility blocker form. It asks for the affected workflow, the assistive technology and version, and the steps to reproduce. You do not need to give a diagnosis or any personal medical information. Agents can open this topic with app.help topic "access".

Background tasks - renders from the render queue, stem splits, mastering, library indexing and background video-audio extraction - appear under TASKS in the footer. Click it (or press Space on it) to see each job's progress; Cancel stops the jobs that support it. The list never blocks the window.
