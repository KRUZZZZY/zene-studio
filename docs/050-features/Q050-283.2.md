# Q050-283.2 - Configure neutral tracks for instruments (stage 2 of 3)

Unit (L04, R-workflow-286, P2). Stage 1 (`Q050-283.1.md`) added the neutral arrangement row. This stage lets a
musician or an agent give that row a virtual instrument later, and switch it back to neutral without losing the
instrument. Stage 3 (audio input, switching between audio and instrument) is a separate unit; nothing here has to be
undone by it (see "Format" - the kept-role element is keyed by `kind`).

## What was built

- **`track.set_role`** (`src/core/ControlCommandsTrackRole.cpp`, new): `{track, role: "instrument"|"neutral", instrument?}`.
  A role is the class of the row's `Track` object, so a switch replaces the object but never the row: the replacement
  is built from the row's own captured XML (`control::captureTrackXml`), which carries its `id`, name, mute/solo, colour,
  height, folder and lane flags, then put back at the same index (`control::removeTrack`, `Track::create(element)`,
  `control::moveTrackToIndex` - the remove-undo path). No other track is touched.
  - neutral -> instrument: if the row keeps an instrument role it comes back whole (plug-in and its settings, track
    volume/effects/MIDI settings, clips and notes) with the row's current row fields carried over it (a rename or a
    folder move made while neutral wins); otherwise a fresh instrument track is made and `instrument` loaded into it.
    The row keeps its own name (loading a plug-in would otherwise rename it).
  - instrument -> neutral: the whole instrument track document becomes the neutral row's kept instrument role
    (`NeutralTrack::keptInstrumentRole`).
- **Readback**: `track.get_state` / `track.list` add `role` (`neutral`/`instrument`) on those two kinds of row and, on a
  neutral row, `kept_roles` (`[{role: "instrument", instrument: "<plug-in>"}]`, empty when none). Other types unchanged.
- **GUI** (`src/gui/TrackRoleMenu.cpp`, one call in `TrackOperationsWidget::updateMenu`): a neutral row's Actions menu has
  **Assign instrument** > one item per instrument plug-in that loads by name, or **Restore <plug-in>** when it keeps one; an
  instrument track's menu has **Make neutral (keep instrument)**. Every item invokes `track.set_role` through
  `ControlRegistry` - the agent's command. The call is queued until the menu has closed, because the switch deletes the
  row's view, which owns that menu.
- **Persistence** (`src/tracks/NeutralTrack.cpp`): `<neutraltrack><keptrole kind="instrument" plugin="...">TEXT</keptrole></neutraltrack>`.

## Commands and reversibility

- `track.set_role` (new): **true_inverse**. One structural undo step holds the row's document before and after the switch
  (bounded: a kept role at most 64 Ki characters, the switch documents at most 6x that; a larger track is refused and
  nothing changes), and its undo/redo replace the row by the other document at the same index. Row in
  `ControlReversibilityTableStructure.cpp`.
- `track.get_state` (changed result schema: `role`, `kept_roles`): still `not_mutating`.
- `plugin.load` is NOT used for the switch and its documented limit stands: changing the instrument of an instrument row
  with it still does not restore the replaced plug-in's state. A kept role is given back as it was; naming another plug-in
  for a row that keeps one is refused (`invalid_args`) rather than discarding the kept one.

## Format changes

- A neutral row that keeps an instrument role writes one `<keptrole kind="instrument" plugin="tripleoscillator">` child
  of `<neutraltrack>`, whose TEXT is the captured instrument track (`<zene-track-snapshot><track type="0" ...>`). Text, not
  elements: every `elementsByTagName("track"|"instrument"|...)` walk in the loaders and upgrades would otherwise see the
  kept track as a live one. A neutral row with no kept role saves exactly what stage 1 saved (`<neutraltrack/>`).
- The active instrument role is an ordinary instrument track (`type="0"`): nothing new.
- A stage-1 build loading a file with a kept role ignores the `<keptrole>` child (its loader reads nothing) - the
  row loads as neutral and the kept instrument is dropped on its next save.

## Known limits

- Automation clips that targeted the kept instrument's knobs lose that link when the row goes neutral (the models are
  destroyed with the instrument track) and it is not re-made when the role comes back.
- A mixer channel the instrument used stays in the mixer while the row is neutral; the restored role routes to it again
  by index (the remove/undo path's behaviour).
- A soloed instrument row switched to neutral goes through `TrackContainer::removeTrack`, which un-solos it first (the same as
  track.remove).
- Audio input for a neutral row is stage 3.
- Realtime: no audio-thread code changed. The switch runs on the control/GUI thread; track removal and creation take the
  audio engine's model-change lock themselves (`requestChangeInModel`), as the existing remove/undo path does. TSan does not
  run on this box; reasoned from the code.
