# Q050-324 — Accessibility feedback route

## What changed

One destination is used by `README.md`, `CONTRIBUTING.md` and the manual's **Access** topic:
`.github/ISSUE_TEMPLATE/accessibility-report.yml`. The form asks for the affected workflow, the assistive technology
and version, the operating system/build, and reproduction steps. It has no diagnosis, medical-history or other
personal-medical field.

| Criterion | Test and what it proves | Result |
|---|---|---|
| The same accessibility feedback path is in README, CONTRIBUTING and the in-app Access topic. | `HelpAccessTest::theAccessibilityFeedbackRouteIsTheSameEverywhere` reads all three and compares the exact URL, then opens the Access topic. | `0` |
| The route prompts for workflow, assistive technology and steps without medical information. | Same test reads the issue form, requires those field ids and required validations, and rejects a medical/diagnosis field. | `0` |

No command, format, undo or realtime change; the existing `window.accessibility_report` audit is not the feedback route.
