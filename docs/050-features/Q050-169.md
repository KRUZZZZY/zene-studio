# Q050-169 — Correct hosted-instrument PDC documentation

Unit: `docs/KNOWN-LIMITATIONS.md`'s supported-host bullet ("Instrument hosting is new and
narrow") still said **"no instrument latency compensation"** while the same page's "Hosted
instrument latency" section (updated 2026-10-06, MX-157) documents CLAP/VST3/LV2 latency
reporting measured on rendered audio by `InstrumentLatencyPdcTest` — one page denying and
describing the same capability. This lane removes the blanket denial, says in the
supported-host bullet and in the latency section **which instrument hosts are supported for
delay compensation** (the native CLAP, VST3 and LV2 hosts) and **which paths are not**
(out-of-process, VST2 (Vestige) and Carla — they host and play, they only report no
instrument latency; built-in instruments are 0), keeps the section's polling, clamp,
automation and monitoring limits where they are still accurate, and pins all of that — the
wording *and* the four limits — in the registered test that measures the behaviour.
Docs plus one test slot: no product code, no new command, no project-format change.

## Known limits (stated in the docs as shipped)

- `README.md:65-66` still says "there is no multi-out, no preset management and no
  instrument latency compensation". That paragraph is outside this unit's acceptance (which
  names `docs/KNOWN-LIMITATIONS.md`) and its full correction — editor, multi-out, latency —
  is Q050-003's, whose commits (`e0fafd17d`, `76d4dc73b`) are **not** ancestors of this
  train-5 base but are in `050/m0-train-6`; this lane's paragraph wording therefore
  overlaps that hunk and the merge owner resolves it.
- `InstrumentLatencyPdcTest` does **not** prove the clamp, the automation exclusion or live
  monitoring; those are proven against `PdcMixerTest`, `W3EngineTest` and the source cited
  above. The doc slot pins the wording, not the arithmetic.
- Live playing through a latent instrument ("late by its latency plus the alignment") is
  measured only as the fixture's own 257-frame onset shift; the monitoring path in a real
  session is not exercised by any registered test.
- The doc slot SKIPs if `docs/KNOWN-LIMITATIONS.md` is not reachable from `<build>/tests`
  (two directories up), exactly like `ClipLinkTest`'s doc check — a build outside the
  source tree reports Skipped rather than a pass.
- A layer's latent instrument reports through its own bus handle but is not separately
  tested (already stated at `docs/KNOWN-LIMITATIONS.md:2400-2405`).
- Local TSan does not run on this box (runtime crash at thread creation, train-5 note); no
  product code changed, so no new race surface was introduced.
