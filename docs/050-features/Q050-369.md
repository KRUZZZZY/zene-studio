# Q050-369 - Automation editor List button and focus back to the canvas

Type: feature (size S). Area: GUI item lists.

## What was built

- `src/gui/editors/AutomationEditor.cpp:2088` - the Edit toolbar of the automation editor gains a separator and the
  shared `itemlists::listButton("automation", ...)` button, beside Tan/Flip X/Flip Y. The button opens the same
  `window.item_list` list the canvas's Ctrl+Shift+L opens, and it is disabled while the window has no clip (the
  editor's own rule, not a second one).
- `src/gui/ItemListPanel.cpp:442` `ItemListPanel::closeEvent()` - when the list (a `Qt::Tool`) closes and the list
  or its window had the keyboard focus, the focus and the active window go back to `parentWidget()`, the canvas.
  One shared override, so every item-list panel behaves the same; `include/ItemList.h:160` declares it.
- `tests/src/gui/ItemListButtonsTest.cpp:244` `theAutomationToolbarListsThePoints()` - the acceptance slot: the
  button opens and closes the automation list, Escape and Space return the focus to the editor canvas, the
  `window.item_list` command and the button drive the same list, and with no clip the button is disabled and the
  command refuses the surface.

## New commands / undo / format

- **No new commands.** The button invokes the existing `window.item_list` with `surface=automation`; no command id,
  description, result schema or snapshot row was added or changed.
- **No project format change.**
- **Undo note:** opening or closing a list is not a mutating edit - `window.item_list` is registered with
  `RC::NotMutating` in `src/core/ControlReversibilityTableW3Custom.cpp:130` ("it opens or closes a canvas's item
  list: interface state"). The button only opens/closes the panel, so it creates no undo step; edits made inside
  the list keep their own undo steps as before.

## Known limits

- The test runs on the offscreen QPA platform. It proves that the focus widget and the active window are given back
  to the canvas inside Qt, not that a real window manager raises the window or that a real keyboard's focus follows
  on screen.
- The focus-restore lives in the shared `ItemListPanel::closeEvent()`, so it applies to every item-list panel, not
  only the automation editor's. That is intended, but it means a future panel with a different focus owner would
  need its own rule.
- The button is only enabled while the automation window has a current clip; with no clip there is nothing to list.
