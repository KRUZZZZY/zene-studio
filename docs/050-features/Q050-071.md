# Q050-071 - Third-party plug-in compatibility matrix

Queue unit (P1, L, completion, area L10, members `R-interop-22`, `R-interop-29`): only in-tree fixtures were proven, and the docs
said so. This unit runs real third-party VST3, CLAP and LV2 plug-ins through the host, publishes what happened, and keeps the
third-party results apart from the fixtures. Built on branch `feat/050-Q050-484-oc` together with Q050-484, Q050-103 and
Q050-087 (a feature batch; each unit has its own commits).

## What was built

- **The published matrix: `docs/PLUGIN-COMPATIBILITY.md`** - generated, never hand-edited. 15 pinned third-party plug-ins
  (4 VST3, 4 CLAP, 7 LV2) each with host format, plug-in package/version and system, the sha256 of
  the plug-in file, and four separate outcomes - **listed, load, editor, state round-trip** - each `pass`, `fail`,
  `unsupported` or `not run` (the four mean different things; `not run` is never a pass). Failures and unmeasured cells are listed
  with their detail; what the page does *not* cover (other systems, packagings, versions, VST2/yabridge, audio) is stated.
- **The data it is generated from**: `docs/plugin-compat/subjects.json` (each subject: package, version, download URL, sha256 of
  the package file and of the plug-in binary, licence, project; no plug-in binary is stored in the repo) and
  `docs/plugin-compat/results-linux-x86_64.json` (the measured run: Zene build, system, display, date, one row per subject).
- **The runner `tests/plugin_compat_matrix.py`** (+ `plugin_compat_steps.py`, `plugin_compat_lib.py`, `plugin_compat_page.py`):
  `--fetch` downloads each package and refuses one whose sha256 differs from the pin; one fresh Zene instance per plug-in (a host
  crash is that plug-in's failure); **listing, load and the state round-trip go over the control socket** with `plugin.paths_set`,
  `plugin.rescan`, `plugin.list`, `plugin.load`, `plugin.param_get` / `plugin.param_set`, `plugin.state_save` /
  `plugin.state_load`; the state round-trip moves up to four of the plug-in's own parameters, saves, moves them back, loads and
  compares (a plug-in with no parameter to move is checked by saving, loading and saving again: the two states must be
  identical). **The editor goes through `tests/src/gui/PluginCompatEditorProbe.cpp`** - the real application on a real (virtual) X
  display, `plugin.editor_open`, one second of drawing, `plugin.editor_close` - because `plugin.editor_open` refuses on a
  socket-driven instance (`UnattendedRun.h`). The probe is a registered test that skips unless the runner names a subject.
- **Reruns on the next build**: `--baseline docs/plugin-compat/results-linux-x86_64.json` reruns every named case
  (`<plug-in id>/<step>`, 15 x 4) against the same pinned plug-in files, prints each case whose outcome moved and exits 1 when a
  pass became anything else.
- **The gate `PluginCompatMatrixGate`** (`tests/plugin-compat-matrix-gate.py`, ctest; `PluginCompatMatrixGateSelfTest` is its red
  control): subjects pinned by package and binary hash, one result row per subject, outcomes from the four, a detail for anything
  but a bare pass, no editor `pass` from a run without a display, **the page is byte-for-byte what the renderer produces from the
  results**, no fixture is a row and every fixture the page lists is a real test, and the README, the limitations page and the
  manual point at the matrix. `tests/plugin-formats-docs-gate.py` (`PluginFormatsDocsGate`) was updated: the blanket "no
  third-party plug-in of any kind has been tested" claim is replaced by "no other third-party plug-in than the matrix's", and
  both docs must point at the page.
- **Fixtures stay separate**: the page's last section lists the in-tree fixture tests (`ControlDeviceCatalogueTest`,
  `Vst3InstrumentTest`, `PluginNativeEditorTest`, `Lv2StateTest`, ...) as a second set; they are not rows.
- Docs: `README.md`, `docs/KNOWN-LIMITATIONS.md` and `data/manual/index.html` point at the page.

## What the first run found (the point of the exercise)

Run on CachyOS (Linux x86_64) with the packages named on the page, Xvfb as the display:

- **Load: 15/15 pass.** All fifteen are listed, load and show up as devices. (Before the run two plug-ins looked broken for reasons
  that were the test's, not the host's - an absolute symlink in the Calf package and a missing run-time library, `freeverb3`, for
  Dragonfly - so the runner now repairs package symlinks and the subjects name the library as a pinned dependency.)
- **Editor: VST3 4/4 and CLAP 4/4 open, draw and close** on the virtual display; **LV2 7/7 are `unsupported`**: the host does not
  open an LV2 plug-in's own UI.
- **State round-trip: LV2 7/7, Geonkick VST3, DPF Nekobi CLAP and DPF ProM CLAP pass; five VST3 / CLAP rows fail** - the DPF 3 Band EQ,
  Dragonfly Room Reverb (VST3 and CLAP), DPF Nekobi (VST3) and LSP Compressor (CLAP): after `plugin.state_load` the parameters that
  were moved before saving read back as values other than the saved ones. This is a **known failure, recorded and not fixed here**;
  it is a finding about the host's VST3/CLAP state restore, not a claim about those plug-ins, and the case names
  `<id>/state` are the ones to rerun when it is fixed.

## Commands and reversibility

No command, schema, undo step or project-data change; the runner uses existing read and edit commands on instances it creates
and throws away. No `commands_snapshot.json`, canary or A16 change.

## Known limits

- One system: CachyOS x86_64, the distribution's packages unpacked (not installed), Xvfb as the display. Windows, macOS, other
  distributions and packagings are untested and the page says so; so are plug-ins and versions not in the matrix.
- The editor outcome is "opened, drew for one second, closed" on a virtual display with software rendering: it does not judge
  what the plug-in drew or that input works.
- The state round-trip checks the parameters the host reports (up to four of the plug-in's own); it does not compare audio.
- The mirror URLs are the distribution's; a mirror that drops a version makes `--fetch` refuse (the sha256 pin catches a changed
  file, not a missing one).
