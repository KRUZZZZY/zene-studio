# Q050-158 — Chord-aware keyboard navigation in the MIDI editor

The behaviour was already present on the base: Alt+Left/Right walks notes in time then pitch, Alt+Up/Down moves
within the chord, Shift extends, Ctrl resizes/velocity-steps, Insert adds and Enter edits properties; the canvas
exposes the cursor note through the accessibility value. This unit adds the missing proof that the value includes
the focused note's musical position, not only its pitch, and records the current contract.

| Criterion | Test and what it proves | Result |
|---|---|---|
| Move by pitch/time, identify chord tones, select and edit from the keyboard. | `CanvasKeyboardTest::altArrowsWalkTheNotesInTimeThenPitch` (chord tones at one onset, later onset, additive selection) and `insertAddsANoteAfterTheCursor`. | `0` |
| Focused pitch and bar/beat location are exposed to a screen reader. | `CanvasKeyboardTest::theAreaIsReadAsACanvasWithTheCursorNote` now asserts both the key name and `musicaltime::positionText(192)`. | `0` |
| Tests cover chord grouping, selection and boundaries. | The same keyboard test plus `LaneReadoutTest` cover the lane readout and selection. | `0` |

No command or project-format change. Cursor and selection remain view state (`note.select` is `not_mutating`).
