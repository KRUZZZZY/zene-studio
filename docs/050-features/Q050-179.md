# Q050-179 - Show remaining record time in the UI

Unit: P1, S, completion. Goal: users can see the remaining-time estimate while setting up or
monitoring a recording (WF-085).

## Design notes

- Same shape as the LUFS readout, which already fetched `meter.get_state` from the readouts' tick:
  the budget is asked once a second (LoudnessEvery is 15; QStorageInfo twice a second is cheap, and
  the readout's bindText only repaints when the text changes - `ReadoutField::refresh()` compares).
- "Unavailable" is shown honestly as "-" (the readout idiom the LUFS field already uses), never as a
  fake estimate; the tooltip says what "-" means. A zero estimate is "0m" - the budget spent.
- A blocked refinement: the tick drives the refresh purely by time; a budget that moved and moved
  back inside one second shows the second's value. That is the same one-second resolution the
  command's own model implies and the loudness readout tolerates.

## Commands

None added. `record.remaining` keeps its reversibility row (`NotMutating`, "it reads the free disk

## Known limits

- The words are `record.remaining`'s own estimate (24-bit mono per route, the volume the armed
  routes write to, an implicit route when none is armed); the readout invents no second model.
- One-second resolution on the header (the disk does not move at 60 Hz); the LUFS field keeps its
  finer cadence.
- "-" means "cannot be measured this second", not "some free space exists" - that is the command's
  own refusal, and the tooltip says so.
