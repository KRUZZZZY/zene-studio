# Q050-022 - Show automation lanes as track children

Unit (L06, R-workflow-197, P0): expand an arrangement track to see and edit its
automation lanes directly beneath it. Before this change `automation.lane_add`
already placed an automation track right under the owner and set
`AutomationTrack::followsTrack()`, and the arranger drew it as one more peer row
- never indented, never hidden with its owner, and `automation.get_state` did not
report the relation. The gap is exactly what R-workflow-197 names: lanes "do not
fold with or nest inside the owning track".

## What was built

- `include/Track.h:346` / `src/core/Track.cpp:592,869`: a per-owner `autolanes`
  fold flag (`Track::automationLanesCollapsed()`/`setAutomationLanesCollapsed()`),
  saved on the owner's own `<track>` element only when folded, reset on absence
  (`TRACK_RESTORE_SCHEMA`, `src/core/Track.cpp:89`) - so a project that never
  folded a track re-saves its old bytes.
- `include/Track.h:360` / `src/core/Track.cpp:419`: `Track::automationLaneChildren()`
  and `hasAutomationLaneChildren()` - the lanes whose `followsTrack()` is this
  track's stable id, derived in container order, never stored twice.
- `src/gui/editors/TrackContainerView.cpp:324` (`hiddenUnderOwner`),
  `:338` (`groupedWithLaneChildren`), `:368` (`realignTracks`): a lane row is
  hidden when its owner is hidden (`Track::isVisible`) or folded, or sits under a
  collapsed folder; and the rows are ordered so an owner is immediately followed
  by its lane rows however the flat track list was reordered.
- `src/gui/tracks/TrackView.cpp:174` (`updateFolderIndent`): a lane's settings
  column is indented one level under its owner (inheriting the owner's own folder
  depth) and its accessible description names the owner.
- `src/gui/tracks/TrackOperationsWidget.cpp:160,330,411`: the owner's row gains a
  fold button (`btn-automation-lanes`, visible only when the track owns a lane)
  and a context-menu action, both through the registered
  `automation.lanes_set_collapsed`; the GUI delete path removes the child lanes
  with the owner as one undo step.
- `src/core/ControlCommandsAutomationLanes.cpp:242,318`:
  `automation.lanes_set_collapsed` - folds/unfolds a track's child lanes as one
  undoable Track checkpoint.
- `src/core/ControlCommandsAutomation.cpp:104`: `automation.get_state` now
  reports each lane's owner (`follows`), each track's `automation_lane_count` and
  `lanes_collapsed`, from the fields the arranger renders.
- `src/core/ControlStructuralSupport.cpp:310` (`journalTrackRemovalWithLanes`),
  `src/core/ControlCommandsArrangement.cpp:269`: deleting an owner removes its
  child lanes too, captured as ONE structural step.

## New commands and reversibility

- `automation.lanes_set_collapsed` (group `automation`, args `track`, `collapsed`):
  fold/unfold a track's child automation lanes. Reversibility: **TrueInverse** -
  a live `Track` checkpoint; the owner's own `<track>` element carries `autolanes`
  and `Track::loadTrack` resets it on absence. A16 row in
  `src/core/ControlReversibilityTableArranger.cpp:131`.
- `automation.get_state` gained read-only fields (`follows`,
  `automation_lane_count`, `lanes_collapsed`); still `NotMutating`.

## Format changes

- New per-owner attribute `autolanes` on `<track>` (only written when folded;
  reset on absence). Old projects load and render exactly as before (default:
  lanes shown). New data round-trips (proved by the save/load test).
- No change to the lane's own serialisation (`follows` already existed, ED-181).

## Known limits

- The arranger ORDER is a projection: an owner's lane rows are drawn directly
  beneath it in `realignTracks` (derived from `followsTrack`), while the flat
  container order a `track.list`/save round-trip sees is unchanged. A `track.move`
  therefore moves the owner's row and the lane is regrouped under it visually,
  without rewriting the flat list.
- Folding is a view flag with no audio meaning (like `visible`): a folded lane
  still plays.
- Moving the owner's clips carries its lane's points only when
  `arrangement.modes` `automation_follows_clips` is on (the pre-existing ED-190
  behaviour, unchanged).
- TSan does not run on this box; the new code is control/GUI-thread only
  (`automationLaneChildren` reads the container under its read lock) and adds
  nothing to the audio thread.
