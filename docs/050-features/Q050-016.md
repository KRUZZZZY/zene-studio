# Q050-016 — MPE expression event streams

Unit: capture, edit through commands, save, and play **time-varying** pitch, pressure and timbre
points on individual notes. The merged model stored one scalar `MpeNoteExpression` snapshot per
note (task #601); this unit adds per-axis ordered `(tick from the note's start, value)` streams on
top of it, the agent commands that read and write them, backwards-compatible serialization, and a
playback path that delivers each point at its own frame offset. The GUI curve editor is the
dependent unit Q050-137 and is deliberately not part of this lane (see Known limits).

## Built
- **Model** — `MpeExpressionPoint` and `MpeExpressionStream` in `include/MpeExpression.h:79`/`:106`
  (three axes, `MaxPoints = 256`, points sorted by tick, each holding until the next);
  `MpeExpressionStream::setPitch/setPressure/setTimbre/clear` and `valueAt()` in
  `src/core/midi/MpeExpression.cpp:115`/`:152` clamp and order the points (stable sort, so a
  round trip never reorders a user's points). `MpeExpression::bendForPitchCents()`
  (`src/core/midi/MpeExpression.cpp:219`) is the inverse of the existing bend→cents mapping, used
  to turn a streamed pitch point into a MIDI bend.
- **Note storage** — `Note::hasMpeStream()/mpeStream()/mpeStreamForEdit()/setMpeStream()/
  clearMpeStream()` (`include/Note.h:242`) backed by a `std::unique_ptr<MpeExpressionStream>`
  (deep-copied by the copy constructor and `operator=`, so two notes never share an editable
  stream: `src/core/Note.cpp:421`). Serialized as three **optional attributes** —
  `mpepitchpts` / `mpepressurepts` / `mpetimbrepts`, `tick:value,tick:value,...` — written only
  when an axis is non-empty (`src/core/Note.cpp:566`) and parsed with per-token validation,
  clamping and re-sorting (`src/core/Note.cpp:677`). An attribute, not a child element, because
  `Note::loadSettings` treats any child of a note element as detuning.
- **Playback** — `src/core/MpeExpressionStreamPlayback.cpp` (new): `NotePlayHandle::
  scheduleMpeExpressionStream()` (line 216) is called from `NotePlayHandle::play()`
  (`src/core/NotePlayHandle.cpp:308`) right after the note-on. For every stream axis it emits the
  points whose tick falls in the current period, each at its own frame offset
  (`sendMpeExpressionAxisEvent`, line 108: pitch → MIDI bend on the note's channel, pressure →
  channel pressure, timbre → CC74). `effectiveMpePitchCents()` (line 95) feeds
  `updateFrequency()` (`src/core/NotePlayHandle.cpp:674`), so a streamed pitch curve retunes the
  built-in synthesisers from period to period while the bend event reaches a MIDI consumer
  sample-accurately. `sendMpeExpressionMidi()` skips an axis a stream schedules, so no snapshot is
  sent first. A note with no stream runs none of this: nothing changes for every project saved
  before this feature.
- **Commands** (both on the agent surface, one registered `ControlRegistry` command each) —
  `note.expression_stream_get` (`src/core/ControlCommandsNoteExpression.cpp:268`) and
  `note.expression_stream_set` (line 297, `replaceStreamAxis` line 249). The set command replaces
  the axes the call names (an empty array clears one axis; omitting an axis keeps it; all empty
  removes the stream), is one MidiClip-checkpoint undo step, and its `__transaction` inverse
  restores the previous three axes. Reversibility rows: `note.expression_stream_set` =
  `true_inverse` (`src/core/ControlReversibilityTableLive.cpp`), `note.expression_stream_get` =
  `not_mutating` (`src/core/ControlReversibilityTablePassive.cpp`).
- **Test fixture** — `tests/src/plugins/MpeTestConsumer.cpp` now also consumes `MidiPitchBend`
  (into cents) and records each axis's last value and period offset; `tests/src/plugins/
  MpeConsumerProbe.h` (new) is the readback interface the playback test dynamic-casts to, so the
  offset each event arrived at is observable (the fixture's audio level alone applies a period's
  expression to the whole period and cannot show it).

## Commands, format changes, reversibility
- New: `note.expression_stream_get` (`not_mutating`), `note.expression_stream_set` (`true_inverse`,
  MidiClip checkpoint) — both in the `note` group.
- Format: three optional note attributes (no DataFile version bump). Old projects load with no
  stream and render/save exactly as before; this build's streams are ignored by an older build.
- Canaries updated: README `<!-- canary -->830 ids / 76 groups<!-- /canary -->`, the
  `commands_snapshot.json` regenerated from a live instance, and the A16 histogram re-taken
  (`rows=839 true_inverse=418 snapshot=42 irreversible=22 not_mutating=357`).

## Known limits
- **No GUI curve editor.** The streams are drivable through the socket only; drawing/dragging them
  in the piano roll is Q050-137, which depends on this unit. The existing note-editor expression
  lane edits the scalar timbre/pressure values (`note.expression_set`), not the streams.
- **Point resolution is a tick**, and the pitch axis retunes the built-in synthesisers from period
  to period (a note's frequency is computed once per block); the MIDI bend event is the
  sample-accurate part a hosted instrument or MIDI output sees.
- **No interpolation**: a point holds until the next (step), where `note.pitch_curve` interpolates
  linearly. The two are different stores on purpose — the pitch curve is the note's detuning
  automation, the stream is the MPE gesture log.
- **A DSP consumer of pressure/timbre is still the in-tree test fixture**; no built-in synthesiser
  reads those axes (unchanged from #649).
- TSan does not run on this box, so the realtime race argument is by design: streams are written on
  the UI/control thread, and a playing handle owns its own deep copy (`Note`'s copy constructor),
  so the audio thread never observes a half-written vector.
