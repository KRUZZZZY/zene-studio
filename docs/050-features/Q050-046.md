# Q050-046 - Offer undoable recovery at startup

## Unit
P0, M. Users are prompted about interrupted takes at startup and can place a recovered take with a reversible action. Builds on Q050-045's journal; the journal format and crash-loss bound are unchanged.

## Verified starting point
`record.recovery_restore` only marked the journal restored; the menu then created the track itself (the old `placeOnNewTrack` in `src/gui/RecordingRecoveryMenu.cpp`), outside any undo step. Nothing prompted at startup.

## Built
- `src/core/ControlCommandsRecordingPlace.cpp` (new): `record.recovery_place {take}`. Refuses a journal that is not in progress and a take with no recoverable frames. Writes the journal as `restored`, creates a sample track `Recovered: <take>` with the file in a clip at bar 1, and records ONE `addUndoStep`: undo removes the track (by stable id) and rewrites the journal as `in_progress`; redo places it again and resolves the offer. The WAV is never touched. Registered in `src/core/ControlRegistryRegistrations.cpp`, declared in `include/ControlRegistry.h`, listed in `src/core/CMakeLists.txt`.
- `src/core/ControlReversibilityTableLive.cpp`: `record.recovery_place` is `true_inverse`.
- `src/gui/RecordingRecoveryMenu.cpp`: the menu's "Place on a New Sample Track" now invokes `record.recovery_place` (the duplicated GUI-side track creation is gone). New `interruptedTakes(takes)`, `offerRecordingRecovery(parent, ask)` and `offerRecordingRecoveryAtStartup(parent)`: the startup box (Place on New Tracks / Decide Later) appears only when `record.recovery_get_state` lists a take; an unattended run (control socket, no display) never gets a dialog and gets a stderr line instead. `src/core/main.cpp` calls `offerRecordingRecoveryAtStartup` once the initial project exists (deferred to the first event-loop turn). A FAILED `record.recovery_get_state` is not "nothing to recover": `interruptedTakes()` returns the typed failure, the startup offer logs it and returns `StartupRecoveryChoice::QueryFailed` instead of `NothingToOffer`.
- `record.recovery_restore`'s description and `next_step` now point at `record.recovery_place`.

## Commands and reversibility
New: `record.recovery_place` - `true_inverse` (action step). Surface now 824 ids / 76 groups (README canary updated; snapshot regenerated from a live instance). A16 histogram line in `docs/RELEASE-NOTES-v0.3.0-alpha.md`: 832 -> 833 rows, true_inverse 412 -> 413.

## Format
No project-format or journal-format change.

## Known limits
- Undoing a placement puts the offer back (journal `in_progress`), so the next start offers the take again; that is intended and stated in the command description.
- The startup box cannot be shown headless; its decision logic is tested through the injected `ask` callback, the dialog itself is not exercised.
