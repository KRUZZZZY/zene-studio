# Q050-214 - Plug-in editor gesture undo

Branch `feat/050-Q050-214-oc`, base `2a7fd9f9c` (`050/m0-train-24`). Unit (P2, feature, M, L10): a complete VST3 or CLAP
editor gesture is one project-history step, shared by GUI and agent.

## What changed

- **The plug-in reports.** VST3 `beginEdit`/`endEdit` (`plugins/Vst3Effect/Vst3ComponentHandler.h`) and CLAP
  `CLAP_EVENT_PARAM_GESTURE_BEGIN`/`END` from `process()` (`plugins/ClapEffect/ClapHostInternals.h`, `markGesture`) only
  push the mark and the parameter's value at that moment onto a per-parameter queue, `PluginParamGesture`
  (`include/PluginParamGesture.h`): bounded (32 marks), preallocated inside the host's parameter slot, lock free.
- **The GUI poll replays.** Each 100 ms poll drains the queue, then reads the current value, and hands both to the model's
  `PluginGestureHistory` (`include/PluginGestureHistory.h`), which replays the marks in order. Every gesture that finished since
  the last poll therefore gets its own step, whose undo value is the previous gesture's final value. A gesture's first change takes
  the journal checkpoint while the model still holds the value from before it; later changes of that gesture write with
  `setValue(value, false, false)`. A change outside a gesture takes its own checkpoint, as before, including one made just before a
  begin, which the begin's value reveals.
- **Same stack.** Nothing new is added to the history: the checkpoint is the model's own, on `ProjectJournal`, which Edit > Undo,
  the Undo History panel and `control.undo` all unwind.
- **A shared-history defect fixed on the way.** `control.undo` refused with "EVICTED" when the last agent record's step had
  merely been undone: `plugin.param_set`, then Edit > Undo, then an editor gesture, then `control.undo`. `step < oldest` was
  true for both. `ProjectJournal::newestEvictedSerial()` now tells them apart. A record from a previous document is still refused.

## New commands and reversibility

No new command and no class change. `control.undo`'s description now names the case below, so the snapshot was regenerated from a
live instance (878 ids / 77 groups; only that description and the capture stamps differ); `tests/doc-figures-gate.py` exits 0.
`control.undo`'s behaviour changes in one case: a false "EVICTED" refusal becomes the undo of the journal's top step, reported as
`unrecorded edit` with its `step_serial`, the existing label for a top the record does not match. `plugin.param_set` stays
`true_inverse`. A gesture is one journal step.

## Realtime

The CLAP path runs on the audio thread: `markGesture` does a binary search and one queue push, with no allocation, lock, wait, I/O,
signal, journal, model or Qt work. All of that stays on the GUI poll. The push is Vyukov's bounded queue: a compare-and-swap that claims a
cell, retried only when another reporter just took it, so it never waits for the reader, and a full queue drops the mark and counts it. A
cell's payload is published by its sequence (release/acquire). `begin()` adds a release fence before the gesture's first value is stored,
and `read()` drains, loads the value, takes an acquire fence and looks at the queue again: a value from a gesture whose begin has not been
taken leaves `settled` false, and the next poll takes both. Reasoned, not run under TSan, which does not run on this box;
`PluginParamGestureTest` runs one and two reporting threads against a draining reader and checks order and values.

## Format changes

None. Nothing new is written to a project file, so old projects load and render as before: a gesture changes only what a poll does
with a journal checkpoint, and no render path is touched.

## Portability

No Qt-6-only API (`qMax`, `QMetaObject::invokeMethod` by name). `std::atomic_thread_fence`, `std::span` as neighbours use it. The test's VST3
half is compiled only when the opt-in fixture is (`WANT_VST3_TEST_INSTRUMENT`), and each half SKIPs without its fixture.

## Known limits

See `docs/KNOWN-LIMITATIONS.md` ("Plug-in editor gesture undo"). In short: more than 16 gestures on one parameter between two polls merge past
the 16th; one step per parameter, so an XY pad is two; changes a plug-in does not report as parameters are outside the history; a plug-in that
never ends a gesture merges until its next begin; a gesture has no row in the Undo History list, only its buttons.
