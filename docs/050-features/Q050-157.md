# Q050-157 - Plug-in descriptor lifetime check

Unit: P1, S, fix, area L10 (member `R-effects-8`). Goal: users can rescan plug-ins without invalidating descriptors
held by loaded instances. Branch: `feat/050-Q050-157-oc`, cut from `050/m0-train-19` (`5c1c6715d`).

## Result: clean - no product change

The ASan reproducer was run and came back **clean**. The existing ownership code already keeps every descriptor a
rescan replaces alive: `PluginFactory::discoverPlugins()` moves the outgoing cache-served descriptor store into
`m_retiredCachedDescriptors` instead of freeing it (`src/core/PluginFactory.cpp:234`), the background-scan commit does
the same (`src/core/PluginFactoryBackgroundScan.cpp:363`), and retired stores live until the factory is destroyed
(`include/PluginFactory.h:284-286`). Per the second criterion ("if it fails ..."), no product code was changed.

Where a cache-served descriptor reaches a live instance: `Plugin::instantiateWithKey()` sets the instance key's
`desc` to the factory's current descriptor (`src/core/Plugin.cpp:212`). Instruments such as TripleOscillator ignore
the key and use their compiled-in descriptor, but effects keep the key for their whole life (e.g.
`plugins/Amplifier/Amplifier.cpp:96`, `EffectChain::loadSettings` at `src/core/EffectChain.cpp:201`). So the reproducer uses an
effect: that path is what the unit's `R-effects-8` member is about.

## ASan recipe

The lane guard refuses to configure a second build tree, so the reproducer is not a `WANT_DEBUG_ASAN=ON` tree. It
re-compiles with `-fsanitize=address -fno-omit-frame-pointer` the test translation unit and the four product units on
the descriptor path (`src/core/Plugin.cpp`, `PluginFactory.cpp`, `Effect.cpp`, `EffectChain.cpp`). It uses the normal tree's own
`flags.make`, swaps those five objects into the test's `objects1.rsp`, and relinks `build/tests/PluginScanCacheTest-asan`
with the ASan runtime. ASan therefore intercepts every allocation and free in the process (freed memory is quarantined)
and checks every read made by the instrumented units; reads made by un-instrumented code are not checked. Run with:

    ASAN_OPTIONS=detect_leaks=0:halt_on_error=1:use_sigaltstack=0 QT_QPA_PLATFORM=offscreen \
      build/tests/PluginScanCacheTest-asan testCacheServedEffectSurvivesRescanAndSave

`use_sigaltstack=0` is required for any ASan build of Zene. `CrashReporter` gives each thread its own
`thread_local` 32 KiB alternate signal stack (`src/core/CrashReporter.cpp:100`), and at thread exit ASan tries to unmap
"its" alternate stack. It finds the app's one and dies (`failed to deallocate 0x8000 bytes ... error code: 22`) when
the dummy audio thread stops. This is a tool interaction and is unrelated to the descriptor path.

## Known limits

- Retired descriptor stores are never freed before the factory is destroyed, so memory grows with each rescan by
  one store: the strings and pixmap-name loader of every cache-served plug-in. Freeing them would need reference
  counting across every holder of a raw descriptor pointer (instance keys, browser rows, drag-and-drop keys). That is out of
  scope for this check, and it is the separate patrol finding the scoping brief cites.
- The ASan build instruments five translation units, not the whole tree (see recipe). A read of a freed descriptor
  from other code would not be reported. The mutation run shows the instrumented reads catch the case that matters.
- The reproducer covers the in-process cache-served path on Linux. Windows skips it (test hosts cannot load plug-in
  modules there, same reason as the rest of this suite).
- Threading (TSan does not run on this box, so this is reasoned from the code): stores are created and retired only
  by scans and background-scan commits, which run on the main thread (`include/PluginFactory.h:255-261`). Retiring frees
  nothing, so a reader on any thread cannot lose a descriptor during a rescan. This unit adds no code to any thread.
