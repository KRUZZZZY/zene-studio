# Q050-036 — Complete the specified warp mode set

Unit: Beats, Tones, Texture, Re-Pitch, and Complex selectable per clip with distinct renders.
Goal: users can select the five spec modes per clip and hear their distinct behavior.

## What changed

`WarpStretchMode` (include/WarpMarkers.h:97) grows from Resample/PreservePitch/RubberBand to
Resample(`re_pitch`)/PreservePitch/Beats/Tones/Texture/Complex. `Resample` is the spec's Re-Pitch
(varispeed, the default, value unchanged); `Complex` is the renamed `RubberBand` value (same R3
settings owner decision 12 introduced, same file token `rubberband`). Canonical wire/file names come
from `warpStretchModeName`/`warpStretchModeFromName` (same header): `re_pitch`, `preserve_pitch`,
`beats`, `tones`, `texture`, `complex`, plus the `resample`/`rubberband`/`wsola` aliases every old
file and command still accepts.

Three engines render the six names: the resampler (Re-Pitch), WSOLA at its default parameters
(PreservePitch, 1024/128), WSOLA parameterised (Tones doubles the alignment reach to ±256 frames;
Texture halves the grain to 512), and Rubber Band R3 (Beats = single short window, Complex = full
multi-resolution). Tones/Texture are WSOLA-backed because R3's remaining options are R2-only and
render identically under R3 (measured). A clip keeps one Rubber Band pool per RB-backed mode
(`SampleClip::m_rubberBands`, include/SampleClip.h:264), so switching modes never frees voices a
live play handle holds. `warp.stretch` accepts all names, reports canonical `stretch` plus
`stretch_algorithm` (`resampler`/`wsola`/`rubberband`), and stays one `control.undo` step. The clip
context menu gains a "Warp mode" submenu driving that same command.

## Known limits

- Local TSan does not run on this box (runtime crash at thread creation), so thread-safety of the
  per-mode pools is by design (control-thread build-once, lock-free claim, dirty release, off-thread
  recycle — unchanged from owner decision 12) rather than sanitizer-proven.
- No CPU figure for R3 short-window vs full settings vs WSOLA on the bench projects.
- R3's transients/phase/long-window options are R2-only, so Beats (short window) is the only R3
  personality change offered; Tones/Texture distinctness comes from measured WSOLA parameters.

## Round 4 (Sonnet lane, 2026-10-19)

Luna r3 (code REWORK): the live mode switch was unsynchronized. `SampleClip::setWarpStretchMode` stored a plain
`m_stretchMode` and only then built the new mode's Rubber Band pool (a `unique_ptr` array element), while the render
thread read both at play-handle construction.

- `include/Clip.h` (`m_stretchMode`): now `std::atomic<WarpStretchMode>`, plus a protected virtual
  `prepareWarpStretchMode(mode)` hook. `Clip::restoreState` (`src/core/Clip.cpp`, the warp branch) calls the hook BEFORE it
  stores the restored mode (release), so a load, paste or undo cannot publish a mode before its voices.
- `include/SampleClip.h`, `src/core/SampleClip.cpp`: `ensureRubberBandPool(mode)` builds a mode's pool on the control thread
  and publishes it to `m_rubberBandPublished` (atomic raw pointers, release) after construction; `setWarpStretchMode` builds
  first, then stores the mode (release); `warpStretchMode()` is an acquire load; new `rubberBandPool(mode)` reads that mode's
  published pointer. Rubber Band construction stays on the control thread; the render thread only loads.
- `src/core/SamplePlayHandle.cpp`: the handle reads the mode ONCE and asks for THAT mode's pool, so a switch between its two reads
  cannot hand it the other mode's voices.
- `src/gui/ClipEditsMenu.cpp`: the refusal dialog title is now "Clip edit refused" (it was "Gain and fades" for every clip edit,
  including Beats/Complex on a build without Rubber Band). No unit test: the dialog is modal and unattended runs log instead.
- Regression: `SampleClipWarpModesTest::aFirstLiveSwitchBetweenBeatsAndComplexNeverShowsAModeWithoutItsPool`
  (`tests/src/tracks/SampleClipWarpModesTest.cpp`): a reader thread plays the render thread (mode, then that mode's pool) while
  the control thread makes the first Beats, Complex and Beats switch of six fresh clips; any observed Rubber Band mode must have
  its pool (and, in a no-Rubber-Band build, must not). Negative control: with the two lines of `setWarpStretchMode` swapped back
  (mode first, pool second) the test failed: "2022424 reads saw a mode whose pool state was not published"
  (`q036-r4-negctl-ctest.log`, exit 8); with the fix it passes (about 5.9 million observations, 0 violations).
