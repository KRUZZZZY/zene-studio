# Q050-030 - Neural Amp model-load responsiveness (P0, S)

Goal: selecting a second Neural Amp model never freezes the GUI behind the previous load.

## Verified starting point
The claim held. `setModelPath()` joined the previous worker synchronously (old `NeuralAmpEffect.cpp` ~111), so a
second selection blocked the GUI thread for the whole of the first parse.

## What was built
- `plugins/NeuralAmp/NeuralAmpEffect.cpp` `setModelPath()` (about line 118): records the path in a one-slot request
  (`m_pendingPath`/`m_hasPending`, guarded by `m_loadMutex`) and returns. It starts a worker only if none runs; it
  joins only a worker that has already cleared `m_workerRunning` (a thread on its way out), never a busy one.
- `workerLoop()`: takes the newest request, loads it, repeats until none is waiting. A request made while a load
  runs replaces the waiting one (A, B, C quickly: B is never parsed). After a parse, a newer request or shutdown
  makes the result stale and it is dropped before `publishModel()`.
- `~NeuralAmpEffect()`: sets `m_shuttingDown`, clears the waiting request, joins the one worker (waits for at most
  the parse already under way; a parse cannot be interrupted), then deletes the model.
- Audio side unchanged: `publishModel()` / `processImpl()` still use the seq_cst pointer exchange and the
  `m_audioActive` flag; the audio thread takes no lock and allocates nothing.
- Test seam: `NeuralAmpEffect::s_testBeforeLoad` (header), present only under `ZENE_NAM_TEST_SEAM`, which only
  `NeuralAmpModelLoadTest` defines (it compiles the effect and engine in). The shipped module has no hook and no sleep.
- Status text now reads "loading <path>" from the request on.
- `tests/src/plugins/NeuralAmpModelLoadTest.cpp`, wired in `tests/CMakeLists.txt` (sources, `add_dependencies neuralamp`
  for the generated `plugin_export.h`), registered in `tests/fork-sources.txt` and `tests/all-sources.txt`.

## Acceptance

|---|-----------|------|------------------|------|
| 1 | Selecting during a slow load returns promptly | `selectingWhileASlowLoadRunsReturnsPromptly` | First load held 1.5 s by the seam; two `setModelPath` calls each measured < 150 ms while the hold is still in place (asserted), then the hold is released and C is the published model | 0 |
| 2a | Final requested model wins; no half-built model | `theFinalRequestedModelWins` | A (held), B, C requested; after release status is "loaded C", stays C after 100 ms, the loads that began are exactly A and C | 0 |
| 2b | No leaked worker, no use-after-free on deletion mid-load | `rapidSelectionsAndDeletionMidLoadLeaveNoWorker` | 20 rounds of 50 rapid requests, half deleting with loads in flight; then deletion while a load is held: the destructor waits for that parse, returns, and the queued B is never parsed | 0 |
| 2c | Audio thread allocation-free and lock-free swap, output finite | `audioThreadAllocatesNothingWhileModelsSwap` | 4000 `processImpl` blocks under `AllocationProbe` while another thread swaps models every ms: 0 allocations, finite output | 0 |

Negative control: with the old join restored in `setModelPath`, the test hangs and ctest reports Timeout (20 s limit).
Six consecutive reruns of the final build: ctest exit 0 each.

## Commands, format, limits
- New commands: none. Project format: unchanged (`model` attribute still saved/loaded through `setModelPath`).
- GUI and agent surface: the existing control path (`NeuralAmpControls::setModelPath`) is unchanged and now non-blocking.
- Limit: destroying an effect still waits for a parse already in progress (the parser has no cancellation point);
  waiting requests are dropped immediately.
- Not run: the whole suite (the orchestrator runs the bar); AddressSanitizer was not available in this build.
