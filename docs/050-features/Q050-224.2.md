## What was built

`goal`: crash reports preserve useful raw stack context without doing symbol or module resolution in signal
context.

| Piece | Where | What it does |
|---|---|---|
| `kMaxCrashFrames = 24` | `include/CrashReporter.h` | The budget: the most addresses one report can carry, and the most steps the walk may take. |
| `CrashInfo::frames` / `frameCount` | `include/CrashReporter.h` | A fixed array in the existing trivially-copyable POD snapshot; no allocation, no ownership. |
| `captureFrames(context, out, capacity)` | `src/core/CrashReporterFormat.cpp` | Writes the faulting instruction as frame 0, then walks the crashing thread's saved frame-pointer chain (raw memory reads only). |
| `appendFrames(...)` | `src/core/CrashReporterFormat.cpp` | Appends `frames=<count>` and one `frame[<i>]=0x<hex>` line per address through the same capped appenders as every other field. |
| `recordThreadStackBounds()` | `src/core/CrashReporterFormat.cpp` | Exact stack bounds, from `pthread_getattr_np()` on Linux or `pthread_get_stackaddr_np()` on macOS. Called only from `install()` (main/control thread); it allocates and is not real-time safe. |
| `noteThreadStackMarker()` | `src/core/CrashReporterFormat.cpp` | The real-time-safe half: takes a local's address and raises the thread's ceiling. Called from `installAlternateStackForCurrentThread()`, which the render/JACK paths call. |
| `currentThreadId()` | `src/core/CrashReporterFormat.cpp` | `gettid()` on Linux; the thread's Mach port on macOS (see below). |

`frame[0]` is the faulting instruction. The rest are the return addresses in the saved frame chain; repeated
addresses are kept, never folded, because a recursive chain reaches the same call site at every depth.

### Async-signal-safety, stated rather than assumed

The first version of this unit called `_Unwind_Backtrace()` from the handler. That was wrong: a general
unwinder finds each PC's FDE through the dynamic loader (object lookup under a loader lock) and can enter
the allocator. The frame-count cap bounded the number of steps, not that work. The final handler does **no
unwinder call**:

- It dereferences only `[interrupted SP, recorded stack ceiling]`. The ceiling is an address that was on
  this thread's stack, so every address below it that the thread has used is mapped; the walk never
  touches an unmapped page.
- `recordThreadStackBounds()` (exact, allocation inside `pthread_getattr_np`) runs only in `install()`, on
  the main/control thread at startup - never in `renderNextPeriod()` or JACK's `processCallback()`. Those
  audio-thread paths call `installAlternateStackForCurrentThread()`, whose new work is
  `noteThreadStackMarker()`: one local address plus a thread-local compare/store. No allocation, lock,
  wait, I/O or Qt call is added to the real-time thread.
- Bounded three ways: the recorded stack region, a frame pointer that must be 16-byte aligned and strictly
  increase (a corrupt/cyclic chain stops), and `kMaxCrashFrames`. The frame lines go through the capped
  appenders, so `kMaxReportBytes` still holds.
- `CrashReporterFramesTest::fatal_handler_enters_neither_allocator_nor_loader` puts a REAL fault in a
  forked child whose `malloc`/`free`/`calloc`/`realloc`, `dl_iterate_phdr` and (glibc 2.35+)
  `_dl_find_object@GLIBC_2.35` are interposed. Any entry exits the child with a distinct code; the test
  requires the child to die by `SIGSEGV` and the report to be written, so a regression to the unwinder is
  caught (reverted run: child exit `42`, "the loader's object walk").

### macOS thread id

`pthread_mach_thread_np(pthread_self())` is not async-signal-safe: it can take the pthread lock and
deadlock the handler (OpenJDK bug JDK-8235962, https://bugs.openjdk.org/browse/JDK-8235962). The reporter
uses the fix OpenJDK shipped: `mach_thread_self()` / `mach_port_deallocate()` - two direct Mach traps that
return the same thread-port value, leak nothing and take no lock. The report's `thread=` field is nonzero on
Darwin, and the existing nonzero assertion in the real-fault test is retained.

### Where it does not reach, and why (limits, not silence)

| Platform | What the frame block contains |
|---|---|
| Linux x86_64 / aarch64 | The faulting instruction and the saved frame-pointer chain, as many as the build emits and the 24-frame budget allows. The test's own crashing frames are compiled with `-fno-omit-frame-pointer` so the 200-deep proof measures real frames. |
| macOS (x86_64, arm64) | The faulting instruction (`__ss.__pc`/`.__rip`) and the saved frame chain when the build has frame pointers; `thread=` is the Mach thread port. Not run on this box (Qt 6 on Linux only); hosted CI compiles it. |
| Windows (mingw, MSVC) | Nothing: the reporter is the documented no-op there, `captureFrames` returns 0, and the test asserts that contract instead of pretending. |
| A thread that never registered | The PC and fault address; no walk. A crash above the recorded ceiling (a very shallow frame reached after registration returned) is the same. |

## Commands, GUI, undo, format

- **No new or changed command.** This is what a report file contains; nothing in the reporter's command
  group (`crash.list_reports`, `crash.acknowledge_report`, `crash.discard_report`,
  `crash.enable`/`crash.disable`, `crash.upload_report`) reads or writes the report's fields, so
  `ControlRegistry`, the command snapshot and the A16 reversibility table are untouched. No new
  user-facing action exists; the one report-offer dialog is unchanged.
- **No undo step**: nothing edits the project, so there is no reversibility class to declare.
- **Format change**: still `Zene Studio crash report v1`; additive `frames=<count>` and
  `frame[<i>]=0x<hex>` lines after `project=`. Old project data is untouched.
- **No project data**: nothing is saved or loaded, so old projects load and render exactly as before and
  there is no new data to round-trip.
- **Manual**: `data/manual/index.html` describes the crash report file and its raw frame block.

## Known limits

- Symbols and modules are not resolved, by design (a later stage owns resolution). The addresses need the
  exact build's debug symbols, which the report names in `version=`/`platform=`/`compiler=`.
- Caller frames require the build to emit frame pointers for the frames in question; the faulting PC is
  always present. A very shallow crash above the recorded ceiling yields the PC only. A thread that never
  registered a stack yields the PC only.
- `pthread_getattr_np()` allocates, so it runs only from `install()` on the main/control thread; the
  audio-thread paths use the allocation-free marker. A crash directly in the JACK callback itself (above
  the marker) may therefore carry the PC and its callees, not the callback's own caller.
- macOS is compile-only on this box. Windows captures nothing: the reporter is a documented no-op there.
- Under ASan the reporter's `thread_local` alternate stack interacts with ASan's interceptors (Q050-157);
  that exclusion is unchanged. TSan does not run on this box: the new state is `thread_local` (exact
  bounds, marker) plus one fixed array in the same-thread snapshot, and the re-entrancy guard still admits
  exactly one writer across threads.
