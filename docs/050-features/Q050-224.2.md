# Q050-224.2 - The crash report carries bounded raw stack frames

Type: completion (P2, size L), stage 2 of 4 of Q050-224. Members: `R-performance-57`, `R-platform-52`.
Area: L15. Branch: `feat/050-Q050-224.2-oc`, cut from `050/m0-train-35`.

## What was built

`goal`: crash reports preserve useful raw stack context without doing symbol or module resolution in signal
context.

A report now ends with a frame block:

```
...
project=/home/someone/Music/my track.mmp
frames=10
frame[0]=0x5589894369b0
frame[1]=0x55898943981b
frame[2]=0x558989436fbe
frame[3]=0x7f1277644e70
frame[4]=0x5589894369b0
frame[5]=0x5589894369c5
frame[6]=0x558989436810
...                    # frames=10 in total; the last three lines are elided
```

That is a real report from this branch (`/tmp` probe linking the built `CrashReporter*.o`, a forked child
faulting three calls deep: 499 bytes, 10 frames). The pieces:

| Piece | Where | What it does |
|---|---|---|
| `kMaxCrashFrames = 24` | `include/CrashReporter.h` | The budget: the most addresses one report can carry, and the number of steps the walk may take. |
| `CrashInfo::frames` / `frameCount` | `include/CrashReporter.h` | A fixed array in the existing trivially-copyable POD snapshot, so the handler fills it and the writer reads it with no allocation and no ownership. |
| `captureFrames(context, out, capacity)` | `src/core/CrashReporterFormat.cpp` | Writes the faulting instruction as frame 0 (where the architecture exposes one) and then walks the crashing thread's stack with `_Unwind_Backtrace`, keeping raw `_Unwind_GetIP` addresses. |
| `appendFrames(buf, cap, pos, frames, count)` | `src/core/CrashReporterFormat.cpp` | Appends `frames=<count>` and one `frame[<i>]=0x<hex>` line per address, through the same capped appenders as every other field. |
| the two call sites | `src/core/CrashReporter.cpp:139`, `:524` | `zeneCrashSignalHandler` captures (it has the signal context and the dying thread), `writeReportIfIdle` formats. |

Splitting capture from formatting is deliberate: `writeReportIfIdle` is also the
tests' entry point, which has neither a signal context nor a dying thread, so capture lives in the handler
and the writer stays a pure formatter. It is also what makes the report format's own proofs possible — a
direct-call test can set `frames`/`frameCount` by hand.

`frame[0]` is the faulting instruction, then the platform unwinder supplies the callers. On Linux the
walk crosses glibc's signal trampoline, so the same address appears again where the unwinder's own
interrupted frame lands (index 4 above) and the raw callers follow it: `frame[5]` is the faulting
function's caller. Repeated addresses are kept, never folded: a recursive chain returns to the same call
site at every depth, and collapsing those would hide the depth the report exists to show.

### Async-signal-safety, stated rather than assumed

The handler gains exactly one new call and it is named in the design (as `syscall(SYS_gettid)` already
was, which is likewise not on POSIX's list):

- `_Unwind_Backtrace()` / `_Unwind_GetIP()` is the platform's own table walk. It allocates nothing, does
  no I/O, calls no symbol or module resolver (there is none — no `dladdr`, no `.symtab` read, no
  backtrace_symbols) and returns raw addresses.
- It is **bounded by construction**: the callback returns `_URC_END_OF_STACK` as soon as
  `kMaxCrashFrames` addresses are kept, so a corrupt or cyclic unwind costs at most 24 steps. A walk that
  ignored the budget would be the one way this could hang, and the 200-deep case proves it stops at
  exactly 24.
- It consults the loaded modules' unwind tables through the loader's lock. glibc (`__rtld_lock_define_recursive`)
  and musl define that lock **recursive**, so a fault on the thread that already holds it re-enters instead
  of deadlocking. That case is not assumed: `crash_while_the_loader_is_busy_still_reports` faults inside
  `dl_iterate_phdr`'s callback — the shape of a crash during plug-in loading — and asserts the report is
  written and the child still dies by `SIGSEGV`, within a bounded wait.
- Everything else in the handler path is unchanged, and the frame lines go through the capped appenders, so
  `kMaxReportBytes` still holds whatever the stack looks like.

### Where it does not reach, and why (limits, not silence)

| Platform | What the frame block contains |
|---|---|
| Linux x86_64 / aarch64 | The faulting instruction, the handler's own frames, and — across glibc's signal trampoline — the faulting call chain. |
| macOS (x86_64, arm64) | The faulting instruction (`programCounterFrom` reads `__ss.__pc`/`.__rip`) and the handler's own frames; Darwin's unwinder stops at its signal trampoline, so the interrupted call chain may be absent. Not measured on this box (Qt 6 only, Linux). |
| Windows (mingw, MSVC) | Nothing: the reporter is the documented no-op there, `captureFrames` returns 0, and the test asserts that contract instead of pretending. |
| Architectures where `programCounterFrom` returns 0 | The unwinder's frames only; the sequence then starts at the first walked address. |

Symbolisation is deliberately out of scope: the report carries addresses, and a reader resolves them with
its own `addr2line`/debug symbols for the build it names. That is also why no module list, no maps and no
UUID is written here — those belong to the stage that owns resolution, not to a signal handler.

## Commands, GUI, undo, format

- **No new or changed command.** This is what a report file contains; nothing in the reporter's command
  group (`crash.list_reports`, `crash.acknowledge_report`, `crash.discard_report`,
  `crash.enable`/`crash.disable`, `crash.upload_report`) reads or writes the report's fields, so
  `ControlRegistry`, `tools/mcp-zene-control/zene_control/commands_snapshot.json` and the A16
  reversibility table are untouched. The "GUI and agent use the same command" rule has no new action to
  apply to: a crash report is produced by a process that is dying, and the only user-facing surface — the
  one offer dialog in `main.cpp` — already exists and is unchanged.
- **No undo step**: nothing edits the project, so there is no reversibility class to declare.
- **Format change**: the report is still `Zene Studio crash report v1`; it gains a `frames=<count>` line
  and `frame[<i>]=0x<hex>` lines after `project=`. The block is additive, so a reader that reads the
  named fields is unaffected, and a reader that wants frames only has to look for the `frames=` line
  (absent means "this build or platform could not capture any").
- **No project data**: nothing is saved or loaded, so old projects load and render exactly as before and
  there is no new data to round-trip.
- **Manual**: `data/manual/index.html` describes the report file and its frame block (see below).

## Known limits

- Symbols and modules are not resolved, by design (the issue that owns resolution is a later stage). The
  addresses are only useful with the exact build's debug symbols, which the report names via
  `version=`/`platform=`/`compiler=`.
- On Darwin the walk stops at the signal trampoline, so the interrupted call chain may be missing; the
  faulting instruction is still frame 0. That is why the "reaches the caller chain" assertion is
  `#if defined(__linux__)` and the loader-lock case is `QSKIP`ped elsewhere rather than asserted.
- Windows has no frame capture at all: the reporter is a documented no-op there and the test asserts it.
- `_Unwind_Backtrace` re-enters the loader's recursive lock; a crash while the loader is *corrupting* its
  own structures (rather than merely holding the lock) can still yield fewer frames or none. The report is
  still written with the fields it has.
- Under ASan the reporter's `thread_local` alternate stack interacts with ASan's interceptors (Q050-157);
  that exclusion is unchanged by this unit and nothing here adds state for it.
- TSan does not run on this box. The new data is one fixed array in a snapshot filled on the crashing
  thread and read by the same thread before it dies; nothing shared and mutable is added, and the
  re-entrancy guard (unchanged) still admits exactly one writer across threads.
