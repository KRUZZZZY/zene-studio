# Q050-064 - Note editor input ergonomics (P1, M, L07)

Goal: draw notes with a pitch preview, adjust pitch while drawing, see a cursor for each active tool,
and open clips at a useful zoom and row range.

## What was built

- `NoteCanvas` (include/NoteCanvas.h, src/gui/noteeditor/NoteCanvasInput.cpp):
  - the Draw tool paints a translucent note under the idle pointer on an empty row, using the snap,
    new-note length and velocity the press would use;
  - a draw gesture follows the pointer's row: `followDrawPitch()` releases the old auditioned key and
    presses the new one, and `drawKey()` supplies the same pitch to the preview, the audition and the
    committed `note.add`. The press row is only the fallback when the pointer leaves the key rows;
  - `updateCursor()` gives Draw a crosshair, Erase the forbidden ring, Slice the horizontal split cursor
    and Audition the pointing hand (Select the arrow, Paint the crosshair, Mute the up arrow); over a
    note's resize handle it stays the horizontal resize cursor, and over a note the next action is a
    move. `refreshCursor()` re-applies it from `NoteEditor::setTool`, so a toolbar action or tool letter
    changes it before the pointer moves, and release re-applies it after every gesture.
- `NoteEditor::zoomToFit()` (src/gui/noteeditor/NoteEditor.cpp) now fits both axes when a clip opens:
  the clip length fills the width; the used pitch range gets a margin and a row height between the
  grid's 6 px floor and 32 px. A range too wide for the minimum row is centred at that minimum (the
  fallback), and an empty clip opens on C5 at the normal 14 px row.
- `describe()` now also reports `row_height`, `bottom_key` and `visible_rows` beside the existing
  `zoom`, `scroll_y` and `top_key`; `window.note_editor_set`'s result schema carries them and
  `window.get_state.note_editor` is that same object.

No new command, no project-format change: the editor view is interface state, and committed notes are
ordinary MIDI notes through the existing `note.add`.

## Commands, format, limits

- New commands: none. `window.note_editor_set` and `window.get_state` only gained typed result fields
  (`row_height`, `bottom_key`, `visible_rows`) in their existing schemas.
- Reversibility: `window.note_editor_set` remains `not_mutating`; a draw still commits one `note.add`
  (true inverse through the clip checkpoint). The cursor and preview never edit the project.
- Project format: unchanged. Editor tool, zoom and scroll remain unjournalled interface state.
- Limits: a range wider than the view shows at the 6 px minimum is centred, so its outermost pitches
  may stay off screen; the cursor shapes are the platform's standard cursors. Local TSan does not run
  on this box; the changed code is GUI-thread only (paint, mouse, toolbar setters) and audition still
  goes through `Piano::handleKeyPress/Release`.
