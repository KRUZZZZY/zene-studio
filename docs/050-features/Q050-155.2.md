# Q050-155.2 - Carry 64 channels through device pins and mixer routes

Type: completion (P1, size L), stage 2 of 4 of Q050-155. Member: R-mixing-24. Area: L09. Builds on Q050-155.1
(discrete-2 .. discrete-64 mixer buses).

## What was built

- **Devices see every channel of a discrete bus.** `MixerChannel::processInserts` (`src/core/Mixer.cpp`) runs a
  discrete-N channel's device chain on a wide bus (`surround::processWideInserts`, `src/core/MixerSurroundMix.cpp`):
  `AudioBus` pair 0 is the channel's own buffer, pair p carries side channels 2p and 2p+1 as an interleaved pair. The
  pairs are allocated with the side buffer by `ChannelSurround::setFormat` / `init` (control thread, change lock, grow
  only - `ChannelSurround::insertPair`, `include/MixerSurround.h`). After the chain the pairs are written back to the
  side planes, so the channel's sends, direct outs and master output (Q050-155.1's index routing) carry what the devices
  did. Stereo, mono and the named speaker layouts take the old path, byte for byte.
- **The pin matrix follows the bus.** `AudioPortsModel::growTrackChannels` (never shrinks) widens a device's track
  channels to its host bus: `port.set_pin`/`port.set_pins` accept a `track_channel` up to the host bus's width
  (`controlHostBusChannels`: N for a discrete-N mixer channel, 2 for every other host), and the Pin Connector grows its
  rows when a device card opens it. New rows are all off, so nothing sounds different until a pin on them is set.
- **The router is clamped to the bus it is handed** (`include/AudioPorts.h`, the four `send`/`receive` routings and the
  direct-routing shortcut). A device's track channels may outnumber the bus's pairs (a pin on channel 41 of a device on a
  channel that went back to stereo); the old code only `assert`ed and read past the bus's pair pointers in a release
  build.
- **A pinless device on a wide bus** (`src/core/Effect.cpp`): asleep, it silences only the pair it owns, not the other
  channels; a one-pair bus is silenced exactly as before (`silenceAllChannels`).
- **`port.set_pins`** (new, `src/core/ControlCommandsPorts.cpp`): a list of `{direction, track_channel,
  processor_channel, enabled}` (up to 8192) validated whole before anything moves, applied as one routing edit
  (`AudioPortsModel::setPins`: one change guard, caches rebuilt once, one `dataChanged`), and one undo step on the
  engine's own journal (`control.undo`, Edit > Undo, and redo).
- **Agent-readable state.** `port.get_state` gains `bus` (`format`, `channels`, `reached_track_channels`).
  `mixer.get_state` and `routing.matrix` add `channels` and `channel_routing` (`index` / `speakers` / `pair`) to a send
  whose sender or receiver is not stereo (`control::addRouteChannels`); a stereo route reads back exactly as before.
- **GUI** (`src/gui/PinConnector.cpp`, `src/gui/shell/DeviceCard.cpp`): a device card's pins button gives the Pin
  Connector the device's control address. A pin click then runs `port.set_pins` with that pin, and a new **Channels**
  menu (shown when the bus is wider than its pair) has one entry per pair - `Channels 41-42` moves every pin of the device
  onto that pair. Both go through `ControlRegistry` (entries carry `controlCommand = port.set_pins`). A Pin Connector
  opened without an address (no device card) writes the model directly, as before.
- **Persistence.** Pins are saved as before (`cN_M`). `Mixer::loadSettings` loads a channel's devices inside an
  `AudioPortsModel::HostBusScope` of the channel's saved discrete width (`surround::savedDiscreteChannels`), so a device
  grows to the bus before its pins are read and pins past the pair come back. Outside such a scope a file never grows a
  matrix (the BUG-PINBOUNDS contract `AudioPortsModelTest` holds).

## Commands, reversibility and format changes

- New: `port.set_pins` - `true_inverse` (a journal step whose undo puts every named pin back and whose redo applies them
  again). Snapshot regenerated live: 925 ids / 78 groups; A16 histogram `rows=934 true_inverse=460 snapshot=42
  irreversible=25 not_mutating=407` (the full-configuration figure in `docs/RELEASE-NOTES-v0.3.0-alpha.md`).
- Changed: `port.set_pin` accepts `track_channel` up to the host bus's width (still `snapshot`); `port.get_state` adds
  `bus` (still `not_mutating`); `mixer.get_state` and `routing.matrix` add `channels` / `channel_routing` to non-stereo
  sends (still `not_mutating`).
- Project format: none new. A device's pins past the stereo pair are written with the existing `cN_M` attributes; a
  project with none (every older project) loads and renders as before. Loading such pins in an older build drops them
  (the existing bounds check), and the device plays its pair.

## Realtime and threads

Nothing new allocates, frees, locks, waits, does I/O or emits a signal on the audio path. `processWideInserts` builds
the bus from a stack array of 32 pointers and copies between the side planes and the preallocated insert pairs; the
allocation is in `ChannelSurround::setFormat`/`init` on the control thread under the engine's change lock, like the
side buffer it mirrors (the allocation slot of `WidePinRoutingTest` measures zero allocations for a master mix with 32
wide inserts). Pin edits (`setPins`, `growTrackChannels`) take the engine's model-change guard, as every routing edit
does, so a period sees a whole routing. `HostBusScope` is a thread-local read on the loading (control) thread. Local
TSan does not run on this box; this is the race analysis.

## Known limits (left to later stages or other units)

- **Track routes stay one pair.** A track (and an instrument's own outputs) still feeds a mixer channel its first pair
  (`AudioBusHandle` owns one stereo pair, and the instrument play path renders one pair). The channels of a discrete
  bus come from other surround/discrete channels' sends or from a device pinned onto them. The scoping brief's stage
  title says "device pins and mixer routes"; the stage-1 record had also mentioned track routes, and they are not
  done here.
- Only a mixer channel's plain device chain gets the wide bus: a channel running a rack (two or more chains), its
  post-fader inserts and a named speaker layout's devices still see the pair only. Side channels still get no delay
  compensation, meters or the strip's mono/width/EQ stages (Q050-155.1's limits).
- One send level per route for every channel; independent per-pair sends and their Routing Matrix editing are stages 3
  and 4.
- `port.set_pin` (the single-pin agent command) keeps its command-applied inverse: `control.undo` takes it back, but it
  is not on the journal's redo stack. `port.set_pins` with one pin (what the GUI's click runs) is.
- The Pin Connector's Channels menu is built when it opens; after a format change, reopen it for the new width.
