# Q050-089.1 - Expose hardware insert latency in PDC

Type: completion (P1, size L, stage 1 of 3 of Q050-089). Members: R-mixing-18, R-performance-72. Area: L09.

## What was built

A channel's hardware insert already fed delay compensation (`hardwareio::insertLatency`, counted by
`Mixer::updateLatencyCompensation`), but neither `pdc.report` nor the strip said how much. Now both
read that same function, so they cannot disagree with each other or with what PDC counts:

- `include/HardwareIo.h`, `src/core/HardwareIo.cpp` - `hardwareio::insertLatencySource(channel)`
  names where `insertLatency()`'s figure comes from: `off` (insert disabled), `bypassed` (an export
  runs), `override` (a typed figure), `measured` (the last ping, at this rate and on this route) or
  `unmeasured` (on, but no figure, so it adds 0).
- `src/core/ControlMixerSupport.cpp` - `channelLatencyJson()` (what `pdc.report` and `bus.list`
  list per channel) adds `hardware_insert_latency_frames` = `hardwareio::insertLatency(channel)` and
  `hardware_insert_latency_source`. The override wins over the measured value; it is 0 while the
  insert is off or bypassed.
- `include/MixerLatencyText.h`, `src/gui/MixerStripInfo.cpp` - the strip tooltip (written on the
  mixer view's sync) adds `Hardware insert latency: N frames (X ms, measured|typed)`, or
  `Hardware insert latency: not measured (ping it or type a figure)` when the insert is on with no
  figure. Off or bypassed, it says nothing. The two new parameters of `mixerLatencyText` default, so
  older callers do not change.
- `src/core/ControlCommandsPdc.cpp` - the `pdc.report` description names the two fields; the
  command snapshot was regenerated from a live instance.

Regression runs with the change: `HardwareIoTest`, `PdcMixerTest`, `ControlPdcCommands`,
`ControlBusCommands`, `ControlFeedbackCommands` - all exit 0. `ControlFeedbackCommands` compares
`pdc.report` byte for byte against a baseline, so the baseline in `tests/control-feedback-commands.py`
gains the two new keys (`0`, `"off"`) on each channel. Nothing else in it changed. Its other failures
(a loaded effect, a saved-project hash) happen only when the `amplifier` module is not built, with or
without this change; with it built the test passes.

## Commands

No new command. `pdc.report` stays `not_mutating`, and its result schema is unchanged: the new keys are
inside the `channels[]` objects. Only its description changed (snapshot regenerated, 868 ids / 76 groups).
The GUI path is the strip tooltip, a read. The insert and ping it reports on are still set through the
channel's Hardware I/O menu, which calls `mixer.hardware_insert` / `mixer.hardware_insert_ping`.

## Format changes

None. Projects are untouched: nothing is saved, and the report reads the existing insert settings.

## Realtime

Nothing runs on the audio thread. `insertLatencySource`, `channelLatencyJson` and the tooltip run on the
interface thread (the control handler and the mixer view's sync timer). They read settings written on
that same thread under the change lock, plus the measured figure through the insert's existing atomics.
Local TSan does not run on this box, so this is reasoned from the design and was not measured.

## Known limits

- An export still bypasses the insert: the dry signal is rendered, and the report says `bypassed` / 0
  while it runs. Real-time export through the insert is Q050-089 stages 2 and 3.
- The tooltip refreshes on the mixer view's half-second sync, not at the moment of the edit.
