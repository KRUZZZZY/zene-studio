# Q050-166 - Mono and discrete bus formats

Type: completion (P1, size M). Member: R-mixing-47. Area: L09.

## What was built

- `include/MixerSurround.h` and `src/core/MixerSurround.cpp` extend the format vocabulary with `mono`
  (one `M` channel) and `discrete-2` .. `discrete-8` (role-less layouts). The discrete count is part of
  the canonical name, so a native save carries both the layout and its channel count; the loader also
  accepts `discrete5`, `discrete 5` and `discrete_5` for hand-edited projects. The count range is 2..8,
  the existing eight-channel side-buffer capacity; a wider graph is Q050-155's subject.
- A discrete layout is role-less on purpose: `roleOf()` is `Role::None`, `channelOf()` answers -1 and
  `speakerNames()` is empty; `channelLabels()` reports the indices `1`..`N`. `Mono` is a real speaker
  layout with the single role `M` and one channel.
- The downmix matrix treats discrete layouts by index: `discreteMatrix()` maps sender channel `i` to
  receiver channel `i` and drops a channel the receiver lacks. It does not consult speaker roles,
  reorder or fold. A named layout into a discrete receiver is likewise index-addressed; a discrete
  sender into a named receiver only uses the first matching indices. Mono folds into a named speaker
  layout as the front pair at -3 dB, and a named layout folds into the one mono channel at equal power
  with the LFE dropped.
- `src/core/ControlCommandsMixer.cpp` makes `mixer.get_state` report `format`, `channels`, `speakers`,
  `channel_roles` and `discrete` for every non-stereo channel. A stereo channel keeps the exact shape
  `mixer.get_state` had before, so a project that never leaves stereo serialises and reads back
  byte-for-byte as it did. `mixer.surround_get` reports the same fields beside its existing ones.
- `src/core/MixerSurroundMix.cpp` gives mono a render path (its pair is summed for the master and for a
  direct out) and restricts the surround panner to named speaker layouts; discrete layouts are routed
  by index. Nothing new allocates, locks, waits, does I/O or emits a signal on a render path: the new
  branches only read the already-allocated channel/side buffers and write their existing frames.
- `src/gui/SurroundPanner.cpp` draws a discrete layout as an index strip instead of inventing speaker
  positions. The GUI entry point is unchanged - `Surround > Format` in `MixerHardwareMenu.cpp` is built
  from the command schema, so the new names appear there and each entry runs `mixer.channel_format`
  through `ControlRegistry`, exactly as the agent does.
- `src/core/SurroundExport.cpp` avoids indexing its speaker table with a mono or role-less role; a
  mono file uses libsndfile's MONO map, a discrete layout has no speaker mask.
- `data/manual/index.html` describes Mono and the Discrete formats, their index routing and the lack of
  speaker positions.

## Commands, reversibility and format changes

No new command id. `mixer.channel_format` keeps its `true_inverse` class and its one `AddUndoStep` per
edit; its enum now advertises `mono` and `discrete-2`..`discrete-8`, and its description states the
index routing. `mixer.surround_get` stays `not_mutating`. `mixer.get_state` stays a read (`not_mutating`)
and only gains fields for non-stereo channels. The native project's `<surround format="...">` now may say
`mono` or `discrete-N`; a missing element still loads stereo, and a stereo channel still writes no
`<surround>` element.

## Known limits

- The discrete range stops at 8 because the channel side buffer is allocated for the current eight-channel
  maximum. A 64-channel graph and a no-fixed-count bus are Q050-155's subject, not this unit's.
- A discrete layout has no spatial position: the surround panner does not act on sends into it (the
  normal stereo send feeds the first pair), and the index mapping is the whole routing rule. Mono has one
  `M` role and is summed to the pair on a stereo device.
- Multichannel source/plugin formats and the independent channel-pair routing/send matrix are out of
  scope, as the scoping brief says.
- The multichannel WAV export maps a discrete master's channels by index and gives it no speaker mask;
  the unit's render proof is the hardware direct-out path, not a separate discrete-WAV measurement.
