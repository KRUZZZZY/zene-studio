# Q050-188.1 - Auto-Master run choices (genre and delivery target)

Stage 1 of 3 of cluster **Q050-188** (`R-mixing-19/22/26`, P2, L, area L17). The later stages are the render-side
use of the choices and a richer report; this stage accepts, records, and reads the choices back.

Branch `feat/050-Q050-188.1-oc`, based on `050/m0-train-26`. Goal: `mastering.run` takes two optional labels, a
`genre` and a `delivery_target`, keeps them with the run and on every candidate row, and lets an agent or a person
read them back, without either label changing a measurement or choosing a winner.

## What was built

- **Value sets** (`src/core/ControlMasteringSupport.cpp`, declared in `include/ControlMasteringSupport.h`). Genre is a
  closed, lower-case set: `ambient`, `classical`, `contemporary-alt-r-and-b`, `electronic`, `folk`, `hip-hop`, `jazz`,
  `pop`, `rock`. Delivery target is one of the engine's four target names: `streaming-14`, `streaming-16`,
  `streaming-14-ceiling-2`, `ebu-r128`. Both sets are published by `mastering.list_candidates` as `genres`,
  `delivery_targets` and `genre_max_length`, so the product and any caller read one list.
- **Validation** (`src/core/ControlCommandsMasteringRun.cpp`, `src/core/ControlCommandsMastering.cpp`). A present value
  must be a string (`'genre' must be a string naming one accepted value`), then a member of its closed set
  (`'genre' 'X' is not an accepted value (matched exactly, no case folding)`). There is no case folding: `Electronic`
  is refused, never lower-cased. A present-but-empty value is refused (`'genre' is empty: to ask for no choice, omit
  the key`). JSON `null` is read as absent, so an omitted key or a `null` reads back as `null`. An over-max genre is
  refused only because it is not a member of the set; `genre_max_length` is the longest member's length, not a
  separate check.
- **Command path**: `mastering.run` accepts the two keys, so an out_dir-only call still completes and reports both as
  `null`. A refused choice is `invalid_args` and starts no child; nothing under `out_dir` changes.
- **CLI** (`src/core/main.cpp`): `--genre <genre>` and `--delivery-target <target>` label the `--report` document. Both
  are read only by `master`; given with any other mode they are refused (`reportOptionIsRejectedOutsideMaster`,
  `reportOptionIsRefused`). The render child writes the choices into its own report, and the parent merges the child's
  report with the child's values winning (`src/core/MasteringJob.cpp`, `src/core/ControlMasteringSupport.cpp`,
  `src/core/MasteringReport.cpp`, `include/MasteringReport.h`).
- **Readback**: `mastering.get_state` reports the choices on `last_run` and in a new `candidates` key (the last run's own
  rows, verbatim; empty before a run). `mastering.list_candidates` publishes the lists. The GUI's **Mastering Report**
  (Project Tools) is a list of the last run's candidates, one row each with its retained `genre` and `delivery_target`.
  The Auto-Master form (Project Tools > Auto-Master...) offers the two choices and keeps them when a refusal returns the
  form.

## Known limits

- Labels only. The candidate set, the measurements and the absence of a ranking are unchanged: the choices never pick a
  winner and never change a verdict.
- A FAILED run does not echo the choices; they are reported on a completed run.
- `delivery_target` names one of the engine's four target names. `streaming-16-dynamics` rides `streaming-16`'s target,
  so it is not a separate choice.
- The genre set is closed and lower-case; a value outside it is refused, not normalised.
- The Mastering Report shows the LAST completed run only, and it is process-local: it is not saved with the project and
  a fresh instance shows none.

## Portability

Linux: an absolute POSIX `out_dir` is accepted; relative paths and `:`-containing paths are refused, and both refusals
are exercised by the socket proof. Windows: drive-letter and UNC paths pass the `isAbsolute` rule, but they were NOT
exercised on this branch.
