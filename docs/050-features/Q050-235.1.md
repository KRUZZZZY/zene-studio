# Q050-235.1 — Touch workspace choice and launcher targets

Unit: P2, size L, area L14. Branch `feat/050-Q050-235.1-oc`, base `050/m0-train-12` (`07d6d02bd`).
Stage 1 of 3 of Q050-235. The arranger (stage 2) and the mixer fader / integrated tablet check
(stage 3) are deliberately left out; nothing here has to be undone for them.

## What was built

- **A workspace preference of its own.** `appearance::Options` gains `workspace` (`standard` | `touch`),
  read from and written to `ui/workspace` in the user's config (`src/core/Appearance.cpp`). An absent
  key reads as `standard`, so a config or project from before this change opens exactly as it did.
  It is *not* accessible mode and it does not touch `density`: the legacy `density: "touch"` still
  means accessible mode, unchanged.
- **Agent surface.** `window.appearance` accepts `workspace` (enum, `standard`/`touch`) and always
  reports it back, beside `applies`/`restart_required`/`restart_pending`. The change is one
  `true_inverse` undo step, the reversibility class the command already had.
- **GUI surface.** Project tools > Customise > Theme > Workspace lists the two choices; each runs the
  same registered `window.appearance` command through `addCommandChoices` (`src/gui/WorkspaceMenus.cpp`).
  Help > Appearance... opens the same command's form, which now has the `workspace` field too.
- **Real hit areas, not artwork, for the launcher.** `tokens::tapTargetSize()` is `targetSize()` (24 px,
  32 px in accessible mode) and at least 44 px in the touch workspace; `tokens::touchWorkspace()` reads
  the started workspace once, like the palette. `SessionGridView::makeButton` sizes every launcher cell,
  scene button, per-track stop button and Stop All to at least `72 x tapTargetSize()`, so the touch
  workspace yields 72 x 44 hit rectangles at 100 % zoom (measured in the test, not only declared).
  The standard workspace keeps its prior 72 x 26 exactly.
- **Written at once.** `appearance::setOptions` now saves the config file immediately (as `settings.set`
  does), so the choice does not depend on the process reaching a clean shutdown.

## New commands and reversibility

None. `window.appearance` gains a `workspace` argument (and a `workspace` reply field); its
reversibility stays `true_inverse`, one undo step, and
`src/core/ControlReversibilityTableDevices.cpp` now names the workspace among the four bounded
values it writes. The commands snapshot was regenerated from a live instance
(`snapshot_live.py`, 845 ids / 76 groups, unchanged ids - only `window.appearance`'s schema and
description moved), `tests/doc-figures-gate.py` passes (the canary figure is unchanged), and
`ReversibilityContractTest` passes with the A16 histogram unchanged (no command row changed class).

## Format changes

None to the project format or to `.mmp`/`.mmpz`. The choice is a user preference in
`<config>/ui/workspace`, not project state, so it round-trips by config alone and a project saved
before this change is untouched.

## Known limits

- Stage 1 only: the arranger toolbar/tool/zoom targets (stage 2) and the mixer fader's 44 px
  interaction width (stage 3) are not part of this unit. `tokens::tapTargetSize()` is the seam they
  build on.
- The workspace is read once at start, as the palette is, so a change applies from the next start;
  the reply says so (`applies: next_start`, `restart_required: true`, `restart_pending: true`).
- Only `standard` and `touch` exist. The touch workspace changes target sizes only - no palette,
  motion, density or layout change - and the legacy `density: "touch"` alias is untouched.
- The 44 px minimum is a Qt logical-pixel size measured at 100 % zoom; a global zoom still scales it
  with everything else (that is the design system's one sizing control).
