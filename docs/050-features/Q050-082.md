# Q050-082 - Correct the Follow Action editor limitation in the docs

Unit: P1, S. Goal: tell users that per-cell Follow Action chains can be edited from the launcher grid.

## What was built

Round 1:

- `docs/KNOWN-LIMITATIONS.md:109-118`: updated the stale "Per-cell chain editing is still socket-only"
  limitation. The session-wide switch (`Follow Actions`, `session.set_follow_actions`) remains described as a
  grid-row control, while per-cell/per-scene chain editing is documented as available through the cell and scene
  context menus' `Follow Action Chain...` entry (`chainEntry`, `src/gui/SessionGridMenus.cpp:127`).
- `src/gui/SessionGridMenus.cpp:127`: verified the cell (and scene) context menu exposes `Follow Action Chain...`.
- `data/manual/index.html`: already documents the cell entry (`Right-click a cell for its Follow Action Chain...`),
  and is consistent with the corrected limitation.

Round 2 (review rework):

- `docs/KNOWN-LIMITATIONS.md:118-131`: the older bullet's headline no longer claims Follow Actions are
  socket-only. It now states that **Arrangement Record and Back-to-Arrangement** are drivable through the socket
  and through nothing else, while the **session-wide Follow Actions switch** (the grid's `Follow Actions` row,
  `SessionTransportBar`) and **per-cell/per-scene chain editing** (each cell/scene menu's `Follow Action Chain...`
  entry, `SessionGridMenus`) are in the GUI; only Arrangement Record and Back-to-Arrangement stay socket-only.
- `tests/src/gui/SessionGridViewTest.cpp:230-233`: `theMenusEditTheLauncherThroughTheRegistry` now explicitly
  asserts the cell context menu contains `Follow Action Chain...` and that its `controlCommand` is the registered
  `session.set_slot` command; the scene-menu assertion (same command family, `session.set_scene`) follows at
  244-247.
