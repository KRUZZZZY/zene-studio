# Q050-044 - Undo checkpoints for project opening and scripts

Branch `feat/050-Q050-044-open-script-undo`, base `888934e1b`. Unit (P0, fix, M, L17 scripting/undo): a user can undo
`script.run` mutations and restore the unsaved session `project.open` displaces, each with one undo action.

## What was built

- `include/SessionCheckpoint.h`, `src/core/SessionCheckpoint.cpp` (new): the shared checkpoint.
  `takeSessionCheckpoint` (`SessionCheckpoint.cpp:122`) captures the session as `Song::captureUndoSnapshot` builds it
  (the save document; audio files are referenced by path, never copied; compressed) and measures it against the undo
  stack's byte budget (`ProjectJournal::maxUndoBytes`, set with `control.set_undo_depth`, default 16 MiB). Over the budget
  it returns `TooLarge` with a message and the caller refuses before changing anything.
  `loadProjectWithCheckpoint` (open) and `finishScriptCheckpoint` (script) push the one undo step
  (`pushRestoreStep`, `SessionCheckpoint.cpp:53`): undo captures the session as it is then and restores the checkpoint;
  redo restores what undo captured. The step is a structural step, so its bytes count against the stack budget.
- `project.open` (`src/core/ControlCommandsProjectFiles.cpp:425`, record built by `projectOpenTransaction` at :393):
  a session with unsaved changes is checkpointed first; an over-limit checkpoint answers `refused` before the load. A
  good load leaves the step; undo restores the displaced session and its file name (new
  `Song::restoreUndoSnapshot(compressed, fileName)`, `src/core/SongUndoSnapshot.cpp:93`) and drops the opened project's
  loaded history (new `ProjectJournal::discardLoadedSteps`, `ProjectJournalStructural.cpp:97`). The reply gains a
  `checkpoint` object.
- `script.run` (`src/core/ControlCommandsScript.cpp:252`): the project is checkpointed before the run (over-limit: `refused`,
  the script never executes); after the run the queue is applied and the project is compared with the checkpoint by
  per-section canonical digest (attribute order does not matter). If it differs, the finer steps the script pushed are
  replaced (`ProjectJournal::discardTopSteps`, `ProjectJournalStructural.cpp:85`) by the one step. Also on a script error:
  the edits made before the error stay and are one step. The reply gains `checkpoint` and `changed_project`.
  `ControlRegistry.cpp` (`bracketsEdit`, `markFoldedNestedChanges`): script.run takes the persisted-history bracket, and a
  record flagged `covers_nested` is not downgraded because the script ran registered commands (`zene.command`).
- Classes: `project.open` and `script.run` moved from `irreversible` to `snapshot`, reversible per call
  (`ControlReversibilityTableSnapshot.cpp:87,100`; rows removed from `ControlReversibilityTablePassive.cpp`).
- GUI, same behaviour through the same code: `MainWindow::openProjectFile` (`src/gui/MainWindow.cpp:952`) is used by File >
  Open, the recent-projects menu, the file browser, the editor drop and the OS file-open event; File > Run Script now
  invokes the registered `script.run` instead of calling the engine directly. A refused checkpoint shows a message box.

## New commands and reversibility

None. Changed classes: `project.open` irreversible -> snapshot (reversible per call), `script.run` irreversible ->
snapshot (reversible per call). The commands snapshot was regenerated from a live instance (823 ids / 76 groups, only
the two commands' schemas and `script.run`'s description changed); `tests/doc-figures-gate.py` PASS.

## Test change worth reading

`UndoHistoryPersistenceTest::aSavedHistoryUndoesToEveryPreEditState` now saves the session clean before its "fresh open":
the previous load leaves the session marked modified (its parameter write), and opening over a modified session now adds
the checkpoint step on top of the loaded history. The assertions are unchanged.
The published A16 figure was already one `true_inverse` row stale at the base (no command is added here).

## Format changes

None. A checkpoint is in memory only; nothing new is written to a project file.

## Known limits

See `docs/KNOWN-LIMITATIONS.md` ("Undo checkpoints for project.open and script.run"). In short: audio files by reference;
bounded by the undo byte budget with no override; only unsaved sessions are checkpointed by `project.open`; a partial load
is not checkpointed; the displaced session's earlier undo steps and its undo-history persistence setting are not carried
back; `control.undo` after a `control.redo` of the same step refuses (existing behaviour for every command);
`project.new`, `project.new_document`, `project.switch`, `session.setlist_go` keep their classes.
