# Q050-201 - Loop recording takes follow the record mode

Unit: P1, M, completion (area L03). Goal: when a recording runs while the loop plays, every pass is its
own take lane in every record mode, and the record mode decides which of those takes are heard.

Starting claim, verified: before this change a loop recording already made one take lane per pass in every
mode, and in every mode only the newest pass was audible (the active take). The record mode had no effect on
the loop passes, and `comp.get_state` and the take-lanes panel did not say which takes were heard. Now
Overdub keeps earlier passes audible (Play all takes on); Replace and Keep History keep today's newest-only
behaviour.

## What was built

- **Record mode decides the audible takes** (`src/core/SampleClip.cpp`, `include/SampleClip.h`,
  main-thread completion only - `SampleClip::acceptRecordedTake` -> `addRecordedLane(loopPass)`; the mode
  values in `include/RecordOptions.h`; `comp.get_state` in `src/core/ControlCompSupport.cpp`):
  - *Overdub*: the track's Play all takes is switched on (`TakeLaneModel::setPlayAllTakes(true)`, on the
    main thread under the change lock), so every pass stays audible beside the others.
  - *Replace* and *Keep History*: Play all takes is switched off, so only the newest pass is audible; an
    earlier pass is chosen again from the take list or with `comp.take_select`.
- **Take audibility is reported** (`comp.get_state`): `take_groups[].takes[]` gains the boolean `audible`.
  The take-lanes panel (`src/gui/TakeLanesPanel.cpp`, commit c09323eb45) writes " - audible" or " - muted" after each take
  in its take list, and its Play all takes click goes through `comp.play_all_takes`, so the panel and the
  command stay in step.
- **Tests**: `tests/src/core/RecordingRealtimeTest.cpp` asserts the per-mode audible flags for loop passes
  (commit 4a24f07e75); `tests/src/gui/TakeLanesPanelTest.cpp` asserts the panel's text and its Play all
  takes click.

## Design

- The loop pass path is `SampleClip::acceptRecordedTake` -> `addRecordedLane(loopPass)`. The record mode is
  read there, on the main thread, once per pass.
- Each loop pass sets Play all takes from the selected mode under the change lock: true for Overdub, false for
  Replace and Keep History. This also clears a state left by a previous Overdub loop; the user can change it
  again through `comp.play_all_takes` or the panel afterwards.
- **No audio-thread change.** The audio thread's record path, the ring buffer and the playback path are not
  touched; the audibility gate is the existing one (the active take lane, or the track-level Play all takes); no take clip mute flag is changed.

## Commands

`comp.get_state` (changed): `take_groups[].takes[]` gains the additive boolean `audible`. No new command;
no change to a command's schema, description or reversibility. `comp.play_all_takes` is unchanged and is
the way to switch Play all takes either way. Recording stays one undo step; the arm's checkpoint covers the
track's `playall` attribute.

## Format changes

None. The existing `playall` attribute of the track's take lanes is saved, as before.

## Known limits

- **Play all takes is track-level.** Each loop pass sets it for the whole track from the record mode; a later
  `comp.play_all_takes` can switch it either way.
- The default record mode is Overdub, so a loop recording now leaves the track's Play all takes on by
  default; the earlier behaviour (newest pass only) is Replace or Keep History, or `comp.play_all_takes`
  `false`.
- **A pre-existing quirk:** `comp.get_state`'s `lanes[].take_count` and the top-level `take_count` count the
  take-less shell clip in lane 0. Not changed by this unit.
- **Replace and Keep History behave the same for loop passes:** only the newest pass is audible in both.
- **MIDI take lanes are unchanged.** A MIDI loop pass keeps its existing behaviour.

## Realtime note

Nothing new on the audio thread. The mode decision, the Play all takes switch and the audibility report all
run on the main thread (`SampleClip::acceptRecordedTake`, `TakeLaneModel::setPlayAllTakes`) under the same
change lock the take-lane code already used.
