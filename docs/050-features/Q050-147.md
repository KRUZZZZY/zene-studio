# Q050-147 - Punch recording has its own ruler range

Unit: M, P1, L03 (recording / arrangement ruler). Goal: a musician can set punch-in and punch-out
independently of the loop markers, arm the range, and record only inside it.

## What was built

- **The range was already on the Timeline** (`include/Timeline.h`, `src/core/Timeline.cpp`): two
  tick scalars, an arm flag, `punchChanged`, the half-open `punchCapturesAt()` predicate, and
  optional `<timeline>` attributes that reset to empty/disarmed when absent. No second range model
  was added.
- **The Song Editor ruler now draws a separate punch band** (`src/gui/editors/TimeLineWidget.cpp`).
  The loop brace keeps the room above it; the punch band has a handle at each end, filled when
  armed and outlined when disarmed. `TimeLineWidget` gained `hasPunchRange()`, `punchBandRect()`,
  `punchBeginHandleRect()` and `punchEndHandleRect()` so the gesture and a test see the same
  geometry.
- **The handles are draggable and independent.** `getPunchAction()` grabs the nearest end (or the
  band, to move the whole range). A drag previews directly on the timeline and, on release, puts
  the old range back before invoking `transport.punch_set` once - so the command's Timeline
  checkpoint is the pre-drag range and the whole drag is ONE undo step. Snapping and Ctrl-to-bypass
  follow the loop brace's existing behaviour. The band is painted below the loop rectangle, so the
  two ranges never share a row.
- **The arm control is separate from editing bounds** (`src/gui/editors/SongEditor.cpp`). The
  toolbar's Punch in/out action arms the existing range, or seeds a range at the play position
  (never at the loop markers) when there is none; disarming writes the same bounds with
  `enabled: false` and keeps them. A separate Clear punch range action calls
  `transport.punch_clear`. Both are the registered commands, so the GUI and an agent make the same
  edit. `Timeline::punchChanged` keeps the action's check state honest after an agent edit, an
  undo or a project load.
- **The context menu** also offers Set punch in here / Set punch out here / Arm the punch range /
  Clear the punch range, each through `transport.punch_set` / `transport.punch_clear`.
- **The gate itself was already wired** in R2.4 (`AudioEngine::punchWindow`,
  `SampleRecordHandle::writePunched`, `PunchWindowTest`). This unit keeps it and extends the Dummy
  loopback proof to both sides of the region. The stale claims in
  `docs/KNOWN-LIMITATIONS.md` and the `transport.punch_set` description are corrected.

## Commands, format, realtime

- No new or changed command id. `transport.punch_set`'s description now states that the recording
  gate is wired and that the Song Editor arms/draws the range. Reversibility is unchanged:
  `punch_set` / `punch_clear` are `true_inverse` (Timeline checkpoint), `punch_get_state` is
  `not_mutating`.
- No project-format change. A project that never punched still writes no punch attribute; the
  existing optional attributes round-trip.
- GUI work is on the control thread; the audio path still reads the already-published atomic punch
  window and never allocates, locks, waits or emits Qt signals.

## Known limits

- Punching is a transport range for recording; it does not change loop playback, count-in,
  pre-roll, monitoring or comping.
- Dragging the band or a handle previews on the timeline. A drag canceled by the window system
  (not a normal release) does not restore the pre-drag range.
