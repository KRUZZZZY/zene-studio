# Q050-273.2 Save and reuse MIDI launcher patterns in the shared library

Stage 2 of 2 of Q050-273 (stage 1, audio cells: `Q050-273.1.md`). A MIDI launcher cell plays a PATTERN: a
column across the PatternStore's instrument tracks (`PatternStore.h`). Its notes are therefore not on the
cell, and a cell-to-library path has to write every note of that column and a library-to-cell path has to
make a new column.

## What was built

- **Save** - `browser.save_clip {track, scene}` now accepts a populated MIDI cell (stage 1 refused one by
  name). `src/core/LibraryCellMidi.cpp` gathers every `MidiClip` note on the cell's pattern across all store
  tracks and `MidiSmfWrite.cpp` writes one type-0 Standard MIDI File at the song's tempo (48 ticks per quarter
  as before, note-offs before note-ons at a tick) into `<user samples>/Clips`, which the browser lists with the
  `midi` kind. The file is the notes, not the pattern track's settings. A QSaveFile replaces the target only
  when the whole file is written. The arrangement-clip MIDI save uses the same writer, so the two cannot drift.
- **Reuse** - new command `session.import_midi_cell {track, scene, path, [instrument], [name]}`: reads the SMF
  with the existing defensive reader (`SmfNoteRead.h`, 16 MiB bound), makes a new pattern track, writes the
  notes into the clip of pattern-store instrument `instrument` (default 0) and points the cell at the new
  pattern. One undo step restores the captured `<session>` block and removes the pattern track; its redo builds
  it again from the same notes.
- **GUI** - a populated MIDI cell's right-click menu has **Save to Library...** (the same `browser.save_clip`
  form with the cell's address fixed); a `.mid`/`.midi` file dragged from the browser (drag key
  `importedproject`) or the desktop onto any cell runs `session.import_midi_cell` (`SessionGridDrop.cpp`).
- **Agent** - the same two registered commands over the control socket / MCP. No window is needed.
- **Reversibility** - `session.import_midi_cell` is `true_inverse` (row in `ControlReversibilityTableAction.cpp`);
  `browser.save_clip` keeps `true_inverse`. A16 histogram now `rows=945 true_inverse=466 snapshot=42
  irreversible=25 not_mutating=412` (+1 `true_inverse`). Snapshot regenerated from a live instance (936 ids /
  78 groups; README canary updated).

No project-format change: the pattern, its clips and the cell reference are saved by the existing
`PatternStore` / `<z:scenes>` serialisation, and the library entry is a file outside the project. Old
projects load unchanged. Nothing runs on the audio thread: save and import are registered command handlers on
the control/UI thread.

## Known limits

- An imported file's notes all go to one store instrument (`instrument`, default the first); a multi-track SMF is
  flattened (the reader merges tracks). Note velocities map to the smallest volume that emits the same MIDI
  velocity, so repeated round trips are stable; a volume that is not on that grid does not round-trip exactly.
- A saved entry carries notes only: pattern track name, mute, instrument settings are not in the file.
- Qt 5.15, MSVC and macOS builds are not run on this box; the new code uses no Qt-6-only API, no
  `std::filesystem`, and none of the Windows-macro identifiers.
