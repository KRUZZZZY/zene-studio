# Q050-339 - Track delay for audio tracks and mixer channels

Unit: P2, M, area L08 (B-MX-035). Goal: users can set and save track delay / manual latency offsets on audio tracks and
mixer channels as well as instrument tracks. Batch: `feat/050-Q050-088-oc`.

## What was built

- **Offsets in the PDC graph**: `AudioBusHandle::setOffsetFrames()` (tracks) and `MixerChannel::setOffsetFrames()`
  (channels), samples at the engine rate, +-8192 (`LatencyCompensation::MaxManualOffsetFrames`). A track path is
  aligned by `alignedLatencyFrames()` = latency - offset (`AudioBusHandle.cpp`, `Mixer::updateLatencyCompensation`);
  a channel's output latency is reduced by its offset (`Mixer::resolveLatency`). Positive plays later; negative
  earlier (the other paths are delayed). Additive to the automatic compensation; 0 by default = the old graph.
- **Command** `pdc.set_offset {target, offset_samples}` (`src/core/ControlCommandsTrackOffset.cpp`): audio track,
  instrument track or channel (the master refused); reads back `offset_samples`, `offset_ms`, `kind`; one undo step
  (`true_inverse`); refusals change nothing. `track.set_delay` (note-start delay) is untouched.
- **Projects**: tracks save `offsetframes` (SampleTrack, InstrumentTrack), channels `offset` (mixerstrip), only when
  non-zero; absent = 0; a loaded channel offset is clamped and ignored on the master.
- **GUI**: the track menu's "Track Delay (N samples)..." and a channel's Strip > "Channel Delay (N samples)..." show
  the stored value and open the command's form.

## Commands and format

- New: `pdc.set_offset` (`true_inverse`). Format: `offsetframes` on sample/instrument tracks, `offset` on channels.

## Known limits

- Samples at the engine's rate (not milliseconds): a different engine rate is a different time.
- A hosted instrument's extra routed output buses (InstrumentOutputBuses) are not moved by its track's offset.
- An offset plus device latency beyond the delay line (16384 frames) is clamped and flagged like any PDC excess.
