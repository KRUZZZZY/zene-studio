# Q050-148 - Clarify pitch-preserving warp documentation

Unit: users can tell which warp modes preserve pitch and what limitations remain for each
mode (type: docs, size S, area L05).

Starting state verified: the pitch-preserving stretch (feature-list row 30, WSOLA) and the
optional Rubber Band R3 mode (owner decision 12) were in the engine, but four documents
still carried the blanket claim that warping changes pitch / that pitch-preserving stretch
is not built, and three more described `warp.stretch` as a two-mode command:

- `docs/KNOWN-LIMITATIONS.md` — "Warping changes pitch. ... Pitch-preserving stretch is
  not built" (the warp entry), and the detailed stretch paragraph described only WSOLA.
- `docs/WARP.md` — §0 "The stretch mode is resampling, so it changes pitch. True
  pitch-preserving stretch ... is **not** built"; §3's bold paragraph read as a

  only `resample` / `preserve_pitch` (Rubber Band was documented in its own §7 only).
- `docs/CAPABILITIES-0.3.0.md` — the "Warp and stretch" paragraph named two modes.
- `docs/FEATURE-LIST-0.3.0.md` — row 22's stated limit ("there is no pitch-preserving

## Rework round 1 (the change-sensitive docs test)

The round-1 review was right that the engine tests cannot see a DOCUMENT reverting, so the
docs had no proof of their own. Round 2 adds `tests/warp-docs-agree.py`, registered as the
ctest `WarpDocsAgree` (`tests/CMakeLists.txt`, beside `DocFiguresGate` — offline, no binary,
no socket):

1. **Required corrected statements** — 40 exact phrases across the seven checked docs (the
   three-mode picture in WARP/KNOWN-LIMITATIONS/CAPABILITIES/FEATURE-LIST/STATUS/release
   notes, the `warp.stretch` three-mode schema and refusal cases in PITCH-STRETCH). Every
   phrase is a sentence the docs-correction commit added, so restoring the docs to the
   pre-correction revision fails the test.
2. **Per-algorithm caveats** — WSOLA: formants, transients, ~345 Hz alignment floor,
   linear-interpolation SRC, one rate per audio period; Rubber Band: `WANT_RUBBERBAND`
   optional dependency, the no-library refusal, the WSOLA fallback.
3. **The runnable reviewer example** — the docs must name
   `tests/control-pitch-stretch-transcript.py`, the script must exist and still drive
   `warp.stretch` / `preserve_pitch` / `warp.list`.
4. **The old blanket claims are rejected as current statements** —
   "Pitch-preserving stretch is not built", "no pitch-preserving stretch", "there is no
   pitch-preserving time-stretch", "True pitch-preserving stretch is a DSP project",
   row 30's old "**to build**" state, the old "or **`preserve_pitch`**" two-mode schema and
   STATUS's old "Resampling stretch, so it changes pitch". An occurrence is allowed only
   where the file marks it historical itself (a `Corrected` / `no longer` / `was:` /
   `SUPERSEDED` note on the same line or within the following six lines — the repo's own
   dated-correction convention), so the corrections this unit wrote remain legal text.

`docs/RELEASE-NOTES-v0.2.1-alpha.md` stays outside the set: it is the historical record of
the 0.2.1 release and was true of it; the 0.3.0 notes supersede with the dated correction.
