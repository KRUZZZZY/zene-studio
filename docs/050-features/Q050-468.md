# Q050-468 - Bind Tab navigation to transients (P3, completion, L04)

**Unit.** While the arranger has keyboard focus, Tab moves the play position to the next audio transient and
Shift+Tab to the previous one. The keys run the registered `arrangement.next_transient` command with its
`direction` argument, the same handler as Navigate > Next Transient / Previous Transient, so a key move is the
command's own result. A Tab in a text field, a Tab with Ctrl/Alt/Meta, or a Tab sent to an arranger that does not
have the focus is not claimed. A move with no transient in that direction leaves the position and the refusal is
announced. While the arranger has the focus, Tab no longer traverses keyboard focus out of it.

**Design.** The interception is `SongEditor::event` (`src/gui/editors/SongEditor.cpp:409-418`), not
`keyPressEvent`, because `QWidget::event` takes Tab/Backtab for focus traversal before a key press reaches
`keyPressEvent`; the override has to see the key first.

- The decision and dispatch live in `arrangerkeys::handleTransientKey` (`src/gui/ArrangerClipKeys.cpp:323-339`):
  it accepts only a key press of `Qt::Key_Tab` or `Qt::Key_Backtab`, and only Shift may accompany it, so
  Ctrl/Alt/Meta+Tab pass through to the window.
- A focus guard, `QApplication::focusWidget() == editor`, keeps Tab in a focused text field or any other editor.
- Shift+Tab reaches Qt either as `Key_Backtab` or as `Key_Tab` with Shift; both take the backward branch.
- The key path invokes the same registered command as the menu items, `arrangement.next_transient`; a refusal (no
  transient that way) is announced through the accessibility layer.
- No command is new or changed, so its reversibility stays `not_mutating` and the metadata snapshot is unchanged.
- `transport.seek` is the only effect. There is no audio-thread code and no format change.
- Portability: Qt 5.15 and Qt 6 API only.

## Known limits

- A consumed Tab means there is no keyboard focus traversal out of the arranger by Tab.
- Only audio clips under the play position have transients (the existing command's behaviour).
