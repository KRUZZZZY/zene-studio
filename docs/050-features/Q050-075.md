# Q050-075 — Expose tag and embedded-metadata search in the browser

Queue unit: a musician can search the library by tags and by embedded audio metadata from the
Search view. `tag:` was already parsed by the search field and already matched in the core, but
nothing in the interface reached it, and the whole metadata path (`browser.query`'s `probe`) was
socket-only. The limitations page still called tag search socket-only.

## What was built

- `src/gui/BrowserSearchView.cpp:126` — the **Search file metadata** checkbox
  (`objectName` `browserSearchMetadata`, accessible name and a tooltip that states the 200-file
  probe limit, `controlCommand` `browser.query`). It sits beside **Whole library** in the Search
  row.
- `src/gui/BrowserSearchView.cpp:192` — the toggle is wired to re-run the search when it flips,
  and is disabled while **Whole library** is on, because `browser.index_query` stores no embedded
  metadata and takes no `probe`.
- `src/gui/BrowserSearchView.cpp:290` — `queryArgs()` adds `probe: true` when the toggle is
  checked and the query is the walking `browser.query` (never the index query).
- `src/gui/BrowserSearchView.cpp:327` — `restoreQuery()` restores the toggle from a history
  entry's stored `probe` (and clears it for an index entry), under the same signal blocker as the
  other filters, so Back/Forward and live-search refinement keep the toggle in step with the
  query actually run.
- `src/gui/BrowserSearchView.cpp:462` — `saveCollection()` strips `probe` before
  `browser.collection_save`, which stores the query text and takes no probe switch.
- `src/gui/BrowserSearchView.cpp:112,118,125` — the Kind, Where-to-look and Whole-library
  controls gained stable `objectName`s so the tests (and a11y tooling) can address them the same
  way the search field already was.
- `src/core/ControlCommandsBrowser.cpp:126` — `browser.query` re-reads the tag store file before
  matching. It previously answered `tag:` from whatever happened to be in memory, so a fresh
  session (or tags written by another instance) matched nothing. `browser.index_query` and
  `browser.similar` already loaded it; the query command now does the same.
- `tests/src/core/BrowserTestSupport.h:71` — the RIFF/WAVE fixture writer gained an embedded
  `artist` (`LIST`/`INFO`/`IART`), the twin of the title it already wrote, so a test can prove the
  probe matches an embedded *artist* and not only a title.
- `docs/KNOWN-LIMITATIONS.md:714` — the browser section now says tag search is available in the
  Search field, metadata search is available through the new toggle (bounded at 200 files), the
  index takes no probe, and waveform peaks stay socket-only.

No new control command, no reversibility change, no project-format change. `browser.query` stays
read-only (`mutating = false`); an agent's existing `probe: true` call is untouched.

## Design notes

The toggle is transient view state, like Kind and Where-to-look: it is not journalled and not
saved with a collection. It rides the existing `browser.browse` path, so history keeps the query
arguments it sent and Back/Forward replay them faithfully. Metadata probing stays on the
non-audio query thread the command already used; nothing here reaches the audio thread. The
`browser.query` tag-store reload makes the GUI and the agent path agree on what `tag:` means and
is the one behaviour change an agent can observe.

## Known limits

- The probe is the command's, not the GUI's: one search opens at most 200 audio files
  (`BrowserMaxProbes`, reported as `probe_limit`), and the result says so. A library larger than
  that is searched by name/tag first and narrowed until the audio candidates fit the budget.
- The index (**Whole library**) stores no embedded metadata, so the toggle is disabled there; a
  metadata search is a walking search.
- Waveform peaks and peak drawing stay socket-only (`browser.peaks`); this unit adds no drawing.
- The tag-store reload in `browser.query` re-reads a small JSON file on the query thread on every
  query. It is the same call `browser.index_query` and `browser.similar` already made, on the
  same non-audio path.
