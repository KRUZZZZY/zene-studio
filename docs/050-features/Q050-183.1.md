# Q050-183.1 - Settings > Audio running-output box and an audio test tone

Goal: show which audio backend is actually running next to the configured one (with the backend that failed and
the reason after a fallback), and let a musician or an agent play and stop a test tone through the running output
without touching the project. The box and the commands read the same state.

## What was built

- `audio.test_tone` and `audio.test_tone_stop` (src/core/ControlCommandsAudioTestTone.cpp). `audio.test_tone` takes
  `frequency` 20-20000 Hz, `seconds` 0.1-10 and `level_db` -60 to -6. Both are `not_mutating` with no undo step
  (session audio only), so neither the project nor `control.undo_depth` moves.
- `audio.device_list` gains `requested`, `failure_reason` and `fallback`, beside `current`, `configured` and
  `start_failed`.
- Settings > Audio's Running output box (include/AudioOutputStatusBox.h, src/gui/modals/AudioOutputStatusBox.cpp):
  the running backend and the configured one; after a fallback, the backend that could not start and the reason;
  a note that a restart is needed when the saved choice differs. Play test tone and Stop dispatch the same
  commands through ControlRegistry.
- The tone is a 1 s 440 Hz sine at -18 dBFS through the running output. It starts nothing: the transport and the
  project stay as they were.

## Entry points

- Settings > Audio: the Running output box, Play test tone and Stop.
- An agent: `audio.device_list`, `audio.test_tone`, `audio.test_tone_stop`.
- The socket driver tests/control-audio-test-tone.py runs ControlAudioTestTone (steps a-f) over the real binary.

## New commands and format

- `audio.test_tone` and `audio.test_tone_stop`: `not_mutating`, no undo step, session audio only.
- `audio.device_list` gains `requested`, `failure_reason` and `fallback`.
- Format changes: none.

## Realtime and portability

- Realtime: the tone buffer is built on the calling thread. The handle's `isFinished` and its destructor use relaxed
  atomics only (a generation gate, and a CAS max in the destructor). No locks, allocation, I/O or signals on the
  audio thread. TSan does not run on this box, so this is reasoned, not measured.
- Portability: Qt5/6-neutral; no `std::filesystem`.

## Known limits

- Live switching of the device is stage 2. A switch still takes effect on the next start.
- The tone goes to the master bus, so master effects apply to it.
- `audible` is false on the dummy device, so the tone is not heard there.
- `ControlSocketIntegration`'s new audio block never ran on this box: that test fails earlier on this build (no
  builtin plug-ins, line 687). The failure predates this unit.
