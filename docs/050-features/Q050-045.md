# Q050-045 - Reduce the crash-loss window for recorded audio

## Unit
P0 fix. A crash must lose substantially less buffered recording audio than the old one-second journal interval.

## Built
- `src/core/audio/TrackRecorder.cpp` `commitTake()`: on the disk-writer thread, every journal interval it rewrites the WAV header (`SFC_UPDATE_HEADER_NOW`), syncs the file, then rewrites the journal. Before, libsndfile wrote the data size only on close, so a SIGKILLed take claimed 0 frames. It also counts commits and time spent (`commitCount()`, `commitNanoseconds()`).
- `src/core/RecordingJournal.cpp`: `updateIntervalFrames` = rate/10 (was rate); `lossBoundFrames` = interval + one 4096-frame writer batch; `boundText` states the bound in frames and seconds. A `static_assert` ties the batch constant to `TrackRecorder::WriteBatchFrames`.
- `record.recovery_get_state` / `record.recovery_restore` report `journal_lag_bound_frames` (4800 at 48 kHz) and `bound` text; descriptions updated.
- `docs/KNOWN-LIMITATIONS.md`: new bullet with the bound, limits and I/O cost; old bullet marked superseded.

## Bound
At 48 kHz: 4800 + 4096 = 8896 frames = 0.185 s while the writer is healthy. A stalled writer can still leave up to 65536 ring frames (1.37 s) unwritten.

## Known limits
- The first 0.1 s of a take has no commit: a crash inside it recovers nothing (measured: 0 recovered at 0.0107 and 0.064 s in; loss still within the bound).
- Stalled writer: see Bound.
- I/O cost measured: about 10 commits/s per armed track, mean 3.7 ms each (12 commits, 44 ms) = about 4 % of one writer thread; none on the audio thread.
