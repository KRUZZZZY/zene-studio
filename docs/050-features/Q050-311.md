# Q050-311 - Built-in synth pressure and timbre (P2, feature, L10)

**Unit.** Users can play MPE pressure and timbre expression through the built-in synthesizers.

**Before.** Pressure and CC74 were captured, stored (`mpepressure` / `mpetimbre`), edited
(`note.expression_set`, the note editor's Pressure/Timbre lanes) and sent to the instrument as MIDI, but
every built-in synth ignored them: `Instrument::handleMidiEvent` is the base no-op and the built-ins are
driven by a note's frequency and volume only. `MpePlaybackTest` proved the MIDI route through a test
fixture, not a sound change on a real synth.

## What was built

| Piece | Where |
| --- | --- |
| `MpeSynthExpression`: per-note stage. Pressure -> intensity, gain `1 + p/127` (unity at 0, +6 dB at 127). CC74 -> brightness, `y = x + b*(x - lowpass(x))`, `b = 3*t/127`, one-pole corner 1 kHz (flat at 0, up to +12 dB above the corner). Both neutral at 0, and the stage is the exact identity there. A value change is ramped linearly across one block; the first block starts at the note's values | `include/MpeSynthExpression.h`, `src/core/MpeSynthExpression.cpp:50-140` |
| Hook: applied in `InstrumentTrack::processAudioBuffer` to each note of a per-note (not single-streamed) instrument, right after its envelopes. A note with no expression and no stream is never touched | `src/tracks/InstrumentTrack.cpp:303-309`, `MpeSynthExpression::applyToNote` (`src/core/MpeSynthExpression.cpp:142`) |
| Stream-aware values: `NotePlayHandle::effectiveMpePressure()` / `effectiveMpeTimbre()` (the stream's value at the current tick, else the scalar), mirroring `effectiveMpePitchCents()`; the per-note `MpeSynthExpression::State` member | `src/core/MpeExpressionStreamPlayback.cpp:142,154`, `include/NotePlayHandle.h:385-394,468` |
| Opt-out: `Instrument::appliesMpeExpressionItself()` (default false). A per-note instrument that maps the MIDI axes itself returns true so they are not applied twice. The `MpeTestConsumer` fixture does this, so `MpePlaybackTest`'s ratios are unchanged | `include/Instrument.h:94`, `tests/src/plugins/MpeTestConsumer.cpp:283` |

**Coverage.** Every built-in instrument that renders each note itself (TripleOscillator, Monstro, Organic,
Kicker, BitInvader, Watsyn, NES, SFXR, Vibed, Xpressive, FreeBoy, Mallets, Patman, AudioFileProcessor,
SlicerT, SID, ...) goes through the same `processAudioBuffer` call, so they are all covered by one hook. The
measured proof uses TripleOscillator. Single-streamed built-ins (LB302, OpulenZ, SF2, GIG, the SFZ player,
ZynAddSubFX) render all notes as one stream, so per-note shaping is not possible there. They are unchanged
and still get the axes as MIDI. Hosted plug-ins and MIDI outputs are unchanged.

**Default mapping (an assumption this lane made, since the scope brief left it open).** Pressure ->
intensity and CC74 -> brightness, as the brief suggested. Both are neutral at 0 and not centred at 64.
The reason: `note.expression_set` with only one axis marks the note expressive and leaves the other axis
at 0, so a mapping centred at 64 would change the sound of every one-axis note.

## Commands, GUI, undo

No new commands and no changed metadata. The agent path is `device.mpe_set` (enable live input) plus
`note.expression_set/get/clear` (author/read). The GUI paths already exist: Edit > MPE Input
(`MpeInputActionTest`) and the note editor's Pressure/Timbre lanes. Both go through the same registered
commands as before. Undo is unchanged: `note.expression_set` is `true_inverse` with one clip checkpoint, and
`device.mpe_set` is `true_inverse`. The snapshot was not regenerated because no command id, schema or class
changed.

## Format changes

None. Old projects carry no MPE attributes, so their notes have no expression, the stage is skipped, and
they render bit-identically (proved above).

## Realtime

`MpeSynthExpression::process` runs on the audio thread. It does plain float arithmetic on the note's own
`State` value member (no allocation; the slot proves 0 allocations), takes no lock, does no I/O and emits no
signal. It calls one `std::exp` per block. `effectiveMpePressure/Timbre` read the handle's own immutable
stream snapshot (the same protocol as `effectiveMpePitchCents`). The live path writes the note's scalar ints
from the MIDI input thread (`loadMpeExpressionOntoChannelNotes`), and the audio thread reads them once per
block. That is the same pre-existing unsynchronised int handoff the pitch axis already uses. This lane adds
no new shared state: `State` is touched only by the audio thread. TSan does not run on this box, so this is
reasoned, not measured.

## Known limits

- The mapping is fixed. There is no mapping editor and no per-instrument amount (out of scope).
- Changes take effect per audio block, with a linear ramp across the block. A stream point inside a block is
  heard from the start of the next block's ramp, so the time resolution is one period. Hosted instruments
  still get sample-accurate MIDI.
- Single-streamed built-ins (LB302, OpulenZ, SF2/GIG/SFZ, ZynAddSubFX) are not shaped.
- Pressure adds up to +6 dB per note before the track fader. Dense full-pressure chords are louder.
