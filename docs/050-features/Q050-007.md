# Q050-007 - Opt-in v2 project save/load

Queue unit (P0, M, L12, lane `container-v2-optin`): choose the v2 container format for a project while the
legacy single-blob `.mmpz` stays the default and both formats reopen. Branch `feat/050-Q050-007-v2-container`,
base `888934e1b`. The user-facing description is `docs/PROJECT-CONTAINER-V2.md`.

## What was built

The v2 container code (`ProjectContainer.h`, ARCH-4 S2c) existed with no production caller: nothing saved or
opened one. This unit wires it in, opt-in only.

- `include/ProjectContainer.h` / `src/core/ProjectContainerEntries.cpp`: `writeDocumentContainer` (derive entries,
  write the ZIP) and `readDocumentContainer` (read the ZIP, reassemble the original bytes) - the one call a save
  and a load each make.
- `src/core/DataFile.cpp`: `DataFile::writePayload` (the former inline write block of `writeFile`, plus the v2
  branch, honoured only for a song project headed for a `.mmpz` name; it switches the `<z:index>` on because the
  container is cut along it); the file constructor recognises a container by its ZIP magic (content, never the
  extension) and loads the reassembled document; `isCompleteDocument` adopts a complete v2 `<file>.new` and discards
  a torn one like a legacy temp. `include/DataFile.h`: `setContainerV2`, `containerV2Written`, `loadedFromContainer`.
- `include/Song.h`, `src/core/Song.cpp`: `Song::SaveFormat`, `plannedSaveFormat()`, `isContainerV2Project()`,
  `lastSavedFormat()`, `globalContainerV2()` (config `app/savecontainerv2`), `containerV2Note()` (the larger
  file / older builds sentence), `SaveOptions::saveAsV2Container` + `formatChosen`; `saveProjectFile(...,
  SaveFormat = Legacy)` so every other writer (autosave, templates, renders, handoff) is unchanged.
- `src/core/ControlCommandsProjectFiles.cpp`: `project.save` gains `format` (`legacy`|`v2`) and replies
  `format`, `bytes`, `format_note`; v2 for a non-`.mmpz` path is a typed `invalid_args` before any revision rotates.
- GUI: Save As dialog checkbox (`VersionedSaveDialog.cpp`), File > "Save as v2 Container..." (`MainWindow.cpp`),
  status-bar note after a v2 save, Settings > General > Projects checkbox (`SetupDialog.cpp`),
  `app/savecontainerv2` in the settings-preset catalogue (`ControlCommandsSettingsPresets.cpp`).
- `src/core/ControlProjectAssets.cpp`: the asset verbs refuse a container by name instead of by a misleading
  "declares 1.3 GB" accident.

## Commands and reversibility

No new command id. `project.save` gains the optional `format` argument and three reply fields; its
reversibility class is unchanged (snapshot; the replaced file is kept as revision 0, a v2 file included, which
`theReplacedContainerIsKeptAsARevision` pins). The GUI actions use the same `Song::guiSaveProjectAs` path the
existing Save As does and are declared against `project.save`. The commands snapshot was regenerated (823 ids /
76 groups, unchanged; only `project.save` differs).

## Format

A v2 file is a new on-disk shape; the legacy shape and everything that reads it are unchanged. Old builds cannot
open a v2 file (stated in the product). The document inside a container is the ordinary document plus the
`<z:index>` (the container needs it), reassembled byte for byte.

## Known limits

- Honest about GUI proof: the dialog checkbox, the new menu entry and the Settings checkbox compile and sit on
  the tested `Song` path, but were not driven in a window (offscreen only).
- A partial `project.open {sections}` of a container still reads the whole file (saves parsing, not I/O).
- `project.missing_assets`, `project.hash_assets`, `project.relink`, the revision-timeline compare and
  `zene --dump/--compress` do not read containers; they refuse by name.
- Fixtures are generated in the tests by the product's own writer, not committed binary files.
- Environment note: after editing `Song.h` the plugin libraries must be rebuilt too; with stale plugins the
  headless instance aborted on `free(): invalid pointer` at startup (seen here, fixed by rebuilding them).
- `ReversibilityContractTest::theTableHistogramIsTheDocumentedOne` fails on this tree (I did not run it on the bare base); this unit adds and changes no command row, so it does not explain the +1; the table measures 832 rows,
  release notes publish 831 (+1 true_inverse). Not touched.
