# Q050-001 - DAWproject DEFLATE and tolerant import reporting

Unit: P0, size M, area L12 importers. Branch `feat/050-Q050-001-dawproject-deflate`, base `888934e1b`.

Goal: open valid DEFLATE-compressed DAWproject files and return a complete report for corrupt or unsupported entries.

## What was built

- **Raw DEFLATE reading, bounded.** `src/core/DawProjectZipRead.cpp` (new) is the container reader, moved out of
  `DawProjectZip.cpp` (now writer only). `inflateRaw` (`:405`) uses zlib with negative window bits (a ZIP entry is a bare
  RFC 1951 stream) and `drain` (`:387`) counts the output chunk by chunk, so the bound holds on the bytes produced, the
  approach `ControlProjectAssets.cpp` takes for a `.mmpz`. `sizeAcceptable` (`:333`) holds every entry to
  `DawProjectZipLimits` (512 MiB per entry, 1 GiB total, `include/DawProjectInterchange.h`) on its declared size before
  inflating; inflating stops at the declared size, so a lying header cannot exceed it.
- **Tolerant, complete reporting.** `dawProjectZipReadTolerant` (`:518`) never stops at the first problem. Each of
  corrupt entry, CRC mismatch, unsupported method (named), encryption/ZIP64, oversized, total oversized and a truncated
  directory is a `DawProjectDeviation` (`kind`, `entry`, `detail`). `readDawProject` (`src/core/DawProjectRead.cpp:480`)
  adds `missing_project_entry`, `duplicate_entry` and `missing_referenced_file` (every internal `<File path>` in
  `project.xml` the container does not hold, `:443`; `external="true"` paths are not checked).
- **Command surface.** `dawproject.read` and `dawproject.import` return `deviations[]`, `deviation_count`, `entry_count`,
  `deflated_entry_count`, `referenced_file_count` (`src/core/ControlCommandsDawProject.cpp:111`). A damaged `project.xml`
  leaves nothing to import: a typed `invalid_args` refusal whose message lists every deviation (`:97`) and writes nothing.
  A deviation in any other entry does not stop the import.
- **GUI.** File > Import DAWproject... shows the same list in a dialog after an import that proceeded
  (`src/gui/TrackRenderMenu.cpp:95` `dawProjectImportNotice`, `:114` `importDawProject`); a refusal already shows the
  message with the list. Same registered command as the agent surface.
- **Disclosures superseded.** The STORE-only limit statements in the command description (`dawproject.read` and
  `dawproject.import`; `dawproject.export` now says import reads both), the import tooltip, `dawproject.convention`
  (`container`, `zip_method`), `docs/DAWPROJECT-INTERCHANGE.md`, `docs/CAPABILITIES-0.3.0.md` and
  `docs/KNOWN-LIMITATIONS.md` now describe the DEFLATE reader.
- **Kept as it was.** The `.mmpz` v2 container still calls the strict `dawProjectZipRead`: STORE only, first deviation
  refuses (`DawProjectZipRead.cpp:537`). The writer still stores.
- `dawProjectZipRead` (CCN 36) and `readDawProject` (CCN 12) left the complexity baseline: both are now under CCN 10
  (the two stale entries were removed from `tests/complexity-baseline.tsv` and `-all.tsv`).

## New commands and reversibility

None. `dawproject.import` keeps `true_inverse` (one undo restores the captured session); `dawproject.read` is
`not_mutating`. Result schemas gained five fields each; the commands snapshot was regenerated from a live instance
(823 ids / 76 groups, unchanged).

## Format changes

None to the project format or to the `.dawproject` writer. The reader accepts a strict superset of what it did.

## Known limits

- Not supported, and reported per entry: encryption, ZIP64, spanned archives, methods other than STORE and DEFLATE.
- Entries are held in memory (bounded by the two limits above); only `project.xml` and `metadata.xml` are retained, the
  others are decoded and CRC-checked and then dropped.
- Referenced-file checking covers `<File path>` elements of `project.xml`; the importer still does not import audio
  (LOSSY #1), so a missing audio file is reported but changes no imported content.
- A build without zlib reports DEFLATE entries as `unsupported_method` (zlib is a required dependency; that branch is
  compiled out and was not built).
- The limits are fixed constants (`DawProjectZipLimits` defaults), not settings.
