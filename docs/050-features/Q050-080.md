# Q050-080 - Speak timeline position, selection, and markers

Unit: hear the selected item, the edit position, the transport location, and
named project markers (L14 accessibility).

Starting claim verified: `src/gui/AccessibleAnnouncements.cpp:32` never spoke
the playhead, and `rg announce + marker` found no marker announcement;
`marker.jump` moved silently and playback across a marker ran its action
without saying its name.

## What was built

- `include/TimelineSpeech.h`, `src/gui/TimelineSpeech.cpp` (fork-new):
  `positionSpeech` (the configured `musicaltime::positionText`, so
  `transport.time_format` is what is heard), `clipSpeech` (name, track,
  bar/beat span), `markerSpeech` / `markerCrossingSpeech` (name + bar/beat),
  `noteSpeech` (pitch, bar/beat span, velocity), `say` (Polite through
  `a11y::announceStatus`, so `view.announcements` gates it: All hears it,
  Errors and Off do not), plus `announceNoteSelection` and
  `announceCrossedMarkers` (kept out of the command handlers so the
  complexity ratchet stays green).
- Selection: `src/gui/ControlCommandsSelection.cpp` (`window.select`) says the
  chosen clip (`clipSpeech`), or the track/channel with the edit cursor
  (`positionSpeech` of the play position). `src/core/ControlCommandsNoteSelect.cpp`
  (`note.select`) says the count and the earliest selected note.
  Both go through the same registered commands the GUI uses.
- Transport: `src/core/ControlCommandsTransport.cpp` (`transport.play`,
  `transport.stop`, `transport.seek`) says "Playing from …", "Stopped at …"
  and "Playhead …". Locate and scrub are both `transport.seek`, so every
  scrub step is announced; the text follows the configured time format.
- Markers: `src/core/ControlCommandsMarkers.cpp` (`marker.jump`) says
  `markerSpeech`; `src/core/MarkerActions.cpp` (`advance`, the 15 ms playback
  watcher, never the audio thread) says every named marker crossed via
  `announceCrossedMarkers`. Both are Polite, so Errors/Off suppress the name
  while the jump itself still moves.
- GUI paths use the same commands: Play/Stop buttons (`ShellChrome`,
  `PerformView`), ruler/note-editor seeks (`transport.seek`), marker menus
  (`marker.jump`), clicks (`window.select`).
- Round-2/3 rework (reviews Q050-080.r1 and r2.feature): the GUI paths go
  through the registered commands. `speech::announceSelection`
  (`include/TimelineSpeech.h`, `src/gui/TimelineSpeech.cpp`) is the one shared
  announcer - clip (`clipSpeech`), else track/channel with the edit cursor.
  `window.select` (`src/gui/ControlCommandsSelection.cpp`) owns the
  announcement for a changed selection; `ShellSelection`'s setters only set
  state, and its application event filter invokes `window.select` for a clip,
  track-header or mixer-strip press, with the direct setter as a fallback when
  the command is not ready. The note editor's clip selection invokes the same
  command. A mouse-path change only queues the announcement for the next loop
  turn (`QTimer::singleShot`, coalesced): the pressed `ClipView`'s own handler
  announces its drag hint after the filter runs, and speaking at once would be
  overwritten - the queued message says the selection as it stands then, so
  rapid presses coalesce into one and the repeat window drops pure repeats.
  There is no second announcement in the setters, so a GUI press and the agent
  hear one message.
- Round-3 rework (review Q050-080.r2.feature): the arranger's
  Left/Right/Home keys (`src/gui/editors/SongEditor.cpp`) and Home in the note
  editor (`src/gui/editors/PianoRoll.cpp`) invoke `transport.seek` instead of
  moving the play position directly, so a keyboard cursor move speaks the
  configured bar/beat position like the transport bar and the agent. The
  headless tests drive real mouse and key events through those widgets.
- Registration: `src/gui/CMakeLists.txt`, `tests/CMakeLists.txt`,
  `tests/fork-sources.txt`, `tests/all-sources.txt`. No new commands, no
  project-format change; the commands snapshot stays 833 ids / 76 groups.
- Docs: this file and a spoken-selection paragraph in `docs/UI-SHELL.md` §8.

Realtime: announcements run on the control/GUI thread (command handlers and
the marker watcher timer); nothing on the audio thread allocates, locks, or
emits Qt signals for this. Portability: no Qt-6-only API, no new
`findChild<T>`, no banned identifiers; the helper has an out-of-line
translation unit with only forward declarations in the header.
Reversibility: no command changed its reversibility class; announcements are
a side effect with no undo step (`transport.seek` keeps its one undo step,
`marker.jump` stays NotMutating with the seek's step inside).

## Known limits

- The seek inside `marker.jump` announces "Playhead …" first and the marker
  second; a screen reader hears both, the marker last.
- Unnamed markers have no name to say; a crossing says "Marker, <position>".
- Announcements are Polite: with `view.announcements=errors` or `off`,
  selections, positions and marker names are silent (lastAnnouncement holds).
- The arranger cursor keys are `transport.seek`, so each cursor move records
  the same one-step transport undo entry a ruler click or an agent seek does
  (the transport's existing behaviour; speech itself adds none).
- TSan does not run on this box (runtime crash at thread creation); the
  audio-thread argument is by design (announcements live on the
  control/GUI thread and the marker timer, never the render thread).
