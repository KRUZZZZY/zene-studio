# Q050-054.1 - Record and comp MIDI takes on instrument tracks, stage 1/2: capture armed MIDI tracks into arrangement takes (P1, feature, L03)

**Unit.** Record MIDI from armed instrument tracks through `transport.record` alongside audio, and retain loop
passes as arrangement takes. Stage 2 (Q050-054.2) adds the MIDI-facing comp UI and its proof; nothing here would
have to be undone for it - the takes are ordinary take-lane clips the existing comp model already gates.

**Before (base `5c1c6715d9`, train 19).** `transport.record` captured sample clips and armed automation only.
Live MIDI was recorded only into the clip open in the Piano Roll. An instrument track's header arm button
(`track.set_arm`) arms its *audio input* to a WAV file, not MIDI. An instrument track played every MIDI clip
regardless of take groups.

## What was built

| Piece | Where |
| --- | --- |
| `MidiTakeCapture`: per instrument track, a bounded lock-free multi-producer queue (Vyukov) of note edges, each stamped with the period's song tick and loop pass that `Song::processNextBuffer` publishes in one packed atomic. `capture()` takes no lock, never allocates, never waits; a full queue drops and counts. Storage (4096 events, 96 KiB) is allocated on the main thread the first time the track is armed and kept until the track dies | `include/MidiTakeCapture.h`, `src/core/MidiTakeCapture.cpp` |
| The producer: `InstrumentTrack::processInEvent` hands every External note edge to the capture, after the input transform and before the monitoring gate (a track that is not heard still records) | `src/tracks/InstrumentTrack.cpp` |
| `MidiTakeRecorder` (main thread, a child of the Song): Record opens a session on every armed track, a 50 ms timer drains the queues, Stop closes it and runs `record.midi_capture_commit` through the registry - whoever pressed Stop | `include/MidiTakeRecorder.h`, `src/core/MidiTakeRecorder.cpp`, `src/core/Song.cpp` |
| Commit: a plain pass = one MIDI clip from the bar of its first note (notes at the tick and velocity they were played - the live input's `MidiEvent::volume(baseVelocity)`); a loop recording (the transport wrapped) = one take clip per pass with notes, spanning the loop region, each on a new take lane of one take group, recorded with `TakeLaneModel::recordTake` (newest active unless chosen). A later loop recording over the same region joins that group, so a `comp.take_select` choice survives it. A note held across the wrap ends at the loop end. Replace mode erases the earlier notes a plain pass overlaps (notes only, `recordoptions::replaceOverlapped`). Count-in / pre-roll notes are not kept | `src/core/MidiTakeRecorder.cpp` |
| Playback: an instrument track plays a grouped MIDI take only when it is its group's active take, unless a composite, an audition or play-all-takes decides (`InstrumentTrack::takePlays`, the SampleTrack rule). Clips without a take group are untouched | `src/tracks/InstrumentTrack.cpp` |
| GUI: the track's Record menu (track header menu > More, and the Inspector's menu) gains **Record MIDI Takes > On / Off**, **MIDI Take Status** and **Keep the Captured MIDI**; the header's Record and Stop buttons drive the pass | `src/gui/shell/ShellCommandMenus.cpp` |

| Command | Class | What |
| --- | --- | --- |
| `track.set_midi_arm` {track, armed} (new) | `not_mutating` | arm/disarm an instrument track's MIDI take capture; mode state, not saved (the `midi.retro_capture_arm` precedent). Refused on a non-instrument track |

| `record.midi_capture_commit` (new) | `true_inverse` | the captured passes become clips - ONE journal step: one checkpoint of every track it changes, taken before the first clip. Runs at Stop; refused while recording and when nothing is pending (before any checkpoint) |
| `transport.record` (changed) | `not_mutating` (unchanged) | description names MIDI capture; result gains `midi_tracks` (the armed tracks this pass records) |

## Realtime

The only work added to the MIDI input threads (ALSA sequencer thread; the audio thread for JACK MIDI) is
`MidiTakeCapture::capture`: two atomic loads, a bounded CAS loop on the enqueue index, a 12-byte copy, one release
store - no allocation, lock, wait, I/O or signal (`theCaptureQueueIsBoundedAndAllocationFree` counts zero allocations
and frees over 4106 pushes; `twoProducersLoseNothing` runs two producers against a draining consumer). The audio
thread adds one relaxed store per period (`publishPosition`) and, per MIDI clip, `takePlays` (atomic loads and the
reads `compPlays` already makes). Clips, lanes and journal steps are made on the main thread only. TSan does not
run on this box; the queue's memory ordering is Vyukov's published algorithm (acquire on the cell sequence, release
after the payload), and the storage is published before `m_capturing` is release-stored, never freed while the
track lives, and the capture is declared before the MIDI port so it outlives it.

## Format

No new file format: take clips use the existing `lane` / `takegroup` clip attributes and the existing `<z:lanes>`
take-group state. Old projects contain no MIDI clip with a take group, so they load and play exactly as before.

## Known limits (stage 1)

- Note edges only: controller, pitch-bend and aftertouch input is not captured into the take.
- A track armed after Record was pressed joins from the next pass; the arm is not saved with the project.
- A punch region does not gate MIDI capture; a count-in / pre-roll does (notes before the record point are dropped).
- In a loop recording, older ordinary clips under the loop keep playing beside the takes (overdub semantics).
- Keep History on a plain MIDI pass behaves as Overdub (as RecordOptions documents).
- Positions are stamped per audio period (well under a tick at common settings), not per sample.
- The MIDI take-lane strip and comp proof are stage 2.
