# Q050-062.2 Stem-separation quality, stage 2/4: the quality choice in the sample clip menu

**Unit.** R-ai-2, R-performance-55, R-workflow-102 (`L05`). Musicians can choose the stem-job quality
(stage 1's `quality` on `stem.job_start`) from the sample clip's **Split to stems** action and see, in the
job UI, the setting the job actually ran at. The source clip stays on its track.

## Realtime

Nothing here runs on the audio thread. The menu, the registry calls and the dialogs run on the GUI
thread; inference stays on `StemJobManager`'s worker (unchanged).

## Format changes

None. The quality is not stored in projects. "Last used" lasts for the session only, on the controller.

## Known limits

- The last-used quality is not saved between sessions.
- Comparing the source with each result (a persistent source/result link and auditioning them) is stage 4.
  Real-model SDR per quality is stage 3. This stage only makes sure the source clip is left in place.
- The test runs the external-process backend with the committed stub model, not HTDemucs.
