# Q050-156 - Record directly into a sampler

Unit: P1, M, L10. Goal: a musician captures an input take directly into AudioFileProcessor or
SlicerT, hears/plays it immediately, and an agent can drive and verify the same take through the
control surface.

## What was built

- `include/SamplerTakeRecorder.h` / `src/core/SamplerTakeRecorder.cpp`: one bounded take from
  the engine's configured stereo input. `arm()` (control thread, under the engine's model-change
  lock) allocates the clip recorder's pre-allocated ring and drain thread through
  `SampleRecordAccumulator`; the audio thread's `push()` only stages frames, skips the recording
  round trip (`AudioEngine::recordingLatencyFrames()`), and stops at the requested frame count.
  `stop()` ends it early; `takeFinished()` returns the assembled `SampleBuffer`; nothing is
  allocated, locked, decoded or written on the audio thread.
- `src/core/AudioEngine.cpp:987` taps the same stereo input bus the retrospective capture uses
  and feeds the sampler recorder once per rendered period. While idle this is one relaxed atomic
  load per period.
- `src/core/ControlCommandsSamplerTake.cpp` registers the `record` group:
  - `record.sampler_capture` (`track`, optional `seconds` default 2 / at most 30, `cancel`):
    starts a bounded take into that instrument track's AudioFileProcessor or SlicerT, or drops
    the take in hand with `cancel: true`. Not a project edit.
  - `record.sampler_capture_stop`: ends the take early; the frames taken so far are the take.
  - `record.sampler_capture_status`: state (`idle` / `recording` / `done`), track, device,
    frames, target frames, seconds, dropped frames, sample rate and latency.
  - `record.sampler_capture_land` (`file` optional, absolute): writes a 24-bit stereo WAV and
    loads it through the instrument's own `loadFile()` - AudioFileProcessor shows/plays it,
    SlicerT recalculates its slice points. One undo step: the track checkpoint restores the
    device's previous sample and settings; the WAV stays on disk.
- `include/SamplerTakeButton.h` / `src/gui/SamplerTakeButton.cpp`: the sampler views' shared
  "Record take" button. It invokes exactly those registered commands. The first click starts a
  take, a second click stops and lands it, and the button's own status poll lands a take that
  reached its requested length. No direct model access.
- `plugins/AudioFileProcessor/AudioFileProcessorView.cpp` and `plugins/SlicerT/SlicerTView.cpp`
  place the button in each device window (`audioFileProcessorRecordTake`, `slicerTRecordTake`).
- Registration: `ControlRegistryRegistrations.cpp` / `ControlRegistryGroups.h`; the four A16
  rows are in `ControlReversibilityTableDevices.cpp` (capture/stop/status `not_mutating`, land
  `true_inverse`).

## Format changes

None. Landing writes an ordinary WAV and the devices keep their existing `src` / `sampledata`
save/load formats, including SlicerT's `totalSlices`/`slice_<n>` state. Old projects load and
render exactly as before; the new data round-trips because it is the format the devices already
use.

## Known limits

- One take at a time per instance; starting another while one is in hand is a typed `busy`.
- The take is bounded to 30 seconds by `record.sampler_capture`; the GUI button asks for 2 s and
  can be stopped earlier.
- The capture taps the engine's stereo input bus (the same path the retrospective capture uses),
  not a per-track input route; input routing remains its own feature.
- A take is labelled with the input rate read when it is armed. If the engine's input rate
  changes while a take is recording, the frames are not split by rate the way the retrospective
  capture's window now is (train fix new-p12-200). Changing the audio device mid-take is the only
  way to hit this; it was the accepted design and is not changed by the integration.
- The audio thread never decodes, writes or allocates. Local TSan does not run on this box; the
  thread boundary is the `SampleRecordAccumulator` contract (control-thread arm, audio-thread
  ring write, drain thread assembly) and is reasoned through in the header.
