# Q050-356 — MIDI 2.0 / UMP support position

Unit: MIDI input support statement for MIDI 2.0 and Universal MIDI Packet (UMP).
Goal: the public docs and the in-app manual say plainly that Zene does not take MIDI 2.0 / UMP input yet, that the planned scope is not defined, and which platform backends the MIDI 1 input boundary covers.

## What changed

- `docs/MIDI-INPUT-SUPPORT.md` (new) is the public answer to "does Zene take MIDI 2.0 / UMP input?". Its `## Status` says "not yet supported"; its `## Planned: UMP input` says the scope is "not defined"; its `## Supported-platform boundary` names ALSA, JACK, WinMM and macOS/Apple; every `path:line` citation in it points at a file with that many lines.
- `data/manual/index.html` gains one paragraph, "MIDI 2.0 and UMP input.", stating the same position and linking to `docs/MIDI-INPUT-SUPPORT.md`.
- `tests/midi-input-support-doc-check.py` (new) is the checker behind the `MidiInputSupportDoc` CTest entry. It enforces checks (a)–(k) listed in its docstring: the status, the not-defined scope, the platform names, the absence of any "UMP input is supported" line, the citation line counts, and (round 2) the MIDI 1-only text, the input-path membership with each raw feeder's `.cpp` checked for `parseData(`, the backend-to-guard mapping checked against the `#ifdef` lines in `src/core/midi/`, and the manual paragraph.
- `tests/CMakeLists.txt` registers `MidiInputSupportDoc` (Python3 guard, runs from the source root). `tests/fork-sources.txt` lists the new checker.

Commits on `feat/050-Q050-356-oc`: `66b1472a6c` (doc + manual), `c677123693` (wording: "not defined"), `cb92829bfd` (checker and test registration), `3bba734922` (feature record and report), `e00cd4e984` (checker split into per-check functions for the complexity gate), `e546ed8c82` (report self-check), `9083ef8907` (round 2: doc verified against the source), `a13c2fccaf` (round 2: checker enforces the MIDI 1-only text, the backend guard mapping and the manual wording), and the round-2 evidence commit that adds the Round 2 sections here and in the report.

## Known limits

- The ALSA UMP scope is undefined by the owner; the doc says "not defined" and does not promise a backend, a version or a date.
- The platform table is limited to the CMake and AudioEngine guards that exist today; it is not an audit of every backend.
- This is a statement of non-support, not a runtime UMP claim. No UMP parser, port type or device probe was added, and `midi.device_list` on this host returns ALSA ports only (see the report).
