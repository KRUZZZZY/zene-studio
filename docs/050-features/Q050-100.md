# Q050-100 — Spoken meters and peak watching

## What changed

- `meter.speak` (NotMutating): reads the focused mixer channel's published post-fader sample peak and the master
  loudness tap's short-term LUFS-S, speaks both through `a11y::announceStatus`, and reports null/unavailable rather
  than a plausible zero when the tap is disarmed or its window is not ready. It never arms or resets the tap.
- The focused strip's **Speak Meter** action, shortcut **Ctrl+Shift+M**, runs the same command through `ControlRegistry`.
- `meter.set_peak_watch` (TrueInverse): the input bus and master output each announce one rising crossing of a chosen
  dBFS threshold, stay quiet while above it, and re-arm after falling below. `view.announcements` gates the messages.
- `MasterLoudnessTap` publishes a sample peak even while the LUFS meter is disarmed; `inputmeter` gains a third,
  dedicated peak pair for the watcher so it steals neither `meter.input` nor the live input meter.

## Round 3 fixes

- Qt before 6.8: `announceStatus()` now raises the alert on `a11y::announcementSource()`, a one-pixel live-region label
  of the active window that is named with the message (a source that already has that name is used as it is), so the
  screen reader reads the meter and launcher text instead of the window's name. Qt 6.8 uses the announcement event.
- Each new peak-watch crossing, and each `meter.speak` call, is spoken even when its text equals a recent one
  (`a11y::Repeat::Allow`); the latch still keeps repeated meter updates quiet.
- Speak Meter resolves the strip holding keyboard focus (`MixerView::focusedChannelView()`), not only the selected one.

Commands added: `meter.speak` (`not_mutating`), `meter.set_peak_watch` (`true_inverse`). No project format change.
Known limits: no continuous meter narration, no plug-in-specific meter speech, no rendered-file speech.
