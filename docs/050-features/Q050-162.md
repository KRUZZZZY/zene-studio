# Q050-162 — Synced transient-repeat stretching

Unit: Add synced transient-repeat stretching (L05, member R-editing-88).
Goal: users can repeat or gate transient segments at a synced or free repeat rate to fill a warped clip.

## What changed

Two new `WarpStretchMode` values, `Repeat` (6) and `Gate` (7) (`include/WarpMarkers.h`), wire and file names
`repeat` / `gate`. They sit beside the existing six modes; `Beats` and every other mode render exactly as before
(`rendersThroughStretcher` excludes only the two new modes).

- **Segments.** A segment starts at the head of the clip's window or at a transient and owns the output span until
  the next one starts - its slot, which the clip's warp map sets (mapped in exact fractional ticks,
  `transientTicksAt`). Inside its slot the segment plays at its natural rate (pitch and speed unchanged) from its
  transient. **Repeat** restarts it at every interval; **Gate** plays it once and is silent from the first interval
  on. A segment never reads into the next segment's audio, and the slot ends where the next starts, so the render
  lasts exactly the warped span, with a partial last interval at the clip end. A cut inside a slot gets a 32-frame
  ramp.
- **Rate.** `TransientRepeatRate` (`include/TransientRepeat.h`): a synced division 1/1..1/32 of a whole note (default
  1/16) whose interval is `192/division` ticks at the project tempo of the moment, or a free interval of 5..2000 ms
  that ignores the tempo. Packed into one 32-bit word on the base clip (`Clip::m_transientRate`, one atomic store /
  load). Kept across mode switches.
- **Transients.** Analysed with the existing detector (`clipTransientFrames`) on the control thread when a clip
  enters Repeat/Gate (`SampleClip::prepareWarpStretchMode`, before the mode is published) and again when its audio,
  window or direction changes while in one of them (`sampleChanged` and `wasReversed`, queued if emitted
  off-thread; the clip view's Reverse now announces `wasReversed`; a buffer/window/direction key skips unchanged
  audio). Transients within 20 ms of the window head or of the previous kept one are merged into it (the detector
  reports an onset at the very head one hop late). Stored as play frames in a fixed 256-entry `TransientTable`.
- **Publication (review r1).** `PublishedTransients`: three slots and a reader count per slot. The reader (a play
  handle being built on the audio thread) pins the published slot, re-checks that it is still published, copies,
  unpins - at most 4 attempts, never waiting; if every attempt races a publish it gets an empty table and renders
  the clip as one segment for that pass. The single writer (control thread) only writes a slot that is neither
  published nor pinned, then publishes it; if both unpublished slots are pinned it yields (control thread only).
  Every access is a sequentially consistent atomic, so no slot is ever written while a reader copies it.
- **Agent.** `warp.stretch` takes `mode: repeat|gate` and optional `rate_division` (enum `1/1`..`1/32`) or `rate_ms`
  (5..2000; both at once is `invalid_args`). A rate may change with or without a mode change; mode + rate is one
  clip checkpoint and one undo step (still `true_inverse`; the recorded inverse carries the previous mode and rate).
  `warp.list` / every warp read-back reports `repeat_rate` (`name`, `synced`, `division`, `interval_ms` at the current
  tempo) and `transient_count`; `stretch_algorithm` is `transients` for the two modes. Like the other pitch-keeping
  modes they are refused for a clip that renders linearly.
- **GUI.** The clip's Warp mode menu gains "Repeat transients", "Gate transients" and a "Repeat rate" submenu
  (Synced 1/4, 1/8, 1/16, 1/32; Free 50, 100, 250, 500 ms), every item through `warp.stretch`, current choice checked.

## Integration onto `050/m0-train-22` (r3)

The accepted patch (`545f8cb9b9`) conflicted with Q050-111 (per-clip effects) in `include/SampleClip.h` and
`src/core/SampleClip.cpp`, plus the two registration lists and the snapshot. Both sides were additive and are kept
whole: the header keeps Q050-111's `m_clipEffects` / `m_clipEffectsBusy` / copy-save-load helpers and this unit's
transient members, with `prepareWarpStretchMode` declared out of line (this unit's definition, which calls
`ensureRubberBandPool(mode)` exactly as Q050-111's inline one did, then analyses transients for Repeat / Gate); the
copy constructor runs `copyClipEffects(orig)` and then this unit's connects and `prepareWarpStretchMode`. In
`SamplePlayHandle::play` the transient renderer feeds the same post-processing chain as the other paths (edits, take
gate, comp, then Q050-111's clip effects), so Repeat / Gate clips get clip effects like any other clip. No semantic
difference from the accepted patch. Evidence: `~/.local/share/zene-bunny-fix/qwen/runs/Q050-162.r3/logs`.

## Commands and project format

No new command id (871 ids / 76 groups on the original base; 878 ids / 77 groups on the integration base `050/m0-train-22` - the difference is other units' commands; `wasm.*` out; snapshot regenerated live both times). `warp.stretch` gains two optional
args and two result keys (`previous_repeat_rate`, plus the shared `repeat_rate` / `transient_count`); its
reversibility class stays `true_inverse` (`ReversibilityContractTest` passes, histogram unchanged).
Format: the `<warp>` element may carry `stretch="repeat"|"gate"` and `repeat_rate="1/8"|"125ms"`; the attribute is
written only when not the default, so every older project serialises and renders exactly as before, and an older
build reading a new file falls back to Re-Pitch (unknown stretch name) as for any unknown mode.

## Known limits

- Segments play at the source's natural rate; the clip's transpose and speed curve are not applied in these two
  modes (amplification and direction are, since review r1).
- The interval is taken from the project tempo when a play handle starts; a tempo-map change inside one pass does
  not re-time that pass.
- At most 256 transients per clip; later ones are ignored (the last segment then runs to the clip end).
- The menu offers preset rates; any other free interval is set through the agent command.
- Local TSan does not run on this box. The race reasoning: the rate is one atomic word; the mode is published
  after its transients; the table is published through `PublishedTransients`, whose pin / re-check / write-only-
  unpinned protocol means no slot is written while a reader copies it (deterministic and stress tests above).
- A play handle built while every one of its 4 read attempts races a publish renders that pass as one segment.
