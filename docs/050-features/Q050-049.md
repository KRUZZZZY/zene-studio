# Q050-049 - Crash-aware plug-in quarantine

Unit: P0, M. Goal: users are offered quarantine for the plug-in that caused a scan or startup crash.
Branch `feat/050-Q050-049-crash-quarantine`, based on train 2 `190242990`.

## What was built
- `include/SafeStart.h`, `src/core/SafeStart.cpp`: `ActivePlugin` record, `beginActivePlugin` / `endActivePlugin`
  / `ActivePluginScope` (nesting stack under a mutex; rewrites the existing marker, only for third-party files, never
  creates a marker), `currentActivePlugin()`, `crashSuspect()`. Marker lines `active_phase`, `active_format`,
  `active_plugin`, `active_file` (written before `project=` so the 1 KiB cap trims the project hint first);
  `parseMarker` split into `applyMarkerField` (complexity ratchet).
- Instrumented points: `src/core/PluginFactory.cpp` `loadPluginDescriptor` (phase `scan`, the dlopen) and
  `src/core/Plugin.cpp` `Plugin::instantiate` (phase `instantiate`, around the module's `lmms_plugin_main`).
  Both run on the loading thread; nothing touches the audio thread.
- `src/core/ControlCommandsSafeStart.cpp`: `safestart.get_state` gains `crash_suspect` and `offer.quarantine`
  (`accept_with` = `plugin.scan_cache_quarantine_add`, with `accept_args`).
- `src/gui/PluginQuarantineMenu.cpp` / `include/PluginQuarantineMenu.h`: `offerCrashQuarantine()` (one prompt, yes
  calls the registered `plugin.scan_cache_quarantine_add`), `setCrashQuarantineAsker()` for tests.
- `src/core/main.cpp`: `offerCrashQuarantineIfNamed(bool)`: GUI start prompts once; headless/unattended start prints one stderr line.
- `docs/KNOWN-LIMITATIONS.md`: update bullet after the safe-start entry.
- POSIX-only code stays in tests (`SafeStartTest` fork/exec, already `#ifndef Q_OS_WIN`); product code is Qt-only.

## Known limits
- Instrumented: the in-process LMMS module scan and instantiation. Not instrumented: LADSPA's constructor-time scan
  (it runs before the session begins), out-of-process hosts, VST3/CLAP editor opens. A crash there still gives
  safe-start with no suspect.
- No test loads a real crashing shared library; the crash is a real signal raised inside the instrumented scope
  over a test-local plug-in path (a placeholder file), because the instrumentation, not dlopen, is what is proven.
- The GUI prompt in `main.cpp` is not exercised by a screenshot or interactive run (offscreen tests only).
