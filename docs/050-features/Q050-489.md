# Q050-489 — Make session and clip state transitions preserve shared invariants

Unit (L02, owner-approved 2026-10-25, HS-004): launch, stop, edit, record, undo and reload transitions leave the
launcher, the arrangement and the project model mutually consistent. Branch `feat/050-Q050-489-oc`, cut from
`050/m0-train-18` (`7641e9493`).

Not counted as fixes (stated, not changed):
- **Columns are track positions.** Moving or deleting a non-pattern track does not move the grid's columns
  (`Song.cpp:660`; `docs/KNOWN-LIMITATIONS.md`, sub-scenes). Changing that is a model change outside this unit.
- **`track.move` does not swap pattern numbers** (the GUI's move does, `TrackContainerView.cpp:256`); the cells follow
  the numbers either way, so they stay consistent with the pattern store.
- **Undo of a pattern-track deletion** restores the track as a NEW pattern number (`ControlStructuralSupport.cpp`,
  existing behaviour). Since round 2 the same undo step also puts back the cells the deletion emptied, pointing at that
  new number (`sessionCellsOfPatternTrack` / `restoreSessionPatternCells`, `SessionTransitions.cpp`).
- **Follow plans armed on a cleared cell** stay armed (arming is engine state set by `session.follow_set`, not project
  state); a launch of the empty cell is refused by `launch_slot` as before.

## Stage two: the one common boundary

`syncSessionLauncher(scheduler, before, after)` — `src/core/SessionTransitions.cpp:63`, declared in
`include/SessionPlayback.h`. For each cell whose rendered content differs (`sameSessionContent`, `:54`) it publishes the
new content (`publishSessionCell`, `src/core/SessionPlayback.cpp:204`, extracted unchanged from
`publishSessionSlotContent`, `:228`), and a cell that held a clip and holds none is stopped exactly as
`session.stop_slot` stops it. Launch settings, chains and scenes are untouched (read at the next launch, as before).

Used by every route that changes the grid, GUI and agent alike (the grid's menus, drops and Undo all go through the
same registered commands):
- `recordSessionEdit` in `src/core/ControlCommandsSession.cpp:91,100` (set_grid, set_quantisation, set_scene, set_slot,
  clear_slot, clear) and in `src/core/ControlCommandsSessionShared.h:464` (capture_scene, set_playlist, sub-scenes):
  the edit, its undo and its redo (`restoreSessionBlockAndSync`, `:454`);
- `capture_to_slot` build/unbuild (`ControlCommandsSessionCapture.cpp:102,108`) and a landed audio take and its undo
  (`ControlCommandsSessionAudioRecord.cpp:219,241`);
- pattern renumbering: `SessionModel::patternRemoved` / `patternsSwapped` (`SessionTransitions.cpp:87,101`), called
  from `PatternTrack`'s destructor and `swapPatternTracks` (`src/tracks/PatternTrack.cpp:105,276`).
  `Song::clearProject` now empties the grid before deleting tracks (`src/core/Song.cpp:1736`), so a closing project or
  a snapshot reload is not rewritten track by track.

T4's fix is in the scheduler itself: each queued command carries the reset generation it was queued in
(`include/SessionScheduler.h`, `Command::generation`). Round 2: `drainCommands` judges a command AFTER popping it - any
reset requested by then is carried out first (clock caught up as the period's start would set it), then the command is
applied only if no reset came after it was queued - so there is no window between a check and the pop.

Round 2 also bounds the boundary by the queue: `syncSessionLauncher` counts the commands it needs and, if the queue
cannot take them now (`SessionScheduler::commandQueueSpace`), stops the whole launcher with one atomic reset.

**Realtime.** All of the boundary runs on the model thread; the engine sees only lock-free queue pushes of POD
commands (the existing `CommandQueue`). The one audio-thread change is in `drainCommands`: one relaxed-to-acquire atomic
load and an integer compare per command - no allocation, lock, wait, I/O or signal
(`SessionSchedulerTest::audioThreadPathDoesNotAllocate` still passes). TSan does not run on this box: the reasoning is
that the generation is written only by `reset()` (an atomic increment) and read with acquire on both sides, and a
command's tag is fixed before its release-store into the queue.

## Commands and formats

No new command. `session.set_slot`, `clear_slot`, `set_grid` and `clear` descriptions now say what happens to a
playing cell (snapshot regenerated live, 867 ids / 76 groups). Reversibility classes unchanged (each is one journal
step, as before). No project-format change: the saved grid is unchanged, and a project loads and renders as before.

## Known limits

- A single edit that needs more commands than the launch queue can take right now (256 at most; e.g. a clear of over
  ~128 filled cells) stops the WHOLE launcher at once, as `session.stop_all`, instead of leaving any removed cell
  playing; the next launch publishes the grid again.
- An emptied cell stops at its launch quantisation (as `session.stop_slot`), so a cell launched on a bar grid falls
  silent at once (its content is gone) but frees its track at the next line.
- The four items under "Not counted as fixes" above.
