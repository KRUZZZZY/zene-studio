# Q050-486 - Validate and own saved plugin waveform data through one shared loader (P0, fix, L10)

**Unit.** Malformed or truncated saved waveform data cannot trigger an out-of-bounds read, leak overwritten decoded
buffers, or introduce nonfinite samples; valid existing presets keep identical data and audio.

**What the code did before (base `639e1d23e`).** Eight plug-ins save drawn graphs as base64 float arrays. The templated
`base64::decode` (`include/base64.h:44`) allocated `new T[size/sizeof(T)]` from whatever the attribute held, and most
callers passed the result to `graphModel::setSamples(const float*)` (`src/gui/widgets/Graph.cpp:527`), which copies
`length()` values with no source length:

| Caller (base line) | Defect reproduced on the base build (ASan, `GraphWaveformLoadTest`) |
| --- | --- |
| `plugins/Watsyn/Watsyn.cpp:589` | heap-buffer-overflow, READ of 880 bytes from a 0-byte/876-byte buffer; three of four decoded buffers leaked per load (LeakSanitizer: three direct leaks of 44000 bytes in 50 objects over 50 valid loads) |
| `plugins/MultitapEcho/MultitapEchoControls.cpp:90` | heap-buffer-overflow, READ of 64 bytes from a truncated `ampsteps`; by reading the code, the `ampsteps` buffer leaked on every load (the leak run stops at Watsyn, the first plug-in it checks, so this leak was not separately measured) |
| `plugins/WaveShaper/WaveShaperControls.cpp:78` | heap-buffer-overflow, READ of 800 bytes (empty, absent or truncated `waveShape`) |
| `plugins/FreeBoy/FreeBoy.cpp:282` | heap-buffer-overflow, READ of 128 bytes (owned buffer, but no size check) |
| `plugins/Vibed/Vibed.cpp:202` | heap-buffer-overflow (only a debug `assert` guarded the 128-value copy) |
| `plugins/BitInvader/BitInvader.cpp:191` | heap-buffer-overflow on an empty payload; a huge payload resized the graph without bound |
| `plugins/Xpressive/Xpressive.cpp:184` | size-checked already; NaN/infinity were zeroed and loaded, nothing was reported |
| `plugins/DynamicsProcessor/DynamicsProcessorControls.cpp:87` | size-checked already (restores its default); NaN/infinity loaded, nothing was reported |

Q050-477's old-project corpus is not on this train (its commits are not ancestors of the base), so the bundled
`data/presets` and `data/projects` corpus is the compatibility set here (139 graphs of these plug-ins).

| Piece | Where |

**Malformed-data policy (documented in `include/WaveformData.h` and the manual).** A present but damaged graph is not
used: the graph keeps what it had (a freshly loaded device keeps its default; DynamicsProcessor restores its default
curve, as it already did) and one line is reported: `<Device>: the saved waveform "<attribute>" was not loaded
(<reason>); the current or default waveform is kept`. An absent or empty attribute is an older writer's file: kept
silently. BitInvader accepts exactly `sampleLength` values (older writers, e.g. the bundled presets with 8-128) or
`wavetableSize` (200, this writer); its valid-load sequence (clear at the previous length, copy, set `sampleLength`) is
unchanged. Behaviour change: Xpressive no longer zeroes NaN/infinity inside an otherwise loaded wave - it refuses the
whole wave under the shared policy (`PluginPortsMigrationTest::xpressiveLoadedWaveSamplesAreFinite` still holds).

## Commands, format, undo

No new command; no command schema, snapshot or reversibility row changes. The change is inside each device's
`loadSettings`, so every existing path that restores a device's saved XML goes through it - proven here for the
device's own editor in the GUI (`GraphWaveformEditorGuiTest`: the Wave Shaper editor restored from saved XML) and for the
agent's `project.open` (`ControlGraphWaveformLoad`). In the GUI the diagnostic appears in the existing load error report
box `Song::loadProject` shows after opening (`src/core/Song.cpp`, `hasErrors()`). Undo behaviour is untouched. The saved format is
unchanged (the writers were not touched).

## Known limits

- The ASan/LSan proofs run on Linux GCC/Clang; elsewhere the same tests run without the sanitizer (the behavioural
  checks still apply, the leak case skips).
- On this box the engine needs `ASAN_OPTIONS=use_sigaltstack=0` (a loaded library replaces a thread's alternate signal
  stack, which ASan then fails to unmap); the test sets it in `__asan_default_options` and in its ctest environment.
- Out-of-range but finite values (e.g. a FreeBoy step of 20) are loaded as before: the shared policy validates
  structure and finiteness, not each device's value range (outside the brief).
- `Jousboxx-BuzzerBeater.mmpz` and `Greippi - Krem Kaakkuja (Second Flight Remix).mmpz` (the demos with Wave Shaper and
  Dynamics Processor) abort with `std::bad_alloc` in the CLI render in this worktree on BOTH the base and the fixed
  build (exit 134 each), so their render comparison is not available here; their graphs are covered by
  `bundledPresetsRoundTripExactly`.
- TSan does not run on this box. Nothing here adds threading: every changed function runs in `loadSettings` on the
  loading (main) thread.
