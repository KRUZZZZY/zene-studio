# Q050-231.2 - Apply masking proposals (stage 2 of 3, L08, R-mixing-7)

**Unit.** `mixer.apply_masking_proposal` writes one clash's proposed cut (stage 1's `strip_eq`) to the target
channel's strip EQ as a single undo step. It is the bridge between the read-only report and stage 3's full musician
workflow: the proposal already carries the exact `mixer.channel_eq` arguments, so applying it is one call and one
undo.

## What it does

- **Command.** `mixer.apply_masking_proposal` takes `{strip_eq: object}`, the `strip_eq` object of one clash from
  `mixer.masking_report`. It is `mutating: true` and classed **TrueInverse**
  (`src/core/ControlReversibilityTableDevices.cpp`).
- **Same edit path as `mixer.channel_eq`.** It shares `control::applyChannelEq`
  (`src/core/ControlCommandsMixerTools.cpp`, declared in `include/ControlMixerSupport.h`) with `mixer.channel_eq`,
  so key handling, clamping and the undo rule are identical. The low/high shelf or the mid bell is written; the
  values are absolute, not deltas.
- **Reply.** The `channel_eq` reply plus `applied` (a boolean: true when the write changed the EQ, false for a no-op
  proposal that records no step) and `before` (the four EQ values read before the write).
- **One undo step.** The whole write is one journal checkpoint: one `Undo` (Ctrl+Z) puts every value back. A no-op
  proposal (values already equal to the current ones) records no step.
- **Validation** (`InvalidArgs`): `strip_eq` missing or not an object; unknown key; none of `low`/`mid`/`high`;
  `mid_freq` without `mid`; a non-number; `low`/`mid`/`high` outside -18..18; `mid_freq` outside 100..10000;
  a malformed channel id. `NotFound`: a well-formed but unknown channel. A refused proposal writes nothing.
- **GUI.** Mixer View > Masking Report... gained an **Apply** button (accessible name `Apply proposal`,
  `controlCommand` property `mixer.apply_masking_proposal`; `src/gui/MixerMaskingReport.cpp`). It is disabled while
  no clash row is selected, applies the selected row, and refreshes the report afterwards. Ctrl+Z in the GUI goes
  through `MainWindow::undo` -> `projectJournal()->undo()`, the same journal as `control.undo`.
- **Snapshot.** Regenerated live: 933 ids / 78 groups. The A16 histogram line now reads
  `rows=942 true_inverse=465 snapshot=42 irreversible=25 not_mutating=410`.

## Realtime and threads

The handler runs on the control (main) thread and writes only EQ `FloatModel` values, exactly as `mixer.channel_eq`
already does. No audio-thread code was added, no mixer period buffer is touched, and the undo checkpoint is taken in
the handler. Local TSan is not available on this box, so the race argument is by design only.

## Known limits

- A stale proposal sets absolute values: it does not re-read the report, so applying an old row overwrites with the
  values recorded when it was produced.
- Two proposals for the same target's mid band overwrite each other (last applied wins; each is its own undo step).
- Applying is one clash at a time; the full workflow (stage 3) remains.
