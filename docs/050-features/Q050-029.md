# Q050-029 - Reject invalid remote knob indices

Type: fix (P0, size S). Member: R-workflow-12. Area: L15.

## What was built
- `src/core/RemoteControls.cpp:139` `RemoteControls::applyKnob` now validates `knob` against `0..Knobs-1`
  (`:142`) *before* it computes the paged model index. The index is accumulated in `qlonglong`
  (`:143`), is checked for both bounds (`:144`) and only then narrowed for `models.at` (`:145`). A
  negative, first-invalid or extreme `int` knob therefore returns `false` and touches no model, and
  the old signed-`int` overflow `pageOffset * Knobs + knob` cannot happen.
- `src/core/RemoteControls.cpp:163` `sendPage()` and `:177` `state()` use the same wide-index
  arithmetic so the one paged-index rule is not duplicated with a narrower type in the two readers.
- `tests/src/core/DeviceCopyTest.cpp:470` `remoteKnobsDriveAPageOfParameters` was rewritten to use a
  deterministic multi-page device (a test-only `Effect` with synthetic controls, `:149` `:167`)
  instead of whatever first effect a build happens to load, and to exercise the malformed path.

## Known limits
- The sanitizer evidence is a partial-instrumentation build (only `RemoteControls.cpp` is
  instrumented, the rest of the test links normally), which is sufficient for this path: the hanging
  UBSan diagnostic names `RemoteControls::applyKnob` itself. At `-O2` the pre-fix overflow is
  optimized away (the compiler drops the unused computation once the `knob` guard short-circuits),
  so the discriminating pre-fix run is done at `-O0`; the command lines are kept under
  `logs/san/`.
- Local TSan does not run on this box (runtime crash at thread creation, per the lane brief);
  `applyKnob` runs on the UI thread (`MidiSurfaceInput::drain`), so no audio-thread race is
  introduced and nothing here allocates, locks or does I/O on the audio thread.

## Round 5 (Sonnet lane, 2026-10-18): all 24 controls, every malformed request

already have changed another, and the page-1 `INT_MAX` check looked at page 1 only.
