# Q050-062.3 Stem-separation quality, stage 3/4: measure real-model quality and time

**Unit.** R-ai-2, R-performance-55, R-workflow-102 (`L05`). The record holds comparable SDR and
processing-time results for each quality setting of Q050-062.1 (`fast` / `standard` / `high`, the
segment overlap). They were measured on the pinned real HTDemucs model against a fixed reference set
with aligned source stems.

## Result

Mean over four 30 s MUSDB18-HQ test excerpts, global SDR (higher is better), two identical passes:

| quality | overlap | model passes per 30 s | mean SDR | vs standard | time vs standard (median per-run ratio) |
| --- | --- | --- | --- | --- | --- |
| `fast` | 25 % | 8 | 7.613 dB | -0.111 dB | 0.64x |
| `standard` | 50 % | 11 | 7.723 dB | 0 | 1.00x |
| `high` | 75 % | 22 | 7.768 dB | +0.045 dB | 2.01x |

`high` was not better on every excerpt: on *Tom McKenzie - Directions* it scored 0.012 dB below
`standard`. Per-stem and per-excerpt SDR, every run's time and load, the hardware and the exact
commands are in `doc/STEM-SPLIT.md` "End-to-end §5". The machine-readable record of the run is
`docs/050-features/Q050-062.3-bench.md`.

## Known limits

- **Contended timing.** The run was inside the fix loop's cgroup (CPU quota 4 CPUs, shared with other
  lanes' builds), so the absolute times are 2-3x slower than Q050-131's lightly loaded figures (§4).
  The per-setting ratios and the deterministic pass counts are the comparable figures; the doc says so.
- **Small reference set.** Four 30 s excerpts. The differences between settings (≤ 0.23 dB per
  excerpt) are far smaller than the differences between excerpts, and no significance test was run.
  The SDR is the MDX global SDR, not BSSEval v4.
- **One backend measured.** The real-model run used the external-process path (the GUI's). The
  in-process ONNX backend uses the same hop formula (`stemHopFrames`, proven equal in Q050-062.1's
  tests), but it was not run on the real model.
- **Data licence.** MUSDB18-HQ is for non-commercial research use. The tool downloads it to a scratch
  directory; no audio is committed, only hashes.
- `StemQualityBench` does not exercise `fetch` (ctest stays hermetic, with nothing leaving loopback). `fetch` was
  exercised for real twice, as recorded above.
