# Q050-343 - Document the sample generator menu route

Type: docs (P2, size S). Member: B-MX-141. Area: L08.

## What was built

The route already existed and was described as if it did not. `src/gui/shell/ShellCommandMenus.cpp`
adds **Insert Test Signal...** to a **SampleTrack**'s `populateTrack` menu (so the track header's
**More** menu and the Inspector's **More** menu both carry it), wired to `sample.generate` with that
track fixed and defaults position `0`, length `192` and kind `tone`; `ask=true` opens the shared
command form (`src/gui/shell/ShellMenuParts.cpp`). What was stale was the help a user and an agent
read:

- `src/core/ControlCommandsSample.cpp` - the `sample.generate` description no longer says
  "Socket-only in this release: no interface reaches this verb". It now names both routes: a sample
  track's **More** menu (the track header's and the Inspector's) as **Insert Test Signal...**, which
  opens this command's form with that track fixed and position `0`, length `192` and kind `tone`
  pre-filled, AND the control socket / MCP / script path. It still describes a generated buffer in a
  NEW clip, never a live signal-generator device. The file's header comment says the same.
- `src/core/ControlCommandsSampleEdit.cpp` - the four bakers (`sample.amplify`, `sample.normalize`,
  `sample.reverse`, `sample.fade`) carried the same stale claim; they are offered by a sample clip's
  **Process** menu, so their descriptions and the file comment now say so, and the file comment no
  longer denies a menu entry.
- `src/core/ControlRegistryRegistrations.cpp`, `include/ControlRegistryGroups.h` - the registration
  comment and the group's declaration comment said "no interface reaches them yet"/"Socket-only this
  release"; both now name the menus.
- `docs/KNOWN-LIMITATIONS.md` - the `sample.*` section's heading and first paragraph said
  "socket-only, no interface" and "no interface reaches any of them ... there is no waveform view, no
  menu entry, no toolbar button". Rewritten: every id has its menu entry (track **More > Insert Test
  Signal...** for the generator, clip **Process** for the bakers), the remaining absence is a
  waveform view that shows a bake in place and any placement beyond those two menus (still the open
  owner decision, board card #706 question 4). Every other bound in the section (whole-source bakes,
  trimmed-window refusal, no limiter, the engine's undo bound, the deferred verbs) is unchanged.
- `data/manual/index.html` - the Arranging section now describes the route a musician takes: a
  sample track's **More > Insert Test Signal...** opens the command's form with that track set and a
  tone at position 0 / length 192, Run makes the clip in one undo step, and a sample clip's
  **Process** menu has Normalize, Amplify, Reverse and Fade. The same command is what a script or an
  agent calls.
- The command id, its schemas, its handler, the menu, the menu defaults and the `true_inverse`
  reversibility row are UNCHANGED. This unit is text only.

None. `sample.generate` keeps its id, its args/result schemas, its `mutating` flag and its

  recorded in `design/specs/DECISION-706-DESTRUCTION-MODEL.md`; this unit took no decision.

  in this worktree (`git ls-files research` is empty), so the older "socket-only" classification and
  proposed labels they carry were not editable here; the product surfaces (help, snapshot, manual,
  known limitations) are the ones this unit corrects.
