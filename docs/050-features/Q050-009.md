# Q050-009 - Preset-based range and section export in the GUI

Unit: P0, size L, area L12 (projects, files, import/export, interchange, recovery). Branch
`feat/050-Q050-009-oc`, base `050/m0-train-5` (`de5a85a96`).

Goal: choose render presets in the export dialog, render a selected range, and export named
sections as separate files.

## What was built

- **Render presets in the export dialog.** `include/ExportProjectDialog.h` and
  `src/gui/modals/ExportProjectDialog.cpp` gain a "Render preset" picker above the settings rows.
  It lists Default Settings and every stored preset (`export.preset_list`), selects the applied one
  and shows its settings (`showPresetSettings`, `ExportProjectDialog.cpp:407`); choosing one applies
  it (`export.preset_apply`, `:428`) and moves the rate/bit-depth/stereo rows; **Save Preset...**
  stores the rows the dialog holds (`export.preset_add`, `onSavePresetClicked`, `:438`). Saving
  writes ONE document and does NOT apply it: the picker gains the name, but the applied selection
  and the settings rows stay where the user left them, so one click is one undoable action (the
  store write) rather than two (a store write plus an apply). The
  settings Start would export with are now built by one accessor, `exportSettings()` (`:354`), which
  `onStartButtonClicked` (`:473`) also uses, so the dialog's own render and the preset store cannot
  disagree. A test seam, `setExportPresetNamePrompt` (`:68`), supplies the Save-Preset name without
  a modal.
- **Render Selection from the range menu.** New fork source `src/gui/RenderRangeMenu.cpp` (header
  `include/RenderRangeMenu.h`) adds two actions to Navigate ▸ Range (`MenuBarExtras.cpp:140`):
  **Render Selection...** (`renderSelection`, `:85`) reads `range.get` and invokes `render.render`
  with the range's exact `start_ticks`/`end_ticks` to a picked file, and **Export Sections...**
  (`exportSections`, `:115`) invokes `render.sections` into a picked directory. Both declare their
  command in the `controlCommand` property (`:136`), so the menu item and the socket reach the same
  implementation (the `agent_surface` gate passes).
- **`render.sections`, the batch section export.** New fork source
  `src/core/ControlCommandsRenderSections.cpp` (`:163`): every named section (`section.add`) is
  rendered to its OWN file, named after the section (sanitised, made unique -
  `sectionFileStem`, `:77`), bounded to the section's own ticks. Each file goes through the existing
  `render.render` (with `start_ticks`/`end_ticks`), so the export settings in force reach every
  file and there is no second renderer. Registered in
  `ControlRegistryRegistrations.cpp:206`; declared in `ControlRegistry.h`.
- **Stem export follows the selected rate and bit depth.** `ControlCommandsRenderStems.cpp` now
  reads `ControlExportPresetSettings::effective()` (`:148`) and starts the `exportstems` child with
  `controlExportPresetRenderArgs` (`:158`) instead of a hardcoded `-s 44100`; the reply names the
  `sample_rate`, `bit_depth`, `stereo_mode` and `applied_preset`. With no preset applied the
  arguments are the single `-s 44100` they always were, so an un-applied export is byte-identical.

## Known limits

- `render.sections` and Render Selection run each render in a child process and keep the declared
  bound (the dispatch thread does not answer until each finishes, once per section); see
  `docs/RENDER-CHILD-WAIT.md` and the rows' own descriptions.
- A preset still carries the three settings only (rate, bit depth, stereo mode); the stereo mode is
  read only by the MP3 encoder, so a WAV export stores but is unaffected by it.
- The export dialog's picker lists presets and saves the settings the dialog holds; it does not
  delete or rename them (File ▸ Render Presets does).

## Round 3 (Sonnet lane, 2026-10-19)

Luna review r2 (REWORK): section file names were made unique with a case-sensitive set, so `Intro` and `intro` collided on
case-insensitive filesystems, and Windows-reserved names and trailing dots/spaces made no valid file.

- `src/core/ControlCommandsRenderSections.cpp`: names are now portable on every platform (no host-OS branch).
  `isWindowsReservedStem` (CON, PRN, AUX, NUL, COM1-9, LPT1-9, any case, with or without an extension) and
  `sectionFileStem` (helpers `cleanedSectionName`, `withoutTrailingDotsAndSpaces`, split to keep CCN under target; a trailing run of dots/spaces becomes one `_`; a reserved base gets `_` appended to the base:
  `CON` -> `CON_`, `nul.mix` -> `nul_.mix`); `sectionFileKey` (NFC-normalised, case-folded) is the key
  `sectionFileStems` compares, so `intro` after `Intro` becomes `intro-2` (a name that differs only by case never overwrites).
- `tests/control-render-sections.py` (`check_portable_names`): adds sections `intro`, `CON` and `Coda. ` and exports all five;
  asserts the exact file set `CON_.wav`, `Coda_.wav`, `Intro.wav`, `Verse.wav`, `intro-2.wav`, no two names equal after
  lower-casing, the reply's per-section `start_ticks`/`end_ticks`/file name, and each file's frame count bounded to its own
  ticks. The old code would have written `intro.wav` over `Intro.wav` on a case-insensitive disk and a `CON.wav` Windows cannot create.
  `SECTIONS_TIMEOUT` grew to five section children.
