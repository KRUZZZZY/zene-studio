# Q050-294.1 - Melodic step-sequencer view, stage 1/3: scriptable melodic step state (P2, L, L07)

Goal: expose scale-aware step state and reversible per-step pitch, velocity, chance and ratchet edits
on ordinary MIDI clips. Stage 2 (the grid editor) and stage 3 (seeded shape and random fills) are
separate units and are NOT built here.

## What was built

- `src/core/ControlCommandsNoteStep.cpp` - two commands in the `note` group:
  - `note.step_get_state {clip, step_ticks?, root?, scale?}` (`not_mutating`): the clip as a step grid.
    Every note with `step`, `offset`, `position`, `length`, `key`, `pitch_class`, `velocity`, `chance`,
    `ratchet`, `muted`, `in_scale` (null when no scale is set) and `scale_degree` (0 when out of scale);
    the occupied `columns` with each step's note ids and pitches; the `scale` block read against.
  - `note.step_set {clip, edits, step_ticks?, scale_mode?, root?, scale?}` (`true_inverse`): a batch of cell
    edits, validated whole first, then ONE MidiClip checkpoint. An edit names a note (`note`) or a cell
    (`step` + `key`) and gives `velocity` (0..200), `chance` (0..1), `ratchet` (1..16), `length`, `key`
    (note-addressed: the new pitch) or `remove`. An empty cell gets a new note (one step long, velocity 100,
    chance 1, ratchet 1 unless given). `scale_mode` snap (default; nearest in-scale key, tie down), strict
    (refused) or off applies to the pitches the call WRITES only: a note left on its key stays, so
    out-of-scale notes remain editable. A batch that changes nothing records no undo step.
- The step view stores nothing of its own. The cells are the clip's ordinary notes, and the three settings are
  fields the engine already saved and played: velocity = `Note::getVolume`, chance = `Note::probability`
  (optional `prob` attribute, rolled by `InstrumentTrack::notePlaysNow`), ratchet = `NoteConditions::repeats + 1`
  (optional `rep` attribute, played as evenly spaced hits by `InstrumentTrack::triggerNote`).
  `note.list`, `roll.get_state` and the piano roll therefore show exactly the same notes.
- `NoteTransform::snapKeyToScale` (include/NoteTransform.h): the nearest in-scale key for one key, the rule
  `snapToScale` already applied per note.
- Reversibility table: `note.step_set` `true_inverse`, `note.step_get_state` `not_mutating`; the A16 histogram
  in `docs/RELEASE-NOTES-v0.3.0-alpha.md` is re-taken (889 / 435 / 42 / 25 / 387). Snapshot regenerated live:
  880 ids / 77 groups; the README canary follows. The manual's "Editing notes" section describes both commands.

## Commands, format, limits

- New commands: `note.step_get_state`, `note.step_set`. No new group.
- Project format: unchanged. Chance and ratchet use the existing optional `prob` and `rep` note attributes.
- Realtime: both commands run on the control thread only; nothing on the audio path changed. Local TSan does
  not run on this box; the commands touch the clip exactly as `note.add_many` and `note.edit` do.
- GUI: stage 1 has no editor. The grid editor (stage 2) is to drive these same two commands.
- Limits: ratchet is capped at 16 attacks (the engine's repeats bound is 16 extra hits); a new cell is one step
  long unless `length` is given; a ratchet cannot be larger than the note has frames for (the engine shortens
  it); the scale context from `scale.set` is process state, so a caller that needs a fixed scale passes
  `root` / `scale`.
