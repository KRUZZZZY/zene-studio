# Q050-294.2 - Melodic step-sequencer view, stage 2/3: melodic step-grid editor (P2, L, L07)

Goal: let musicians open a MIDI clip in a grid and edit its notes through the same registered commands
agents use. Stage 1 (Q050-294.1, `note.step_get_state` / `note.step_set`) is the command half this
builds on; stage 3 (seeded shape and random fills) is a separate unit and is NOT built here.

## What was built

- `StepGridPanel` (include/StepGridPanel.h, src/gui/noteeditor/StepGridPanel.cpp) and `StepGridCanvas` /
  `ScaleKeySpinBox` (src/gui/noteeditor/StepGridCanvas.cpp): a non-modal window over one MIDI clip.
  - Columns are steps of the Step box's resolution (1/32, 1/16 triplet, 1/16 default, 1/8, 1/4); rows are keys,
    two octaves from the lowest note's C (C4 for an empty clip) widened to every note, highest first.
  - The Scale box reads the clip against the project key (default; `scale.set`), no scale, or a named scale
    on a chosen key - passed as `root` / `scale` on each call, never written to the project's scale context.
    Out-of-scale rows are shaded; Scale rows only hides empty out-of-scale rows but never a row that holds a note.
  - Left click on an empty cell adds a note (one `note.step_set {step, key}`; the command snaps an
    out-of-scale pitch into the scale) and selects it; left click on a note selects it; right click removes it.
  - The inspector edits the selected note: Pitch (a `ScaleKeySpinBox`: its arrows step through the
    scale's keys, so a step never lands on a key the command would snap straight back), Velocity 0..200,
    Chance 0..100 % (sent as 0..1), Ratchet 1..16, Remove. Fields commit on Return / arrow (keyboard tracking
    off), so a typed "150" is one edit.
  - The panel has NO model of its own: everything it paints is the last `note.step_get_state` answer, and
    it re-reads on the clip's `dataChanged`, so an agent's command, a piano-roll edit and an undo show at
    once. The selection is kept by note id across a re-read (an undo reloads the notes with their ids).
- `window.step_grid {clip?, step_ticks?, scale?, root?, scale_rows_only?}` (src/gui/ControlCommandsStepGrid.cpp,
  `not_mutating`): opens or re-targets the one grid window and answers the grid's own state - `clip`,
  `step_ticks`, `steps`, `rows`, `cells` (each note's id, step, key, velocity, chance, ratchet, length,
  in_scale), `scale`, `scale_choice`, `scale_rows_only`, `selected`. With no `clip` it takes the shell's
  selected MIDI clip, then the control surface's, then the grid's own. It needs a widget application; the
  main window, when there is one, parents the grid.
- Entry points, all dispatching `window.step_grid`: Edit > Step Grid... (src/gui/MainWindow.cpp) and the note
  editor's Notes > Tools > Open in Step Grid (src/gui/noteeditor/NoteEditorMenus.cpp). The grid's controls
  declare `note.step_set` (`controlCommand` property).
- Reversibility table: `window.step_grid` `not_mutating` (src/core/ControlReversibilityTableShell.cpp); A16
  histogram re-taken (934 = 459 / 42 / 25 / 408). Snapshot regenerated live: 925 ids / 78 groups; README canary
  follows. The manual's "Editing notes" section has a Step Grid paragraph.

## Commands, format, limits

- New command: `window.step_grid` (`not_mutating`). No new group. The grid's edits are the existing
  `note.step_set` (`true_inverse`, one MidiClip checkpoint per call) and its reads `note.step_get_state`.
- Project format: unchanged. The grid stores nothing; its resolution, scale choice and row filter are interface
  state and are not saved.
- Realtime: GUI-thread only (paint, mouse, spin boxes, a registry call per gesture); nothing on the audio path
  changed. Local TSan does not run on this box; the grid touches the clip only through `note.step_set`, which
  edits it exactly as `note.edit` does.
- Limits: one grid window (a second `window.step_grid` re-targets it); a note with an offset inside a step is
  shown in that step's cell, and a click there selects it rather than adding a second note; two notes with the same
  key in one step show as one cell (the first); deleting the clip empties the grid (an undo of the deletion does not
  re-open it); the rows span two octaves widened to the notes - a key outside them is reached through the Pitch field;
  live step input, hardware mapping and fills (stage 3) are not built.
