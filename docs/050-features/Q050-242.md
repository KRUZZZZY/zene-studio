# Q050-242 — Pattern recurrence controls

Unit (L07, P2, completion, M), item `R-editing-60`. Branch `feat/050-Q050-242-oc`, cut from
`050/m0-train-24` (`2a7fd9f9c7`). Goal: "Set the recurrence length and pass mask from the note
editor so notes can repeat predictably across clip passes."

The recurrence algorithm (`NoteConditions::recursOnPass`, length 0 → every pass, else bit
`pass % length`), the optional `recl`/`recm` note attributes, `note.edit`'s
`recur_length`/`recur_mask` fields with their inverse capture, and the playback gate
(`InstrumentTrack::notePlaysNow` → `recursOnPass(MidiPlayback::pass())`) already existed. What
was missing is the editor surface and the agent-visible readback: the properties box had no
recurrence controls, `roll.get_state`'s `noteState` carried no such fields, and nothing tested
recurrence through a locally looped clip.

## Built

- **Editor** — `NotePropertiesDialog` (`src/gui/noteeditor/NoteProperties.cpp`,
  `include/NoteProperties.h`) gains a **Recurrence (passes)** row: a `recur_length` spin box
  (0..16) beside sixteen `recur_pass_1..16` check boxes, one per pass of the pattern, plus a
  one-line hint. The row initializes from `note.conditions()` (`recurLength` / `recurMask`) and
  names its bits the way the model does: check box *n* is pass `n - 1`, i.e. bit `n - 1`
  (`NoteConditions::recursOnPass` uses `pass % recurLength`). A positive length shows exactly
  its own passes; 0 (every pass) shows all of them greyed, so a mask can be ticked before a
  length is chosen and a length can be cleared back to neutral. The controls carry accessible
  names/descriptions through `a11y::announce`, like every other field in the box.
- **One command, one undo step** — OK still goes through the existing `note.edit` (the same
  registered command an agent sends), never a private write. `changes()` sends the pair
  **together**: `recur_length` plus the mask the visible boxes spell, cut to the new length. That
  is required, not cosmetic — `note.edit`'s `conditionsAfter()` masks the value to
  `(1 << recurLength) - 1`, so a length-only edit would silently rewrite the mask. At length 0
  the mask is sent as 0, which is what the model stores. No new command and no new
  reversibility row: `note.edit` stays `true_inverse` with its one `MidiClip` checkpoint (its
  rationale text in `src/core/ControlReversibilityTableLive.cpp` now names the recurrence pair
  and why it is captured together).
- **Agent readback** — `control::noteState()` (`src/core/ControlEditSupport.cpp`) now reports
  `recur_length` and `recur_mask` for **every** note, so `roll.get_state` (and every command
  whose reply is built on `noteState`: `note.add`, `note.resize`, `note.velocity_set`,
  `note.probability_set`, `note.slide_set`) publishes what `note.edit` wrote. Each of those
  closed `resultSchema`s declares the two fields
  (`src/core/ControlCommandsNotes.cpp`, `ControlCommandsNoteProbability.cpp`,
  `ControlCommandsNoteSlide.cpp`), so `ZENE_CONTROL_CHECK_RESULTS=1` holds the replies to
  their contract instead of reporting undeclared keys.
- **Playback** — no engine change was needed: `notePlaysNow` already gates each note through
  `recursOnPass(MidiPlayback::pass())`, and `MidiPlayback::pass()` counts a song transport loop
  wrap (`Song::m_loopWraps`) while a seek or a clip's own `loopTicks` fold does not advance it.
  This unit proves that contract for the combination nobody had tested: recurrence *through a
  locally looped clip*.

## Commands, format changes, reversibility

- **No new command.** The editor uses `note.edit` (existing, `true_inverse`, one `MidiClip`
  checkpoint); `roll.get_state` stays `not_mutating`. The only schema change is the two
  recurrence fields added to closed result schemas that already return `noteState` fields.
- **Format:** none. `recl`/`recm` were already optional note attributes written only when
  `recurLength > 0`, and absent/invalid recurrence loads neutral
  (`src/core/NoteConditions.cpp`). Old projects load and render exactly as before; a note with no
  recurrence writes neither attribute.
- **Realtime:** no audio-thread code was touched. The gate already runs in
  `InstrumentTrack::notePlaysNow` (audio thread, under `play()`'s tryLock) reading plain ints
  copied into the note; `noteState` and the dialog run on the UI/control thread only.
- **Snapshot / canaries:** `commands_snapshot.json` regenerated live (878 ids / 77 groups — the
  count is unchanged, only the two result schemas changed); README's canary figure and the A16
  histogram do not move.

## Known limits

- **A pass is a song transport loop wrap.** Seeking does not advance the pattern, and a MIDI
  clip's own loop (`clip.set_loop`) repeats notes within a pass without advancing the mask —
  asserted by `recurrenceSelectsThePassesOfALocallyLoopedClip`. There is no per-clip pass
  counter, and no preview of the pattern on the note itself beyond what the boxes show.
- **The box always sends the pair** when either changes; it cannot send a mask alone, because
  the command cuts the mask to the length. An agent can still send `recur_length` alone (the
  mask is cut to it), which is the documented `note.edit` contract.
- **16 passes is the model's maximum** (`NoteConditions::MaxRecurLength`), and the box exposes
  exactly that many bits.
- The properties box is a dialog, not an inline lane: it reads the note's saved values when it
  opens. A command that changes the same note while the box is open is not reflected in the open
  box (the existing behaviour for every field).
- TSan does not run on this box; the realtime argument is by design (the audio path reads plain
  ints already copied into the note, and this unit adds nothing to it).
