# Q050-155.1 - Discrete mixer buses through 64 channels

Type: completion (P1, size L), stage 1 of 4 of Q050-155. Member: R-mixing-24. Area: L09.

## What was built

- `include/MixerSurround.h`, `src/core/MixerSurround.cpp`: the discrete layouts run from `discrete-2` to
  `discrete-64` (`surround::MaxChannels` is now 64, `Format::Discrete64` the last format, `FormatCount` 69).
  The count is still part of the canonical name, so a native save carries the layout and its count; the
  loader still takes `discrete5` / `discrete 5` / `discrete_5`, and refuses anything outside 2..64.
  The named-layout table only holds stereo .. mono now: a discrete layout's count, name (`discrete-N`), roles
  (`None`) and labels (`1`..`N`) follow from the format.
- Downmix matrices and panner gains stay at the eight-channel named layouts (`surround::MaxSpeakers` = 8). A
  discrete layout never needs either - it is routed by index - so there is no 64 x 64 table. `matrix()` for a
  wider discrete layout returns the identity over the first eight channels (the discrete matrix's rule).
  `panGains()` of a discrete layout is all zeros; the panner never acts on one (`panTakesSend` already refused).
- `src/core/MixerSurroundMix.cpp`: `addSideChannels` routes a send whose sender or receiver is discrete by
  index - side channel i of the sender into side channel i of the receiver, at the send's level and the
  sender's fader, for i < min(sender count, receiver count). A channel the receiver lacks is dropped, never
  folded. `foldInto` returns at once for a discrete layout (a stereo receiver drops its side channels, as
  the discrete matrix always did). The named-layout path is unchanged.
- Side buffer: `ChannelSurround` is still built with six side planes (the 7.1 maximum). `setFormat` grows it
  when a wider discrete layout is set, on the control thread under the change lock (`mixer.channel_format`
  runs `underChangeLock`; a project load sets it in `Mixer::loadSettings`, which also allocates the hardware
  I/O buffers). It never shrinks, so going back to a narrower layout, or the next period, does not allocate.
  `capacity()` reports its width.
- GUI: `Surround > Format` (`src/gui/MixerHardwareMenu.cpp`, also reached from the mixer mode bar's master
  chip) lists every name `mixer.channel_format`'s schema enum advertises. Stereo .. 7.1, Mono and
  discrete-2 .. discrete-8 stay on the menu; discrete-9 .. discrete-64 are grouped in `Discrete 9-16`,
  `Discrete 17-32`, `Discrete 33-48` and `Discrete 49-64`. Every entry runs `mixer.channel_format` through
  `ControlRegistry`, exactly as an agent does. The Surround Panner draws a discrete layout's index strip in
  rows of sixteen (`src/gui/SurroundPanner.cpp`).
- `src/core/SurroundExport.cpp`: the speaker tables are sized for the named layouts; the export tap's side
  planes follow `SideChannels` (now 62), allocated when an export is armed, as before.
- `mixer.channel_format`'s description names the new range; the manual (`data/manual/index.html`, Mixer)
  describes the 2..64 range, the submenus, index routing between discrete channels and the current source
  limit.

## Commands, reversibility and format changes

No new command id. `mixer.channel_format` keeps `true_inverse` and one `AddUndoStep` per edit; its enum now
advertises `discrete-2` .. `discrete-64` (snapshot regenerated live: 878 ids / 77 groups at the original base; re-regenerated live on the 050/m0-train-25 integration: 917 ids / 78 groups, the train's counts, unchanged by this unit).
`mixer.get_state` and `mixer.surround_get` stay `not_mutating`. The project's `<surround format="...">` may now
say `discrete-9` .. `discrete-64`; every existing value, and a missing element (stereo), loads as before.

## Realtime and threads

Nothing new allocates, frees, locks, waits, does I/O or emits a signal on the audio path: the index route is a
loop of multiply-adds over the channels' existing planes. The only allocation is the side buffer's growth inside
`setFormat`, on the control thread, under the engine's change lock (no worker or render reads the buffer meanwhile).
Local TSan does not run on this box; the argument above is the race analysis.

## Known limits (left to the later Q050-155 stages)

- Sources: a track or a device still feeds a mixer channel its first pair only (`AudioBusHandle` is one stereo
  pair, device pins are not wired to side planes). A discrete bus's extra channels today come from another
  surround or discrete channel's send. Stage 2 carries device pins and track routes through 64 channels.
- One send level per mixer route for all channels; per-pair sends and their Routing Matrix editing are stages 3-4.
- A discrete layout's side channels get no delay compensation, devices, meters or post-fader inserts - the same
  limits every surround side channel already has (MixerSurroundMix.cpp header).
- A discrete-64 master's 64-channel WAV export goes through the existing generic tap and writer; it was not
  measured by a separate test in this unit.
