# Q050-146 - Keep wide and stereo capture blocks aligned

Unit: P1, S, fix (area L03). Goal: wide-channel routes and their stereo-bus view use the same captured
frames without skew.

Starting claim, reproduced on the unit's base (`050/m0-train-8`): `AudioDevice::publishCaptured`
(`src/core/audio/AudioDevice.cpp`) pushes one captured block to the N-channel stage
(`pushInputFramesWide`) and then to the stereo ring (`pushInputFrames`); the render thread drained the
two rings one after the other in `swapBuffers()`. A period that landed between the two pushes took the
block from the wide ring only: "stereo bus holds 64 frames, wide stage 128" - the stereo bus (monitoring,
the stereo recorder path, the retrospective capture) ran one block behind the wide routes' channels.

## Integration onto `050/m0-train-16` (round 5)

The accepted patch (`feat/050-Q050-146-oc` @ `a06112903`, built on train 8) fixed this with a seqlock:
`AudioEngine::beginInputPublish()` / `endInputPublish()` bracketed the two pushes and
`drainInputStages()` deferred a period that overlapped a publication.

While the unit waited, the line merged an independent fix of the **same defect**: cluster 3705
(`9102db166` "the wide block and the stereo pair are one capture block", `dea6dbab9` "bound wide drain to
its snapshot"). On the line:

- `AudioEngine::drainCaptureStages()` (`src/core/AudioEngine.cpp:840`) drains the two stages as ONE block:
  `min(wideStaged, stereoStaged)` frames from each once the capture path uses the wide stage
  (`m_captureWideInUse`), so a block whose stereo pair is not published yet waits for it.
- `AudioDevice::publishCaptured` publishes the stereo pair for exactly the frames the wide stage took and
  publishes a block the wide stage refuses to neither path.

Both designs prevent the same interleaving; the conflict in `AudioEngine.h/.cpp`, `AudioWideInputStage.h/.cpp`
and `AudioDevice.cpp` is between them. Layering the seqlock on top would add a second gate for the same
property and would only make it worse in one respect: it defers a block that is already complete in both
rings (block A in the schedule test) by a period whenever a render collides with the next publication,
where the 3705 drain delivers it. So the integration **keeps the line's 3705 mechanism and drops the
now-redundant seqlock** (no `beginInputPublish`/`endInputPublish`/`drainInputStages` on the branch); this
is the line's existing design, not a new one. What Q050-146 adds on the line is its regression coverage:
the two tests below, unchanged except that the schedule test no longer calls the dropped bracket.

## Known limits

- Local TSan does not run on this box; the race is reasoned, not machine-checked. The publisher pushes
  the wide block before the stereo pair, and the drain reads the stereo count before the wide count, so
  `min()` can only under-count a block in flight (it then waits a period), never pair a stereo frame
  with a wide frame of another block.
- The threaded test is a stress check; the schedule test is the deterministic reproduction.
