# Q050-031 - Safely accept plug-in MIDI and media drops (P0, fix, L04 arranger)

**Unit.** Dragging a generated MIDI file or a supported audio file out of a plug-in editor (VST, CLAP, LV2 windows drag
files as `text/uri-list`) into the arranger creates a clip at the drop position, or safely refuses the file.

**Finding that shaped the work.** The brief pointed at "the registered commands the agent surface uses for importing a MIDI
file / adding a sample clip". Neither exists for clips: `interchange.smf_import` imports only the *tempo map* of a file,
`project.import` runs the MidiImport filter (new tracks at tick 0, a modal progress dialog, tempo and time-signature
automation tracks, not undoable), and no command makes a sample clip from a file (`sample.generate` makes synthetic audio;
a sample clip from a file was only reachable through the GUI's `SampleClip::setSampleFile`). So one new command was added,
`clip.import_file`, and the GUI drop runs it - one door for the GUI and the agent.

## New command and reversibility

`clip.import_file` - group `clip`, mutating, `true_inverse`. Into an existing track: a Track journal checkpoint (the `clip.add`
shape; inverse `clip.delete`). With no track: the created track is recorded with `control::recordCreatedTrack` after its clip
is filled, so undo removes track and clip together and redo rebuilds both. Row: `src/core/ControlReversibilityTableDevices.cpp`.
Snapshot regenerated from a live instance (824 ids / 76 groups), README canary 823 -> 824, A16 published histogram re-taken
in `docs/RELEASE-NOTES-v0.3.0-alpha.md` (`rows=833 true_inverse=413 snapshot=40 irreversible=24 not_mutating=356`; at the base
commit `ReversibilityContractTest` already failed by one `true_inverse` row, 823 measured vs 822 published, so this edit also
absorbs that).

## Format changes

None. A temp-folder audio drop is saved as the existing embedded-sample form (`data` attribute); a MIDI drop is an ordinary
MIDI clip. Old projects load unchanged.

## Known limits

- Only the first local file of a multi-file drag is imported; the message says how many were left.
- "Temporary" is the system temp folder (`QDir::tempPath()` / `TempLocation`). A plug-in that writes elsewhere and deletes the
  file gets a clip that references the (now missing) path, which a reload cannot find (not exercised by a test); the audio
  stays playable for the session because the clip decodes at drop time. Embedding is not applied to non-temp files so a large
  audio file does not bloat the project.
- Audio files over 512 MiB, MIDI files over 16 MiB or with more than 200,000 notes are refused. The MIDI clip holds every
  channel and track of the file merged into one clip; tempo, time signature, controllers and program changes are not read
  (a clip carries notes in beats, tempo is the session's).
- A drop onto a pattern-editor lane is refused with a message (the command works on song tracks only).
- A new instrument track gets TripleOscillator when that plug-in is installed, otherwise no instrument (the same as
  `clip.audio_to_midi`).
