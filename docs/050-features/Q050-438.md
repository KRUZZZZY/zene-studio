# Q050-438 — Document the existing Revisions UI

Unit: docs, L12, member R-workflow-219. The tree already has **Project tools ▸ Revisions...**
(`CommandLists::revisions`, over `revisions.list`) with **Restore** and **Compare With Now**,
but the manual still said **Project > Revisions** and `docs/KNOWN-LIMITATIONS.md` still ended its
revision bullet with "UI absence — one line: the revision timeline is drivable through the socket,
not from the interface". This unit rewrites both documents from the live interface and pins them
with a GUI test that opens the menu entry and reads the list's own sources. Docs only: no command,
schema, project format, storage source or audio-path change.

## What was built

- `data/manual/index.html` (Projects): a **Revisions** paragraph names the real route
  **Project tools ▸ Revisions...**, the four row fields (id, source, UTC time, size), the four
  sources (`rotation` `<file>.rev0..rev2`, `backup` `<file>.bak`, `autosave` `recover.mmp` with
  `savedUTC` from its `.info` sidecar and `recover.mmp.bak` when present with its file timestamp,
  optional bounded `git`), **Compare With Now** as a structural summary and

  session. It keeps numbered **File ▸ Save as New Version** saves and named **Alternatives**
  distinct from the list, and gives an agent the same `revisions.list` / `revisions.compare` /
  `revisions.restore` path, saying that it reopens the project to work on restored bytes.
- `docs/KNOWN-LIMITATIONS.md` (revision bullet): the obsolete no-UI sentence is gone. The
  current-facing paragraph describes **Project tools ▸ Revisions...**, its columns, **Restore**
  (confirmed) and **Compare With Now**, and retains only the accurate limits: artefacts only (a
  numbered save and an alternative are not sources), 24 entries / 10 git commits, optional
  bounded git, structural compare rather than a musical diff, and a restore that changes the
  file on disk only.
- `tests/src/gui/RevisionsDocsTest.cpp` (new, registered): starts the real application over a

- `tests/CMakeLists.txt`: `RevisionsDocsTest` registered beside `VcaStripViewTest`, with the

## New commands and reversibility

None. `revisions.list` and `revisions.compare` stay `not_mutating`; `revisions.restore` stays
`true_inverse`. The list's **Restore** row action is the same `revisions.restore` and is
confirmed; **Compare With Now** is the same `revisions.compare`. The menu entry itself runs only
the read-only list.

## Format changes

None. No project reader, writer, revision policy or storage source was touched; rotation, backup
and autosave entries use existing files, and Git entries come from the project's existing
repository history.

## Known limits (stated in the docs as shipped)

- The list covers the retained rotation, `.bak`, the current autosave and its previous `.bak`
  when present, and optional git history -
  not numbered **Save as New Version** files and not named **Alternatives**.
- At most 24 entries are listed, 10 of them git commits; the git half is skipped without a
  repository, without `git`, or with `include_git: false`, and the reply says which.
- **Compare With Now** is a structural element-count summary, not a musical diff.
- **Restore** replaces the file on disk and does not reload the open session; `project.open`
  reads the restored bytes back. It is reversible only through the keep-3 set, so an over-cap
  live file is refused before anything is written.
- A git entry has no `sha256` (its commit sha is its identity), and an `mmpz` document over
  64 MiB decompressed is reported unreadable rather than counted.
