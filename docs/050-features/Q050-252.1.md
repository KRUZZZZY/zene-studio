# Q050-252.1 External Instrument device - stage 1/3: External MIDI device controls and preset state

Unit: P2, L09 (MX-062, R-recording-44). Base `2a7fd9f9c` (train 24), branch `feat/050-Q050-252.1-oc`. Stage 1 of 3:
this stage owns the MIDI half of the device (port, channel, bank, program, presets). The audio return and its
monitoring (stage 2) and the manual latency offset (stage 3) add their own settings to the same device and the same
commands later; nothing here has to be undone for them.

## What was built

- **State.** The device is the instrument track's own `MidiPort` (`include/MidiPort.h`): output port and channel as
  before, plus two new models, bank select MSB and LSB (`-1` = send none, `0..127`), beside the existing program model
  (1..128, sent as 0..127), and a list of named presets (`MidiPort::DevicePreset`: name, port, channel, bank MSB/LSB,
  program; at most 64 per device, name 1..64 characters).
- **What reaches the output** (`MidiPort::sendOutputPatch`, `src/core/midi/MidiPort.cpp`): bank select CC 0 (MSB) and CC 32
  (LSB), when set, then the program change, on the port's channel. `setOutputPatch()` sets the three values together and
  sends ONCE (a synth must not step through the patches in between); a bank with no program change would not take effect,
  so a bank edit also re-sends the program. A port that never chose a bank sends the program change alone, as before. The
  restore from a project or an undo loads bank and program as one patch too (one send, not one per model).
- **Commands** (`src/core/ControlCommandsExternalDevice.cpp`, group `device`):
  `device.external_get_state` (port, `available_ports`, channel, bank MSB/LSB, program, presets),
  `device.external_set` (`port`, `channel`, `bank_msb`, `bank_lsb`, `program`, `enabled`; `patch_sent` in the reply),
  `device.external_preset_save`, `device.external_preset_recall`, `device.external_preset_remove`.
  `port` is the ONE output the device sends to (any other it was sending to is left) and turns the output on. A refused
  call (unknown port, number out of range, nothing named, unknown preset, wrong track type) changes nothing and takes no
  undo step. Recall applies a preset's port only when that port exists now (`port_applied`, `missing_port`), the rest
  always, and sends the patch even when the values were already the preset's.
- **Card** (`src/gui/instrument/ExternalDeviceCard.cpp`, `include/ExternalDeviceCard.h`): Track > MIDI Out >
  "External Device..." (`src/gui/shell/ShellMenuEntries.cpp`, declares `device.external_set`). Port combo, channel,
  bank MSB/LSB and program spin boxes, a preset name box with Save / Recall / Delete. Every control runs one
  `device.external_*` command through `ControlRegistry` and re-reads `device.external_get_state`; the card holds no state of
  its own, so a refused edit shows what the device really holds, and it refreshes when the window is re-activated (after an
  undo or an agent's edit).
- **Presets live in the project**, inside the track's `<midiport>` element, not in a user-wide store: they are the
  settings of this device on this track, and keeping them in the track lets the ONE Track checkpoint cover them (and the
  ports a later stage adds). Cross-project sharing is not offered by this stage.
- **A fix to inherited code the undo needed** (`MidiPort::loadSettings`): it could only SUBSCRIBE writable ports, never
  leave one, so restoring a track whose saved port differed from the current one left both ports subscribed (this also
  affected `track.midi_out`'s undo). It now unsubscribes a port the restored state does not list. A project load starts with
  every port unsubscribed, so loading is unchanged.

## Format

`<midiport>` gains, only when set: attributes `outputbankmsb`, `outputbanklsb` (0..127), and one child
`<devicepreset name port channel bankmsb banklsb program/>` per preset. An absent bank is read as "none" (-1), an absent preset
list as empty, so projects written before this open as they did and a track that never used the device saves the same bytes.

## Realtime

Nothing on the audio thread changed. Bank/program sends and every command run on the main thread (the same thread the PROG
box already sent its program change from); `MidiPort::processOutEvent` and the note path are untouched. No TSan locally: the new
state (bank models, preset list, `m_patchBatch`) is read and written only on the main thread; the audio thread reads only the
existing output channel and flags, as before.

## Known limits

- Presets are per track and saved with the project; there is no user-wide preset store yet.
- Changing only the port or the channel sends no patch; recall or an explicit program/bank edit does.
- A preset's port is matched by name; a renamed or unplugged port is reported (`port_applied: false`), not substituted.
- Named hardware patch maps and SysEx dumps are out of scope (as in the brief). The audio return and monitoring (stage 2),
  manual return latency and the complete device preset (stage 3) are later units.
- `MidiPort::loadSettings` still only subscribes readable ports (the same latent issue exists on the input side); only the
  output side was in scope and is fixed.
- Tests need a MIDI client with ports; this box has no ALSA sequencer, so they use a recording client through
  `MidiPort::rebindClientForTest`. A real ALSA loopback was not measured for this stage.
