# Q050-320 — Announce launched and stopped clips and scenes

## What changed

`SessionAnnouncer` (GUI thread, 150 ms timer) observes the published `session.get_state` and speaks only completed
transitions: a `launching`/queued cell is silent, a refused launch does not alter state and is silent, a playing cell
is announced once, a stop is announced after the cell leaves the playing phase, and a multi-cell scene launch/stop is
one scene message rather than a burst. All messages go through `a11y::announceStatus`, so `view.announcements` applies.
The observer is parented to the main window; it does not read the audio thread or depend on which route (UI, bound
controller, agent command) caused the state change.

| Criterion | Test and what it proves | Result |
|---|---|---|
| Launch/stop cells and scenes from UI and a bound controller produce one announcement naming the cell/scene and state. | `SessionGridViewTest::theAnnouncerSpeaksCompletedLaunchesOnceAndHonoursTheLevel` drives queued → playing → stop transitions, including a whole scene. The existing `PerformViewTest` and `SessionGridViewTest` exercise the MIDI-bound and UI launch paths into the same published state. | `0` |
| Routine announcements honor `view.announcements`; refused/not-yet-active launches do not fire. | Same test proves `all`, `errors` and `off`, and that the launching phase is silent. | `0` |

No command change; `session.launch_*` / `session.stop_*` remain `not_mutating`. No project format change.
