# Q050-322 — Keyboard context menus for track headers and the ruler

## What changed

- A focused track header (the label button) now takes Tab focus and opens its **Actions** menu with the Menu key or
  Shift+F10. Right-click opens the same menu; double-click still renames. The menu is the existing
  `TrackOperationsWidget` builder, so it is the same action list.
- The time ruler takes focus and opens the same loop menu the mouse path uses, at the play position with the current
  snap. Menu / Shift+F10 and right-click both call `buildLoopMenu`.

|---|---|---|
| Focus a track header/ruler and open the same menu with Menu or Shift+F10. | `ArrangerTimelineTest::trackHeaderAndRulerOpenMenusFromTheKeyboard` exercises both keys on both surfaces and compares the action text with the mouse-opened menu. | `0` |
| Menu actions match the mouse menu and stay keyboard navigable. | Same test compares the action lists; the menu is a normal `QMenu` and closes with the keyboard. | `0` |
| Regression coverage includes both surfaces and focus behavior. | Same test checks focus policy, accessible names and each trigger. | `0` |

No new command, undo step or project-format change. Track rename remains one command; loop edits remain timeline
commands. Focus/menu work is GUI-thread only.
