# Q050-041 — Carla processing mutex fix

## What changed

Carla MIDI now crosses from `handleMidiEvent` to the render callback through the fixed-capacity `CarlaMidiHandoff` queue. `playImpl` stages queued events and calls Carla's native process function without taking a shared mutex. Overflow channel cuts and queued events share the fixed native-event budget; work that does not fit remains pending for the next period.

The output-budget regression was found while building the native event array: a due all-notes-off cut had not counted against the array capacity. `drainMidi` now caps successfully emitted events and cuts together.

## Carla runtime availability and limits

No system `libcarla`, `carla-host-plugin`, Carla executable, or Carla pkg-config metadata was available, including under `~/.local/zene-deps`. The configured build therefore uses weak Carla linking and its dummy native plug-in module. The tests compile the production hand-off against the bundled Carla native API header and pass a compile-time stand-in for `NativePluginDescriptor::process`.

This proves the queue, event encoding, ordering, output budgeting, render offsets, allocation behavior, and process-boundary delivery exercised by the stand-in. It does not prove behavior inside a real Carla instance or a third-party Carla plug-in, and the lock scan does not instrument runtime locks.
