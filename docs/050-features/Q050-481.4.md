# Q050-481.4 - Remove the legacy VST2 hosts (stage 4 of 4)

Queue unit (L10, modernisation). VST2 instruments and effects are hosted through Carla: native plug-ins in process, Windows plug-ins in Carla's Wine bridge. Zene builds no VST2 client of its own.

## What was removed

- `plugins/VstBase` (`vstbase`, `RemoteVstPlugin32/64`, `NativeLinuxRemoteVstPlugin64`), `plugins/Vestige`, `plugins/VstEffect` and `include/aeffectx.h`.
- The qt5-x11embed build; its submodule entry remains in `.gitmodules`, unused.
- Six tests that compiled those sources, and the `vestige`/`vsteffect` rows of the out-of-process family table.

## What stays and the resolved question

Saved `vestige` and `vsteffect` XML remains readable through `LegacyVst2Conversion`, `MissingDevices` and `UpgradeExtendedNoteRange`. A missing or unloadable binary becomes a Q050-018 missing-device placeholder that keeps its original state. Saving preserves that state so conversion can succeed when Carla and the plug-in are available.

## Fixes exposed by removal

- In `src/core/Song.cpp`, targetless automation no longer builds a fallback model on the render thread, avoiding `std::bad_alloc`; `AutomationModesTest::testRecordingClipWithoutTargetWritesNothing` covers it.
- The file-browser VST2 instrument path uses `legacyvst2::instrumentKeyForBinary` to resolve the Carla instrument.

## Commands and format

No commands were added or changed; no snapshot change. The project format is unchanged.

## Realtime

`Song.cpp` now does less on the render thread; there is no new audio-thread code.

## Portability

A macOS build has no VST2 host for macOS (.vst) plug-ins: the Carla VST2 modules accept only Linux ELF (.so) and Windows PE (.dll) binaries, and that path is untested on macOS. 32-bit Windows VST2 needs Carla's 32-bit bridge, untested here.

## Known limits

The placeholder is silent until Carla and the plug-in are there. The file-browser path is covered through `instrumentKeyForBinary` plus `loadInstrument`, not by a driven drag. Local TSan is not available.
