# Q050-125 - Edit clip gain, envelope and polarity on the waveform (P1, L05 audio editing)

**Unit.** Drag a clip's gain, draw and move gain-envelope points, and invert a clip's polarity directly on
the waveform, while the drawn waveform follows the gain curve so the level is visible as you edit.

**Design.** The wave keeps the model that already existed and adds the missing halves:

- the **gain handle** is a square on the clip's left edge, held inside the clip so a boosted clip's handle
  stays grabbable. A drag previews the level in `m_dragEdits` (`SampleClipView::shownEdits`) and sends
  `clip.set_gain` ONCE on release, so the gesture is one journal step. The drag's own distance from the press
  sets the level (`clipGainDraggedDb`), so the handle follows the pointer rather than jumping to it.
- a **gain-envelope point** is added by Alt-clicking the waveform and moved by dragging the point. The same
  `withGainPoint` re-sorts the points into tick order, which is what `clip.gain_envelope_set` requires, so a
  point dragged past its neighbour takes its place. A point is taken within `PointReach` pixels; a plain press
  anywhere else is still the clip's move gesture. A drag previews and one release writes the whole list.
- **polarity** is a new `ClipEdits` field (`polarityInverted`) - a signed multiplier on the same non-destructive
  gain stage as the clip gain, applied in `SamplePlayHandle::applyClipEdits` and `ClipPreFades::applyPreFaded`.
  It is persisted additively (`invert="1"` only when set) and reset by absence, so every project written before
  this loads with polarity off and renders exactly as it did. `Sample::render` is untouched, so the browser
  preview and the metronome keep their own sign.
- the **drawn waveform** is the thumbnail with a per-column gain: `SampleThumbnail::VisualizeParameters::gainAt`
  (empty for the browser preview and the sample editor, whose draws are unchanged) is sampled by
  `SampleClipView::gainAtPixel`, returning `clipGainCurveAt(edits, length, tick) * polaritySign()`. That is the
  same curve, the same single definition (`ClipEdits.cpp`), that the audio path applies and the automation
  editor's ghost draws - so the drawn amplitude is the rendered one.

## New commands and reversibility

- `clip.set_polarity` - args `clip`, `inverted`; result adds `inverted` and the existing edits block. Mutating,
  `true_inverse`: the polarity is part of the Clip's serialized state (`invert`), so the Clip checkpoint taken
  before the write is a live inverse (`src/core/ControlReversibilityTableLive.cpp:181`).
- No new read command: the polarity is reported by every command that already answers a clip's state
  (`clip.add`, `clip.delete`, `clip.set_gain`, `clip.set_fade`, `clip.crossfade`, `roll.get_state`,
  `arrangement.get_state`).
- `clip.set_gain`, `clip.set_fade`, `clip.add`, `clip.delete`, `roll.get_state` grew the `inverted` key (their
  closed result schemas were extended with it, so `ZENE_CONTROL_CHECK_RESULTS=1` still passes).

## Format changes

- A clip element gains `invert="1"` ONLY when the clip is inverted. The attribute is additive and
  reset-on-absence, so every older project loads non-inverted and renders bit for bit as before; the
  `ClipFadesRenderTest` neutral-render identity still holds.

## Known limits

- The gain handle edits the clip's flat gain; the envelope points edit the curve on top of it. The handle is
  held inside the clip, so a boost above roughly +20 dB on a short clip draws its line at the clamp rather than
  its exact pixel (the value still travels between -60 and +24 dB).
- A point is added with Alt-click; a plain press on empty waveform is still the clip's move gesture. There is no
  per-point delete gesture yet - Remove the envelope through `clip.gain_envelope_set` with the remaining points.
- Polarity is a clip property, not a mixer-channel or track property, and the sample editor's own draws (and
  the browser preview) keep the source's sign, deliberately: the inversion is the clip's, not the buffer's.
- The thumbnail's gain curve is sampled per drawn column, so at extreme zoom-out a column can cover several
  envelope points; the drawn band is the sampled column's gain, as the audio's own per-frame gain is.
- No local TSan run (it does not work here): the audio thread reads `m_edits` as the POD snapshot
  `SamplePlayHandle` already took at construction, exactly as it reads the gain and fades today, so the
  inversion adds no new cross-thread access.
