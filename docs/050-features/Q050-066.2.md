# Q050-066.2 - Drum-rack pad workflow, stage 2/4: visible pad editor and independent chains (P1, feature, L10)

**Unit.** Let musicians edit sample pads and their per-pad effect chains from a drum-rack view using the registered
command surface. Members: B-MX-111, R-instruments-55, R-instruments-66, R-instruments-73, R-instruments-77. Stage 1
(`docs/050-features/Q050-066.1.md`) made the pad state contract, the pad commands and the pad panel; stages 3-4 (pad
links and one-shot slots, the launcher transfer) are later units.

**What was there (base `37eaf07557`, train 21).** The pad panel (Folder > Drum Rack Pads...) created and edited pads
(name, trigger key, sample, Add Pad...) through `track.drum_rack_pad_add` / `_pad_set`. Every pad already had a mixer
channel of its own (its chain), but nothing showed or edited what was on it from the rack, and the pad read-back did not
carry it.

step is exact), `plugin.bypass` (`true_inverse`) and `plugin.unload` (`true_inverse`); their classes are unchanged.

## Realtime

All new code runs on the UI/control thread: the read-back walks the channel's effect list and the song's tracks there,
and the panel only invokes registered commands. The effect loads, bypasses and removals are the existing commands'
paths (unchanged). Nothing new runs on the audio thread. (TSan does not run on this box; this is by reading.)

## Known limits

- The chain read back is the channel's chain 0; parallel rack chains on a pad's channel (`rack.add_chain`) are not listed.
- The panel adds built-in effects only (`plugin.list` format `builtin`); agents can load any device with `plugin.load`.
  Effect parameters are edited in the mixer's own effect view or with `plugin.param_set`, not in the pad panel.
- Existing undo behaviour of the shared plugin commands, not changed here: a redo of `plugin.load`, or an undo of
  `plugin.unload`, makes a new device instance, so a recorded edit on the old instance (a `plugin.param_set` or
  `plugin.bypass` made before that undo) no longer reaches it when undone or redone across it. Each step on its own
  undoes and redoes exactly (the tests check them one at a time); `plugin.unload`'s undo restores the device's
  settings, including its bypass.
- `chain_shared` only refuses in the panel; an agent may still load onto a shared channel with `plugin.load`.
