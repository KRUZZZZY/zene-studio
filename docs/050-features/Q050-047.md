# Q050-047 - Correct rack UI limitations documentation

Queue unit (P0, S, docs, area L10, member `R-workflow-123`): the limitations page said rack chain effects and
key/velocity zones were socket-only although the Device panel, the channel's Rack menu and the Inspector already
exposed them. This unit rewrites those bullets against the tree and closes the one gap the rewrite found: an
**empty** parallel chain had no card, so no card menu could give it its first device. Branch
`feat/050-Q050-047-oc`, base train 5 (`de5a85a96`).

## What was built

- `docs/KNOWN-LIMITATIONS.md`: the 2026-09-30 Rack bullet no longer says "putting effects into a parallel chain is
  still socket-only"; it names the Device panel's parallel-chain headings, the card's Insert Effect Before/After,
  `rack.wrap` and the Inspector's `plugin.load` form (`chain` field). The "No racks in the interface" bullet is
  marked superseded. A new corrected bullet records the GUI macros and zones (`Rack > Zones...`, `Rack > Add Zone...`)
  and says what is genuinely still absent (a binding narrower than the full range, a visual key map for the zones,
  a Lua binding). Cross-checked file:line claims: `docs/KNOWN-LIMITATIONS.md:259-295`.
- `README.md:105-111` and `data/manual/index.html:132`: the same correction in the user-facing registers.
- `src/gui/shell/DevicePanel.cpp` / `include/DevicePanel.h`: an empty parallel chain's heading now carries an
  **Add device...** button (`DevicePanel::addChannel`, `:390-409`), and the panel's own **Add device** fills the
  channel's selected parallel chain (`addTargetChain`, `:171`; `addDevice`, `:181`). Both run `plugin.load` with a
  `chain` field - the same call the socket takes, one undo step each. A track's Add device (no rack) still loads
  into the track's own chain.
- `include/DevicePicker.h` / `src/gui/shell/DevicePicker.cpp`: `DevicePicker::setChooser` - a test-only hook so a
  QtTest can answer the modal picker deterministically. It defaults empty, so production `pick()` is unchanged.
- `tests/src/gui/RackMenuTest.cpp`: four cases (see Acceptance) and `tests/CMakeLists.txt` adds
  `add_dependencies(RackMenuTest amplifier)` so a targeted build builds the effect module the new cases load
  (the train-2 attempt skipped when it was absent; the rework asks for this dependency).

## Commands and reversibility

No new command id, so no `commands_snapshot.json`, canary or A16 change. The new GUI controls dispatch the
existing registered commands: `plugin.load` (added `chain` argument below the schema's existing optional field) -
reversibility unchanged (snapshot; `control.undo` removes the loaded device, one step). The picker's
`setChooser` hook is test-only and does not touch the registry.

## Format

No project-format change: a device loaded into a parallel chain is the `plugin.load` the socket already writes,
persisted in the channel's existing `<rack><chain><fxchain>` element. Old projects load and render as before.

## Known limits

- Zones still have no visual key map: they are rows in `Rack > Zones...` and the `rack.zone_add` form, not a piano
  roll or keyboard editor. A macro binding is still full-range only from the menu. There is still no Lua binding
  for the rack. All three remain in `docs/KNOWN-LIMITATIONS.md`.
- The empty-chain Add button appears only while the chain is empty; once it holds a device the card's
  Insert Effect Before/After and the panel's Add device are the routes.
