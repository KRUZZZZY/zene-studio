# Q050-212 - Track creation output routing and auto-channel assignment

Unit (L09, R-workflow-232 + R-workflow-274, P2). A new track can name where it plays, several can be added on a new
shared bus, and a preference gives each new instrument or sample track its own mixer channel with the name kept in step.

## Decision on "bus" (the scoping brief left it open)

A bus here is a **regular mixer channel**. A parallel bus (`bus.create`) is skipped by `Mixer::mixToChannel`, so a track
routed to one would be silent. `track.add` refuses it with `invalid_args`, the menu does not list it, and
`track.add_to_new_bus` makes a regular channel.

## Commands

- `track.add` (changed): optional `output` (a `ch-<n>`) and `instrument` (a plug-in name). The reply adds `channel`,
  `channel_name`, `channel_linked`. Still `true_inverse`: the one undo step also deletes a channel made for the track, and
  redo makes it again under the same `ch-<n>`.
- `track.add_to_new_bus` (new, `true_inverse`): `count` 1..64, `type` instrument|sample, `bus_name`, `name`, `instrument`.
  One undo step covers the channel and all the tracks.
- `settings.set` key `app/autotrackchannel` ("1"/"0", absent is off): the preference. Settings > General writes it through
  the same command.
- `mixer.rename_channel` (behaviour): also renames the track linked to that channel, in the same undo step.

## Interface

Song Editor track toolbar: **Add track to** (`src/gui/editors/AddTrackMenu.cpp`) lists Instrument track to / Sample track
to with the mixer's regular channels, plus **Add tracks to new bus...** (a dialog for number, type and name). Add
sample-track now dispatches `track.add` rather than a `Song` slot, so it follows the preference and gains an undo step.

## Format

`mixlink` on `<track>`: the stable id of the channel made for the track. Written only for such a track, so other projects
save the bytes they always did. Absent means no link (`TRACK_RESTORE_SCHEMA`). It is not read from a copy (clone, drag) and
not touched by a preset, so a duplicate does not own the channel. A link only acts while the track plays into that channel,
so a rerouted track renames nothing while away, and a stale id matches nothing. Routing it back gives the channel the track's current name, inside the routing edit's one undo step, whichever control routed it (`Track::reconcileLinkedChannelName`, called from each track type's route change). Old projects load as before:
opening a project never assigns anything, and an older build ignores the attribute.

## Fixes this needed

- `src/core/main.cpp`: the registry was set ready only with `--control-socket`, so in a plain interactive run an interface
  action needing the engine answered Busy. Add sample-track would have stopped working. **Not covered by a test**: it sits
  in `main()`'s startup path, which the GUI test fixture does not run (it sets readiness itself); established by reading
  `ControlRegistry::invoke` and `main.cpp`.
- `track.set_mixer_channel`: widens the model's range first. A channel added since the track was built was otherwise clamped
  away in a run with no mixer window, while the reply named that channel (`aReroutedTrackOrACopyRenamesNoChannel`).

## Realtime

Nothing here runs on the audio thread. Channel creation takes the existing engine change lock (`Mixer::createChannel`) on
the UI thread. `InstrumentLoaderThread` names a track off the UI thread, so the channel rename follows `nameChanged` through
an auto connection, which queues it to the UI thread. TSan does not run here: this is reasoned, not measured.

## Known limits

- Auto-assignment covers `track.add`, the toolbar, the Browser (double-click, plug-in, file and preset drops on the arranger, file lists, Send to new SlicerT instance),
  `browser.load` and `clip.import_file`. Tracks derived from other material (bounce, flatten, stems, slices, recording,
  drum rack) and Pattern Editor tracks keep their routing.
- A track opened from the Browser had no undo step before this and still has none; its channel is not undoable either.
- `track.remove` leaves the channel in place. Undoing the removal restores the link.
- `track.set_mixer_channel` still accepts a parallel bus, as before; only creation refuses it.
