# Q050-490 - Open VST3 and CLAP plug-in windows on Windows and macOS

Queue unit (P0, L, completion, area L10): a hosted VST3 or CLAP plug-in's own editor refused every non-X11 view
(`Vst3EditorSession.cpp:190`, `ClapHostGui.cpp:65` at `7641e9493d`), so no third-party plug-in window could open on
Windows or macOS. Branch `feat/050-Q050-490-oc`, cut from `050/m0-train-18`.

## What was built

- **The window system is chosen when an editor opens** (`include/PluginWindowSystem.h`, header-only):
  `PluginWindowSystem::{X11, Win32, Cocoa, None}`. `pluginWindowSystemFor(QGuiApplication::platformName())` returns
  Win32 on Windows, Cocoa on macOS, and X11 on Linux and the BSDs. A native Wayland session (`wayland*`) gets None, because
  it has no X11 window to give. `QWidget::winId()`, which `PluginNativeEditor` already hands the hosts, is the matching
  handle on each platform (an X11 id, an `HWND`, an `NSView*`), so the window code needed no change.
- **VST3** (`Vst3EditorSession::open`): asks `isPlatformTypeSupported` and `attached` with `kPlatformTypeX11EmbedWindowID`,
  `kPlatformTypeHWND` or `kPlatformTypeNSView`. A Wayland session (None) is refused before a view is created.
- **CLAP** (`HostedPlugin::openEditor`, `ClapHostGui.cpp`): `is_api_supported` / `create` with `CLAP_WINDOW_API_X11`,
  `CLAP_WINDOW_API_WIN32` or `CLAP_WINDOW_API_COCOA`, and `set_parent` with the matching `clap_window_t` union member
  (`x11`, `win32`, `cocoa`).
- **The refusal is typed and names the platform and the window API.** `plugin.editor_open` returns
  `ControlErrorKind::Refused` with, for example, *"trk-1/fx-2 (X): the plug-in's editor cannot embed on Windows (VST3
  platform type HWND)"* or *"... cannot embed on macOS (CLAP window API cocoa)"*. Nothing is created, so no empty window is
  left. The GUI button shows the same text on its refusal line.
- **Content scaling per platform** (`plugin.options editor_scale`):
  - **X11 and Windows** (physical pixels): unchanged. A VST3 view with `IPlugViewContentScaleSupport` is told the factor
    (ByView); any other view that can resize is given the scaled size (ByWindow). A CLAP editor gets `set_scale`.
  - **macOS** (logical points, both specs): the VST3 SDK says its content-scale interface is for Windows and Linux only,
    so the host skips it and gives a resizable view the scaled size (ByWindow). `clap/ext/gui.h` says not to call
    `set_scale` for cocoa, so the host does not, and `editor_scale` has no effect on a CLAP editor on macOS (documented).
- **Test hooks:** `HostedPlugin::setEditorWindowSystem` (VST3 and CLAP) lets a test choose the window system, so the
  Windows and macOS paths run on any machine. Nothing in the product calls it.
- **Fixtures:**
  - **Both:** they embed in all three APIs, as a cross-platform plug-in does. `VST3_TEST_EDITOR_PLATFORM` /
    `CLAP_TEST_GAIN_GUI_API` restricts each to one API, so the refusal can be exercised.
    `VST3_TEST_EDITOR_REQUEST_RESIZE` / `CLAP_TEST_GAIN_REQUEST_RESIZE` make the plug-in resize its own editor (VST3
    `IPlugFrame::resizeView`, CLAP `request_resize`).
  - **CLAP only:** the fixture reads the parent from the union member of the API it was created for. It refuses a
    `set_scale` on cocoa, as the spec requires.
  - **VST3 only:** the fixture refuses `attached` with any type it would not accept.

## Known limits

- **Hosted CI on Windows and macOS has not run this change yet.** Lanes are not pushed. Its first observation is the
  first hosted run of the line that merges it.
- **The VST3 fixture does not build on Windows or macOS** (`tests/data/vst3-test-instrument/CMakeLists.txt`: Linux
  bundle layout, `linuxmain.cpp`). The VST3 HWND / NSView path is proved by the explicit cases on Linux only. Porting
  the fixture (a `.vst3` folder with `dllmain.cpp` on Windows; a CFBundle with `macmain.cpp` and an `Info.plist` on macOS)
  and turning on `WANT_VST3_TEST_INSTRUMENT` on those jobs is the remaining step.
- **No real plug-in window has been opened on Windows or macOS.** The owner's Windows laptop and Mac mini are the check
  for a third-party VST3 and CLAP editor: open, draw, host and plug-in resize, close, reopen, `editor_scale`.
- **The host window does not follow a plug-in-initiated resize.** The view gets the size, but the Qt window keeps the
  size it opened at, on every platform (as on X11 before).
- `HostPlugFrame` still answers `Linux::IRunLoop` on every platform. A Windows or macOS view does not ask for it.
