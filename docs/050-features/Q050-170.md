# Q050-170 — Filter browser results by category

Unit: in the Search view a musician narrows the library by **category** beside Kind and
Where to look; the same filter answers direct (`browser.query`) and indexed
(`browser.index_query`) search, **Any category** restores the full result set, a file's
category can be assigned from the GUI, and a category-filtered search survives being
saved and re-run as a collection (0.5.0 L11, WF-007 completion).

Resumed from the round-2 session's saved patch (the branch had no commits at `de5a85a96`);
this round fixed two latent bugs in it (a dangling `QJsonObject` temporary pair in
`BrowserTagStore::load` that crashed every store read with a categories table, and test
fixtures living outside every library root), added the GUI acceptance tests, and finished
the surface/mechanics (snapshot, canary, A16 figure, manual, gates, commits).

## New commands and reversibility

| id | class | reversibility |
|----|-------|---------------|
| `browser.categories` | `not_mutating` | read of the store's categories table (`ControlReversibilityTablePassive.cpp:351`) |
| `browser.category.set` | `snapshot` (reversible) | one undo step; recorded inverse is the COMMAND `browser.category.set` with the previous category, or `browser.category.clear` when there was none (`applies: command`, dispatched by `control.undo`) — `ControlReversibilityTableSnapshot.cpp:219` |
| `browser.category.clear` | `snapshot` (reversible) | one undo step; recorded inverse is the COMMAND `browser.category.set` with the category the file carried (`:230`) |

GUI and agent use the same registered commands: the Category submenu and the Search view's
facet run `browser.category.set` / `browser.category.clear` / `browser.categories` /
`browser.query` / `browser.index_query` / `browser.collection_*` through `ControlRegistry`.

## Format changes

- **No project-format change.** Categories are user-library state in the tag store, like
  tags.
- `browser-tags.json` gains an OPTIONAL `"categories"` table. An old file without the key
  loads as one with no categories (proven: `theCategoryTableRoundTripsAndAnOldStoreLoadsEmpty`);
  a damaged (non-object) table is refused, never overwritten.
- `browser-collections.json` entries may carry a `category` inside `query`; an old
  collection without it runs as Any category.
- Surface artefacts re-taken: commands snapshot (831 ids / 76 groups), README canary, the
  published A16 histogram (+1 `not_mutating`, +2 `snapshot` → 840 rows), the manual's
  Browser section.

## Known limits

- ONE category per file (by design: the classification a file *is*, where tags stay
  free-form); re-setting the same category case-insensitively is refused as a no-op.
- The vocabulary is what files carry: a category no file holds any more disappears from
  the filter and the menu. There is no standalone category manager.
- Categories live in the user's config store, not the project file: they do not travel
  with a project (same bound as tags, `docs/CAPABILITIES-0.3.0.md` §3.10).
- The Category submenu is in the Search source's row menu; the file-list tabs' Tags
  submenu (FileBrowser) does not offer it.
- In indexed mode the category (like the tags) is read from the store live, not persisted
  in the index: an index built before an edit still answers with the current category —
  freshness of the facet is the store's, as the command descriptions state.
- `tools/dawproject-proof.sh` part 1 is red at the base (its TU list predates the
  `DawProjectZipRead.cpp` split — pre-existing, untouched); the A16 figure was measured
  with its part 2 recipe run directly (same probe, `HIST_EXIT=0`, output
  `MEASURED rows=831 ... DECLARED rows=831 entries=831 duplicates=0` on this wasm-off
  build; the published block moves by exactly +3 rows).
- Local TSan does not run on this box (documented limitation); no audio-thread path was
  touched — all work is control-thread/GUI/catalog. Race reasoning: the store is a
  control-thread singleton; edits are serialized by `ControlRegistry::invoke`'s UI-thread
  dispatch, and the store reloads its file before each write path.
