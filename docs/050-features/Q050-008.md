# Q050-008 - Repair freeze-region audio and recovery

Unit: P0, size L, fix, area L15 (R-performance-1/2/3). Branch `feat/050-Q050-008-freeze-region`, base `de5a85a96`.

## What was built

- **Overlap duplication / silent outside** (`src/core/ArrangementEdits.cpp` `arrangement::isolateRegion`,
  `src/core/ControlCommandsFreeze.cpp` `control::isolateFreezeRegion`, used by `freeze.region` and the queued
  `render.queue_bounce` freeze): a region freeze first cuts every unmuted clip that crosses the region's start or
  end at that edge (inside the same journal checkpoint, so one `control.undo` removes the freeze and the cuts), then
  mutes only the pieces inside. `overlapping_clips` now lists the clips that were cut, as they were.
- **Source plays outside the region** (`include/Track.h` `FrozenTake::region`, `Track::frozenTakeSilencesSource`;
  `src/tracks/InstrumentTrack.cpp`, `src/tracks/SampleTrack.cpp`): before, `play()` returned the take's answer for
  every pass, so a region-frozen track was silent outside its window. The take now owns a pass only inside a region
  take's window (a whole-track take owns every pass, unchanged). The flag is saved as `frozenRegion` on the
  `<track>` element (absent in old files: inferred from start > 0 or muted clips).
- **Tempo map** (`src/core/BounceInPlace.cpp` `BounceInPlace::framesBetweenTicks`, `src/core/Track.cpp`
  `Track::frozenTakeSourceFrame`, `playFrozenTake`): the take's start frame was `(tick - start) * current
  frames-per-tick`; it is now the same function the render uses to cut the take, following an active tempo map.
  The lock-free `TempoMapPublisher::snapshot()` (fixed-size stack copy) is read once per pass; no allocation, lock
  or I/O was added to the audio thread.
- **Missing take** (`src/core/ControlProjectAssets.cpp` table row `track`/`frozenAudio`; `Track::loadFrozenTake`;
  `Track::frozenTakeFileMissing`; `control::insertFrozenRecovery`): the take file is now a project asset, so
  `project.missing_assets` lists it and `project.relink` repoints it (existing machinery, no parallel path). On load a
  missing file adds a load error naming both ways out. A take whose audio is not loaded never silences the source.
  `freeze.*` results and `track.get_state` report `audio_missing` / `recovery` (`frozen_audio_missing`,
  `frozen_recovery`) with the way out: `freeze.unfreeze` (undoable by `control.undo`; the existing Unfreeze item in the
  track menu also covers the GUI) and relink.

## Rework (Luna review of a91d7317c)

- Missing REGION take: `Track::loadTrack` (after the clip walk) unmutes the clips the freeze muted when the take's audio
  could not be loaded, so the source is audible after reopening; a loaded take silences its window by itself
  (`frozenTakeSilencesSource`), so the mute flags are redundant for playback. Unfreeze and undo still work.
- Queued region freeze (`applyFreeze`, `ControlCommandsRenderBounce.cpp`): one Track checkpoint before the cuts and the
  freeze, replacing the unfreeze-only undo closure; one `control.undo` restores the pre-cut arrangement
  (`ControlRenderJobTest::regionFreezeAndBounceLandApplyAndUndoOnce` now cuts a clip and checks 3 -> 1 clips).
- Realtime tempo read: `TempoMapPublisher::inForceForRealtime` (one atomic load, nothing copied for an inactive map) and
  `withRealtimeMap` (two published slots, reader pin counts, three bounded attempts, no loop, no data race; the control
  thread waits for a pinned slot before writing it). `playFrozenTake` uses them; the old `snapshot()` is no longer on this path.
- Tempo test compares the frames the render cuts (`BounceInPlace::prepareRenderTracks` start/length) with the take's
  playback frame at the region start and end.
- Red/green: with the behaviour hunks reverted but the APIs kept (no cuts, take always silences, no mute release,
  constant-tempo frame, unfreeze-only undo) the build was EXIT=0 and ctest EXIT=8 with 6 failing assertions across
  `FreezeRegionRepairTest` and `ControlRenderJobTest` (logs `test-red.log`); restored: build EXIT=0, ctest EXIT=0.

## Commands and format

No new command ids (snapshot unchanged). Result fields added: `audio_missing`, `recovery` on `freeze.track/region/unfreeze`;
`frozen_audio_missing`, `frozen_recovery` on `track.get_state`. Project format: optional `frozenRegion` attribute on
`<track>`; old projects load as before.

## Known limits

- The tests were written after the fix; the red state on `de5a85a96` was not captured separately.
- A region cut leaves the pieces split after `freeze.unfreeze` (audio-identical, but more clips); `control.undo` of the freeze removes them.
- A MIDI note held across a region edge can still ring on (clip splitting does not shorten a live note).
- A take moved while the session is open keeps playing from memory; it is detected at the next load/undo restore or by `project.missing_assets` on the saved file.
- Hosted CI not run; TSan unavailable locally (the only shared state is the existing take fields under `requestChangesGuard`).
