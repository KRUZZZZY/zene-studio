# Q050-014 Document supported plug-in formats and caveats

Unit: P0, size S, area L10 devices/instruments/effects/plug-in hosting. Branch
`feat/050-Q050-014-oc`, base `de5a85a96` (train 5).

Goal: users can distinguish native format **loading** from unverified bridge and Kontakt-library
**compatibility**.

The unit is a documentation-truth fix (members `R-instruments-11`, `R-instruments-26`, `R-ui-19`):
two current-facing docs blurred what this build *loads* with what has been *tested*, and both still
carried a stale claim that the plugin scan cache and its per-file records were socket-only / "not a
GUI" even after `CommandLists::pluginModules()` ("Plug-in Modules") shipped the interface.

Docs-only, plus one hermetic documentation-truth gate. No command, GUI action, reversibility row,
snapshot, canary figure or project format changed.

The gate checks (all file reads, no binary, no network):
1. the named location is **real** — `src/gui/CommandLists.cpp` defines `ListSpec pluginModules()` as
   the "Plug-in Modules" list over `plugin.scan_cache_list` with the `plugin.scan_cache_quarantine_add`
   / `_remove` actions, and `src/gui/shell/ShellCommandMenus.cpp` registers it;
2. the named commands are on the **agent surface** — `plugin.scan_cache_list`,
   `plugin.scan_cache_quarantine_add`, `plugin.scan_cache_quarantine_remove`, `plugin.rescan` are all
   in `tools/mcp-zene-control/zene_control/commands_snapshot.json`;
3. `README.md` names **Plug-in Modules**, states the loading-vs-tested separation, names **Kontakt**,
   and no longer carries the "not a GUI" / hand-edited-JSON claim; it advertises the **Linux** format
   list **inside the bounded plug-in-formats paragraph** (markers `**Plug-in formats vs. tested
   compatibility` … `**AI DSP**`), scopes that list to Linux, says availability varies by platform,
   and no longer says "on Linux and the other platforms alike";
4. `docs/KNOWN-LIMITATIONS.md` has the **Linux** formats section (`## Plug-in formats and libraries on
   Linux` … the next `##`), names **Plug-in Modules** for per-file scan status and quarantine
   controls, names **Kontakt**, advertises the same format list **inside that section**, scoped to the
   Linux build with availability varying by platform, and no longer says the per-file records are only
   on the socket;
5. every format name in the list (VST3 / CLAP / VST2 / LV2 / LADSPA / SoundFont2 / GUS) must appear in
   **both** scoped regions — a mention elsewhere in either document does not satisfy the claim — and
   each format's mapped **loader source registers it** (`plugins/Vst3Effect/Vst3Effect.cpp`
   `vst3effect_plugin_descriptor`, `plugins/ClapEffect/ClapEffect.cpp` `clapeffect_plugin_descriptor`,
   `plugins/VstEffect/VstEffect.cpp` `vsteffect_plugin_descriptor`,
   `plugins/Lv2Effect/Lv2Effect.cpp` `lv2effect_plugin_descriptor`,
   `plugins/LadspaEffect/LadspaEffect.cpp` `ladspaeffect_plugin_descriptor`,
   `plugins/Sf2Player/Sf2Player.cpp` `sf2player_plugin_descriptor`,
   `plugins/Patman/Patman.cpp` `patman_plugin_descriptor`), not merely that a path exists;
6. the platform qualification is **real** — `CMakeLists.txt` disables VST hosting in the Apple build,
   so the docs may not promise VST2/Vestige on macOS;
7. `data/manual/index.html` names the same list.
