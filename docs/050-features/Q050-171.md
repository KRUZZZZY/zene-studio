## New commands and reversibility

None. No command was added, removed or re-described. The notes record the existing classes: each
**submitted mutating** UI action is one recorded step, except **New VCA group**, which is
`vca.create` followed by `vca.assign` and therefore two. The launchers do not edit by themselves:
**Groups...** opens a list whose read-only `vca.list` makes no undo step, and **Move With Edit
Group...** (like **Colour a Group's Channels...**) opens a form that becomes one step when
submitted.

## Format changes

None. No project read or write path was touched; a pre-edit-half `<vcagroup>` still loads as
locked with an empty set, as the note says.

## Known limits (stated in the docs as shipped)

- Only the move has a menu line among the five phase-locked edits; split, trim, slip and fade
  are socket / `zene.command()` only.
- The channel menu never sends `vca.assign` with `also: true`, so a channel already in another
  group is refused without a message.
- The Groups list cannot show an edit set's tracks.
- A deleted track stays in the edit set (`missing_tracks` / `skipped_tracks`) until
  `vca.track_remove`.
- `vca.set_solo`'s undo does not restore the transient `MixerChannel::m_muteBeforeSolo`.
- DELETE, clip gain and crossfade are not carried by the phase lock.
- There is no dedicated Lua binding; every `vca.*` id is reachable through `zene.command()`.
