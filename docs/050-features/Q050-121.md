# Q050-121 — usage and unused assets in Project Media

Project Media now reads `project.media_usage` instead of only the reference list. Each row is one file, with a
`Uses` count that adds every reference occurrence: two clips and an AudioFileProcessor pointing at the same file
show 3. The rows also carry an explicit state — `used`, `unused`, `missing`, `external` or `unresolved` — and only
`unused` local files in the project's managed `media/` folder are cleanup candidates.

## Commands

| id | class | what it does |
|---|---|---|
| `project.media_usage` | `not_mutating` | Reads the saved project file, groups references by resolved file identity, counts every occurrence, and lists the unreferenced files in the managed folder. `dir` names the folder (default `media`). |
| `project.media_cleanup` | `irreversible` | Takes `paths`, an optional `dry_run`, and `confirm: true` for a real removal. A fresh scan rechecks every path: only files that are still unused, existing, non-symlink files inside the managed folder are removed. Without `confirm` (and without `dry_run`) the call is refused, so an agent must show the paths to its human first. Refuses while the named project is open with unsaved changes, because the scan reads the saved document. `dir` names the same managed folder the preview used. |

`project.missing_assets` now also carries `usage_count` on each reference, so existing clients see the same count
without a second parser.

## GUI

The Search view's **Project Media** button runs the same command. **Unused Only** hides the used rows while keeping
missing/external references visible with their own state. **Clean Up Selected...** accepts a multi-row selection,
shows the exact absolute paths, asks for confirmation, and calls `project.media_cleanup`; Cancel makes no changes.

## Format and compatibility

No project-format change. Old `.mmp`/`.mmpz` files are read by the existing `controlScanProjectAssets()` parser.
Cleanup only touches files under the project's managed media folder; the project document is never rewritten.

## Known limits

- Cleanup is irreversible: a removed media file is not restored by `control.undo`.
- The scan reads the saved project file, so cleanup refuses while the open project is dirty. Save first.
- Files outside the managed folder are never candidates, even when unreferenced.
- A symbolic link inside `media/` is reported/refused, never followed and deleted.
