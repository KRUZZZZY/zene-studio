# Q050-027 - Preserve mixer and hardware I/O on track import (L09, P0, fix, M)

## The unit
Import or paste tracks and keep their mixer channel plus named hardware input/output assignments, creating a
matching channel when needed. Before: `project.import_tracks`, `project.paste_tracks` and `reference.copy_tracks`
pointed every imported track at the master (`detach()` zeroes `mixch`) and their descriptions said mixer channels
do not carry between projects.

## What was built
- `src/core/ControlProjectTransplantChannels.cpp` (new, in `tests/fork-sources.txt`): a copied track carries a
  *description* of its mixer channel (name, colour, bus flag, volume, pan and the channel's `<hardwareio>`: direct
  out, cue sends, hardware insert send and return - stored as interface channel numbers, so the same buses on the
  same machine). Building the tracks resolves it by NAME: the lowest-numbered non-master channel of that name here
  is used as it is (its own routing is not touched); otherwise a channel is created from the description
  (`resolveNeed`, line ~118). Tracks on the master, tracks without a named source channel, and folder/other track
  types stay on the master as before.
- `include/ControlProjectTransplant.h`: `ChannelNeed`, `TrackPlan`, `ChannelNeeds`, `Built`, `buildAsOneStep`,
  `madeResult`, `noteLiveChannel`, `describeLiveChannel`.
- `src/core/ControlCommandsImportTracks.cpp`: `chosen()` notes each chosen track's channel from the source
  project's `<mixer>` before `detach()`; `copyTracks` records the live channel of each copied track in a
  `<zene-mixer>` element of the clipboard document (the track keeps its number in `source-mixch` on its settings
  element); `pasteTracks` and `importTrackElements` build through `transplant::buildAsOneStep`. Command descriptions
  rewritten (import, paste; `reference.copy_tracks` in `ControlCommandsReference.cpp`).
- `ReferenceProject::mixer()` (`src/core/ReferenceProject.cpp`) so `reference.copy_tracks` brings channels too.
- The GUI ("Import Tracks...", "Paste Tracks From Another Project", the reference panel) call these same registered
  commands, so they use the same logic.
- Undo: ONE step removes the tracks and then deletes the channels created for them (by stable id); its redo
  recreates both. A channel created for a document that made no track is deleted again at once.
- Replies gain `created_channels` (array of `ch-<n>`).

## New commands / reversibility
None added. `project.import_tracks`, `project.paste_tracks`, `reference.copy_tracks` stay `TrueInverse` (mechanism
text now names the channels). Commands snapshot regenerated from a live instance (823 ids / 76 groups, only the three
descriptions changed).

## Format changes
None in project files. The clipboard document (`application/x-zene-tracks`) gains a `<zene-mixer>` element and a
`source-mixch` attribute; an older clipboard document without them pastes onto the master as before.

## Known limits
- Resolution is by exact channel name (including default names such as "Channel 2"); a same-named but unrelated
  channel here is reused. Sends between created channels, FX chains, the rack and the surround panner of the source
  channel are not carried - only name, colour, bus flag, volume, pan and hardware I/O.
- Hardware routes are stored as channel numbers; on a machine whose interface buses are named differently the
  numbers still land on the same physical channels.
- `ReversibilityContractTest::theTableHistogramIsTheDocumentedOne` fails on this branch's base (888934e1b): the
  table measures 823 rows, the published block expects 822. Not caused by this unit (no row added or reclassified).
