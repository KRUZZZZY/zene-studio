# Q050-020 - MIDI export: tempo, timing, program and track channel

Unit: P0, M. Goal: export the tempo map and per-track MIDI identity at 480 PPQ and keep every note's
position exact.

## The export paths, and why they now agree

| path | what it writes |
| --- | --- |
| File > Export MIDI (`MainWindow::onExportProjectMidi`, `src/gui/MainWindow.cpp:1822`) | dispatches `project.export_midi` |
| `project.export_midi` (`src/core/ControlCommandsProjectLifecycle.cpp:240`) | `Song::exportProjectMidi` -> the `midiexport` plug-in (`plugins/MidiExport`) |
| `interchange.smf_export` (`src/core/ControlCommandsInterchange.cpp`, Edit > Tempo Map... > Export MIDI) | a conductor-only file (tempo map, no notes) by design |

There is one note exporter (`plugins/MidiExport`). Its track 0 is now built from
`interchange::exportEvents()` (`src/core/SmfInterchange.cpp`), the function `interchange.smf_export`
uses, so the tempo and metre events, the 10-file-ticks-per-LMMS-tick scaling, the rounded
microseconds-per-quarter tempo encoding and the tick-0 seed are the same code in both files.
`interchange.smf_export` stays conductor-only: its contract (a file that is only the grid, with
`overwrite` semantics and a report) is separate from the note export.

## What was built

- `plugins/MidiExport/MidiFile.hpp`: division 480 (was 128, which truncated 3 of every 8 LMMS tick
  positions: tick 5 -> 13.33 -> 13); `addNoteTicks` (exact integer ticks), `addTimeSignature`
  (`FF 58 04`), tempo encoded as rounded microseconds per quarter (was truncated).
- `plugins/MidiExport/MidiExport.cpp`: `writeConductor` (track 0), `beginInstrumentTrack` (track name
  `FF 03`, program change at tick 0, the track's channel), `writeMidiClipToTrack` writes
  `LMMS tick * 10`. The old per-track single tempo and the commented-out program change are gone;
  a track-count header now counts the conductor track.
- `docs/SMF-INTERCHANGE.md`, `include/SmfInterchange.h`, the `project.export_midi` description.

## Unset program / channel: what is written and why

- Output channel `--` (0): channel 1. This is what the engine itself plays on
  (`MidiPort::realOutputChannel`), so the file says what the session sounds like. Channels 1..16 map to
  0..15; there is no automatic spreading of tracks over channels, and percussion channel 10 is not
  special-cased.
- Output program: always written, `outputProgram - 1` (1..128 -> 0..127). The model has no "unset"
  state (default 1), so the default is written as program 0, Acoustic Grand Piano, which a General MIDI
  player assumes anyway.

## Format changes

None to projects. The exported file changes: division 128 -> 480, track 0 is now the conductor track,
each instrument track gains a program change and its own channel, and per-track tempo events are removed
(they moved to track 0). Pattern-editor (beat+bassline) instrument tracks use the same identity code.

## Known limits

Tempo ramps are not exported (the map holds steps only). Notes keep LMMS' 1/48-beat resolution, which
is 10 file ticks, so sub-tick means "positions between the old 128-ppq ticks", not finer than LMMS stores.
Track buffers are growable since round 2: no track is capped or truncated, whatever its size.
`ControlSuccessPaths` (python, `tests/control-success-paths.py`) aborts in `session.stop_all` at line 61,
before any MIDI export; not investigated further here.
