# Q050-051 - Sandboxed Lua module imports

Unit: a script author can reuse Lua source files while imports stay confined to the
script's directory (the package directory for a package).

Starting claim verified: `docs/LUA-PACKAGE-FORMAT.md` documented sibling files, but
`require` was set to nil in `ScriptWorker::openSandbox` (`src/core/ScriptEngine.cpp`) and nothing loaded modules.

## What was built

- `include/ScriptImport.h`, `src/core/ScriptImport.cpp`: `ScriptImport` - name parsing
  (`parseModuleName`), canonical resolution (`resolve`), checked open and bounded read
  (`readModule`), the `require` closure (`requireFunction`/`require`/`runModule`), per-run
  cache in the Lua registry (`zene.imports`), cycle/depth/count/size bounds.
- `src/core/ScriptEngine.cpp`: `ScriptWorker::run` takes an import root and installs `require`
  only when it is non-empty; `runFile` passes the entry script's directory; `runString`
  passes none (no `require`, so `ScriptEngineTest::testSandboxStdlibRemoved` is unchanged).
  `include/ScriptEngine.h`: `runOnWorker` gained the `importRoot` parameter.
- `data/scripts/hello.lua`: its `assert(require == nil)` now asserts the file loaders
  (`package`, `dofile`, `loadfile`) are nil and `require` is the sandboxed function.
- Docs: `docs/LUA-PACKAGE-FORMAT.md` (layout and new section 1a), `docs/LUA-COMPATIBILITY-POLICY.md` item 5.
- Registration: `src/core/CMakeLists.txt`, `tests/CMakeLists.txt`, `tests/fork-sources.txt`, `tests/all-sources.txt`.
- Round-2 hardening: `include/ScriptImport.h:52`, `src/core/ScriptImport.cpp:122` (POSIX handle info),
  `src/core/ScriptImport.cpp:159` (Windows handle info), `src/core/ScriptImport.cpp:196` (post-open validation),
  `src/core/ScriptImport.cpp:312` (identity capture), and `tests/src/core/ScriptImportTest.cpp:289`
  (hard-link regressions).

Design notes: all C++ objects with destructors live in frames that no Lua error can unwind
through (the module body and cache lookup are POD-only functions run under `lua_pcall`; errors
are re-raised after the C++ frame exits). Modules load with mode "t" (no bytecode) and run in
the same globals, so `os`, `io`, `package`, `dofile`, `loadfile`, `load` stay absent. Resolution
saves a file identity from an open handle; the later open must match it and report one link.
POSIX uses device/inode and `fstat`; Windows uses volume/file index and
`GetFileInformationByHandle`. No `std::filesystem`; paths use
`QFileInfo::canonicalFilePath`.

## Known limits

- Symlink tests skip on Windows because creating symlinks needs privileges. Hard-link and device
  basename tests use Windows APIs and are included in the Windows test build.
- The residual TOCTOU between the post-open re-check and the read is bounded by holding the
  open handle: the bytes read are those of the file that was verified.
- A loose script can import the packages under its own directory (they are inside its root).
- `require` returns only the module value (not Lua 5.4's second loader-data value).
- Modules do not carry an `--! lmms-api` header gate of their own.
