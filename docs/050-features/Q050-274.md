# Q050-274 - Touch swipes for comp selection

Unit: S, P2, L03 (comping). Goal: a touch screen can select a take region by swiping along a lane,
using the same selection command as the mouse and keyboard.

## What was built

- `CompSwipeStrip` now accepts touch events (`WA_AcceptTouchEvents`) and handles a single-finger
  `TouchBegin` / `TouchUpdate` / `TouchEnd` / `TouchCancel` sequence in `touchEvent()`.
- The start lane is `laneAt()` at the first press; the range is `tickAt()` at each move. Release
  normalises it to `[min, max)` and commits ONE `comp.select` through the registry, exactly the
  mouse path. A tap (zero-length) and `TouchCancel` clear the preview and commit nothing.
- Touch points are mapped with `mapFromGlobal()` from the point's global position, so the same
  code works with Qt's window-relative touch coordinates under Qt 5.15 and Qt 6.8.
- Accepting the touch sequence also stops Qt synthesising a mouse press for the same finger.
  Mouse press/release are additionally ignored while a touch sequence is live.
- Existing mouse drag and the keyboard comping path are untouched; the mouse release was factored
  through the same `commitDrag()` helper so the two gestures cannot diverge.

No command, schema, undo class, project format or persistence change was made. `comp.select`
remains `true_inverse` with a Track checkpoint; `comp.get_state` remains `not_mutating`.

## Known limits

- Single-finger horizontal swipes only; multi-touch, pinch and other touch surfaces are out of
  scope.
- A swipe commits the lane it starts on even if the finger drifts vertically.
