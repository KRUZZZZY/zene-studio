# Q050-024 - Stream audio between Link peers (P0, L, area L16)

Goal: two instances on a local network exchange audio, independently of tempo, beat phase and start/stop sync.
Operator and network documentation: docs/LINK-AUDIO.md (read it for the limits).

## Decision: our own stream, not Ableton LinkAudio

The vendored Link 4.1 (`src/3rdparty/ableton-link/README.lmms`) says "Not taken: LinkAudio"; its licence
(GPL-2.0-or-later, docs/LINK-SYNC.md section 1) is the project's. LinkAudio's API, wire format and any extra
dependency at the pinned commit could not be read here (no network), so it was not vendored or used - unverified, not
rejected. Link's discovery also gives only a peer count, never addresses, and multicasts (the hermetic-test rule).
So this is a small float32-stereo UDP stream between two addresses the user names. It only connects Zene instances.

* `src/core/LinkAudioStream.cpp` - stream: `process()` (audio thread, line ~`process`), `receivePeriod()` jitter buffer,

* `src/gui/LibraryCommandMenus.cpp` - Sync menu: Link Audio Stream (on/off), Link Audio Peer..., Link Audio Status.
* Docs: `docs/LINK-AUDIO.md`; `docs/LINK-SYNC.md` item 8 now points to it.

## Commands and reversibility

* `link.audio_set_enabled {enabled, peer?, peer_port?, send?, receive?, bind_address?, listen_port?, latency_ms?}` - true_inverse
  (one undo step restores the previous configuration). A refusal (bad literal, range, neither direction, send without peer)
  changes nothing; an OS bind failure restores the previous stream.
* `link.audio_get_state` - not_mutating.
* Snapshot regenerated live: 830 ids / 76 groups (was 828); README canary and the A16 histogram line in
  docs/RELEASE-NOTES-v0.3.0-alpha.md updated (837 -> 839).

## Format changes

None. The stream configuration is session state (like `link.set_enabled`) and is not saved in projects.

## Known limits

* Zene-to-Zene only; not Ableton LinkAudio, not Live/Bitwig.
* Peers are named by IPv4 address; no discovery; default bind is loopback. LAN use needs `bind_address` and the peer address.
* No encryption or authentication; no NAT traversal; one peer.
* No resampling: a peer at another sample rate is dropped and counted. Clock drift is handled by trimming the buffer
  (bounded latency), shown as `trims`/`underruns`.
* Windows: a winsock2 backend exists (`LinkAudioStream.cpp`, `ws2_32` linked in `src/CMakeLists.txt`) but is UNVERIFIED on
  Windows; macOS and Windows were not built here. The Link-active test skips on Windows (the loopback seam is POSIX only).
* Existing Link regressions not re-run: `AbletonLinkInteropTest`, `AbletonLinkSessionTest`, `ControlLinkInterop`,
  `ControlLinkCommandsTest` and `ControlLinkSync` all send a real multicast datagram to 224.76.78.75:20808 (the fallback transport's
  probe, default interface) before testing, so they can leave the host; they were not run.
* TSan does not run on this box; the SPSC design (one producer and consumer per ring, acquire/release counters) is
  reasoned, not measured. Two periods of the engine's real audio thread tapping the process-wide instance are exercised
  by the command tests (Dummy audio engine), not by an end-to-end two-binary test.
* The stream is not exposed in a dedicated dialog; the Sync menu offers on/off, a peer prompt through the command form, and status.
