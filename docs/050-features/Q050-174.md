# Q050-174 - Low-latency monitoring for latent instruments

Unit: P1, M, area L01 (B-MX-159). Goal: users can monitor a latency-producing instrument with less delay while
retaining the normally aligned playback path. Branch: `feat/050-Q050-174-oc` (cut from `050/m0-train-19`).

## What was built

- **Policy** (`src/core/ControlCommandsLowLatency.cpp`): `transport.low_latency` keeps stopping latent *effects* on
  the monitored chains, and now also takes in latent *instruments*. Every instrument track in scope (record-armed
  under the default `scope: armed`, every one under `scope: all`) whose instrument reports more than `max_ms`
  (`AudioBusHandle::sourceLatencyFrames()`, which hosted CLAP/VST3/LV2 instruments fill) is **monitored unaligned**.
  The instrument keeps playing; it is not muted or bypassed. Each call re-evaluates. Off clears exactly the tracks
  the mode set.
- **Engine** (`include/AudioBusHandle.h`, `src/core/AudioBusHandle.cpp`, `src/core/Mixer.cpp`): one
  `std::atomic<bool>` per track handle (`setMonitorUnaligned` / `monitorUnaligned`). While it is set, the handle
  applies a 0-frame PDC delay instead of `channelInputLatency - alignedLatencyFrames`, so the path is heard after
  the instrument's own latency only. Its latency still counts in the graph, so every other path keeps the
  alignment it had. The mixer's clamp check skips such a handle because it applies no delay. The audio thread does
  one relaxed atomic load per period: no allocation, lock, wait, I/O or signal.
- **Result**: a new `instruments` array, one object per path taken: `track` (trk-id), `name`, `channel` (ch-id),
  `path` (`"trk-N -> ch-M"`), `latency_frames`, `latency_ms`, `alignment_skipped_frames`. `bypassed` is unchanged.
- **GUI**: the existing Project > Low-Latency Monitoring On/Off runs the same registered command.
- **Session only**: there is no project field, no undo step, and the command stays `not_mutating`.

## Commands and format

- Changed: `transport.low_latency`. Its description is new, and its result has an `instruments` array. It is still
  `not_mutating`, with the same arguments. The snapshot was regenerated live (868 ids / 76 groups, unchanged).
- Format: none. Nothing new is written to `.mmp`/`.mmpz`, so old projects load and render as before.

## Known limits

- The instrument's own reported latency is still heard. Only the alignment delay on its track handle is removed.
- A PDC delay further downstream still applies, for example on the send from the channel the track plays into to a
  later channel or the master.
- A multi-output instrument's routed output buses (`InstrumentOutputBuses`) keep their alignment.
- `alignment_skipped_frames` is computed from the alignment the mixer last published, which updates once a period.
- Local TSan does not run on this box. The race reasoning is that the flag is a `std::atomic<bool>`, written on the
  control thread and read relaxed once per period by the audio thread. A stale read for one period only shifts the
  delay for that period.
