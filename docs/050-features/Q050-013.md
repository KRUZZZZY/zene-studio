## Known limits
- The warp uses the song tempo at publish time (every launch publishes); a tempo change under a cell that already plays
  applies at its next launch. Tempo-map tempo changes inside a launch are not followed.
- WSOLA follows only periods under 128 frames (about 345 Hz at 44.1 kHz; AudioStretcher.h); lower pitches stretch as plain overlap-add with some pitch drift (measured 91 Hz for a 100 Hz sine).
- Variants are capped at 256 per project; past it the cell plays its file unmodified.
- No GUI control for warp / warp_bpm was added in this unit (the agent command and the saved attributes exist; the grid's
  existing cell editor still shows gain, transpose, detune, loop). BLOCKED for the GUI half: not done, no GUI build verification possible in this lane.
- `ReversibilityContractTest` was not built (no command added).
