# Q050-015 Articulation map editor

Unit: P0, L07 note editing. Create and edit named articulation maps, assign keyswitches, programs and
controllers, and manage the map from the interface. Base `de5a85a96` (train 5), branch `feat/050-Q050-015-oc`.

## What was built

- `src/gui/noteeditor/ArticulationMapEditor.cpp`, `include/ArticulationMapEditor.h`: the editor dialog
  (table of number, name, keyswitch, program, controller, value; New, Duplicate, Move Up, Move Down,
  Remove; cells editable). Every edit is one `track.articulations_set` through `ControlRegistry` (`commit`,
  ArticulationMapEditor.cpp:264); the table is re-read from `track.articulations`.
- Entry points: Track menu "Articulations..." (`src/gui/shell/ShellCommandMenus.cpp:266`) and the note
  editor's Articulation > "Edit Articulations..." (`src/gui/noteeditor/NoteEditorMenus.cpp:148`); both declare
  `track.articulations_set` as their command.
- `src/core/ArticulationRemap.cpp`, `include/ArticulationRemap.h`: `track.articulations_set` takes an optional
  `from` (old 1-based position of each new entry, 0 = new) so notes follow a moved entry and ask for none when
  theirs is removed. `applyArticulationEdit` replaces the map and moves the notes under ONE InstrumentTrack
  lock and returns the clips whose notes changed; the caller emits their `dataChanged` after unlocking
  (`ControlCommandsNotePlayback.cpp:174`). Playback (`InstrumentTrack::play`, `tryLock`) can therefore only
  read the old map with the old indices or the new map with the new ones, never the new map with the old
  indices. Undo and redo go through the same one-lock call. Reply gains `notes_remapped`.
- Order fix found by the playback test (round 1; replaced in round 2, below): the keyswitch's play handle was
  added before the note's, and the engine takes new handles newest first, so its note-on arrived after the note's.
- `tests/src/plugins/MpeTestConsumer.cpp`: the test instrument also logs note-ons, program changes and control
  changes in order (read through `saveState`, reset through `restoreState` with `clearlog`).
- `docs/NOTE-EDITOR.md` section 5a.

## Commands and reversibility

No new command. `track.articulations_set` (true inverse, unchanged class) gains `from`; the commands
snapshot measures 828 ids / 76 groups (unchanged - no command or schema changed in any round), the canary
figures pass (`tests/doc-figures-gate.py` exit 0). Undo covers the map and the notes `from` moved.

## Format

None. The `articulations` attribute of the track element is as before (written only when non-empty);
a note's `articulation` index is as before.

## Known limits

- Without `from`, notes keep their numbers (the previous behaviour). Linked clips on other tracks are not
  re-mapped (they index their own track's map).
- Names are unique case-insensitively in the editor; the command itself still accepts duplicates.
- No per-articulation lead time, colour or note-head.
- The hosted Windows test host cannot load the test instrument module, so `ArticulationPlaybackTest` skips there
  (same as `MpePlaybackTest`).
