# Q050-035 Correct stem separation availability docs

**Unit.** R-platform-26 (`L05`): a user/reviewer must be able to tell that offline HTDemucs stem
separation is built in, local and available by default in the supported configuration. The docs said
the opposite: `docs/KNOWN-LIMITATIONS.md` called it "compiled out of these builds" and reported
`WANT_STEM_SPLIT='OFF'`, while owner decision 14 had already made the option default ON and the
release-honesty manifest row require ON. This is a release-truth error: advertising as absent a feature
the release ships.

## New commands / reversibility / format

- New command **`stem.tracks_create`** (`stem.*`): materialises a completed job's four stems as four
  `SampleTrack`s in the song. Reversibility class **`true_inverse`** (a recorded action checkpoint):
  ONE `control.undo`/Ctrl+Z removes all four tracks; the redo rebuilds them from the job's shared,
  immutable buffers (no XML snapshot, so no base64 audio in the undo record). Registered `mutating`.
- The other seven `stem.*` verbs remain `not_mutating`. The A16 histogram moves
  `837 → 838 rows`, `417 → 418 true_inverse`, and the published `stem.get_state` option row becomes
  `rows=8 true_inverse=1 not_mutating=7` (`docs/RELEASE-NOTES-v0.3.0-alpha.md:1006`).
- The commands snapshot is regenerated from a live no-`wasm` instance: **829 ids / 76 groups**
  (`README.md` canary `828 → 829`).
- Project format: unchanged. Old projects load and render as before; no new persisted data.

## Known limits

- Only the specific current-facing documents were corrected (`KNOWN-LIMITATIONS.md`,
  `RELEASE-NOTES-v0.3.0-alpha.md`, `STATUS.md`, `FEATURE-LIST-0.3.0.md`) plus the active source comments.
  Dated historical records (`docs/COVERAGE-*`, `docs/INTEGRATION-MERGES-*`, `docs/INDEPENDENT-NOTES-READ.md`,
  `docs/RELEASE-NOTES-v0.1.0-alpha.md`, `docs/reports/*`) keep the measurement that was true when they were
  written; the gate scopes itself to the current docs so it keeps passing.
- The input-rate limit is now documented accurately: the **output** is the model's 44.1 kHz; other input
  rates are resampled offline (0.5.0 E27). The GUI writes an in-memory clip (recorded/pasted/generated) to
  a temporary WAV so it still travels through `stem.job_start`; a file-backed clip is passed directly.
- What remains absent from the interface is the agent-facing chrome: no job list, no model manager and no
  menu item/toolbar/keybinding reaches a `stem.*` id — the only click route is the clip context menu.
