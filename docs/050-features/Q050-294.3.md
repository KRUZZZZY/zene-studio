# Q050-294.3 - Melodic step-sequencer view, stage 3/3: seeded step fills (P2, L, L07)

Goal: let a musician or an agent fill a clip's existing step columns with seeded, scale-aware keys, through
one registered command the grid's Fill row also dispatches. Stages 1 (Q050-294.1, `note.step_get_state` /
`note.step_set`) and 2 (Q050-294.2, the grid) are the base this builds on.

## What was built

- `note.step_fill` (src/core/ControlCommandsNoteStepFill.cpp). Arguments: `clip` (required); `kind` `shape` or
  `random`; `contour` `walk`, `rise`, `fall`, `arch` or `valley` (the handler's default is `walk`); `seed`
  (the project's MIDI seed when left out); `spread` 0..12 (default 2); `density` 1..100 % (default 100);
  `step_ticks` (default 12, a sixteenth); `low` / `high` (default 48 / 72); `root` and `scale` optional
  (named scale, custom scales too, without changing the project's scale). The grid's own Fill row starts on
  `arch`; the command's default is `walk`.
- Semantics: the call re-pitches the clip's existing step columns in the resolved scale and keeps a chord's
  shape in scale degrees. Shape moves each column along the contour inside `low`..`high`, moved by up to
  `spread` degrees either way (walk is a seeded random walk). Random picks one in-scale key per column and
  keeps each column with `density` %; the other columns are removed, so random may empty columns. A fill
  never adds notes. The same clip, arguments and seed give the same notes.
- Reply: `clip`, `kind`, `seed`, `step_ticks`, `columns`, `filled` (columns written), `keys` (each one's
  lowest key after the fill), `notes` (the ids still written), `pitched` and `removed`.
- Undo: one MidiClip journal checkpoint per fill (checkpointNoteEdit); none when the fill changes nothing
  (no-op), so `control.undo_depth` does not move.
- Reversibility: TrueInverse row for `note.step_fill` at src/core/ControlReversibilityTableArranger.cpp:146.
  A16 is now 941 = 464 true_inverse / 42 snapshot / 25 irreversible / 410 not_mutating (published in
  docs/RELEASE-NOTES-v0.3.0-alpha.md, commit 06419dae58); the live snapshot is 932 ids / 78 groups
  (commit e4ee3eb32d, README canary follows). The A16 figure was re-derived from ReversibilityContractTest's
  own measured line, because tools/dawproject-a16-histogram.cpp does not link on this tree (pre-existing:
  stub signature drift at :87 vs include/ControlReversibility.h:511, and a missing controller-scripts TU).
- Grid: `StepGridPanel` (include/StepGridPanel.h, src/gui/noteeditor/StepGridPanel.cpp) gained the Fill row
  (`buildFills`): Shape/Random combo, Contour combo (default arch), Seed, Spread (0..12, 2), Density (1..100 %,
  100), and the Fill button (`stepGridFill`, `controlCommand` = `note.step_fill`).

## Entry points

- Edit > Step Grid... and Notes > Tools > Open in Step Grid open the grid (unchanged, `window.step_grid`).
- The grid's Fill button dispatches `note.step_fill` through ControlRegistry.
- An agent sends the same `note.step_fill`.
- The socket driver `ControlFill` (tests/control-fill.py) proves both the agent path and the grid path over the
  real binary.

## Known limits

- A fill re-pitches or empties the clip's existing step columns; it never adds a note. To add notes, use the
  grid's click-to-add or `note.step_set`.
- A clip with no notes is refused as NotFound.
- A grid on No Scale has no scale to fill from and is refused.
- Random ignores `contour` and `spread`; shape ignores `density`.
- The handler's default contour is `walk`; the grid's Contour box starts on `arch`.
- `note.generate_melody` is unchanged.
- Everything runs on the control thread; nothing runs on the audio thread.
- The A16 histogram tool does not link on this tree (pre-existing, see above), so the figure is re-derived from
  the contract test's measured line rather than the tool.
- The `complexity` ratchet flagged three functions this branch added: `lmms::stepFill` (CCN 28) in
  src/core/ControlCommandsNoteStepFill.cpp, and `agrees` (CCN 14) and `check_shown` (CCN 11) in tests/control-fill.py.
  They are now split into helpers with behaviour unchanged: `readFillArgs`, `planFill`, `fillReply` and the others
  in the command file; `same_ids`, `row_agrees`, `reads_agree`, `check_reads_agree` and `check_grid_shows_fill` in
  the driver. feature_check (log 054-feature-p12, exit 0) now reports `RESULT: PASS`: complexity, file-length and
  the other six gates all pass.
