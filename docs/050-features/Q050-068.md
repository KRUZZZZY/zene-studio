# Q050-068 - Keyboard traversal through mixer controls

Unit: P1, M. Goal: move through mixer strips and controls with predictable keyboard focus and
accessible names.
Branch: `feat/050-Q050-068-oc`, cut from `050/m0-train-8` (`2da2ed356`).

## What was built

- `src/gui/MixerChannelView.cpp:266` (`keyboardFocusOrder`): each strip's eligible controls in the
  order the eye reads them - send knob, solo, mute, pan, rack macros, fader - filtered to what is
  visible and enabled in the mixer's current view/density/filter mode.
- `src/gui/MixerChannelView.cpp:307` (`handleTraversalKey`): Tab and Shift+Tab walk that list and
  wrap inside the strip (`moveFocusWithinStrip`, `:317`); Ctrl+Tab and Ctrl+Shift+Tab search the
  adjacent visible strip for the control with the same identity (`moveFocusToAdjacentChannel`,
  `:328`). At the first or last channel the command consumes the key and leaves focus and selection
  in place - it never wraps between channels. If the same control is not available on the adjacent
  strip (a send knob hidden in that mode, a rack with fewer macros), the nearest position in that
  strip's eligible list is used.
- `src/gui/MixerChannelView.cpp:248`: a `FocusIn` on any strip control selects that strip, so the
  mixer's existing Left/Right and Up/Down shortcuts and the contextual send knob target the strip
  the keyboard is in, not the one clicked earlier.
- `src/gui/MixerChannelView.cpp:358` (`updateAccessibleNames`): Mute, Solo, Pan, Fader and Send are
  named with their channel ("Mute Lead"); the strip itself keeps the channel's name and the macro
  container is named "Macros of Lead", so repeated control names are told apart through Qt's
  accessibility layer. Names follow a rename (`syncName`, `renameFinished`).
- No new command, project data, undo step or persistence: this is GUI focus state only.

## Commands and format

No command was added or changed. Focus movement is not a project edit: there is no
`ControlRegistry` command, no undo step and no reversibility row. The mixer already exposes its
controls to agents through their own commands (`mixer.set_volume`, `mixer.set_mute`, ...); agent
mixer navigation and screen-reader certification are out of scope for this unit. No project format
changed; old projects load and render as before (no data is written).

## Known limits

- Tab wraps inside the focused strip by design; Ctrl+Tab is how a keyboard user moves between
  channels, and it does not wrap at the mixer's first or last channel.
- A control hidden by the current view/density/filter mode is skipped; when the adjacent strip
  lacks the same control, its nearest eligible control receives focus.
- The accessibility results are asserted through Qt's bridge (`QAccessible`); no real screen reader
  (NVDA, VoiceOver, Orca) was run, as recorded in `docs/KNOWN-LIMITATIONS.md`.
- The traversal is GUI-thread work only; it does not touch the audio thread.
