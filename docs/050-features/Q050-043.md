# Q050-043 - Bound SessionTuning reader retries

Type: fix (P0, size S). Member: R-performance-29. Area: L15.

## What was built
- Product code was already fixed before this unit: `SessionTuning::commit()` drops the writer claim bit before it flips the
  front slot, and holds `m_writeMutex` across claim, publish and release (`src/core/SessionTuning.cpp`, commit()).
  The audio reader `acquireReadSlot()` (`include/SessionTuning.h`) takes no lock and does not allocate.
- This unit adds test evidence only (`tests/src/core/SessionTuningPublicationTest.cpp`):
  1. `readerReturnsWhileWriterIsPausedAfterPublication` now also asserts the reader's `isActive()` + `noteToFreq()`
     calls make zero allocations (`AllocationProbe`, thread-local counter) while the writer is paused.
  2. New `readersKeepProgressingUnderPublicationStress`: the writer republishes 2000 times
     (`setNoteFrequency(60, 450)` then `reset()`, each with a changing source string) while a reader loops on
     `noteToFreq(60)`. Every read must be 0 or 450 (no torn value). The reader must advance by 1000 reads during the
     writes and by 1000 more after them, within 10 s each.
