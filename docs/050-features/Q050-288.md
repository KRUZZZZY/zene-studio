## What was built

The cited KNOWN-LIMITATIONS section called the destructive sample editor "socket-only, no
interface" and claimed "there is no range/selection model" and "a fade therefore always spans the
whole clip". All three claims were stale: the Sample Editor dialog, its eight range buttons and the
registered `sample.edit_range` command had landed. The section is rewritten around what the tree
actually implements, and the agent-facing command descriptions that repeated the same stale claim are
corrected.

- `docs/KNOWN-LIMITATIONS.md:2333-2372`: the section now documents the Sample Editor's selected-range
  operations - the GUI buttons **-3 dB**, **+3 dB**, **Silence**, **Delete**, **Reverse**,
  **Fade In**, **Fade Out**, **Crop** and their `sample.edit_range` `op` values `gain` (with
  `gain_db`), `silence`, `delete`, `reverse`, `fade_in`, `fade_out`, `crop` - and states the real
  bounds: range gain applies **no limiter**, the destructive fades are **linear** (no curve choices),
  and the range tools have **no noise reduction** (`sample.edit_range` registers no denoise
  operation; the plug-in denoiser is a separate effect, not a range operation). It keeps the
  whole-source **Process** menu bakes (`sample.normalize`, `sample.amplify`, `sample.reverse`,
  `sample.fade`), `sample.generate` behind **Insert Test Signal...**, and distinguishes the editor's
  **Crop** (`sample.edit_range` `op: "crop"`) from **Crop the Sample** (`sample.crop`), with
  `clip.set_fade` / `clip.set_gain` named as the non-baking window controls.
- `data/manual/index.html:155`: the Sample Editor paragraph names the same eight buttons, says Silence
  keeps the range length and Delete closes the gap, states the no-limiter and linear-fade bounds and
  the absent noise reduction, and points at the separate Process-menu bakes and Crop the Sample.
- `src/core/ControlCommandsSample.cpp` and `src/core/ControlCommandsSampleEdit.cpp`: the five
  whole-source commands' descriptions and the file comment said "Socket-only in this release" and
  "no interface reaches them". Each now names its real GUI entry point (`Insert Test Signal...`,
  Process > `Normalize...` / `Amplify...` / `Reverse` / `Fade`) and points at `sample.edit_range` for
  the selected-range surface; `sample.fade` no longer claims the tree has no range/selection model.
  No id, schema, handler, undo or project-format change - only the description text.
- `tools/mcp-zene-control/zene_control/commands_snapshot.json`: regenerated from a live instance

## Known limits (as the corrected page now states)

- Range gain applies **no limiter**; values past 0 dBFS stay.
- The destructive range fades are **linear**; there are no curve choices.
- The Sample Editor has **no noise reduction** range operation (the plug-in denoiser is a separate
  effect).
- The whole-source Process bakes refuse a clip playing a trimmed `srcin/srcout` window; the range
  operations do not.
