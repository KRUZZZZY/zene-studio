# Q050-048 - bound browser feature analysis to the analysis window

Unit: large audio files cost memory and decode time proportional to the analysed window (BrowserFeatures::FeatureSeconds, 20 s),
while the browser still reports the full-file duration.

## Built
- `SampleDecoder::decodeLimited(path, maxSeconds)` (include/SampleDecoder.h, src/core/SampleDecoder.cpp:202 onward, entry point :354):
  tries libsndfile, then Ogg Vorbis, then DrumSynth, as decode() does. It allocates and decodes only the leading window and
  returns the file's full length in frames (`BoundedResult::totalFrames`).
  - libsndfile: length from the header (`sfInfo.frames`). If the header carries none (frames 0 or unknown, e.g. a streamed WAV),
    the rest is counted by reading through a 64K-frame scratch chunk, so memory stays bounded and the duration is still true.
  - Ogg Vorbis: `ov_pcm_total` (last page granule position); only the window is read.
  - DrumSynth: synthesised whole by nature, then cut to the window (known limit; DS files are short).
- `BrowserFeatures::analyse` (src/core/BrowserFeatures.cpp:123) uses it; duration = totalFrames / rate.
- decode() and all existing callers (clips, preview, peaks) are unchanged.

## Commands, format changes
None.

## Known limits
- OGG/FLAC lengths are as the container states them; a Vorbis stream without a seekable length is refused by the bounded path and falls to the DrumSynth decoder (which refuses too), same as decode() would effectively.
- The no-length fallback in libsndfile (sfInfo.frames == 0 with data present) was not reproducible with a real file here; libsndfile itself derives the length for the streamed-WAV case tested.
- DrumSynth is not bounded in memory.
