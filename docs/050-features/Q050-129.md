# Q050-129 — Follow arranger selection in the mixer

The mixer's **Selected** filter can follow the focused arranger track and its
channel. With **Follow Selection** on, selecting a track or a clip re-lays the
visible strips at once: the focused track's mixer channel stays beside the
master. The manual Selected set is not overwritten, so turning following off
brings back the channels picked with **Pick…** or Ctrl+click. The preference is
kept in the user's configuration (`ui/followchannel`, off when absent), never in
the project, and `window.mixer_view` sets and reports it.

## Commands

`window.mixer_view` gains the boolean `follow_selection` argument and the
`follow_selection` and `visible_channels` result fields. The filter itself is
unchanged; `visible_channels` reports what `shows()` would draw now, master
included. Interface state: nothing is journalled, so the command's A16 class
stays `not_mutating` (its existing row in
`src/core/ControlReversibilityTableMixing.cpp`).

## Format changes

None. The preference lives in the user configuration (`ui/followchannel`);
projects gain no new saved data.

## Known limits

The selection is one focused track (or the owner of one focused clip), matching
`ShellSelection`; multi-track selection and a filter over every arranger-visible
track are out of scope. The manual Selected set is interface state, as it was
before this change: a project change forgets it (the preference does not).

While following, nothing to follow (no selection, a track playing straight into
the master, a track with no mixer channel, a removed track) shows the master
alone; the manual set is not used as a fallback until following is turned off.
Removing the selected track emits no selection change, so its strip goes at the
view's next periodic sync (at most half a second).
