# Cluster ci-12f4249981b085d6 - macos-arm64: `snprintf` undeclared in the VST2 test fixture

**Verdict: REAL, fixed.** The hosted `macos-arm64` build on the train commit
`a1a98b67b2f9c961fd6e79c078815b4aedaa8695` failed while compiling
`tests/data/vst2-test-instrument/vst2-test-instrument.c`:

```text
tests/data/vst2-test-instrument/vst2-test-instrument.c:173:2: error:
call to undeclared library function 'snprintf' ...
note: include the header <stdio.h> or explicitly provide a declaration for 'snprintf'
```

The file already includes `<stdio.h>` (`vst2-test-instrument.c:50` since its first
commit `b63ef18dd6`), so the include was not missing. The cause is the feature-test
macro immediately above it.

## Evidence

- Before the fix, `tests/data/vst2-test-instrument/vst2-test-instrument.c:46-48`
  defined `_POSIX_C_SOURCE 199309L` for `nanosleep` and nothing else. On Darwin a
  POSIX source level without `_DARWIN_C_SOURCE` pins `__DARWIN_C_LEVEL` to the
  restricted POSIX set, and Darwin's `<stdio.h>` declares the C99 functions
  (`snprintf`) only at the full level. That is exactly the reported error.
- Linux did not see it: glibc defines `__USE_ISOC99` from `__STDC_VERSION__` even
  when `_POSIX_C_SOURCE` is 199309 (`/usr/include/features.h:283-288`), so
  `stdio.h:392` still declared `snprintf`. Only the macOS job failed.
- The tree already uses the proven remedy: `src/core/CrashReporter.cpp:33-37`
  defines `_DARWIN_C_SOURCE` under `__APPLE__` after `_XOPEN_SOURCE`, with the
  hosted-run comment that the extension macro "brings them back". The same guard is
  applied here.
- No product C++ code, audio-path code, command, undo path or saved data is
  involved. The fixture is a test plug-in that is never installed.

## Fix (`tests/data/vst2-test-instrument/vst2-test-instrument.c:46-56`)

```c
#ifndef _WIN32
#define _POSIX_C_SOURCE 199309L  /* nanosleep */
// _POSIX_C_SOURCE alone hides Darwin's C99 declarations (<stdio.h>'s snprintf:
// macos-arm64 "call to undeclared library function 'snprintf'", cluster
// ci-12f4249981b085d6); _DARWIN_C_SOURCE restores the full header. Apple-only,
// so glibc's feature visibility is untouched.
#if defined(__APPLE__) && !defined(_DARWIN_C_SOURCE)
#define _DARWIN_C_SOURCE
#endif
#endif
```

`nanosleep` stays available (it is POSIX.1b, the reason for the original macro);
`_DARWIN_C_SOURCE` is Apple-only, so glibc, mingw/winegcc and the native Linux build
keep exactly the visibility they had. The Wine PE build stays inside `_WIN32` and
never reaches this block.

## Regression test (`tests/vst2-fixture-darwin-headers-check.py`, ctest `Vst2FixtureDarwinHeaders`)

The check compiles the **real fixture source** twice with the host C compiler:

1. **normal path** - system headers, unchanged: must compile (pins the Linux build).
2. **failure path** - `-D__APPLE__ -D__MACH__` plus a fake `<stdio.h>` ahead of the
   system headers that models Darwin's rule: `_POSIX_C_SOURCE` without
   `_DARWIN_C_SOURCE` hides `snprintf`; the fixture must define `_DARWIN_C_SOURCE`
   (or not restrict the level) to compile. Before the fix this reproduces the hosted
   error at the same line, `vst2-test-instrument.c:173: implicit declaration of
   function 'snprintf'`.

It is deterministic - two compiler runs over fixed inputs, no timing, sleeps or
races, and the fake header lives in a fresh temporary directory. Registered in
