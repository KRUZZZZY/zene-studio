## Cause (file:line)

`ClientIdleTimeoutMs` is a static member of `lmms::ControlServer`
(`include/ControlServer.h:96`), not a namespace-scope constant. The test has
`using namespace lmms;` (`tests/src/core/ControlShutdownHookTest.cpp:90`), but a
using-directive never imports a class member, so the unqualified name cannot resolve.

The two Windows-only cases in `tests/src/core/ControlShutdownHookTestParts1.h` used it
unqualified at lines 149, 155, 161, 169, 196 and 209. Their sibling in
`ControlShutdownHookTestParts2.h:132,134` already spells
`ControlServer::ClientIdleTimeoutMs`, which is the intended contract. Both cases sit
inside `#if defined(Q_OS_WIN)`, so the Linux build preprocesses them away and only the
Windows lane observes the error.

## Fix

Qualified all six references in `ControlShutdownHookTestParts1.h` as
`ControlServer::ClientIdleTimeoutMs`. No product code, API, limit, save format or
behaviour changed: the fix is confined to the test-support header that only
`ControlShutdownHookTest.cpp` includes (verified: no other translation unit names
`ControlShutdownHookTestParts1.h` or `Parts2.h`).

Completeness check: `grep -rn` over `tests/src` for `ClientIdleTimeoutMs`,
`MaxClients`, `MaxQueuedReplyBytes` and `MaxRequestLineBytes` shows no other
unqualified use; every remaining reference to a `ControlServer` bound is qualified.
