# Cluster ci-165e1914b308f189 — windows-arm64: `template` keyword without an argument list in vendored atomic_queue

**Verdict: REAL, fixed.** The hosted `windows-arm64` build failed on
`plugins/SfzPlayer/sfizz/external/atomic_queue/include/atomic_queue/atomic_queue.h` while compiling
sfizz's `FilePool.cpp` and `Synth.cpp`:

```
atomic_queue.h:394:31: error: a template argument list is expected after a name prefixed by the
template keyword [-Wmissing-template-arg-list-after-template-kw]
  394 |         return Base::template do_pop_any(states_[index], elements_[index]);
4 errors generated.
```

## Decision: REAL (product/build defect in a vendored header the fork ships)

- `plugins/SfzPlayer/sfizz/src/sfizz/FilePool.h:364` declares
  `using FileQueue = atomic_queue::AtomicQueue2<QueuedFileData, config::maxVoices>;`, and every sfizz
  translation unit that includes `FilePool.h` instantiates it: the CI log names `FilePool.cpp` and
  `Synth.cpp`, and `grep -rn "FilePool.h" plugins/SfzPlayer/sfizz/src` covers the rest.
- `AtomicQueue2` (`atomic_queue.h:391-401`) and `AtomicQueueB2` (`:519-529`) called their base's member
  templates as `Base::template do_pop_any(...)` / `Base::template do_push_any(...)`: the `template`
  keyword with no explicit template argument list after the name. The standard only permits (and
  requires) the keyword when an explicit argument list follows (`x.template f<T>()`); with the
  arguments deduced the keyword makes the program ill-formed. Clang enforces it as an **error**
  (`-Wmissing-template-arg-list-after-template-kw`), so the CI line's `-Wno-error` cannot waive it.
- Reproduced on this box with the real CI compile command. `build/compile_commands.json`'s
  `FilePool.cpp` command, re-run with `clang++` (23.1.4) instead of the configured GCC, exits 1 with
  exactly the four CI diagnostics (`build/qwen-logs-ci-165e1914b308f189/1-clang-filepool-before.log`).
  A bare `#include "atomic_queue/atomic_queue.h"` is enough to trigger it on Clang, so this is not a
  caller-specific defect. GCC 16.2.1 accepts the construct (exit 0), which is why the Linux CI job
  stayed green and only the Clang-based windows-arm64 job saw it.
- Classification: **product** (the fork ships and builds this header; the failure is in the source it
  compiles, not in CI infrastructure or a test). It is also a real conformance bug, not just a warning:
  upstream atomic_queue removed the construct when it restructured these functions (v1.9.0 tag has no
  `do_pop_any`/`do_push_any`; the vendored copy is the sfizz 1.2.3 pin).
- Siblings checked: `grep -rn --include=*.h --include=*.hpp --include=*.cc --include=*.cpp
  --include=*.cxx --include=*.c -E '::template\s+[A-Za-z_]\w*\s*\(' src include plugins tests modules
  tools` returns exactly these four lines and nothing else in the tree; the sibling calls that DO pass
  an explicit argument list (`Base::template do_pop_atomic<T, NIL>`, `do_push_atomic<T, NIL>`,
  `std::allocator_traits<A>::template rebind_alloc<...>`, `spec.bounds.template to<int64_t>()`) are
  well-formed and untouched.

## Fix (smallest, at the cause)

`plugins/SfzPlayer/sfizz/external/atomic_queue/include/atomic_queue/atomic_queue.h:394,400,522,528`:
drop the keyword before the deduced call, `Base::template do_pop_any(` → `Base::do_pop_any(` and
`Base::template do_push_any(` → `Base::do_push_any(`. `Base` is the current instantiation's base, so
the unqualified-through-base lookup resolves to the same function: no semantics, no code generation,
no realtime or save/load behaviour changes. The well-formed `template` uses with explicit argument
lists on lines 353, 358, 438, 443, 415, 423, 506 stay as they are.

`plugins/SfzPlayer/LICENSE-NOTICE.md` said the vendored tree was unmodified; it now records the two
declared local changes (the sfizz render-callback change that was already there, and this keyword fix),
and `tests/upstream-modifications.txt` records the header's one declared local change and why.

## Regression test

New `tests/clang-template-keyword-check.py`, registered as ctest `ClangTemplateKeywordCheck` in
`tests/CMakeLists.txt` (one `add_test`, one `TIMEOUT`). Two halves, both deterministic, no network, no
wall clock:

1. **Source scan** of every `git ls-files` C/C++ source for `::template name`, `.template name` or
   `->template name` where `name` is not followed by `<` (comments and string/char literals blanked
   first so prose does not count). This half is red on GCC hosts too, which is the point: the local
   suite must catch a construct only Clang rejects.
2. **Compile probe**: if the supplied compiler rejects a known-bad fixture (Clang does, GCC does not),
   the real `atomic_queue.h` is compiled through a probe that instantiates `AtomicQueue2` and
   `AtomicQueueB2` with `try_push`/`try_pop`. On GCC the probe reports "skipped" and half 1 is the
   authoritative check; on Clang the probe compiles the real header.

The file's own `--self-test` fixtures are the red/green control: a bad fixture must be flagged at the
expected lines (4 findings on lines 6, 12, 17, 17) and a good fixture (deduced call, explicit
`template f<T>()`, `typename ...::template rebind_alloc`, prose) must be clean. It runs as part of the
ctest test, so a scanner that cannot fail fails the test.
