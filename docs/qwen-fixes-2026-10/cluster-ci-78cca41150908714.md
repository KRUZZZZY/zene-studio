# cluster ci-78cca41150908714 - builds without FFmpeg could not compile the multi-clip video tests

## Verdict

**REAL** - a test-source portability defect, not product behaviour and not infrastructure. The hosted
`build / macos-x86_64` job at `cc29a63dde09cf28bb00498a2d2a5b124d4d614d` compiles the video tests in a
configuration without `ZENE_HAVE_FFMPEG`. `tests/src/core/VideoTestClip.h:50` opens the FFmpeg-only block,
`:228` defines `videotest::makeClip` inside it, and `:237` closes it, so the helper does not exist in that
configuration. `tests/src/core/VideoClipsTest.cpp:530` called it unconditionally, which is exactly the CI
diagnostic:

    VideoClipsTest.cpp:530:33: error: 'makeClip' is not a member of 'videotest'
    VideoClipsTest.cpp:530:60: error: 'makeClip' is not a member of 'videotest'

The same unguarded helper call existed in the GUI sibling `tests/src/gui/VideoClipsGuiTest.cpp:337`; the CI
log stopped at the first failing target, so the hosted job would have failed there next. Every other caller
is already inside the same `#ifdef ZENE_HAVE_FFMPEG` guard:

- `tests/src/core/VideoTrackTest.cpp:298-306` (the sibling `needClip()` the fix follows)
- `tests/src/core/VideoTrackTestParts1.h:233-236`
- `tests/src/core/VideoFfmpegTest.cpp:65-69` and `:94-98`
- `tests/src/gui/ArrangerOverlaysVideoLaneTest.cpp:400-404`
- `tests/src/core/VideoTestClipTest.cpp:104-110`

## Cause and fix

`needClips()` already returns early when `VideoDecoder::available()` is false, so the helper is never called
at run time in a no-FFmpeg build; only the compile-time reference was missing. Both `needClips()` functions
now guard the clip construction with `#ifdef ZENE_HAVE_FFMPEG` and return `false` otherwise, matching
`VideoTrackTest::needClip()`. The FFmpeg branch is byte-for-byte the previous code, so the multi-clip
acceptance path (identity/offsets/metadata across save and reopen, legacy one-`<video>` load, `project.new`
clearing, one undo step per edit, playback frame selection without stale frames, and `video.render_frames`
across clips and gaps) is unchanged. With no FFmpeg the existing `QSKIP("no FFmpeg in this build, or the test
clips could not be made")` path is preserved.

Changed:

- `tests/src/core/VideoClipsTest.cpp:524-539`
- `tests/src/gui/VideoClipsGuiTest.cpp:331-346`
- `tests/CMakeLists.txt:9317-9333` registers `VideoClipsNoFfmpegCheck` (CTest #977)
- `tests/VideoClipsNoFfmpegCheck.py` (new regression check)

## Regression test

`tests/VideoClipsNoFfmpegCheck.py` reads the build's `compile_commands.json`, takes the real command line for
each of `tests/src/core/VideoClipsTest.cpp` and `tests/src/gui/VideoClipsGuiTest.cpp`, and compiles each one
twice with syntax-only: as configured, then against a shadow `lmmsconfig.h` whose `#define ZENE_HAVE_FFMPEG`
line is removed. Two fixtures prove the shadow actually takes effect in both directions (the configured header
still defines the macro; the shadow removes it). The unit is generated with the configured Qt moc. Missing
`compile_commands.json`, entry or moc exits 2 instead of passing. No timing, sleep or race is involved: the
only inputs are the recorded compile line and the shadowed configuration header.
