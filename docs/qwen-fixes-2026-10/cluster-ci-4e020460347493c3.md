# Cluster ci-4e020460347493c3 - macOS: RemotePluginBase.h's shm-FIFO branch has no getpid()/usleep() declarations

Train 050/m0-train-27, base 0c3b9e3c23 (`050/m0-train-27`). Evidence:
`~/.local/share/zene-bunny-fix/qwen/train-ci/0c3b9e3c23434f269526f189c02e88698ce63ec5/run-43076107122-job-130716216083.log`
(macos-arm64) and `...-130716216442.log` (macos-x86_64).

## Verdict: REAL - one build defect in the header, reproduced by the fork's own probe

The two macOS CI jobs stop in the same three lines:

```
include/RemotePluginBase.h:145:30: error: use of undeclared identifier 'getpid'
include/RemotePluginBase.h:146:33: error: use of undeclared identifier 'getpid'
include/RemotePluginBase.h:451:4:  error: use of undeclared identifier 'usleep'
```

Cause (this branch, current lines):

- `include/RemotePluginBase.h:48-51`: when `LMMS_HAVE_SYS_IPC_H`/`LMMS_HAVE_SEMAPHORE_H` are not both
  defined, the header selects the shared-memory FIFO itself and defines `SYNC_WITH_SHM_FIFO`. macOS has no
  `<sys/ipc.h>`, so this is the **product** branch there, not a test-only branch.
- `include/RemotePluginBase.h:153-154` call `getpid()` and `include/RemotePluginBase.h:459` calls `usleep()`
  inside that branch. Before this fix the branch included only `<process.h>` when
  `LMMS_HAVE_PROCESS_H` was set (`:53-55`). `<unistd.h>` was included only in the *other* branch
  (`:64-67`), and the socket path's `<unistd.h>` (`:82`) is behind `#ifndef SYNC_WITH_SHM_FIFO`, i.e. not
  compiled exactly when the shm branch is.
- `tests/src/core/RemotePluginShmFifoNoSysIpcProbe.cpp` built this branch on every host through the shadow
  `lmmsconfig.h` at `tests/CMakeLists.txt:3050-3051` (`#undef LMMS_HAVE_SYS_IPC_H`). It papered over the
  missing declaration with `#ifdef __unix__ / #include <unistd.h>` at its old lines 20-22. Apple clang
  defines `__APPLE__` and `__MACH__`, **never** `__unix__` (verified: `clang -target arm64-apple-macos14
  -dM -E -` prints `__APPLE__`/`__MACH__` and no `__unix__`), so on macOS the probe got the header's raw
  error. Linux always defined `__unix__`, which is why this box and the Linux jobs were green.

Not a test-only defect: the same header is the first include of `src/common/RemotePluginBase.cpp:25` and is
pulled in by `include/RemotePlugin.h`, `include/RemotePluginClient.h`, `src/gui/MainWindow.cpp`; every macOS
TU that includes it before any `<unistd.h>` would hit the same three errors. CI simply reached the probe
first.

The third CI line quoted in the finding (`ranlib: ... the table of contents is empty`) is a warning on
`libabsl_bad_optional_access.a`, printed after `Built target absl_bad_optional_access`; it is not the
failure and is not touched here.

## Fix (smallest, at the cause, no behaviour change)

`include/RemotePluginBase.h:56-63`: the shm-FIFO fallback branch now includes `<unistd.h>` itself when
`lmmsconfig.h` reports `LMMS_HAVE_UNISTD_H`. No other line of the branch changes; the socket branch keeps
its existing include; Windows has no `LMMS_HAVE_UNISTD_H` and keeps `<process.h>` only. No macro, flag or
data-format change, so old projects and saved data are untouched.

## Regression (fails without the fix, passes with it)

`tests/src/core/RemotePluginShmFifoNoSysIpcProbe.cpp` no longer includes `<unistd.h>` itself (the
`#ifdef __unix__` crutch is removed; its comment now states why). The probe is compiled into
`RemotePluginShmFifoTest` on every platform (`tests/CMakeLists.txt:3050-3061`), so a host build now compiles
`RemotePluginBase.h`'s shm branch with exactly the declarations the header provides - the macOS contract.
Without the product fix that TU fails to compile with the CI's own two identifiers; with it, it compiles and
the target's runtime slots run.

The proof is a pure compile contract: no wall clock, no sleeps, no injected timing (the target's existing
runtime slot `headerKeepsTheBuildsShmFifoDefinitionWithoutSysIpc` is unchanged).

Also checked by hand with Apple's predefine set, same TU/flags as the target:
`c++ -U__unix__ <target defines/includes/flags> -c tests/src/core/RemotePluginShmFifoNoSysIpcProbe.cpp`:
exit 1 with 2 errors before the fix (logs 22), exit 0 after (log 24).
