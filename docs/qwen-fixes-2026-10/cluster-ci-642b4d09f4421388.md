## The fix (4 files, 71 insertions)

1. **`src/core/ControlCommandsScript.cpp`** — the reported cause. The include is
   now inside `#if QT_VERSION >= QT_VERSION_CHECK(6, 0, 0)`, and the chunked
   hash loop (`:100-113`) uses the Qt 5 `QByteArray` overload in the `#else`
   branch. This is the exact sibling pattern already used by
   `src/core/ControlCommandsWasmRender.cpp:40-42,89-95` and
   `src/core/ControlProjectAssets.cpp:70-72,568-572`; the comment there
   ("Qt 5 (hosted CI) has no QByteArrayView") is the precedent.
2. **`tests/src/core/ControlAutomationScriptTest.cpp`** — same guard; the Qt 5
   branch of the expected-hash loop uses `addData(constData(), int)`.
3. **`include/TelemetryConsentDialog.h`** — `#include <QVariant>` beside
   `<QDialog>`; no behaviour change.
4. **`src/core/OscBridge.cpp`** — `qFromBigEndian<quint64>`; `quint64` and
   `std::uint64_t` are both 8 bytes, so the decoded value is unchanged.

No command was added, removed or reordered, so `ControlCommandsSnapshot` is not
regenerated. No audio-thread code was touched.

## The regression test

`tests/src/core/ControlAutomationScriptTest.cpp::scriptListHashesTheChunkBoundaries`
(new, in the existing test binary). It writes three scripts — 0 bytes, exactly
64 KiB, and 64 KiB+1 — and requires `script.list` to report the SHA-256 of the
bytes each file actually holds. The expected digests are **not** computed with
the product's own hasher; they are the `sha256sum` values of 0 / 65536 / 65537
zero bytes, so a fix that hashed the wrong bytes would fail here too:

```
0      e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
65536  de2f256064a0af797747c2b97505dc0b9f3df0de4f489eac731c23ae9ca9cc31
65537  3266304f31be278d06c3bd3eb9aa3e00c59bedec0a890de466568b0b90b0e01f
```

The whole `ControlAutomationScriptTest` binary is the regression: without the
product fixes it does not compile on Qt 5 (RED), with them it builds and all 13
slots pass (GREEN). The pre-existing slots
`scriptListShowsTheShippedScripts` (small files), `anUnreadableScriptIsListedWithAnEmptyHash`
(unreadable file) and `scriptListHashesScriptsLargerThanControlDataLimit`
(64 MiB+1, multi-chunk) run unchanged and pass on both toolchains.
