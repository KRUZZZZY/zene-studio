## Item 1 — 893a28421 (cluster 5513): FIXED

The original commit ordered input ports main-first for the transport's channel layout, but `HostedPlugin::Impl::runChunk`
(`plugins/ClapEffect/ClapHost.cpp`) still filled `inBuffers[p]` in that sorted order. A plug-in reads `audio_inputs` by its
own port index. The SDK says the main port is index 0 (`build/clap/include/clap/ext/audio-ports.h:27`, "Main port must be at index 0").
The header says nothing about plug-ins that break that rule. The inference that such a plug-in still reads its buffers by
index, so the side-chain signal landed on its main port, is ours, not the SDK's. The existing test covered a malformed descriptor only.

Fix (no rejection; original-index mapping):
- `ClapBusMap.h` / `ClapBusMap.cpp`: each mapped input keeps its plug-in input index (`inputPortIndices`); `pluginInputPorts`
  records the plug-in's full input port count.
- `ClapHost.cpp` `runChunk`: each buffer is written at its plug-in index.
- `ClapHostLifecycle.cpp` `prepare`: `inBuffers` is sized to `pluginInputPorts`, so ports the channel budget dropped keep a
  zeroed buffer instead of shifting the others.
- Channel placement in the transport is unchanged; the existing assertions in `ClapBusMapTest` are preserved.

Proof: `ClapBusMapTest` red with `ClapBusMap.cpp`, `ClapHost.cpp` and `ClapHostLifecycle.cpp` reverted to pre-fix
(`pluginInputPorts` and `inputPortIndices` unpopulated): `Actual (layout.pluginInputPorts): 0`, EXIT=8. Green after restore: EXIT=0
(`ctest -R '^ClapBusMapTest$'`); `ClapHostTest|ClapLoaderErrorTest|ClapEffectIntegrationTest` EXIT=0.

Not covered in batch 1: the host-side buffer placement in `runChunk`. Round 2 closes this (see below, commit ca43ed0c4).

## Item 2 — 635d5300e (cluster 4691): FIXED, original claim corrected to NOT-A-DEFECT

The original claim was that a flush an active plug-in requested was dropped. The SDK does not require a flush here:
- `build/clap/include/clap/ext/params.h:297-301`: while the plug-in is processing, the `process()` call already achieves the
  parameter update, "so a call to flush isn't required".
- `build/clap/include/clap/ext/params.h:373-375`: request_flush makes the host schedule a call to either `process()` or
  `params.flush()`.

The request was answered by `process()`, which cleared the flag. The added `serviceActiveFlush()` made a second, redundant
`params.flush()` on the audio thread after process, and the test asserted that redundant call (`hostFlushes == 1`). The
"duplicate parameter delivery" was not shown either: `eventState.count` is cleared before that flush.

Fix:
- `ClapHost.cpp` / `ClapHostInternals.h`: `serviceActiveFlush()` removed; the flag clear at the start of `process()` is
  restored (the pre-635 behaviour, review L01-1 #9).
- `tests/data/clap-test-plugin/clap-test-gain.c`: the fixture returns the value it changed on the main thread through the
  next `process()`'s output events (`CLAP_EVENT_PARAM_VALUE`), gated on `CLAP_TEST_GAIN_REQUEST_FLUSH`.
- `ClapHostTest::testAnActiveFlushRequestIsAnsweredByProcess` (renamed from `...IsServicedOnTheAudioThread`): measures the
  returned value through `paramPlain()` (0.75 after the process that answers the request, not before), and asserts
  `hostFlushes == 0`, i.e. the host makes no redundant flush. The `hostFlushes == 0` assertion pins the host's own
  design choice (no redundant work); it is not a requirement CLAP imposes.

Proof: `ClapHostTest` red with the commit's host code (HEAD before af017b9d3): `Actual (state.hostFlushes): 1`,
`Expected 0`, EXIT=8. Green with the fix: EXIT=0 (`ctest -R '^ClapHostTest$'`); `ClapHostTest|ClapBusMapTest|ClapLoaderErrorTest|ClapEffectIntegrationTest`
EXIT=0.

## Item 3 — f21b46179 (batch-01 report): REPORT-CORRECTED

The batch-01 report (`docs/bunny-fixes-2026-10-05/plugins/batch-01.md`) is left as the record of what was claimed. The
corrections are:

- **Cluster 5513 (commit 893a28421).** The report's "Verdict: FIXED" stands for the sidechain-first case, but its evidence
  is incomplete. The report says `ClapBusMap.cpp` "orders input ports by `isMain` and maps the remainder as sidechains". That
  ordering alone swapped port identities, because the host still delivered buffers in sorted order. The corrected fix
  is commit 9a0d25c23 (original-index mapping, see Item 1). Its regression test is
  `ClapBusMapTest::testInputIndicesFollowThePluginsOwnPorts`; the two tests the report names are unchanged and still pass.
- **Cluster 4691 (commit 635d5300e).** The report's "Verdict: FIXED" is wrong. The claim that the active flush request was
  dropped is not supported: `process()` answers the request under `params.h:297-301` and `:373-375`. The corrected verdict is
  NOT-A-DEFECT as originally stated; the commit's extra flush was redundant and is removed by af017b9d3. The test named in the
  report (`testAnActiveFlushRequestIsServicedOnTheAudioThread`) no longer exists; it is now
  `testAnActiveFlushRequestIsAnsweredByProcess`. The report's red/green figures for that test (`Actual 0, Expected 1`) describe
  the original test, not the corrected one.
- **Fixture state.** The report's leftover note says the fixture state block is version 3 (128 bytes). That is still true: the
  `host_flushes` counter stays in the fixture, because the corrected test uses it to assert no redundant flush.
