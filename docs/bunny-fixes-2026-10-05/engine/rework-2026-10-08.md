## Per-item notes

1. **2fa142d5b.** The main load pass rejected `num <= 0`, so master (0) was never loaded. Only a negative
   `num` is refused now. The bus pre-pass still rejects zero, as before (a master cannot be a bus).
   Related runs: only `MixerRoutingBackwardCompatTest` was built and run in this lane.
2. **4d50f628b.** The receiver walk and the sender-only walk shared one visited set. Each direction now
   has its own set (`include/Mixer.h`, `src/core/Mixer.cpp`). The dangling
   `unmuteForSolo(std::set&)` declaration from the original commit is removed. Related: `MixerStripTest` exit 0.
3. **f1a74cc54.** The audio read in `sumSidechainInputs()` now uses a new lock-free
   `AutomatableModel::publishedValueAt()` (`include/AutomatableModel.h`, `src/core/AutomatableModel.cpp`),
   which reads the published ramp and applies the same transform as `valueBuffer()`. It takes no mutex,
   allocates nothing and writes no cache. A period with no published ramp keeps the scalar path.
   **Red proof BLOCKED:** the old path (which takes `m_valueBufferMutex`) gives the same values and zero
   allocations, so no test in this suite fails without the change. A mutex acquisition is not observable
   from a test (the mutex is private, and the RTSan build needs Clang, which this lane does not use).
   The lock-freedom rests on reading `publishedValueAt()`'s callees (`automationRamp`, `AutomationRamp::valueAt`,
   `scaledValue`, `effectiveAutomationValue`, `fittedValue`), none of which takes a lock.
   **Still open, not in this item:** the regular-send path still calls `valueBuffer()` on the audio thread at
   `src/core/Mixer.cpp:526` (volume), `:624` (send) and `:784` (pan), and `valueBuffer()` takes
   `m_valueBufferMutex` at `src/core/AutomatableModel.cpp:554`. This is a pre-existing realtime-rule
   violation, outside this rework.
4. **480fd367e (report).** The batch-07 report is corrected at its top: the master guard, the solo sets and
   the sidechain lock claims were all false when written, and the rework commits that fixed them are named.
5. **1e1ccd541.** `applySends()` now writes each send inside `requestChangesGuard()`, the same change
   boundary `Mixer::createChannelSend()` uses for an existing route. Recall and undo/redo both reach it.
   Related: `ProjectStateTest` exit 0.
6. **2e3ee5581 (report).** The batch-09 report's cluster 1501 "FIXED" is corrected at its top: the recall
   path lacked the change boundary, now fixed in `2ef8d233c`.
7. **390ec761c.** `SessionSlotContentTable::install()` removes an entry when its cell loses its pattern
   (the last entry moves into the hole; a bounded move, no allocation). The header comment now says so, and
   the thread comment is corrected from "model thread" to "audio thread", which is where `install()` runs.
   Related: `SessionPlaybackRenderTest`, `SessionModelTest` exit 0.
8. **4218c1e30.** `MidiClipView::clearNotesOutOfBounds()` and `destructiveSplitClip()` now build their clones
   under `ClipLinks::MirroringSuspension`. The test drives the real song editor through
   `MidiClipView::bulkClearNotesOutOfBounds`. **Split is not verified by a test:** `destructiveSplitClip` is
   private and reachable only through a knife-mode mouse release, and no test drives that. The split is
   covered by the same change in code only. Related: `ClipLinkTest`, `ClipLinkPersistenceTest` exit 0.
   The test is a new GUI test: `tests/src/gui/MidiClipLinkedEditTest.cpp`, registered in `tests/CMakeLists.txt`
   and `tests/fork-sources.txt`.
