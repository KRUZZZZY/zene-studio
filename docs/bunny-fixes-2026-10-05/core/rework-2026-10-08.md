## Item notes

- **1 (dd604aa40).** Only the registry line changed. The "test" is the existence check; it cannot be
  a ctest.
- **3 (230b454d0), BLOCKED.** The length fix holds for the later clip: its fade-in is 20 ticks and
  reaches full gain at its last frame. The earlier clip's fade-out is anchored to its tail
  (`ClipEdits`), so for `[0,100)` with a contained `[20,40)` it still covers `[80,100)`, not the shared
  span. A correct containment crossfade needs an owner decision: split the containing clip at the
  contained clip's end (this changes the moved clip's identity when it is the container), or add an
  offset fade to `ClipEdits`. Not done. Note: the `~0.37` figure in the commit message of e318ae28c is
  a hand estimate; the measured red was the `gainAt(frames - 1) > 0.99` assertion.
- **5 (14cd371ca).** `namesTheSameFile` also asks `std::filesystem::equivalent` (same inode). The
  symlink test body is now under `#ifndef Q_OS_UNIX` with QSKIP. The hard-link test skips only when
  `create_hard_link` fails.
- **8 (f7056046f).** The commit e7278bd34 was made while `file-length-gate.sh --check` was failing
  (505 code lines in DeviceToolsTest.cpp): the gate command's exit was not checked before the commit.
  000ab1155 condenses the test to bring the file back under the ratchet. No threshold was changed.
  Other ParameterAliases callers were not run.
- **10 (02492a165).** Staging uses a unique `QTemporaryFile` sibling, the replacing move is
  `std::filesystem::rename`, and the test seam `setRevisionReplacementFailureForTest` (LMMS_EXPORT,
  test-only, in `include/ProjectRevisions.h`) fails the replacement after the staged copy is complete.
  The seam is the only way to reach that window deterministically. The existing chmod-based shift test
  is unchanged; it runs as uid 1000, not root.
- **11 (be00be4f2).** `replaceProjectWithStaged` no longer removes the live file, and it has no
  fallback copy. The staging file is removed only when the replacement is in place.
  `RevisionTimeline.cpp` removes its own `.timeline-stage` file on a failed replace.
- **13 (6b0f58b0d).** The last frame is held until `position >= size`. The integer-step tests still pass.
- **14 (2fe70d746).** `processMessage` records an out-of-range request in two atomics and a flag. Those
  are written by `RemotePlugin::reportRefusedChannelCounts()`, called from `updateAudioBuffer`,
  `processFinished` and the destructor. The allocation probe alone did NOT catch the HEAD log path,
  because Qt's log path allocates with malloc; the test therefore also counts warnings with a message
  handler. Other audio-path logging in `processMessage` (a removed message id, the debug message, and the
  model write) is unchanged and remains part of cluster 3417.
