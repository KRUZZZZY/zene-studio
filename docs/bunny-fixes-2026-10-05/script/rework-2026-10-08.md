## 51e7da51f — FIXED

The original test could only SKIP, because this build loaded no effect module. The fix does three things:

1. `applyRemoveEffect` (`src/core/ScriptDawEdit.cpp`) journals the removal with `control::journalEffectRemoval`
   before the removal, as `plugin.unload` does. If the device cannot be captured, the device is still removed (as
   the script asked), and the log says the removal is not undoable. No undo step is claimed in that case.
2. The first version of the fix did not pass. Emptying a chain runs `m_enabledModel.setValue(false)`
   (`src/core/EffectChain.cpp`, `removeEffect`), which pushes a checkpoint after the structural step. One
   `journal->undo()` only reverted the enabled flag. The fix now folds the removal's checkpoints into one step with
   `mark = undoDepth()` and `mergeCheckpointsFrom(mark)`, the same mechanism the control registry uses.
3. The test loads the build's BassBooster module: `tests/src/core/ScriptDawBindingTest.cpp` sets
   `LMMS_PLUGIN_DIR` from `LMMS_TEST_PLUGIN_DIR` (as `RackMenuTest` does), and `tests/CMakeLists.txt` adds the
   test to the list that defines that directory. The test now runs (verified with `./ScriptDawBindingTest -v2`:
   PASS, 8 passed, 1 skipped for an unrelated amplifier case).

  `:204-206` through the control socket. The direct C++ path `renderOffline()` still has no upper bound on `frames`,

  output plane through the same cached pointer at about `:270`. Nothing re-resolves it after the call. The pooled
  path has the same stale-pointer shape as the inline path. A fix must cover both, and the report's "pooled path
  re-resolves per block" statement must be removed.
- **Still open, unchanged:** 3648 (sample-rate guard), 5441 (component-wise worst pair), 4562 (ABI version
