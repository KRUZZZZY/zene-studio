Notes:
- The hand-off rollback itself is not exercised by a test. The rollback needs a failure after the
  session copy is written, and no clean failure can be forced there. The dangling-link test checks the
  preflight, which is what protects the link.
- A save over a dangling link is refused as unreadable. Its message says "exists but cannot be read".
- Time scale refuses a whole clip when any tick would not fit. Nothing is changed on refusal.
- The SMF writer refuses a clip with two notes more than 0x0FFFFFFF ticks apart, or a note that
  starts at or past 2^28 after the track start. The save then writes nothing. The message says "delta time".
- The note on the top-tick refusal (review item 969aff1b4 (a)): the refusal blocks the whole clip,
  not just the note that causes it. This is intended and is stated here.
- Not changed: the `cdb96259f` commit message cites only the change lock. The review notes that the
  mutex in `renderNextPeriod` is the actual guarantee, so that rationale is recorded here, not amended.
- Not changed: the library save's redo still re-renders the live clip (review item (d) on 969aff1b4).
- LibraryBrowserTest's `aSaveNeverReplacesAFileItCannotRead` skips for any account that can read a
  write-only file (root). On such a host it reports SKIP, not PASS.
