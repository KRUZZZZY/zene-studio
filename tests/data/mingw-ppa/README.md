# MinGW PPA metadata fixture (cluster ci-3eb9bda8aa6785a3)

`InRelease` is the **real** Launchpad-signed release file of the MinGW PPA the
`mingw64` CI job installs Qt 5 and libgig from:

    http://ppa.launchpad.net/tobydox/mingw-w64/ubuntu/dists/focal/InRelease

It is committed so `tests/mingw-ppa-key-check.sh` can check, offline and
deterministically, that the signing key the workflow vendors is the key the PPA
actually signs its metadata with — instead of trusting a run-time fetch from a
network keyserver.

| attribute | value |
|---|---|
| fetched from | `https://ppa.launchpadcontent.net/tobydox/mingw-w64/ubuntu/dists/focal/InRelease` |
| sha256 | `1d56a54d028396cb1fc79d683fe2c8812e3db6c2e1f1d7f1e02df89c90caf837` |
| signed by | `AD1A987F6AC01FA7B66FB4EB9C0C72C11E0AF891` (Launchpad PPA for Tobias Junghans, 2024) and `72931B477E22FEFD47F8DECE02FE5F12ADDE29B2` (Launchpad PPA for tobydox, 2009 — the key the old workflow fetched by key id) |
| suite | `focal`, component `main` |

`InRelease` verifies only with the committed keyring
`.github/workflows/keys/tobydox-mingw-w64.gpg`: it carries two signatures and every
one of them must check out (`gpgv` exits 2 when a signer's key is missing), which is
why the keyring holds both keys. The fixture is never regenerated by a test; if the PPA rotates
its signing key, refresh this file from the URL above (and the keyring) in one
commit, recording the new sha256 here.
